伴随 v1.6.64 与 v1.6.66 两个版本，AMMDS 在“功能智能化”之外，也悄悄补齐了一整套系统维护工具。从音视频基础依赖 FFmpeg 的自动管理，到一键系统检查、按需导出运行日志，再到封面裁剪工具箱与优雅关机，这些都是让 AMMDS 更“好管”的关键拼图。本文带你一次看懂这套维护工具箱的用法。

## 一、FFmpeg 集成工具

### 为什么需要它

FFmpeg/FFprobe 是音视频处理的“地基”——视频时长探测、音频提取、截图、字幕流程里的音频分段都离不开它。但 FFmpeg 在不同平台、不同架构（x86 / ARM）下的安装方式不一，一直是 NAS 用户的小痛点。v1.6.64 起，AMMDS 把它“收编”进了集成体系。

### 怎么用

入口：**集成 → FFmpeg**

页面使用通用的资源下载卡片，支持：

- 手动触发下载
- 查看下载进度
- 删除已下载文件

更重要的是**启动后自动下载**：AMMDS 启动时会自动检查 FFmpeg/FFprobe 是否安装，缺失则异步提交下载，不阻塞启动；下载未完成时每 60 秒重新检查一次。

这意味着你升级或迁移部署后，无需再为 FFmpeg 单独操心——AMMDS 会自己把它装好。

## 二、通用工具下载服务

FFmpeg 之外，v1.6.64 还引入了一套统一的工具程序异步下载框架，替代各插件原本各自为政的下载逻辑。

### 支持的工具

| 工具标识 | 工具名 | 组件 |
|---|---|---|
| `TOOL_FFMPEG` | FFmpeg | FFmpeg + FFprobe |
| `TOOL_METATUBE` | MetaTube | MetaTube 程序 |
| `TOOL_VIDEO_HASHES` | VideoHashes | VideoHashes 程序 |
| `TOOL_VIBEVOICE` | VibeVoice | 常驻服务程序 + 命令行推理程序 |

### 它解决了什么

- **异步下载**：固定 2 线程池异步下载，不阻塞主流程
- **防重复**：已就绪或下载中的组件自动跳过，避免同一组件被重复提交
- **多源回退**：下载地址支持多源，失败自动回退到下一源
- **进度跟踪**：统一返回文件名、路径、是否就绪、下载进度等状态
- **统一路径展示**：所有工具下载路径展示逻辑统一，排查时一目了然

MetaTube、ThePornDB、VibeVoice 等插件的集成页面都新增了资源下载卡片，从此插件依赖的本地程序也能“一键到位”。

## 三、系统检查

### 解决什么问题

AMMDS 跑得久、跑得稳之后，最怕的就是“不知道哪里不对劲”——某个站点认证过期、某个依赖缺失、网络到某个源不通……v1.6.66 的系统检查功能把这些“看不见的健康指标”一次性扫出来。

### 怎么用

入口：**系统 → 系统检查**

点击扫描后，系统会逐项检查并生成报告：

- 系统基础配置
- 软件依赖
- 运行状态
- 网络连通性（多 URL 多角度探测）

进度条会从 0 慢慢爬到 1，扫描完成后延迟 600ms 切换为完成状态。最小保底时长 8 秒，避免扫描太快造成闪烁；网络检查采用多 URL 多角度探测，比单点检测更可靠。

> 建议每次升级、迁移部署或遇到“莫名其妙的刮削失败”时，先跑一次系统检查，往往能直接定位到是依赖缺失还是网络不通。

## 四、运行日志导出

### 解决什么问题

排查问题离不开日志，但 AMMDS 长时间运行会产生主日志和多个滚动日志文件，手动拼起来既繁琐又容易漏文件。v1.6.66 的运行日志导出功能把它变成了一次点击的事。

### 怎么用

入口：**系统 → 运行日志**

支持 1 / 7 / 30 天范围导出（参数范围 1~90 天）。导出特性如下：

| 特性 | 说明 |
|---|---|
| 时间范围 | 支持 1/7/30 天范围导出，参数范围 1~90 天 |
| 日志聚合 | 自动聚合指定时间范围内的主日志与滚动日志文件，按日期升序拼接 |
| 文件命名 | `ammds-logs-{起始日期}-{结束日期}.log` |
| 大小上限 | 导出大小上限 100MB，超出时截断最旧部分，保留最新日志 |
| 单文件截断 | 单个日志文件超过剩余配额时，仅读取最新部分 |
| 编码格式 | UTF-8 编码，`text/plain` 类型 |

导出文件包含元信息头（导出时间、时间范围、文件数量）与各日志文件内容，结构清晰：

```
AMMDS 系统日志导出
导出时间: yyyy-MM-dd HH:mm:ss
时间范围: 起始日期 ~ 结束日期
文件数量: N

==== 文件: AMMDS.log ( 日期: yyyy-MM-dd) ====
<日志内容>

==== 文件: AMMDS-2026-08-20.log ( 日期: 2026-08-20) ====
<日志内容>
...
```

> 提交问题反馈或寻求社区帮助时，附上一份近 7 天的运行日志导出，能大幅提升沟通效率。注意超大文件浏览器可能短暂卡顿，建议按时间范围分批导出。

## 五、封面裁剪工具箱

### 解决什么问题

影视封面常常需要按媒体服务器要求裁剪成不同比例（海报、缩略图、背景图等），手动裁剪又慢又容易切歪。v1.6.66 的封面裁剪工具箱把它变成了可视化、可批量、可复用的操作。

### 怎么用

两个入口：

- **工具箱 → 封面裁剪**：独立的图片裁剪页面，支持本地图片裁剪和服务器图片批量生成裁剪副本
- **媒体编辑 → 封面裁剪**：在编辑某条影视资源时，直接对封面快速裁剪

主要能力：

- 通用裁剪弹窗组件，可在多处复用
- 工具箱页面替换原有裁剪面板为弹窗组件
- 媒体编辑页面新增封面快速裁剪入口
- 影视编辑页面新增海报、缩略图等图片的上下移动排序功能

v1.6.66 还重构了裁剪面板的测量逻辑，修复了几个让人头疼的错位问题：

| 问题 | 修复方案 |
|---|---|
| 裁剪选框错位 | 使用 `offsetWidth` 替代 `getBoundingClientRect`，避免动画缩放导致选框错位 |
| 裁剪框定位偏差 | 新增图片舞台偏移计算，修正裁剪框定位 |
| 跨来源裁剪结果残留 | 新增窗口 resize 监听和组件卸载时的资源清理 |
| 本地/服务器图片选择 | 重构页面，新增双预览区域和裁剪结果展示 |

现在裁剪封面，所见即所得。

## 六、优雅停止

最后是一个不起眼但很重要的改进——系统服务新增了 `stop` 异步停止接口，实现优雅关机流程。

它解决的是强制终止时任务未正常释放、文件未写完、连接未关闭的问题。升级、迁移、维护时，用优雅停止代替直接 `kill`，可以让正在进行的刮削、字幕任务尽可能收尾，避免数据不一致。

## 七、一套组合拳：典型维护流程

把这些工具串起来，一次完整的健康巡检可以这样走：

1. **升级前**：跑一次 **系统检查**，确认依赖与网络都正常
2. **升级后**：进入 **集成 → FFmpeg** 确认音视频依赖已就绪，必要时手动触发下载
3. **日常**：用 **系统检查** + **运行日志导出（近 7 天）** 做定期体检
4. **出问题时**：先用 **运行日志导出** 拿到现场，再用 **系统检查** 看健康度，定位后再修
5. **维护收尾**：用 **优雅停止** 平滑关机，避免任务被强杀

## 结语

智能化是 AMMDS 这两个版本的“台前”主角，但维护工具箱的完善是“幕后”的底气。FFmpeg 自动就位让音视频能力开箱即用，系统检查与日志导出让问题无处遁形，封面裁剪让媒体库更整洁，优雅停止让运维更安全。

把这些维护能力用熟，你会发现 AMMDS 不仅功能多，而且越来越“好管”。后续版本我们将继续打磨系统级体验，让私人数据平台的日常运维真正轻松起来。
