# 连通性诊断：把「刮削失败」拆成可执行的结论

「刮削没结果」是 support 里最常见的一句话，但它至少可能是四种完全不同的故障：网络不通、域名被墙、接口鉴权失败、站点风控。新版本在仪表盘补了一张连通性清单，目的就是把这句话拆成可执行的结论。

## 为什么不是「能 ping 通就行」

AMMDS 依赖的站点差异极大：DMM 会跳年龄验证、TMDB 需要 API Key、ThePornDB 对未授权请求返回 401、部分 DoH 端点只接受特定 Content-Type。

因此判定标准定为：**后端能否拿到目标服务器的 HTTP 响应**。

| 结果 | 含义 |
| --- | --- |
| 收到任意状态码（200/302/401/403/404） | 链路可达，服务在响应 |
| 域名解析失败 | DNS 问题 |
| 连接超时 | 出网被阻断或目标不可达 |
| 连接被重置 | 中间设备干扰或站点封禁 |
| TLS 握手失败 | 证书、时间或 TLS 版本问题 |

这条标准的价值在于：**可访问但功能失败，问题就不在网络**。这时应该去查 API Key、配额、站点账号状态，而不是反复改代理。

## 为什么坚持串行

清单动辄四五十个域名。并发探测更快，但会同时占用出口带宽与连接数，弱网或代理环境下互相拖慢，耗时数据也失去参考意义。

所以这里刻意采用串行：按表格顺序逐行发起，每行完成立即回显。你看到的不只是最终结论，还有「卡在哪一行」——如果前几行都是 200 ms，到某个域名突然变成 4 秒超时，问题范围就很小了。

## 几个实用判读

**大面积超时，且每行都接近 4 秒**

这是「出网被封」的典型形态：连接超时时间固定，所有目标都等满再失败。先查主机网络与防火墙，而不是逐个排查站点。

**只有境外域名失败**

跨境链路问题。在 **系统配置 → 网络代理** 启用代理后重测，同一张表会立刻告诉你哪些恢复了。

**全部可访问，但刮削仍然空**

网络已排除，去查：插件是否启用、API Key 是否有效、站点账号是否可用、番号是否本身不存在。

**DNS 分组整体失败**

DoH 端点常被网络策略拦截，属于预期现象，通常不影响其他功能。

## 与系统检查的分工

| 工具 | 回答的问题 |
| --- | --- |
| 连通性清单 | 某个域名现在通不通、多快 |
| 系统检查 | 数据库、磁盘、依赖程序、插件配置、许可证是否正常 |

前者是「网络快照」，后者是「整体体检」。排障顺序建议先看连通性定位网络，再看系统检查确认配置，最后回到任务日志看具体报错。

## 一个使用习惯

升级或更换网络环境后，先跑一次连通性清单，把结果当作基线。之后出现刮削问题，再跑一次，对比哪几行从可访问变成了不可访问——这比逐条试插件快得多。
