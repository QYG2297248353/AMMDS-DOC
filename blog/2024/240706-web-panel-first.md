在决定 AMMDS 的主界面形态时，我们做过一次认真的讨论：做桌面客户端，还是做 Web 面板？最终 Web 面板胜出。这篇文章复盘当时的判断。

{/* truncate */}

## 一个绕不开的前提：它跑在你自己的设备上

自托管软件有一个和 SaaS 完全不同的使用场景：程序装在一台长期开机的设备上——可能是家里的 NAS、一台迷你主机，或者一台旧电脑。你不一定坐在它面前，但你需要随时能管理它。

如果做桌面客户端，意味着你必须走到那台设备前，或者配置远程桌面。而 Web 面板天然解决了这个问题：只要浏览器能访问到那台设备，你就能管理媒体库。

## 随处可用的管理体验

Web 优先带来的最直接好处，是设备无关：

- **PC**：坐在电脑前，用完整的面板做批量整理；
- **平板 / 手机**：躺在沙发上，随手补一条元数据、看看任务进度；
- **NAS**：直接在 NAS 管理界面的浏览器里打开，无需额外安装客户端。

对很多把 AMMDS 装在 NAS 上的用户来说，"打开浏览器就能用"几乎是使用门槛能否跨过去的关键。

## 移动优先不是一句口号

我们说的"移动优先"，不是把桌面界面缩小，而是从一开始就让布局在小屏幕上也能成立：

- 常用操作放在拇指能够到的位置；
- 表格在小屏下自动转为卡片式布局；
- 关键状态（任务进度、扫描结果）一眼可见。

这些细节今天看起来平常，但在 2024 年做设计决策时，是实实在在多花了几周打磨的地方。

## 我们没有放弃本地体验

需要说明的是，Web 优先并不等于"只有 Web"。后来我们仍然推出了 Windows 原生客户端（Launcher），用于解决"不想记地址、想一键打开"的场景。但它的本质是一个 Web 面板的壳——真正的界面和逻辑，仍然是同一套 Web 应用。

这个选择让维护成本保持在可控范围：我们只需要维护一套界面，而不是分别维护桌面端和 Web 端。
