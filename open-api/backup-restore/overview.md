# 备份包里有什么

AMMDS 可以把影视和演员的资料导出成一个压缩包（备份包），也可以把这个包再导入回去。这一页是给想**自己写备份脚本**、或者想**打开包看看里面有什么**的人看的：讲清一个合规的包长什么样、哪些地方容易出错。

只想在界面上备份和恢复的话，后台功能里的「备份与恢复」那一步就够了，不用看这一页。

## 先说清楚

> **备份包**：一个 zip 压缩包，里面装着导出的资料。可以拿来在两台 AMMDS 之间搬家，或者长期归档。

> **JSON**：包里资料文件的排版格式，由「字段名」和「值」组成，人和程序都能读。

> **清单**：包里那份写着「这个包是什么、有多少条、图片在哪」的说明文件，AMMDS 导入时先看它。

> **唯一识别码**：一部影片的编号。导入时靠它判断「这条资料是不是已经存在」。

## 一个包里装什么

| 文件 | 必须有吗 | 里面是什么 |
| --- | --- | --- |
| `manifest.json` | 是 | 清单：格式标识、版本、数据类型、生成时间、条目数、图片映射 |
| `data.json` | 是 | 真正的资料，一个 JSON 数组，一条元素对应一部影片或一个演员 |
| `images/` | 否 | 图片目录。只有导出时勾了「同时导出图像文件」才会有 |

两个必需文件都放在压缩包的**根目录**下。

:::warning[一个包只装一种数据]
一个包只能装**影视**或**演员**中的一种，不能混着装。类型写在清单的 `type` 字段里：影视是 `movie`，演员是 `actor`。
:::

## 清单里写了什么

| 字段 | 说明 |
| --- | --- |
| `format` | 格式标识，固定是 `ammds-backup` |
| `formatVersion` | 格式版本号，当前是 `1` |
| `type` | 数据类型：`movie`（影视）或 `actor`（演员） |
| `generatedAt` | 生成时间 |
| `appVersion` | 生成这个包的 AMMDS 版本号 |
| `includeImages` | 包里有没有图片文件 |
| `count` | `data.json` 里有多少条资料 |
| `imageFiles` | 图片映射列表，每条记着「原来的路径 → 包里的路径 → 文件摘要」 |

没勾「同时导出图像文件」时，`images/` 目录不存在，`includeImages` 是 `false`，`imageFiles` 是空列表。

## 图片怎么处理

包里的图片字段保持**原始引用**的样子，分两种：

| 方式 | 长什么样 | 导出时进不进包 | 导入时怎么处理 |
| --- | --- | --- | --- |
| 网络外链 | `http` 或 `https` 开头的完整网址 | **不进包** | 全程原样保留，不会被改写 |
| 本地路径 | `data` 开头的本地相对路径 | 文件真实存在时才进包 | 落盘后回写成新的 `data` 路径 |

两种可以同时在同一个字段里出现。

要点只有两句：外链在导出和导入全程都不动；本地路径只有在文件真的存在时才会进包，导入后会被换成新的路径。

:::note[导入时图片会去重]
包里带图片时，导入会按文件内容做去重：内容一样的文件只存一份。这样反复导入同一个包不会把磁盘撑大。
:::

## 导入时怎么对上号

| 数据类型 | 凭什么认定是同一条 |
| --- | --- |
| 影视（`movie`） | 唯一识别码有交集。已有记录的编号和导入条目的编号只要有一个相同，就算同一条 |
| 演员（`actor`） | 姓名完全一致才算同一条 |

碰到已经存在的记录时，按你选的策略处理：

| 策略 | 行为 |
| --- | --- |
| 跳过 | 已有的不动，只把新记录加进来 |
| 覆盖 | 已有的更新成包里的版本，没有的新建 |

## 什么样的包会被直接拒收

出现下面任何一种情况，整个导入会被拒绝，并且**不会改动任何已有数据**：

- 清单里的 `format` 不是 `ammds-backup`。
- 格式版本比当前程序支持的更高。
- 缺少 `manifest.json` 或 `data.json`。
- 包里有试图跳出解压目录的可疑文件路径。

## 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| `format` | 固定写 `ammds-backup` | 写错整个包被拒收 |
| `formatVersion` | 写当前版本 `1` | 高于支持范围会被拒收 |
| `type` | 写 `movie` 或 `actor` | 填别的类型或两种混装，包不合法 |
| `data.json` | 资料数组，每条字段跟 AMMDS 里的实体一致 | 缺文件会被拒收；字段不对会导入失败 |
| 图片引用 | 外链写完整网址，本地图写 `data` 开头的相对路径 | 路径写错时导入后端图片会不存在 |
| 冲突策略 | 选「跳过」或「覆盖」 | 不选的话碰到重复记录时行为不确定 |

## 出问题了怎么办

- **导入被拒收**：先打开 `manifest.json` 看 `format` 是不是 `ammds-backup`、`type` 是不是 `movie` 或 `actor`，这两个错得最多。
- **导入后图片不显示**：图片是外链的话不会被处理，检查一下那个网址现在还能不能打开；是本地路径的话，确认导出时勾了「同时导出图像文件」。
- **导入后条目数不对**：影视按编号匹配、演员按姓名完全匹配。编号写法不一致、姓名多了空格，都会被认为是新记录。
- **想确认包有没有被改动过**：对比清单里每条图片映射记录的文件摘要和包里实际文件的摘要。
