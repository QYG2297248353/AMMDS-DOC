# 功能概述

本文介绍 AMMDS 备份恢复功能的能力范围、使用流程与基本概念，帮助开发者快速理解备份包的用途与使用方式。

{/* truncate */}

AMMDS 备份恢复用于影视 / 演员元数据的**导出（备份）**与**导入（恢复）**，以 zip 压缩包为载体在实例之间迁移或归档元数据，并可选携带图片文件。

## 能力范围

备份恢复支持以下数据类型：

| 类型 | code | 说明 |
|------|------|------|
| 影视 | `movie` | 影视元数据（`MovieEntity`），含文件信息、演员、系列、磁力、字幕等 |
| 演员 | `actor` | 演员元数据（`ActorEntity`），含基本信息、身材数据、社交链接等 |

> 单个备份包只承载**一种类型**的数据，影视与演员不能混装于同一包内。

## 使用流程

### 导出（备份）

1. 在 AMMDS 影视 / 演员管理界面，选中需要导出的条目
2. 选择「导出」操作，系统将选中条目序列化为 `data.json`
3. 可选勾选「同时导出图像文件」：
   - 勾选时，将本地 `data` 路径图片一并打入 `images/` 目录，并生成 `manifest.json` 映射
   - 不勾选时，包内只含 `data.json`（及空映射的 `manifest.json`），图片字段保留原始引用
4. 下载生成的 zip 备份包

### 导入（恢复）

1. 在 AMMDS 管理界面选择「导入」操作，上传备份包
2. 系统解析 `manifest.json` 校验合法性（格式标识、版本、路径穿越等）
3. 校验通过后读取 `data.json`，按匹配规则逐条写入：
   - 影视按 `uniqueid` 交集匹配
   - 演员按 `name` 完全一致匹配
4. 若包内含图片，则按内容 SHA-512 去重落盘并回写字段引用
5. 按所选冲突策略（`skip` / `overwrite`）处理已存在记录

详细的匹配规则与冲突策略见 [包结构](./package-structure.md#导入规则)。

## 图片处理方式

备份包中图片字段保持「原始引用」形式，分为两种存储方式，二者可在同一字段列表中共存：

| 方式 | 值形式 | 导出是否进包 | 导入处理 |
|------|--------|-------------|---------|
| http 外链 | `http` / `https` 开头的完整 URL | **不进包** | 全程原样保留，不做改写 |
| data 本地路径 | `data` 开头的本地相对路径 | 文件存在则进包 | 落盘并回写为新的 `data` 路径 |

> **要点**：`http` 外链在导出、导入全程不被改写；`data` 本地路径仅在文件真实存在时进包，导入后会被回写为新路径。详见 [包结构 - 图片映射规则](./package-structure.md#图片映射规则)。

## 备份包基本结构

一个完整的备份包为 zip 压缩包，根目录包含：

```
backup.zip
├── manifest.json    # 清单：格式标识、版本、类型、条目数、图片映射
├── data.json        # 元数据数组（JSON）
└── images/          # 可选：仅当导出时勾选「同时导出图像文件」才存在
```

完整的目录布局、清单字段与元数据字段定义见 [包结构](./package-structure.md)。
