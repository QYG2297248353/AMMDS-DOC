# 第一次调用

这一页带你完整走一遍：发一句话给 AMMDS，收到回答，然后看懂回答里每个字段是什么意思。例子可以直接复制，只改地址和你自己的钥匙。

开始前请准备好[先拿一把钥匙](./api-key.md)里的那两样东西：开放接口开关已打开、手上有一把 X-API-KEY 类型的钥匙。

## 先说清楚

> **请求**：发给 AMMDS 的一句「我要什么」。

> **响应**：AMMDS 回答回来的一包内容。

> **JSON**：回答内容的排版格式，样子像 `{"code": 200, "data": true}`，一层层由「字段名」和「值」组成。

> **状态码（错误码）**：回答里的 `code` 字段，一个数字，直接告诉你这次是成了还是没成。

## 准备

| 项目 | 说明 |
| --- | --- |
| 实例地址 | AMMDS 那台机器的地址，例如 `http://192.168.1.10:8080` |
| 钥匙 | 在「系统 → 密钥管理」里创建，类型选 X-API-KEY |
| 开放接口开关 | 在「系统 → 系统配置」里打开（配置键 `GLOBAL_OPEN_API`） |

后面的例子统一用 `http://192.168.1.10:8080`，你换成自己的地址就行。

## 第一步：先用浏览器确认服务在不在

健康检查这个地址**不需要钥匙**，所以可以直接用浏览器打开。把下面这行粘到浏览器地址栏里回车：

`http://192.168.1.10:8080/api/v1/health/check`

浏览器里会显示这样一段：

```json
{
  "code": 200,
  "message": "success",
  "data": true,
  "timestamp": 1753958400000
}
```

`data` 是 `true`，说明服务正在运行、地址也没写错。

:::note[这一步不检查别的]
健康检查只证明程序在跑。数据库、磁盘、外部服务正不正常，它不管，那些要在后台的「系统检查」里看。
:::

## 第二步：带钥匙问一次影片总数

这一步要带钥匙，浏览器地址栏没法带钥匙，所以要用命令行。下面是一整行，复制后在终端里回车（`<你的密钥>` 换成你自己的）：

```bash
curl -s -H "x-api-key: <你的密钥>" \
  http://192.168.1.10:8080/api/v1/movie/count
```

回答是这样：

```json
{ "code": 200, "message": "success", "data": 1286, "timestamp": 1753958400000 }
```

`data` 里的 `1286` 就是库里的影片总数。如果这里的 `code` 是 `401`，回头对照[先拿一把钥匙](./api-key.md)逐条检查。

## 第三步：按编号检索一部影片

```bash
curl -s -X POST http://192.168.1.10:8080/api/v1/movie/search \
  -H "x-api-key: <你的密钥>" \
  -H "Content-Type: application/json" \
  -d '{"keyword":"ABC-123","waitTime":30}'
```

回答里的 `data` 是一个列表，每个元素是一条资料：

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "source": "metatube",
      "provider": "jav",
      "number": "ABC-123",
      "title": "示例标题",
      "summary": "示例简介",
      "cover": "https://example.com/cover.jpg",
      "actors": ["演员A"],
      "genres": ["类型A"],
      "score": 8.6,
      "runtime": 120,
      "release": "2025-10-16 00:00:00",
      "extras": {}
    }
  ],
  "timestamp": 1753958400000
}
```

### 这些字段都是什么意思

| 字段 | 意思 |
| --- | --- |
| `code` | 这次调用成没成。`200` 到 `299` 之间算成功 |
| `message` | 一句话说明，失败时会写清原因，可以直接看 |
| `data` | 真正的资料本体。失败时一般是 `null` |
| `timestamp` | 服务端回答的时刻，是一串毫秒数 |
| `source` / `provider` | 资料来自哪个来源、来源下的哪个分类 |
| `number` / `title` / `summary` | 编号、标题、简介 |
| `cover` | 封面图地址 |
| `actors` / `genres` | 演员、类型，方括号里可以有多项 |
| `score` / `runtime` / `release` | 评分（10 分制）、时长（分钟）、发行日期 |
| `extras` | 只有这个来源才有的额外字段 |

:::note[字段可能是空的]
不同来源能给的资料不一样，给不出就返回空值。这不是出错，别把它当异常处理。
:::

## 第四步（可选）：把检索到的资料存进库

拿到 `source` 和 `id` 之后，就可以直接存进去：

```bash
curl -s -X POST http://192.168.1.10:8080/api/v1/movie/import/from-source \
  -H "x-api-key: <你的密钥>" \
  -H "Content-Type: application/json" \
  -d '{"source":"metatube","id":"12345","provider":"jav"}'
```

回答的 `data` 就是存好之后的影片 ID。

## 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 实例地址 | `http://<地址>:<端口>`，端口默认 `8080` | 填错就一直连不上，直到超时 |
| `x-api-key` | 你创建的那把 X-API-KEY 钥匙 | 不对就返回 `code` 为 `401` |
| `keyword` | 要查的编号或标题关键词 | 是必填的，不填会被判参数错误 |
| `waitTime` | 最多等各个来源多少秒，不填按默认值走 | 网络慢的时候填得太小，可能还没等到结果就返回了 |
| `source` / `id` | 上一步检索结果里的来源和编号 | 填错或来源没启用，会导入失败 |
| `Content-Type` | 发 JSON 正文时写 `application/json` | 不写的话，服务端可能读不懂你发的正文 |

## 出问题了怎么办

- **浏览器打不开健康检查**：说明地址或端口不对。先确认 AMMDS 在运行；如果访问的是另一台机器，别用 `127.0.0.1`。
- **`code` 是 `401`**：开放接口开关没开，或者钥匙类型不是 X-API-KEY、钥匙复制不全。
- **检索回来是空列表**：多半是一个资料来源都没启用。去插件配置里启用一个并测一下连接。
- **导入失败**：先确认 `source` 这个来源已经启用、参数没写错；编号已经存在的话，重复导入不会产生两条记录。
