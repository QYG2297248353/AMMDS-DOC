# 申请与鉴权

开放接口使用 API Key 鉴权。本文说明开启开关、创建密钥、携带方式与失败排查。

{/* truncate */}

## 第一步：开启开放 API

![系统配置](/img/api/sys-api-01.png)

1. 登录后台，进入 **系统 → 系统配置**
2. 找到开放 API 开关（配置键 `GLOBAL_OPEN_API`）并开启
3. 保存配置

:::warning[两个条件缺一不可]
请求头必须携带有效的 `x-api-key`，**并且** `GLOBAL_OPEN_API` 处于开启状态，否则鉴权失败。
:::

## 第二步：创建密钥

![创建 API Key](/img/api/sys-api-02.png)

1. 进入 **系统 → 密钥管理**
2. 点击创建密钥
3. 填写名称（如「自动化脚本」）便于日后区分用途
4. 类型选择 **X-API-KEY**（`secret_x_api_key`）
5. 保存后立即复制密钥；页面关闭后无法再次查看完整内容

:::note[密钥类型是隔离的]
密钥管理里还有「AMMDS 助手」与「Mihon 扩展」两种类型。**只有 X-API-KEY 类型**能在 `/api/v1` 使用；Mihon 授权码只能在 `/api/mihon` 使用，两者不能混用。
:::

## 第三步：携带密钥

```bash
curl -H "x-api-key: <你的密钥>" \
  "http://127.0.0.1:8080/api/v1/movie/count"
```

| 项目 | 值 |
| --- | --- |
| 请求头名称 | `x-api-key` |
| 作用范围 | 仅 `/api/v1/**` |
| 免鉴权路径 | `/api/v1/health/**` |

## 鉴权失败的表现

鉴权失败返回统一响应体，`code` 为 `401`：

```json
{
  "code": 401,
  "message": "您的登录已过期，请重新登录",
  "data": null,
  "timestamp": 1753958400000
}
```

排查顺序：

1. `GLOBAL_OPEN_API` 是否已开启
2. 请求头名称是否拼写为 `x-api-key`（小写，连字符）
3. 密钥类型是否为 X-API-KEY
4. 密钥是否已被删除或重置
5. 请求路径是否确实属于 `/api/v1`（带上 `x-api-key` 访问管理端接口会被拒绝）

## 安全建议

- **按用途拆分**：不同脚本用不同密钥，泄露时可单独撤销
- **不写入前端**：密钥会出现在浏览器网络面板中，只应保存在服务端或本地环境变量
- **定期轮换**：删除重建即可完成轮换
- **配合网络隔离**：开放 API 建议只在内网或反向代理鉴权之后暴露

## 常见问题

**Q：密钥丢失了怎么办？**

删除旧密钥并新建一个，然后更新调用方配置。

**Q：可以给访客使用吗？**

不建议。API Key 等价于账号权限，且不会经过登录日志的用户维度审计。

**Q：为什么管理端接口带上 `x-api-key` 反而报错？**

设计如此：携带 `x-api-key` 时只允许访问 `/api/v1`，避免用长期密钥绕过 JWT 与登录审计。
