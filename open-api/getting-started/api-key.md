# 先拿一把钥匙

想让别的程序读 AMMDS 的资料，第一步是拿一把「钥匙」。这一页讲钥匙是什么、怎么拿到、怎么保管、丢了怎么办。

如果你还不确定自己需不需要钥匙，先看[开放平台能做什么](./overview.md)。

## 先说清楚

> **API Key**：一串字符，相当于你家的家门钥匙。谁拿着它，谁就能按权限读你的资料。AMMDS 不看你是谁，只看这串字符对不对。

> **鉴权**：进门之前先亮身份的过程。对开放接口来说，就是把钥匙放进请求里一起发出去。

> **请求头（Header）**：跟着请求一起发出去的一小段附加信息，写在正文外面，用来交代「钥匙是什么、内容是什么格式」这类事情。

## 分三步拿到钥匙

### 第一步：打开开放接口开关

1. 登录 AMMDS 后台，进入 **系统 → 系统配置**。
2. 找到开放接口的开关（配置键 `GLOBAL_OPEN_API`），把它打开。
3. 保存配置。

:::warning[两个条件缺一不可]
请求里必须带着有效的 `x-api-key`，**并且**开放接口开关是打开的，两个条件都满足才进得去。少一个都会被挡住。
:::

### 第二步：创建钥匙

1. 进入 **系统 → 密钥管理**。
2. 点创建密钥。
3. 名称填一个你能认出来的用途，例如「自动备份脚本」，以后好区分。
4. 类型选 **X-API-KEY**（`secret_x_api_key`）。
5. 保存后**立刻复制**钥匙内容；页面关掉之后就再也看不到完整内容了。

:::note[钥匙类型之间不通用]
密钥管理里还有「AMMDS 助手」和「Mihon 扩展」两种类型。**Mihon 类型的授权码只能用在 `/api/mihon`**，不能调用 `/api/v1`；其余类型（含 X-API-KEY、AMMDS 助手）技术上都能用于 `/api/v1`。不过开放接口推荐统一用 **X-API-KEY**，语义最清楚，也最容易排查问题。
:::

### 第三步：把钥匙带在请求里

下面是命令行里的一次完整调用，`<你的密钥>` 换成你刚复制的那一串：

```bash
curl -H "x-api-key: <你的密钥>" \
  "http://127.0.0.1:8080/api/v1/movie/count"
```

| 项目 | 值 |
| --- | --- |
| 请求头名称 | `x-api-key`（全小写，中间是连字符） |
| 作用范围 | 只管 `/api/v1/**` |
| 不用钥匙的地址 | `/api/v1/health/**` |

## 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 开放接口开关 | 在「系统 → 系统配置」确认已打开，配置键 `GLOBAL_OPEN_API`（默认是开的） | 关掉的话，钥匙再对也进不去，一直报没权限 |
| 密钥名称 | 随便填，写成用途最好认 | 不影响使用，只是以后不好区分是哪把钥匙 |
| 密钥类型 | 推荐 **X-API-KEY** | Mihon 类型不能用于 `/api/v1`；其余类型虽可用，但不推荐 |
| 钥匙内容 | 创建时复制下来的那一整串字符 | 少复制一个字符、或多了空格，都会鉴权失败 |
| 请求头名称 | 必须是 `x-api-key` | 写成 `api-key`、`X_API_KEY` 之类都不认 |

## 钥匙丢了或泄露了怎么办

钥匙不像密码那样能改，只能是「作废旧的、换一把新的」：

1. 进 **系统 → 密钥管理**，把出问题的那把钥匙**删除**。
2. 重新创建一把，复制好新内容。
3. 把所有用到旧钥匙的地方（脚本、客户端、工具配置）都换成新的。

:::warning[钥匙泄露了先做这一步]
删除旧钥匙是第一优先。删掉之后旧钥匙立刻失效，别人拿到也用不了。换完新钥匙后，把新钥匙当成密码一样保管，不要贴在聊天记录、论坛或代码仓库里。
:::

平时保管的几条建议：

- **按用途分开**：备份脚本一把、手机客户端一把。哪一把出问题就只作废那一把。
- **不要放进网页前端**：钥匙会出现在浏览器的网络面板里，等于公开。只放在服务端或本机。
- **定期换**：删掉重建就算换过一次了。
- **尽量只在内网用**：开放接口最好只在家里局域网里暴露，确有必要放到公网时，前面再加一层登录保护。

## 被挡在门外是什么样子

鉴权失败时，AMMDS 照样回答一段内容，只是里面的 `code` 是 `401`：

```json
{
  "code": 401,
  "message": "您的登录已过期，请重新登录",
  "data": null,
  "timestamp": 1753958400000
}
```

按顺序检查下面几条：

1. 开放接口开关是否已经打开。
2. 请求头名称是不是拼成 `x-api-key`（全小写、连字符）。
3. 钥匙类型是不是 X-API-KEY。
4. 钥匙是不是已经被删除或重建过。
5. 访问的地址是不是真的属于 `/api/v1`（带着钥匙去访问后台管理接口会被拒绝，这是故意的）。

## 出问题了怎么办

- **报 401**：照上面五条顺序查一遍，最常见的两个原因是开关没开、钥匙类型选错。
- **钥匙复制不全**：删掉重建一把，复制时不要漏掉开头或结尾的字符。
- **带着钥匙反而访问不了后台管理接口**：这是设计如此。钥匙只允许访问 `/api/v1`，避免用一把长期钥匙绕开登录记录。
- **想给访客用一把钥匙**：不建议。钥匙的权限等同于你的账号，而且不会按用户留下登录记录，出事查不到是谁。
