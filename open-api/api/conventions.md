# 请求和返回怎么读

所有开放接口都遵守同一套规则。先看这一页，能省掉后面大半的解析和判断错误。

## 先说清楚

> **请求**：你的程序发给 AMMDS 的一句「我要什么」。

> **响应**：AMMDS 回答回来的一包内容。

> **JSON**：内容的排版格式，由「字段名」和「值」一层层组成，例如 `{"code": 200, "data": true}`。

> **请求头（Header）**：跟请求一起发出去的一小段附加信息，写在正文外面，用来交代钥匙、内容格式这类事情。

> **错误码**：回答里的 `code` 字段，一个数字，直接说明这次是成了、还是因为什么没成。

> **分页**：资料太多时一次只给一页，用页码和每页条数分批取。

## 基础信息

| 项目 | 说明 |
| --- | --- |
| 地址 | `http://<主机>:<端口>`，端口默认 `8080` |
| 字符编码 | UTF-8 |
| 请求和返回的格式 | `application/json`（上传文件的接口是 `multipart/form-data`） |
| 鉴权 | 请求头带 `x-api-key` |

## 返回的包长什么样

不管成功还是失败，返回的都是同一副样子：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1753958400000
}
```

| 字段 | 意思 |
| --- | --- |
| `code` | 一个数字，说明这次是成了还是没成 |
| `message` | 一句话说明，失败时会写清原因，可以直接拿给用户看 |
| `data` | 真正的资料本体，失败时通常是 `null` |
| `timestamp` | 服务端回答的时刻，一串毫秒数 |

:::warning[别只看网页状态码]
除了漫画阅读器那套接口，业务上的失败通常**仍然返回成功状态的 HTTP 响应**，真正的结果要看返回包里的 `code`。判断成功的标准是 `200 <= code < 300`。
:::

## 错误码对照

| `code` | 意思 | 常见原因 |
| --- | --- | --- |
| `200` | 成了 | `data` 里就是要的资料 |
| `400` | 你发的东西不对 | 参数没通过校验、必填的没填 |
| `401` | 没权限 | 钥匙没带、钥匙无效，或者开放接口没开 |
| `403` | 不给访问 | 权限不够 |
| `404` | 找不到 | 地址或那个对象不存在 |
| `500` | 服务端出错了 | 程序内部异常，`message` 里会写原因摘要 |

:::note[有的接口用 data 表达失败]
少数接口（比如导入）失败时返回 `code=500` 且 `data=false`，这样调用方在一个字段里就能拿到结果。以各接口自己的说明为准。
:::

## 时间怎么写

| 场景 | 格式 | 例子 |
| --- | --- | --- |
| 返回包里的日期时间 | `yyyy-MM-dd HH:mm:ss`（东八区时间） | `2025-10-16 20:30:00` |
| 请求里要填的日期 | `yyyy-MM-dd` | `2025-10-16` |
| 时间戳 | 毫秒 | `1753958400000` |

## 一个字段里有多项怎么办

影片资料里的「编号、封面、类型、标签、导演、制作公司」都是**多值字段**。

- **读的时候**：返回的是标准 JSON 数组，例如 `"actors": ["演员A", "演员B"]`。
- **写的时候**：快捷导入接口直接收数组；表单上传接口（`multipart/form-data`）要收数组的字符串形式。

## 分页

开放接口这一块的影片接口**不分页**，检索结果一次全给你。

漫画阅读器那套接口用 `page` 和 `pageSize` 分页，页码从 `1` 开始。

## 重复调用会不会出事

- **检索、详情、总数、匹配**：只是读一读，重试多少次都安全。
- **导入**：按唯一编号判重，重复导入不会产生两条记录。
- **翻译**：没有任何副作用。

## 等多久算超时

| 接口类型 | 建议超时 |
| --- | --- |
| 健康检查、取总数 | 5 秒 |
| 详情、本地匹配 | 10 秒 |
| 多来源检索 | 60 秒以上（`waitTime` 可调） |
| 翻译 | 30 秒 |

## 请求头一览

| 名称 | 值 | 用在哪些地址 |
| --- | --- | --- |
| `x-api-key` | 你的钥匙 | 只管 `/api/v1/**` |
| `Authorization` | `Bearer <授权码>` | 只管 `/api/mihon/**` |
| `Content-Type` | `application/json` 或 `multipart/form-data` | 按接口要求写 |

> **User-Agent**：请求里附带的一行小字，说明「我是什么程序」。你不用填，也不用改。

## 设置项说明

发一次请求要填的东西就这几样：

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 主机和端口 | `http://<主机>:<端口>`，端口默认 `8080` | 填错就一直连不上 |
| `x-api-key` | 系统里创建的 X-API-KEY 钥匙 | 不带或写错，返回 `code` 为 `401` |
| `Content-Type` | 发 JSON 正文写 `application/json`；传文件写 `multipart/form-data` | 写错的话，服务端可能读不懂你发的正文 |
| 多值字段 | 快捷导入用 JSON 数组；表单上传用数组的字符串形式 | 格式不对会被判参数错误 |
| 日期参数 | 按 `yyyy-MM-dd` 写 | 写成别的格式，校验通不过 |

## 出问题了怎么办

- **HTTP 显示成功，但资料不对**：别只看 HTTP 状态码，回到返回包里看 `code` 和 `message`。
- **`code` 是 `400`**：对照接口说明检查必填参数，尤其是字段名和类型。
- **`code` 是 `401`**：确认开放接口开关已打开、钥匙类型是 X-API-KEY、请求头名字拼成 `x-api-key`。
- **时间对不上**：返回里的时间是东八区时间，跟你的本地时区可能差几个小时，这是正常的。
- **某个字段是空的**：不同来源能给的资料不一样，给不出就返回空值，不是故障。
