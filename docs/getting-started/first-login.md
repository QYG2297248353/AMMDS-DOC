# 第一次打开：登录和基本设置

装好并完成初始化后，用你的管理员账号进后台，再按顺序做几件必要的事：改掉初始密码、收好恢复密钥、按需要绑域名和填站点信息。全部做完大概十分钟。

按顺序走完，再去做扫描和刮削，能省下很多排查时间。

## 账号从哪来

| 情况 | 用户名与密码 |
| --- | --- |
| 全新安装，启动时没设 `ADMIN_USER` / `ADMIN_PASS` | 初始化向导里你自己填的那一组，见[初始化向导](./install-wizard.md) |
| 启动时设置了 `ADMIN_USER` / `ADMIN_PASS` | 环境变量里指定的用户名和密码 |
| 2.x 小版本之间升级（如 2.0 → 2.1） | 沿用原来的管理员账号，不会重置 |

:::note[这里说的「升级」不包括 v1 → v2]
「沿用原来的管理员账号」只适用于 2.x 内部的小版本升级。从 1.x 换到 2.x 是一次全新安装，账号在初始化向导里重新设置，原因见[升级说明](../upgrade.md)。
:::

:::note[密码规则]
6–22 个字符，同时包含大写字母和小写字母，并且包含数字或特殊字符。之后改密码也按这个规则。
:::

## 登录

1. 浏览器打开 `http://主机IP:端口`。端口以你的安装方式为准：Docker 看你映射的主机端口，NAS 看安装时填的端口，直接运行默认是 `8080`。
2. 输入初始化时设置的用户名和密码。
3. 默认进入后台的工作台。如果之前把落地页改成了「优先进入前台」，登录后会先到前台首页，从菜单切回后台即可。

:::note[先用最终要用的地址登录一次]
登录成功时，系统会把你这次访问的地址自动记成「服务地址」，供文档和局域网自动发现等功能使用。所以请**先用以后长期要用的那个地址登录一次**，再去做域名绑定。
:::

## 第一步：改掉默认密码

1. 点右上角头像，选**用户中心**。
2. 在个人信息页头部点**修改密码**。
3. 依次填**当前密码**、**新的密码**、**二次确认**。
4. 点**提交修改**。成功后会自动登出，用新密码重新登录。

新密码要满足这些规则：

| 规则 | 说明 |
| --- | --- |
| 长度 | 6–22 个字符 |
| 组成 | 同时包含大写字母和小写字母，并且包含数字或特殊字符 |

## 第二步：收好恢复密钥

系统首次启动时会生成恢复密钥，保存在程序目录的 `data/secret/recovery.key`。忘记管理员密码时，在登录页点**忘记密码**，填入恢复密钥就能重置。

> **恢复密钥**：一个保存在文件里、用来在忘记密码时重置密码的钥匙。它不依赖数据库。

:::tip[现在就备份]
重装时如果只备份了 `db/` 而丢了 `data/secret/`，就再也找不回密码了。请把这个文件和数据库一起备份到安全的地方。
:::

## 第三步：绑定域名（可选）

打算用域名访问的话，先在域名服务商那里把域名解析到这台主机（也就是让域名指向这台机器的 IP），再进入**系统配置 → 基础配置 → 域名绑定**：

1. 点**修改**，填写域名。
2. 保存后标签会从「未绑定」变成「已绑定」。
3. 打开**系统检查**，确认「域名绑定」这一项通过。它会真的去验证域名是否指向本机；失败通常意味着解析还没生效、端口没放行，或者中间隔着一层没配好的反向代理（站在前面替你转发的服务器）。

只在内网用的话可以跳过这步，继续用 IP 访问。绑域名不是用其他功能的前提。

## 第四步：填站点信息

进入**系统配置 → 站点配置 → 基本配置**，填站点名称、副标题、描述和公司名称。这些内容会出现在前台页面标题、分享摘要和页脚。需要备案信息的，可以在同一页填写备案号和对应查询链接。

「系统配置」的其他标签页里还有主题外观、通知配置和安全配置。不确定的选项保持默认，以后随时能回来改。

## 第五步：配网络（按需）

如果服务器访问境外站点不稳定，进入**系统配置 → 网络配置**：

1. 打开**开启代理模式**。
2. 选择代理协议（HTTP / SOCKS4 / SOCKS5），填代理主机、端口和认证信息。
3. 按需维护「免代理」列表，把内网地址排除在代理之外。
4. 保存后重新测试连通性。

## 第六步：接插件、加媒体目录

基础设置完成后，再按实际需要接外部服务和加目录：

| 顺序 | 做什么 |
| --- | --- |
| 1 | 配置资料来源、下载器、媒体服务器等外部服务 |
| 2 | 添加媒体目录并建立扫描任务 |
| 3 | 对扫描结果执行刮削 |
| 4 | 浏览与整理影片库 |

具体怎么做见[十分钟整理好第一批影片](./first-library.md)。

## 第七步：跑一次系统检查

点右上角头像，选**系统检查**，执行一次扫描。它会检查数据库、磁盘、端口、系统时间、依赖程序（FFmpeg 等）、代理和插件配置，并把问题按类别列出来。

:::tip[把系统检查当验收清单]
首次部署后出现的黄色或红色项，基本都能在对应的配置页修掉。确认全部通过，再开始批量扫描和刮削。
:::

## 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 用户名 | 固定为 `ammds`，不用填 | 改成别的值会导致启动直接失败 |
| 当前密码 / 新的密码 / 二次确认 | 原密码，以及符合规则的新密码（6–22 位，含大小写，且含数字或特殊字符） | 新密码两次不一致或不符合规则会提交失败；忘了原密码就用恢复密钥重置 |
| 域名绑定 | 已解析到本机的域名 | 不填就只能用 IP 访问；填了但没解析生效，系统检查里这一项会不通过 |
| 站点名称 / 副标题 / 描述 / 公司名称 | 会显示在前台标题、分享摘要和页脚的文字 | 不填就用默认文案，不影响功能 |
| 落地页 | 登录后先到后台还是先到前台 | 选了「优先进入前台」，登录后要先从菜单切回后台 |
| 开启代理模式 | 开关，以及选 HTTP / SOCKS4 / SOCKS5 | 用不到代理就不用开；开了但地址填错，会大面积连不上网 |
| 代理主机 / 端口 / 认证信息 | 代理服务器的地址和端口，需要时填用户名密码 | 填错就连不上；SOCKS 不支持填用户名密码，只有 HTTP 支持 |
| 免代理列表 | 不走代理的地址，例如内网网段 | 不填的话访问内网服务（NAS、播放器）也会走代理，导致连不上 |

改完这些设置**一般不用重启**，保存后立即生效。

## 出问题了怎么办

- **登不进去**：确认用户名是 `ammds`；密码输错多次或忘了，就用恢复密钥在登录页重置。
- **改密码总失败**：对照上面的规则检查——长度、大小写、数字或特殊字符，三项都要满足。
- **恢复密钥找不到**：到程序目录的 `data/secret/` 下找 `recovery.key`；文件确实丢了又没有备份，就只能重装并重新整理。
- **域名绑了还是不通**：检查解析是否生效、端口是否放行、中间的转发服务器（反向代理）有没有配好；系统检查里的「域名绑定」一项会告诉你结果。
- **登录后页面样式错乱**：强制刷新一次（`Ctrl` + `F5`），升级后尤其容易遇到。
