# 用 Docker 安装

这是最常用的安装方式：一个容器里同时跑网页和后台，页面和数据都由同一个端口对外提供。这一页给你两条可以直接抄的命令，并讲清目录和权限该怎么配。

镜像里跑的就是发行包里的那个可执行程序，所以容器里不用装 Java，也没有 JAR / WAR 要管。

开始前请先确认：设备上已经装好 Docker，并且你知道自己的影片文件放在哪个目录。还没决定用哪种方式的话，先看[先选一种安装方式](./overview.md)。

> **镜像**：软件的打包文件，相当于「安装盘」。名字写成 `qyg2297248353/ammds:latest` 这样，冒号后面是版本标签。

> **容器**：镜像跑起来之后的那一份运行实例。

> **挂载**：把主机上一个真实目录接到容器内部，让容器能读写它，写法是「主机目录:容器内目录」。

## 选哪个镜像

| 镜像 | 说明 |
| --- | --- |
| `qyg2297248353/ammds:latest` | 最新版本，推荐用这个 |
| `qyg2297248353/ammds:版本号` | 固定某个版本，适合想控制升级时机的场景 |
| `qyg2297248353/ammds:latest-ol8` | 为较老的系统准备的变体。老机器跑标准镜像起不来时换这个 |
| `ghcr.io/qyg2297248353/ammds:latest` | 另一个下载源，拉取不顺畅时可以换成它 |

镜像同时提供 64 位 x86 和 ARM 两种架构，拉取时会自动匹配你的设备。

## 一条命令跑起来

```bash title="docker run"
docker run -d \
  --name AMMDS \
  -p 8080:80 \
  -v /opt/ammds/data:/ammds/data \
  -v /opt/ammds/db:/ammds/db \
  -v /opt/ammds/download:/ammds/download \
  -v /mnt/media:/mnt/media \
  -e TZ=Asia/Shanghai \
  -e PUID=1000 \
  -e PGID=1000 \
  --restart always \
  qyg2297248353/ammds:latest
```

启动后用 `http://主机IP:8080` 访问。如果 8080 已经被别的程序占用，只改冒号左边那个主机端口就行，例如 `8090:80`。

## 用 Compose 文件（推荐长期用）

把下面内容存成 `docker-compose.yml`，放在你打算存放数据的目录里。

```yaml title="docker-compose.yml"
services:
  ammds:
    image: qyg2297248353/ammds:latest
    container_name: AMMDS
    ports:
      - "8080:80"          # 页面与接口
      - "47823:47823/udp"  # 局域网发现（可选）
      - "47824:47824/udp"  # 局域网广播（可选）
    volumes:
      - ./data:/ammds/data
      - ./db:/ammds/db
      - ./download:/ammds/download
      - /mnt/media:/mnt/media
    environment:
      TZ: Asia/Shanghai
      PUID: "1000"
      PGID: "1000"
      UMASK: "022"
    restart: always
```

然后执行：

```bash
docker compose up -d
```

:::note[两个 UDP 端口要不要留]
网页服务只转发 TCP。如果不需要手机或客户端自动找到服务，可以删掉这两行 UDP 映射，改为在客户端里手动填服务地址。
:::

## 端口都是干什么的

| 端口 | 用途 | 要不要映射到主机 |
| --- | --- | --- |
| `80` | 容器内的网页，负责提供页面和数据 | 要，可以改成别的主机端口 |
| `8080` | 容器内的后台，只由容器里的网页转接 | 不要 |
| `47823/udp` | 让客户端能探测到服务 | 需要自动发现时才映射 |
| `47824/udp` | 服务主动广播自己的存在 | 需要自动发现时才映射 |

## 目录怎么挂

| 容器里的路径 | 装的是什么 | 建议 |
| --- | --- | --- |
| `/ammds/data` | 图片、缓存、字幕、日志、依赖程序、恢复密钥 | 必须挂出来持久保存 |
| `/ammds/db` | 数据库文件 | 必须挂出来，并纳入备份 |
| `/ammds/download` | 预留的下载目录，通常和下载器共用 | 建议挂出来 |
| 你的媒体目录 | 要扫描和整理的影片文件 | 主机路径和容器内路径保持一致 |

:::warning[不要把影片放进 /ammds]
`/ammds` 是程序和数据的根目录。影片目录请单独挂载（例如 `/mnt/media:/mnt/media`），否则清理数据或重装容器时容易一起删掉。
:::

## 文件权限：出现「写入失败」时看这里

容器默认以最高权限运行。把 `PUID`、`PGID` 设成非 0 之后，程序会换成这个用户的身份读写文件；新建文件的权限由 `UMASK`（默认 `022`）决定。

挂载的主机目录出现「写入失败」「无权限」时，优先把 `PUID` / `PGID` 改成主机上拥有该目录的那个用户。

## 怎么确认已经启动好了

```bash
docker logs -f AMMDS
```

日志里出现「服务已启动」，表示网页和后台都准备好了。如果页面提示「服务正在启动，请耐心等待」，说明网页已经能打开，后台还在初始化，稍等一下刷新即可。

:::tip[第一次启动会慢一点]
首次启动会自动下载 FFmpeg 等依赖程序，耗时取决于网络。是否就绪可以在头像菜单的**系统检查**里逐条确认。
:::

## 设置项说明

| 设置项 | 它管什么（大白话） | 不填会怎样 | 改完要不要重启 |
| --- | --- | --- | --- |
| 访问端口（主机端口映射，容器内是 `NGINX_PORT`） | 浏览器里访问用的端口 | 不填用容器内的默认值；不映射就访问不到 | 要（重建容器） |
| 时区（`TZ`） | 日志时间和定时任务按哪个时区算 | 不填用默认时区，任务时间可能对不上 | 要 |
| 运行用户（`PUID` / `PGID`） | 程序以哪个用户身份读写文件 | 不填以默认用户运行；和主机目录属主不一致会出现无权限 | 要 |
| 新建文件权限（`UMASK`） | 新生成文件的默认权限 | 不填用默认值，一般不用改 | 要 |
| 上传大小（`AMMDS_MAX_FILE_SIZE` / `AMMDS_MAX_REQUEST_SIZE`） | 单个文件、单次请求的大小上限 | 不填用程序默认值；传大文件失败时再调大 | 要 |
| 自动发现开关与端口（`AMMDS_DISCOVERY_ENABLED` / `AMMDS_DISCOVERY_PORT` / `AMMDS_DISCOVERY_ANNOUNCE_ENABLED` / `AMMDS_DISCOVERY_ANNOUNCE_PORT`） | 能不能让客户端自动找到服务，用哪两个 UDP 端口 | 不填按默认开启；不映射 UDP 端口就发现不到，只能手动填地址 | 要 |
| 内存上限（`AMMDS_MAX_HEAP`） | 程序最多能用多少内存 | 不填按容器内存限额自动算，一般不用改 | 要 |

更多启动设置见[环境变量](./settings.md)。

## 怎么升级

1. 备份挂出来的 `db/` 和 `data/` 目录。
2. 拉新镜像：`docker compose pull`（或 `docker pull qyg2297248353/ammds:latest`）。
3. 重建容器：`docker compose up -d`（或删掉旧容器后重新 `docker run`）。
4. 打开页面确认版本号和「系统检查」的结果。

数据都在挂载目录里，重建容器不会丢；但跨大版本升级前，仍建议留一份数据库副本。

## 出问题了怎么办

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 容器起来就退出 | 设备架构和镜像不匹配，或目录没有写权限 | 用 `docker logs AMMDS` 看报错；ARM 设备确认拉的是 arm64 镜像 |
| 页面 502 或提示「服务正在启动」 | 后台还在初始化 | 等一会儿并看日志，确认没有端口占用或数据库损坏 |
| 写不进媒体目录 | 容器内用户和主机目录属主不一致 | 调整 `PUID` / `PGID`，或修正目录权限 |
| 客户端发现不到服务 | 只映射了 TCP 端口 | 加上两个 UDP 映射，或在客户端手动填地址 |

- **上面四条都对不上**：先看日志 `docker logs AMMDS`，再到[常见问题](../faq.md)按现象找。
- **确认配置有没有生效**：打开工作台「系统信息」卡片看监听地址和版本号；插件是否连通在头像菜单的**系统检查**里看。
