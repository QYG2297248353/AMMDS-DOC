# 十分钟整理好第一批影片

这一页是一次走到底的教程：从「刚装好、什么都还没有」到「媒体库里第一批影片有封面、有简介」。按顺序做 1-2-3，每一步后面都写了**做完你应该看到什么**，卡住时照着检查点查就行。

开始前请先完成[第一次打开：登录和基本设置](./first-login.md)，并且跑过一次系统检查。

## 先说清楚

只需要三样东西：

| 要准备什么 | 说明 |
| --- | --- |
| 一个放着影片文件的目录 | 先拿一小批试，比如十来部，别一上来就丢几万个文件 |
| 文件名里能看出番号 | 番号就是影片的识别编号，程序靠它认片子。文件名里有它，识别才准 |
| 一个能用的资料来源 | 补资料要去资料网站查，需要先在集成应用里配好，并测一下能不能连上。完全内网的话这一步做不了 |

> **扫描**：让 AMMDS 去你指定的目录里翻一遍文件，认出里面有哪些影片。

> **刮削**：程序自动去资料网站查这部片子的封面、简介、演员、标签，然后填回来。

> **番号**：影片的识别编号，通常写在文件名里。认不出来就补不到资料。

## 第 1 步：告诉它文件在哪

1. 进入扫描任务页面，找到添加媒体目录的地方。
2. 填上你放影片的那个目录路径。Docker 用户请填**容器里看到的路径**——所以挂载时最好让主机路径和容器路径一致。
3. 保存。

### 这一步做完你应该看到什么

目录出现在列表里，而且程序能读到它——保存时没有报「路径不存在」或「无权限」。

### 卡住了？先查这几点

- 路径填错：多一层或少一层目录都会读不到，先把路径复制出来对着看一遍。
- 没有权限：NAS 上最常见。到 NAS 的共享文件夹权限里给 AMMDS 授权（见[在 NAS 上安装](./nas.md)）。
- Docker 里路径不存在：检查有没有把这个目录挂载进容器。

## 第 2 步：扫一遍，让它认识文件

1. 在扫描任务页面新建任务，选中刚才添加的目录。
2. 选择整理模式（决定扫完之后要不要动你的文件）。第一次建议用**只识别、不动文件**的模式，先看看效果；目录已经整理得很好、只想补齐图片和资料文件的，可以用「查漏补缺」模式。
3. 执行任务，等它跑完。

### 这一步做完你应该看到什么

任务状态变成完成，列表里出现识别出来的影片条目，条目上的番号看着是对的。

### 卡住了？先查这几点

- 任务报失败：到任务日志里点开这条任务看详情，失败原因和最后一个成功步骤都写在里面。
- 列表是空的：目录里可能没有可识别的文件，或者文件格式不在识别范围内。先用一个确定能识别的文件试。
- 扫到一半不动了：文件特别多时本来就慢，先看任务是否还在跑，再看日志有没有报错。

## 第 3 步：核对番号认对没有

1. 在扫描结果里随便挑几条，看程序认出来的番号和你自己认的是不是同一部片子。
2. 认错的，先改文件名（把番号写在开头、用统一的分隔符），再重新扫一次。

### 这一步做完你应该看到什么

大部分条目的番号都对得上。个别认不出来是正常的，不必追求一次全对。

### 卡住了？先查这几点

- 番号写法特殊：文件名里没有可识别的番号，或者写法太罕见，就认不出来。改成常见写法再扫。
- 同一部片子出现好几条：文件名写法不一致导致，把它们统一成同一种写法。

## 第 4 步：补上封面和简介

1. 进入刮削任务页面，新建一次刮削任务，选中刚才扫描出来的条目。
2. 选择要用哪个资料来源（配了多个的话可以只勾一个先试）。
3. 执行，等它跑完。一次批量处理有条数上限，条目多就多跑几次。

### 这一步做完你应该看到什么

影片条目开始出现封面图、简介、演员和标签；原来空白的地方填上了内容。

### 卡住了？先查这几点

- 任务成功但资料是空的：番号没认对，或者这个资料来源里没有这部片子。回到第 3 步核对番号，或换一个资料来源重试。
- 一直失败、提示连接失败：资料来源的地址或授权码不对，或者被对方站点拦了。到插件配置页点一次连通性测试（试试能不能连上），再用系统检查看它是「异常」还是「配置不完整」。
- 部分失败：正常现象，挑失败的单独重刮一次。

## 第 5 步：到媒体库里看成果

打开媒体菜单，看影片列表：一批有封面、有简介的片子已经排好了。点进详情还能看到海报、剧照、演员和标签。

到这里，第一批就整理完了。接下来可以做这几件事（都对不上也没关系，随时能回来）：

| 想做什么 | 去哪儿 |
| --- | --- |
| 按系列、厂牌、标签归类 | 媒体菜单里的整理页 |
| 让以后自动扫、自动补 | 扫描任务里开「目录监控」，或加一个定时扫描任务 |
| 在电视上看到海报墙 | 在集成应用里接媒体服务器 |
| 持续盯着新资源 | 在订阅相关页面设置 |

## 第 6 步：让它以后自己跑

1. 打开扫描任务里的**目录监控**开关：文件有变动就自动扫。
2. 或者建一个定时扫描任务，例如每天扫一次。
3. 确认定时任务总开关是打开的——关掉之后连手动执行也会被拒绝。

## 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 媒体目录路径 | 放影片文件的目录 | 填错或没权限就扫描不到文件；Docker 场景要填容器内路径 |
| 整理模式 | 第一次建议用「只识别、不动文件」；已整理好的目录可用「查漏补缺」 | 选了会移动 / 改名的模式，文件位置会变，动手前先想清楚 |
| 目录监控开关 | 文件有变动就自动扫 | 关掉后就只能靠定时扫描或手动执行 |
| 定时任务时间 | 多久跑一次 | 填错不会报错，只是跑的时机不对 |
| 资料来源（数据源） | 补资料去哪个网站查，以及它的地址、授权码 | 不配或填错就补不到资料；先在插件页做连通性测试 |
| 单批刮削条数上限 | 一次处理多少条 | 不填用默认值；条目多时会分批，多跑几次即可 |

## 出问题了怎么办

- **扫描结果一片空白**：多半是目录路径或权限的问题，回到第 1 步的检查点。
- **刮削一直失败**：先确认能不能访问那个资料网站；系统检查里的网络相关项能直接看出问题。
- **有封面但没简介（或反过来）**：说明资料来源本身这条数据不全，换一个资料来源补一次。
- **日志里没有明显报错但任务失败了**：到任务日志里点开这条任务的「详情」，看执行明细里的失败原因和最后一个成功步骤。
- **以上都对不上**：按现象去[常见问题](../faq.md)找，或带上版本号、时间点和日志片段到 GitHub 提问题：https://github.com/QYG2297248353/AMMDS-Docker/issues/new
