# 初始化向导：第一次配置

程序装好之后第一次打开，如果系统里还没有管理员账号，会自动进入初始化向导（地址是 `/setup`）。四步填完，就可以用刚创建的账号登录了。

:::note[什么时候会看到向导]
只有还没完成初始化时才会出现。已经初始化过再访问 `/setup`，会自动跳回首页；想重新走一遍，只能换一个空数据库。
:::

## 开始之前

- 准备一个邮箱，用于个人资料和头像同步（不验证邮箱真实性）
- 想好管理员用户名和密码（规则见下文）
- 整套流程两三分钟，中途可以点「上一步」返回修改

## 第一步：同意协议

页面提供「摘要」「用户协议」「隐私政策」三个标签页。摘要用大白话说明程序做什么、第一次打开会写哪些文件、数据存在哪里；完整条文通过页面上的链接打开。

读完后勾选「我已阅读并同意」，才能点「下一步」。

:::warning[必须勾选]
没勾选就点下一步，页面会提示需要同意协议，流程不会继续。
:::

## 第二步：创建管理员

| 项目 | 怎么填 | 规则 |
| --- | --- | --- |
| 用户名 | 以后登录用的名字 | 3–32 位，只能用字母、数字、下划线、中划线 |
| 邮箱 | 联系邮箱 | 必填，格式要对；后面的头像同步会用这个邮箱 |
| 密码 | 登录密码 | 6–22 位，必须同时有大写和小写字母，并且含数字或特殊字符 |
| 确认密码 | 再输一次 | 必须和上一项完全一致 |

> 如果启动时已经通过环境变量 `ADMIN_USER` / `ADMIN_PASS` 建好了管理员，这一步会显示「已完成」，只需要填邮箱，其余三项不用再填。

## 第三步：站点信息

| 项目 | 怎么填 | 不填会怎样 |
| --- | --- | --- |
| 站点名称 | 显示在浏览器标题、页脚的名字 | 必填 |
| 落地页 | 「优先后台」或「优先前台」 | 默认优先后台；选前台的话，以后打开根地址先进前台首页 |
| 备案号 | 需要就填，可选 | 不填页脚不显示备案信息 |

## 第四步：补全个人资料

这一步决定你在前台展示的身份。

| 项目 | 说明 |
| --- | --- |
| 头像 | 自动按邮箱去 Gravatar（一个按邮箱找头像的公共服务）取头像，取不到时生成一张带首字母的图；也可以自己上传，支持 PNG / JPEG / GIF / WebP / BMP，不超过 2 MB |
| 用户 ID | 4–32 位字母、数字、下划线、中划线；不能是 `admin`、`root`、`ammds` 这类保留字（被系统占用的名字），也不能全是数字 |
| 昵称 | 前台显示的名字，最多 32 个字 |
| 手机号 | 可选 |
| 社交链接 | 可选，最多 20 条；地址必须以 `https://` 开头 |

点「同步资料」可以按邮箱重新拉一次头像和昵称；已经手动改过的内容不会被覆盖。

## 提交之后

点「完成初始化」，成功后会自动跳到登录页，用第二步创建的账号登录即可。

:::tip[账号信息请记好]
向导里填的用户名之后不能在界面里修改；密码可以随时在用户中心改。恢复密钥是另一套东西，由程序首次启动时自动生成，和这里的密码无关。
:::

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 打开任何地址都跳到 `/setup` | 说明还没完成初始化，按向导走完即可 |
| 访问 `/setup` 又跳回首页 | 已经初始化过，直接登录 |
| 提示用户 ID 已被占用 | 换一个；保留字和纯数字也会被拒绝 |
| 社交链接提交不了 | 检查地址是不是以 `https://` 开头 |
| 头像上传失败 | 确认图片不超过 2 MB、格式在支持范围内 |
| 提交后登录不上 | 确认用的是第二步填的用户名和密码；忘记密码可以用恢复密钥重置 |
