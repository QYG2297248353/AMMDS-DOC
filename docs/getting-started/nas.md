# NAS 部署

NAS 是 AMMDS 常见的运行环境。除了用 Docker，飞牛 FnOS、威联通 QNAP 还提供原生应用包：由系统应用中心负责安装、启停和升级，不需要自己维护容器。本页说明两条路线的差别、安装步骤与目录规划。

{/* truncate */}

## 先选路线

| 路线 | 特点 | 适合 |
| --- | --- | --- |
| NAS 应用包（FPK / 威联通应用包） | 由应用中心安装，安装向导里设置密码与端口；启停、升级都在应用中心完成 | 希望少折腾、以 NAS 为主要使用设备 |
| Docker 容器 | 端口、目录、环境变量完全可控，升级即换镜像 | NAS 支持 Docker / Container Station，且你熟悉容器 |

两条路线的数据目录含义相同：`data/` 存图片、缓存、日志与依赖程序，`db/` 存数据库，媒体文件单独放在存储空间里。具体端口与挂载见[Docker 部署](/docs/getting-started/docker)。

:::warning[应用包来源]
只从官方发行页下载安装包。第三方改包可能夹带脚本，或使用与当前版本不一致的目录结构，导致升级后数据丢失。
:::

## 飞牛 FnOS

### 下载

在官方发行页下载最新的 FPK 安装包：

- [AMMDS-Offline-FnNas Releases](https://github.com/QYG2297248353/AMMDS-Offline-FnNas/releases)

可以把安装包下载到电脑后再上传，也可以直接在飞牛设备上下载。

### 安装

1. 打开 **应用中心**，点击左下角的 **手动安装**，选择下载好的 FPK 文件。
2. 点击 **安装**，在提示页确认后进入安装流程。
3. 阅读许可说明并同意。
4. 选择安装位置：挑选空间充足、且**不会被系统当临时目录清理**的存储空间。
5. 设置管理界面登录密码，建议使用强密码。
6. 设置访问端口，并记下该端口，安装完成后用它访问。
7. 确认配置无误，等待进度条走完。

安装完成后，可以在「文件管理 → 应用文件」中找到 AMMDS 的安装目录，查看程序文件；`data/`、`db/` 等数据目录的实际位置以安装包布局为准。

### 安装后

- 用 `http://NAS_IP:安装时填写的端口` 打开页面。
- 如需扫描媒体，先在 NAS 上确认 AMMDS 对媒体目录有读取权限，再在 AMMDS 里添加目录。
- 升级时在应用中心安装新版本包；升级前先备份安装目录下的 `db/` 与 `data/`。

## 威联通 QNAP

### 下载

在官方发行页按设备架构下载对应安装包（x86 或 ARM）：

- [AMMDS-Offline-QNAP Releases](https://github.com/QYG2297248353/AMMDS-Offline-QNAP/releases)

### 安装

1. 登录 QNAP 管理界面，打开 **App Center**。
2. 选择手动安装 / 导入本地应用包，选中下载好的安装文件。
3. 按向导选择安装卷，设置访问端口。
4. 安装完成后从应用列表启动 AMMDS。

若设备已启用 Container Station，也可以改用 Docker 方式部署，目录与端口配置与通用 Docker 部署一致。

### 安装后

- 用 `http://NAS_IP:端口` 访问；端口以安装向导中填写的为准。
- 媒体目录建议放在同一存储池，避免跨卷扫描带来的权限问题。
- 升级前同样先备份 `db/` 与 `data/`。

## 目录规划

| 位置 | 建议 |
| --- | --- |
| 程序与数据目录 | 放在主存储卷的独立目录，不要放在系统盘或会被自动清理的临时目录 |
| 媒体目录 | 单独建共享文件夹（如 `/媒体/影视`），授权给 AMMDS 运行账号只读或读写 |
| 下载目录 | 与下载器共用同一目录，容器或应用内路径保持一致 |
| 备份 | 定期把 `db/` 与 `data/` 复制到另一块磁盘或远程存储 |

:::tip[媒体路径保持一致]
如果 NAS 上同时跑了 qBittorrent、Jellyfin 等应用，让它们看到媒体目录的**路径完全一致**（例如都用 `/媒体/影视`），可以避免 AMMDS 推送下载后找不到文件。
:::

## NAS 上的常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 安装时提示空间不足 | 选择的卷剩余空间不足 | 换一个存储卷，或先清理空间 |
| 页面能打开但扫描不到文件 | 应用账号没有共享文件夹权限 | 在 NAS 的共享文件夹权限中授权 |
| 重启 NAS 后服务未启动 | 应用未设置开机自启 | 在应用中心开启自启动 |
| 升级后数据为空 | 新版本安装到了不同目录，或旧目录未保留 | 恢复升级前的 `db/`、`data/` 备份，并核对安装路径 |

首次登录与初始化设置见[首次登录与初始化](/docs/getting-started/first-login)。
