# 在 NAS 上安装

NAS 是很多人跑 AMMDS 的地方。除了用 Docker，飞牛 FnOS、威联通 QNAP 还提供**应用包**：由 NAS 自己的应用中心负责安装、启停和升级，不用你维护容器。

这一页讲两条路线怎么选、具体的安装步骤，以及目录该怎么规划。通用 Docker 部分见[用 Docker 安装](./docker.md)。应用包只是 NAS 帮你把程序装好的入口，里面装的仍然是同一个程序，不是另一种版本。

> **NAS**：专门用来存文件的网络设备，例如飞牛 FnOS、威联通 QNAP。

> **应用包**：NAS 专用的安装包，由 NAS 的应用中心负责安装和更新。

## 先选路线

| 路线 | 特点 | 适合 |
| --- | --- | --- |
| 应用包 | 由应用中心安装，安装向导里设置密码和端口；启停、升级都在应用中心完成 | 想少折腾、以 NAS 为主要使用设备 |
| Docker 容器 | 端口、目录和启动设置都能自己定，升级就是换个镜像 | NAS 支持 Docker，而且你熟悉容器 |

两条路线的数据目录含义是一样的：`data/` 存图片、缓存、日志和依赖程序，`db/` 存数据库，影片文件单独放在存储空间里。

:::warning[安装包只从官方下载]
只从官方发布页下载安装包。第三方改包可能夹带别的脚本，或者目录结构和当前版本不一致，升级后数据会丢。
:::

## 飞牛 FnOS

### 下载

在官方发布页下载最新的安装包：https://github.com/QYG2297248353/AMMDS-Offline-FnNas/releases

可以先下载到电脑再上传，也可以直接在飞牛设备上下载。

### 安装

1. 打开**应用中心**，点左下角的**手动安装**，选中下载好的安装包。
2. 点**安装**，在提示页确认后进入安装流程。
3. 阅读许可说明并同意。
4. 选择安装位置：挑一个空间充足、且**不会被系统当临时目录清理**的存储空间。
5. 设置管理界面的登录密码，建议用强密码。
6. 设置访问端口，并记下来，装完后就用它访问。
7. 确认无误，等进度条走完。

### 装好之后

- 用 `http://NAS的IP:安装时填的端口` 打开页面。
- 要扫描影片，先在 NAS 上确认 AMMDS 对影片目录有读取权限，再回到 AMMDS 里添加目录。
- 升级时在应用中心装新版本包；升级前先备份安装目录下的 `db/` 和 `data/`。

## 威联通 QNAP

### 下载

按设备架构（x86 或 ARM）在发布页下载对应安装包：https://github.com/QYG2297248353/AMMDS-Offline-QNAP/releases

### 安装

1. 登录 QNAP 管理界面，打开**App Center**。
2. 选择手动安装或导入本地应用包，选中下载好的安装文件。
3. 按向导选择安装卷，设置访问端口。
4. 装完后从应用列表里启动 AMMDS。

如果设备已经装了 Container Station，也可以改用 Docker 方式，目录和端口配置与通用 Docker 一致。

### 装好之后

- 用 `http://NAS的IP:端口` 访问，端口以安装向导里填的为准。
- 影片目录建议放在同一个存储池里，避免跨卷扫描带来权限问题。
- 升级前同样先备份 `db/` 和 `data/`。

## 目录怎么规划

| 位置 | 建议 |
| --- | --- |
| 程序与数据目录 | 放在主存储卷的独立目录，不要放系统盘，也不要放会被自动清理的临时目录 |
| 影片目录 | 单独建一个共享文件夹，把读取（或读写）权限授予 AMMDS 的运行账号 |
| 下载目录 | 和下载器共用同一个目录，两边看到的路径保持一致 |
| 备份 | 定期把 `db/` 和 `data/` 复制到另一块磁盘或远程存储 |

:::tip[让所有程序看到同一个路径]
如果 NAS 上还跑了下载器、播放器之类的应用，让它们看到的影片目录**路径完全一致**（例如都用同一个共享文件夹路径），可以避免 AMMDS 推送下载后找不到文件。
:::

## 设置项说明

| 设置项 | 它管什么（大白话） | 不填会怎样 | 改完要不要重启 |
| --- | --- | --- | --- |
| 访问端口 | 浏览器里访问用的端口号，安装向导里填写 | 不填就拿不到访问地址；装完后忘了端口可以到应用中心的设置里查看 | 要 |
| 管理密码 | 登录管理界面的密码，安装向导里设置 | 不设就用默认密码，任何能访问到这个端口的人都能进来 | 不用，登录后可改 |
| 安装位置 | 程序和数据放在哪个存储卷 | 选到空间不足或会被清理的卷，会出现安装失败或数据丢失 | 要（重装） |
| 影片目录与权限 | 告诉程序去哪里找文件，以及它有没有读取权限 | 没授权就扫描不到文件，现象是「目录是空的」 | 不用，改权限后立即生效 |
| 开机自启 | NAS 重启后服务是否自动起来 | 不开自启，每次重启 NAS 都要手动启动一次 | 要 |

登录之后还能改的启动设置，见[环境变量](./settings.md)。

## NAS 上的常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 安装时提示空间不足 | 选的存储卷剩余空间不够 | 换一个存储卷，或先清理空间 |
| 页面能打开但扫描不到文件 | 应用账号没有共享文件夹的权限 | 在 NAS 的共享文件夹权限里授权 |
| 重启 NAS 后服务没起来 | 应用没设置开机自启 | 在应用中心里打开自启动 |
| 升级后数据为空 | 新版本装到了别的目录，或旧目录没保留 | 恢复升级前的 `db/`、`data/` 备份，并核对安装路径 |
| 手机或客户端发现不到服务 | NAS 网络里广播被拦，或 UDP 端口没放通（Docker 路线） | 在客户端手动填服务地址，或按 Docker 那篇的说明映射 UDP 端口 |

## 出问题了怎么办

- **装不上**：先看是不是空间不足或选错了架构的包（x86 / ARM 要对应）。
- **打不开页面**：确认 NAS 的防火墙放行了这个端口，并且你用的 IP 和端口是对的。
- **扫描不到文件**：这是 NAS 上最常见的问题，九成是共享文件夹权限没给；先在 NAS 的权限设置里授权再试。
- **升级后出问题**：先恢复备份的 `db/` 和 `data/`，再核对安装路径是不是变了；现象都对不上时，到[常见问题](../faq.md)按现象找。
