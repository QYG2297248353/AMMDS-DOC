# 实例互通

实例互通用于连接多个 AMMDS 部署：两个站点互为好友后，可以互发消息、检索对方媒体库，并把对方的漫画或小说元数据导入到本地。好友关系基于站点令牌，不需要把账号密码交给对方。

{/* truncate */}

## 前提条件

1. 双方都在 **系统配置** 中打开「互联互通」开关（默认关闭）。
2. 双方站点都能从对方网络访问；使用域名时建议配置 HTTPS。
3. 已知对方的站点地址（含协议或 `IP:端口`）。

未开启开关时，好友申请与检索都不会成功。

## 好友列表

| 字段 | 说明 |
| --- | --- |
| 好友 | 显示昵称或站点名；未互通的记录带「添加」标签，关系以「双向 / 单向」标注 |
| 状态 | 在线、连接中、长期离线、离线 |
| 站点地址 | 对方域名，旁边提供「检测」按钮主动刷新状态 |
| 备注 | 自定义备注 |
| 操作 | 续签、资料、消息、修改、删除 |

- **续签**：通过一次性的换取流程更新访问令牌，令牌失效或对方重置后使用；失败会提示站点不可达或一次性码失效。
- **资料**：修改好友昵称、站点名称与备注；站点地址只读。
- **修改**：只改备注，保存后立即生效。
- **删除**：软删除好友，历史消息与申请记录保留。

## 添加好友

1. 点击「添加好友」，填写对方站点地址（如 `https://blog.example.com` 或 `IP:端口`）。
2. 点击「解析」，系统探测对方的互联互通服务，并自动回填好友 ID 与昵称。
3. 按需填写站点名称、站点备注。
4. 填写申请理由（必填），点击「申请添加」。

申请会以「我发出的申请」形式存在，等对方在收件箱中通过后建立双向关系；长时间未处理时可在已发申请里重发，被拒绝后可以重新发起新的申请。

## 收件箱

入口按钮带未处理申请数量角标，弹窗内有两个页签：

| 页签 | 内容 | 操作 |
| --- | --- | --- |
| 申请 | 收到的好友申请，展示来源站点与申请理由 | 通过、拒绝 |
| 消息 | 各好友站点推送过来的消息 | 仅查看 |

审批后对方即出现在好友列表；已处理的申请不再显示通过/拒绝按钮。

## 已发申请

展示「站点 → 对方昵称」、申请理由与当前状态：

| 状态 | 含义 |
| --- | --- |
| 待处理 | 对方尚未审批，可点「重发」再次投递 |
| 已通过 | 已成为好友 |
| 已拒绝 | 对方拒绝，可重新发起新的申请 |

重发只对「待处理」的申请开放。

## 好友检索

「好友检索」会**并发**向所有好友站点发起查询，再合并结果：

| 项 | 说明 |
| --- | --- |
| 检索类型 | 影视、演员、漫画、小说 |
| 关键词 | 必填，回车或点「搜索」触发 |
| 结果字段 | 好友站点、类型、标题 |
| 导入 | 仅漫画与小说提供「导入」按钮 |

导入会把对方的元数据写入本地库；同名冲突或对方详情缺失时导入失败并给出提示。影视与演员结果只用于查看，不支持一键导入。

正文字段、海报等资源仍由各自站点维护，互通不会复制对方的媒体文件。

## 消息

在好友行点「消息」打开会话窗口：

- 消息按时间排序，自己发送的靠右、对方发来的靠左，时间精确到分钟。
- 输入内容后点「发送」，由对方站点接收并落库；发送失败会提示错误，可稍后重试。
- 消息只保存在双方数据库中，不经中心服务器转发。

## 状态与令牌

| 状态 | 说明 |
| --- | --- |
| 在线 | 最近探测可访问 |
| 连接中 | 正在建立连接或等待响应 |
| 长期离线 | 连续多次探测失败，建议检查对方站点或网络 |
| 离线 | 当前不可达 |

好友状态由探测任务与「检测」按钮共同维护。令牌用于双方接口鉴权；续签走一次性的换取流程，避免长期使用同一凭据。

## 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 解析站点失败 | 地址错误、对方未开启互联互通或不可达 | 核对地址与开关，先在浏览器访问对方站点 |
| 申请一直待处理 | 对方未查看收件箱 | 提醒对方审批，或用「重发」再次投递 |
| 状态长期离线 | 网络隔离、证书失效或令牌过期 | 用「检测」确认，再尝试「续签」 |
| 检索无结果 | 对方媒体库无匹配内容 | 换关键词或类型后重试 |
| 导入失败 | 同名冲突或对方详情缺失 | 先处理本地同名记录，或改用其它来源 |

站点的互联互通总开关与访问地址在[系统配置](/docs/system/config)中维护；互通产生的通知会进入[系统消息](/docs/information/message)。
