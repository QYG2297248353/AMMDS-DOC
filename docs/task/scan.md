# 扫描任务

扫描任务负责把磁盘上的视频文件登记为「待刮削媒体」：按扩展名与忽略规则筛选文件、读取媒体信息、识别字幕与分段标记，再交给刮削流程匹配元数据并整理。

{/* truncate */}

## 打开方式

进入 **任务管理 → 任务配置**，默认停在「任务列表」页签。点击「点击创建扫描任务」卡片打开创建弹窗；已有任务卡片上可以「编辑」「记录」「删除」或执行主操作。

## 创建任务

创建弹窗的字段与后端任务配置一一对应：

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 必填，用于任务列表与日志识别 |
| 分类 | 影视 / 剧集；剧集任务走独立的剧集识别与刮削管线 |
| 媒体类型 | 分类为影视时是影片产地分区（日本AV、欧美、国产、FC2 PPV 等） |
| 剧集分区 | 分类为剧集时替换「媒体类型」位置，可选全部、番剧、日剧等 |
| 整理模式 | 决定整理时文件如何搬运，见下表 |
| 扫描目录 | 必填，只能选择目录节点，文件节点不可选 |
| 整理目录 | 除原地整理与查漏补缺外必填；原地类模式会自动跟随扫描目录 |
| 重命名规则 | 原文件名 / 标准化文件名 |
| 重复文件处理规则 | 目标已存在重复文件时保留哪一份 |
| 目录监控 | 仅新建时可设置，开启后由文件事件触发扫描 |
| 加入收藏 | 扫描并刮削后把影片加入收藏；仅对影视任务生效 |
| 计划任务 | 关闭目录监控时显示，填写 Spring 风格 Cron 表达式 |

:::tip[路径选择]
扫描目录与整理目录都通过服务器文件树选择，展开目录时才按需加载子目录。创建前请确认运行 AMMDS 的进程对该目录有读取（整理目录还需要写入）权限。
:::

## 整理模式

| 模式 | 行为 |
| --- | --- |
| 原地整理 | 不移动文件，只按刮削结果重命名/补充元数据 |
| 标准化整理（移动） | 把文件移动到整理目录，按目录格式与文件名格式落盘 |
| 标准化整理（复制） | 复制一份到整理目录，保留源文件 |
| 标准化整理（软连接） | 在整理目录创建软链接，不额外占用数据空间 |
| 标准化整理（硬连接） | 在整理目录创建硬链接，要求源与目标在同一文件系统 |
| 查漏补缺 | 不改变目录结构与文件名，只补齐缺失的图片与 NFO |

「原地整理」与「查漏补缺」不需要单独选择整理目录；切换到这两种模式时，整理目录会自动填为扫描目录。

## 重命名与重复文件

重命名规则只有两种取值：

- **原文件名**：整理后沿用扫描到的文件名。
- **标准化文件名**：按「影视刮削规则 → 整理文件名格式」生成新文件名。

重复文件规则决定目标目录已存在重复项时保留哪一份：

| 规则 | 保留对象 |
| --- | --- |
| 保留 | 保留原文件，不按体积/日期/分辨率重新取舍 |
| 大文件 / 小文件 | 保留体积较大或较小的一份 |
| 新文件 / 旧文件 | 保留日期较新或较旧的一份 |
| 高分辨率 / 低分辨率 | 保留分辨率较高或较低的一份 |

## 扫描规则

扫描阶段读取「任务配置 → 扫描规则配置」中的全局规则，影视与剧集分别取不同配置项：

| 规则 | 影视 | 剧集 |
| --- | --- | --- |
| 视频格式限制 | `scanning_video_format` | 复用同一项 |
| 忽略目录 | `scanning_ignore_dir` | `scanning_tv_ignore_dir` |
| 忽略文件 | `scanning_ignore_file` | `scanning_tv_ignore_file` |
| 最小视频大小 | `scanning_min_size`（MB） | `scanning_tv_min_size`（MB） |
| 视频分段标记 | `scanning_video_segmentation` | 不使用 |
| 字幕格式 | `scanning_subtitle_format` | 复用同一项 |
| 读取本地 NFO | `scanning_read_nfo` | `scanning_tv_read_nfo` |

剧集还有「特别篇关键词」「集号缺失默认季」「绝对编号识别」等专属规则。修改规则后只影响后续扫描，不会回改已入库记录。逐项说明见 [任务配置](/docs/task/config)。

## 扫描流程

1. 从扫描目录开始递归收集文件，按视频扩展名白名单筛选。
2. 跳过命中「忽略目录」的整棵子树，以及文件名包含「忽略文件」关键词的文件。
3. 全量扫描时按最小视频大小过滤；目录监控触发的单文件扫描不做体积过滤。
4. 读取文件信息与媒体信息（类型、分辨率、大小、音视频编码、码率等）。
5. 检查同目录是否存在同名字幕文件，记录字幕类型。
6. 按分段关键词判断是否为多段文件（如 `cd1`、`part2`）。
7. 开启「读取本地 NFO」且文件已有 NFO 时，解析 NFO 并写入对应步骤记录。
8. 同一路径已入库时不重复创建记录，只把记录重新绑定到本次扫描任务。

## 识别发生在哪一步

扫描阶段**不做番号识别**，只登记文件名与媒体信息；「识别番号」列在刮削匹配后才会有值。番号识别由刮削阶段的「识别码规则」与「番号补全规则」完成。

例外情况是本地 NFO：开启读取后，扫描可以直接从 NFO 恢复元数据与识别码。识别失败或识别错时，可到 **任务管理 → 刮削入库 → 影视刮削** 点击识别番号标签手工修改。

## 运行方式

| 方式 | 触发条件 | 说明 |
| --- | --- | --- |
| 立即扫描 | 未开启目录监控的任务 | 卡片主按钮，提交后异步执行 |
| 初始化 | 已开启目录监控且状态为「创建」 | 首次全量扫描并注册目录监听 |
| 监控中 | 已开启目录监控且已初始化 | 按钮不再触发扫描，只表示监听中 |
| 定时扫描 | 关闭目录监控且填写了 Cron | 由调度器按表达式触发 |

:::warning[目录监控与手动扫描互斥]
开启目录监控后，任务不支持手动扫描；必须先完成初始化。目录监控与 Cron 也是二选一：开启监控时不会保存 Cron，关闭监控时才会按 Cron 注册定时任务。
:::

## 目录监控

目录监控基于文件系统事件，而不是定时轮询：

- 注册扫描目录及其全部子目录，新建子目录会递归补注册。
- 只在检测到**新建视频文件**时触发扫描，且扩展名必须在扫描规则的格式白名单内。
- 只处理本次事件对应的文件，不做整目录重扫。
- 目录删除时自动注销对应监听；应用重启后会按任务配置重新注册。

:::caution[资源开销]
目录监控会占用文件系统监听句柄，目录层级很深或文件变动频繁时资源消耗较大。Linux 下 inotify 句柄耗尽会导致监控服务启动失败，此时应减少监控目录或调整系统上限。
:::

## 查看扫描结果

| 目的地 | 内容 |
| --- | --- |
| 任务管理 → 扫描日志 | 每次扫描的运行类型、开始时间、耗时、状态、识别/新增/更新数量，可取消进行中的任务 |
| 任务管理 → 刮削入库 → 影视刮削 | 已登记的视频文件、识别番号、媒体信息、刮削/整理状态，可绑定、解绑、删除、手工改番号 |
| 任务管理 → 刮削入库 → 剧集刮削 | 剧集文件按剧名聚合后的待确认分组，可合并、拆分、忽略、确认 |

扫描完成后不会自动刮削，除非开启了「自动刮削」或任务模式为「查漏补缺」。刮削的触发方式与步骤见 [刮削任务](/docs/task/scrape)；运行记录的状态与清理见 [任务记录与日志](/docs/task/record)。
