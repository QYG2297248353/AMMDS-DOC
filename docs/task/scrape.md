# 刮削任务

刮削任务接在扫描之后：按番号向已启用的数据源检索影视元数据，命中后写回标题、演员、标签、图片等字段，再按整理格式把文件与附属文件落到目标目录。

{/* truncate */}

## 打开方式

- **任务管理 → 刮削入库 → 影视刮削**：查看全部已扫描的影视媒体，触发刮削与整理。
- **任务管理 → 刮削入库 → 剧集刮削**：查看按剧名聚合的剧集分组，先确认剧集边界再刮削。
- **任务管理 → 任务配置 → 影视刮削规则 / 剧集刮削规则**：配置数据源、整理格式、NFO 字段与图片行为。

## 触发方式

| 入口 | 范围 | 说明 |
| --- | --- | --- |
| 刮削整理 | 全部待刮削影视 | 对未刮削媒体执行刮削 + 文件整理 |
| 仅刮削 | 全部待刮削影视 | 只匹配元数据、生成 NFO 与图片，不移动/重命名视频 |
| 选择整理 | 勾选的媒体 | 批量处理选中项，单次最多 120 条 |
| 自动刮削 | 按配置间隔 | 影视与剧集分别有开关与间隔；开启后默认每 3 分钟检查一次待办 |
| 查漏补缺 | 指定任务源目录 | 扫描完成后只补齐缺失的图片与 NFO，不改变目录结构 |

:::note[重复执行保护]
同一时间只允许一个刮削任务运行。已有任务在执行时，再次提交会被拒绝并提示「重复执行 - 刮削任务运行中」。
:::

## 刮削前准备

1. 至少启用一个元数据源插件，并在「影视刮削规则 → 刮削器」中勾选它。
2. 确认扫描已把目标文件登记到「刮削入库」，且文件路径可访问。
3. 如需自动整理，先确认整理目录存在且可写。
4. 如需生成 NFO 与图片，确认对应开关与字段已配置。

刮削不依赖下载器；下载器只影响订阅与手动推送，不影响元数据匹配。

## 数据源与优先级

「刮削器」是一个多选列表，默认包含：

`本地(默认)`、`MetaTube(插件)`、`ThePornDB(插件)`、`Stash(插件)`、`FANZA_DMM(插件)`、`M-Team_DMM(插件)`、`TheJavDB(插件)`、`R18Dev(插件)`、`TMDB(插件)`

实际执行规则：

1. 勾选的刮削器会**并发**发起检索，单个数据源失败或超时不会阻断其他数据源。
2. 各数据源把命中的影片写入本地影视库，随后系统回读本地匹配结果。
3. 回读时，若 TMDB 已启用且被勾选，优先使用 TMDB 的匹配结果；否则 JAV 番号走 MetaTube，欧美番号走 ThePornDB。
4. 其他数据源（Stash、FANZA_DMM、M-Team_DMM、TheJavDB、R18Dev）作为补充来源，命中后同样落入本地库，再由回读逻辑按番号或哈希找到记录。
5. 番号类数据源都未命中时，TMDB 可用的情况下会再按「片名 + 年份」尝试普通影视匹配。

:::tip[本地数据优先]
开启「本地数据优先」后，媒体已有绑定且绑定的影视仍然存在时直接复用，不再联网刮削；绑定失效才重新检索。适合已经整理过、只想补缺失字段的媒体库。
:::

:::warning[数据源限制]
MetaTube 不支持欧美番号；欧美番号应启用 ThePornDB 或 TMDB。数据源是否可用还取决于插件是否启用、站点账号是否有效以及网络连通性。
:::

## 字段回填

匹配成功后，系统把数据源返回的字段写入影视记录，并按配置补充衍生信息：

| 类别 | 内容 |
| --- | --- |
| 基础字段 | 标题、原始标题、简介、上映日期、时长、评分、导演、制作商、系列 |
| 演员 | 演员名、别名、头像与作品关联；可关闭「演员刮削」跳过 |
| 标签 / 分类 | 按「自动标签」「自动分类标签」的配置项追加分辨率、制作商、识别码、发行日期、演员、马赛克、中文字幕、破解等 |
| 图片 | 海报、背景图、缩略图、剧照；可选高清封面 |
| 翻译 | 开启「字段翻译」后按系统翻译配置翻译标题/简介等字段 |
| 番号 | 识别码与补全后的番号可混合输出，便于兼容不同站点的命名 |

「NFO 字段」决定生成 NFO 时写入哪些标签，默认包含大部分字段（含识别码 `num`）；不需要的标签可以从配置中移除。

## 目录与文件名

整理目录与文件名由「影视刮削规则」中的两个格式串决定：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| 整理目录格式 | `${actor}/${number}` | 每一级 `/` 会切分为一级目录 |
| 整理文件名格式 | `${number}` | 只写文件名主体，不含扩展名 |

可用占位符包括演员、番号、标题、日期、年份、月份、日、马赛克、分辨率、导演、制作商等；以 `_safe` 结尾的变体会把路径分隔符替换为空格。文件名超过 200 字节会被截断，整理后的相对目录路径超过 3600 字节会终止整理。

## 输出文件

刮削完成后，整理目录中可能生成以下文件：

| 文件 | 说明 |
| --- | --- |
| `<文件名>.nfo` | 按 NFO 字段配置生成，随视频同名 |
| `<文件名>-poster.jpg` | 封面；有码影片尽量保证竖版 2:3 |
| `<文件名>-fanart.jpg` | 背景图；有码影片尽量保证横版 |
| `<文件名>-thumb.jpg` | 缩略图；有码影片尽量保证横版 |
| `<文件名>.srt` | 外挂字幕；目标已存在时不覆盖 |
| `extrafanart/fanart1.jpg`… | 开启「刮削剧照」后写入，目录名可配置 |

图片下载失败是否中断整理由「允许图片下载失败」控制。开启高清封面时优先使用高清图；有码影片若封面/背景方向写反，系统会尝试交换文件归一，仍不符合时可用 [海报裁剪](/docs/toolbox/poster-crop) 手工处理。

## 刮削步骤

「刮削入库」列表中的「查看步骤」会打开时间线抽屉，展示每一轮刮削的步骤、状态、耗时与错误信息。主要步骤包括：

`文件校验`、`番号识别`、`数据源检索`、`元数据匹配`、`演员刮削`、`文件移动`，以及整理阶段的 `海报下载`、`背景图下载`、`缩略图下载`、`NFO生成`。

另有 `读取本地 NFO`、`手工绑定`、`查漏补缺` 等特殊步骤。步骤的实际执行顺序以时间线为准；同一媒体可能有多轮记录，抽屉顶部可切换历史轮次，默认展示最新一轮。

## 状态与失败处理

| 状态 | 说明 |
| --- | --- |
| 刮削中 | 任务正在执行，可取消 |
| 刮削完成 | 本批次结束，成功与失败数量见日志 |
| 等待 | 已创建但尚未开始 |
| 取消 | 用户取消 |
| 异常 | 执行过程中抛出异常 |

刮削失败的媒体仍保持「待刮削」，不会自动标记为完成。处理方式：

1. 到 **刮削入库** 点击「刮削整理」重新提交；失败的媒体会再次进入待办。
2. 识别错误时点击识别番号标签手工修改，再重新刮削。
3. 元数据匹配不到时，用「绑定」搜索影视库并手工绑定，再执行刮削。
4. 图片或 NFO 缺失时，用「查漏补缺」模式补齐，不移动视频文件。

运行记录、状态与日志清理见 [任务记录与日志](/docs/task/record)；影视与剧集的字段维护见 [影视](/docs/media/movie) 与 [剧集](/docs/media/tvshow)。

## 剧集刮削的差异

剧集不使用番号匹配，而是按剧名、年份、季集结构匹配 TMDB、Bangumi、TheTVDB 等数据源。扫描后先在「剧集刮削」页确认剧集分组（可合并、拆分、忽略），确认边界后才生成剧集元数据。剧集的目录格式、文件名格式、季海报与 NFO 命名规则见 [任务配置](/docs/task/config) 中的「剧集刮削规则」。
