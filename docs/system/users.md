# 用户与安全

AMMDS 是自托管的单管理员应用：一个实例只有一个管理员账号，不需要维护用户体系。因此「用户与安全」的重点不是增删账号，而是**把唯一的入口守住**——密码强度、登录记录、两步验证、Passkey 与统一登录。

{/* truncate */}

## 账号与角色

| 角色 | 说明 |
| --- | --- |
| 管理员（`admin`） | 唯一可以修改实例许可证、执行敏感操作的账号 |
| 用户（`user`） | 可登录并使用业务功能，但不能修改实例级授权 |
| 游客 | 未登录访问公开页面，受公共接口限流约束 |

- 初始管理员在首次启动时创建，用户名固定为 `ammds`，密码取环境变量 `ADMIN_PASS`，缺省为 `ammds`。该变量只在首次安装生效，之后改它没有意义。
- 重置密码时会校验「管理员账户数恰好为 1」，这是单管理员模型的硬约束。
- 账号信息在**头像下拉 → 用户中心**查看与编辑，包含用户 ID、昵称、邮箱、手机号、角色、状态、注册时间与最后登录时间。

:::warning[首次部署务必改密码]
默认密码是公开的。部署完成后第一件事就是登录并修改密码，见[首次登录](/docs/getting-started/first-login)。
:::

## 登录与令牌

| 环节 | 机制 |
| --- | --- |
| 传输 | 密码用服务端下发的 RSA 公钥加密后提交，明文不出浏览器 |
| 校验 | 用户名、密码、账号状态，启用两步验证时再校验 6 位动态码 |
| 令牌 | 访问令牌有效期 120 分钟，刷新令牌 30 天 |
| 签名 | 由系统 RSA 密钥对签名与验签，密钥缺失会重新生成，届时旧令牌全部失效 |
| 记录 | 每次尝试都写入登录日志，成功与失败都留痕 |

密码强度要求（登录、改密、重置三处一致）：6–22 位，同时包含大写与小写字母，且至少包含一个数字或一个符号。

## 登录安全巡检

1. 打开 **系统管理 → 日志审计 → 登录日志**。
2. 按状态筛「失败」，看是否存在连续撞库；按关键词筛 IP 或地点，确认是否有异地登录。
3. 发现异常时：先改密码（个人中心 → 修改密码），再启用两步验证或 Passkey。
4. 账号被禁用时登录会直接失败，记录原因为「账号已被禁用」。

## 两步验证

入口：**系统配置 → 安全配置 → 两步验证**。

1. 打开总开关（配置项 `security_two_factor_enable`）。
2. 点「启用两步验证」，进入四步向导：了解说明 → 扫码（也可手动输入密钥）→ 输入认证器里的 6 位验证码 → 完成。
3. 完成时会下发 **8 个一次性恢复码**，可复制或下载为文本文件。每个恢复码只能用一次。
4. 启用后页面显示启用时间与剩余恢复码数量。

关闭时同样需要验证：输入认证器当前 6 位验证码，或任一未使用的恢复码。

:::tip[谁能绕过两步验证]
Passkey 登录与统一登录**不需要**二次验证，因为认证本身已经完成强校验。只有账号密码登录会追加动态码。
:::

## Passkey

入口：**系统配置 → 安全配置 → Passkey**。用指纹、面容或设备 PIN 免密码登录。

开启前必须同时满足三个条件，任一不满足页面会给出对应提示：

| 条件 | 不满足时的表现 |
| --- | --- |
| 通过域名访问（不能是 IP 或 localhost） | 提示先绑定域名并用域名访问 |
| HTTPS 安全上下文 | 提示浏览器不会提供认证器 |
| 浏览器支持 WebAuthn | 提示更换较新的 Chrome、Edge、Safari 或 Firefox |

满足后点「创建 Passkey」，系统会调起本机认证器（Windows Hello、Touch ID、手机等），确认后凭据出现在列表中：

| 列 | 说明 |
| --- | --- |
| 名称 | 默认「Passkey N」，可重命名（例如 Windows Hello / iPhone）；支持备份的凭据带「可备份」标签 |
| 创建时间 | 绑定时间 |
| 最近使用 | 上次用该凭据登录的时间，没用过显示「从未使用」 |
| 操作 | 重命名、删除 |

删除后该设备将无法再用这个 Passkey 登录，请确认还有其他登录方式可用。工具栏右侧展示当前 RP ID，便于确认绑定在哪个域名下。

## 统一登录

入口：**系统配置 → 安全配置 → 统一登录**，基于 OAuth 2.0 / OIDC 接入第三方身份。

1. 复制页面给出的回调地址，填到身份提供方的回调白名单里。
2. 点「创建应用」，填写应用名称、图标、按钮文案、Client ID / Secret 与用户映射字段（默认 `sub`）。
3. 保存后可以「绑定」自己的第三方账号，也可以随时「解绑」或停用应用。
4. 登录页会出现对应的登录按钮；统一登录同样不需要二次验证。

:::note[密钥只存本机]
Client Secret 保存在本地数据库，不随页面回显。删除应用会让该入口立即失效，需要重新创建。
:::

## 安全配置项一览

| 配置键 | 作用 |
| --- | --- |
| `security_passkey_enable` | Passkey 总开关 |
| `security_two_factor_enable` | 两步验证总开关 |
| `system_public_rate_limit` | 游客访问公开接口的限流（次/分钟，默认 100） |

前两项可在页面上开关；限流由后端直接读取配置，页面未提供入口。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 忘记管理员密码 | 用恢复密钥重置，见[密钥管理](/docs/system/secret) |
| 改完密码被登出 | 属预期行为，改密成功后 5 秒自动登出，用新密码重新登录 |
| 恢复码用完了 | 先关闭再重新启用两步验证，会重新下发 8 个恢复码 |
| Passkey 创建按钮是灰的 | 检查是否用域名 + HTTPS 访问、浏览器是否支持 WebAuthn、总开关是否开启 |
| 登录页没有第三方按钮 | 统一登录总开关未开，或应用被停用 |
| 启用两步验证后收不到动态码 | 校准宿主时间；TOTP 依赖时间同步，偏差过大会校验失败 |
