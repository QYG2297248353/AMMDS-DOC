# 日志

**系统管理 → 日志审计** 下有三个页面，分别回答不同的问题：登录日志看「谁在什么时候登录过」，运行日志看「服务端刚刚发生了什么」，任务日志看「某个后台任务跑到哪一步、为什么失败」。

{/* truncate */}

## 三个页面的分工

| 页面 | 数据来源 | 适合排查 |
| --- | --- | --- |
| 登录日志 | 每次后台登录尝试（成功与失败都记录） | 密码错误、账号被禁用、异常 IP 登录 |
| 运行日志 | `data/logs` 下的应用日志文件 | 接口报错、插件异常、堆栈信息 |
| 任务日志 | 后台任务表与执行明细 | 扫描、刮削、整理、同步、导入导出失败 |

:::info[关于操作审计]
当前版本没有独立的「操作审计」页面。管理员的关键操作会落到任务日志（如删除文件、导入备份、同步商城）或运行日志中，需要留痕时请按上面三个页面交叉核对。
:::

## 登录日志

表格字段：序号、用户名、记录 IP、登录地点、登录时间、设备信息（操作系统 / 设备 / 浏览器）、登录状态、记录原因。

- 筛选条件：关键词（用户名、IP、地点）与登录状态（成功 / 失败），任一变化都会回到第一页重新查询。
- 分页每页 10 条，按时间从新到旧。
- 失败的登录也会记录，记录原因来自校验环节，例如「用户名不存在」「账号已被禁用」「密码错误」「两步验证挑战生成失败」「token生成失败」；成功记录为「登录成功」。

:::tip[用登录日志做安全巡检]
如果你在异地看到无法解释的成功登录，先在[用户与安全](/docs/system/users)里修改密码，并检查是否启用了两步验证或 Passkey。
:::

## 运行日志

表格字段：序号、时间、线程、日志级别、日志记录器、日志消息。

| 级别 | 展示 |
| --- | --- |
| `ERROR` | 红色「错误」 |
| `WARN` | 橙色「警告」 |
| `INFO` | 蓝色「信息」 |
| `DEBUG` 及其他 | 「调试」或「正常」 |

- 页面读取最近的日志条目（默认取最近 300 条），每 8 秒自动刷新一次，切到其他标签页时暂停。
- 异常堆栈会被并入上一条日志，消息保留换行，便于直接阅读。
- 无法解析成标准格式的行不会展示在表格里，它们仍保留在日志文件中。

### 导出日志

右上角可选择「最近 1 天 / 7 天 / 30 天」并导出：

1. 服务端会聚合主日志与按日期滚动的日志文件，按日期升序拼接成一个文本文件。
2. 汇总体积超过 100MB 时截断最旧的内容，保证下载可用。
3. 文件名形如 `ammds-logs-<起始日期>-<结束日期>.log`；该范围内没有日志时返回一个说明文本文件。

日志文件位于 `data/logs`，主文件为 `AMMDS.log`，按天滚动为 `AMMDS-YYYY-MM-DD.log`，错误日志为 `AMMDS-error*.log`。

## 任务日志

工具栏包含：执行中任务数、任务名称搜索、任务类型、状态、自动刷新开关、刷新与「清理已完成」。

| 列 | 说明 |
| --- | --- |
| 任务 | 任务标题 |
| 任务类型 | 备份导出、备份导入、影视整理、漫画导入、文件上传/下载/删除、RSS 订阅更新、商城同步等 |
| 状态 | 执行中 / 已完成 / 失败 / 已取消 |
| 进度 | 0–100 的进度条，失败任务标红 |
| 已完成 / 总量 | 带计数的任务才有 |
| 耗时 | 开始到结束的时长 |

点「详情」打开抽屉，可以看到任务的描述、失败原因、开始与结束时间，以及**执行明细**：每行带时间、级别（`ERROR` / `WARN` 高亮）与消息，这是定位失败原因最直接的材料。

可执行的操作：

| 操作 | 前提 |
| --- | --- |
| 详情 | 任意状态 |
| 取消 | 仅「执行中」且该任务支持取消 |
| 删除 | 非「执行中」 |
| 清理已完成 | 清理全部已结束的任务日志，执行中的会保留 |

有任务在跑且开启自动刷新时，列表每 3 秒静默更新，任务结束后自动停止轮询。

## 排查顺序建议

1. 先在**任务日志**里找到失败的那次任务，读执行明细里的第一条 `ERROR`。
2. 记下时间，回到**运行日志**按同一时间点看上下文与堆栈。
3. 涉及插件地址、密钥、网络的问题，用[系统检查](/docs/system/system-check)与[网络与连通性](/docs/dashboard/network)确认。
4. 怀疑是登录或权限问题时，再看**登录日志**。

| 现象 | 优先看 |
| --- | --- |
| 扫描/刮削任务失败 | 任务日志执行明细 |
| 页面接口 500、插件请求异常 | 运行日志的错误与警告 |
| 提示「账户或密码错误」 | 登录日志的记录原因 |
| 服务启动异常 | 宿主机上的 `data/logs/AMMDS.log` 开头部分 |

## 日志与磁盘

运行日志会持续增长，占用可以在[存储管理](/docs/system/storage)的 `logs` 分类里看到。不要手工删除正在写入的日志文件；需要释放空间时优先导出后保留必要区间，或按部署方式配置日志滚动与保留天数。
