# 备份与恢复

备份与恢复处理的是**元数据**：把影视、演员、漫画、小说的记录导出成标准备份包，或在另一台实例上导入恢复。图片是否一起打包由每类数据自己的开关决定。

## 页面结构

**系统管理 → 备份与恢复**，页面有四个标签页：

| 标签页 | 用途 |
| --- | --- |
| 数据导出 | 按类型导出元数据，并查看/下载历史导出产物 |
| 数据导入 | 上传备份包，解析校验后导入 |
| 分享导入 | 用分享链接或短码导入他人分享的内容 |
| 链接记录 | 查看分享导入记录与自己提交的申请 |

## 数据导出

界面提供四类数据卡片，每类独立控制是否打包图片：

| 类型 | 元数据范围 | 勾选「同时导出图像文件」后额外打包 |
| --- | --- | --- |
| 影视 | 影视元数据、文件信息、关联演员/系列/磁力/字幕 | 海报、背景、缩略图、剧照及高清图 |
| 演员 | 演员元数据（身材、标签、社交平台等） | 大头照与海报列表 |
| 漫画 | 相册元数据、章节、章节页记录 | 相册封面/封底与全部章节页图片 |
| 小说 | 小说元数据与章节正文 | 封面与封底 |

- 导出在后台异步执行，点完可以离开本页，稍后回到「导出记录」下载。
- 同一类型正在导出时按钮保持加载态，避免重复导出。
- 导出记录展示类型、文件名、状态（导出中 / 已完成 / 失败）、大小与创建时间，可下载或删除。
- 漫画勾选图片后会打包全部章节页，包体可能很大；服务端是流式处理，不会把整包读进内存。

:::tip[图片只收本地文件]
只有值为 `data` 本地路径且文件真实存在的图片才会进包；`http` 外链一律不进包。迁移后若保留了原 `data` 目录，旧路径可直接复用；外链则依赖原站点仍然可访问。
:::

## 备份包结构

标准备份包是 zip，根目录必须包含 `manifest.json` 与 `data.json`，`images/` 目录可选：

```text
backup.zip
├── manifest.json    # 格式标识、版本、类型、条目数、图片映射
├── data.json        # 元数据数组
└── images/          # 仅在勾选导出图片时存在
    └── <条目key>/poster_0.jpg
```

`manifest.json` 的关键字段：

| 字段 | 说明 |
| --- | --- |
| `format` | 固定为 `ammds-backup` |
| `formatVersion` | 格式版本，当前为 `1`，导入端向下兼容旧版本 |
| `type` | `movie` / `actor` / `comic` / `novel` / `tv`，**一个包只能是一种类型** |
| `generatedAt` / `appVersion` | 生成时间与生成该包的版本 |
| `includeImages` | 是否包含图片文件 |
| `count` | 必须与 `data.json` 的实际条目数一致 |
| `imageFiles` | 图片映射（`ref` / `path` / `sha256`），`path` 必须以 `images/` 开头 |

## 数据导入

1. 把 `.zip` 或单个 `.json` 文件拖入上传区。
2. 选择导入方案：**跳过已存在**、**覆盖更新**或**合并更新**。
3. 点「解析预览」，查看条目数、内嵌图片数、包大小与包内文件数。
4. 校验通过后点「开始导入」，完成后展示成功 / 跳过 / 更新 / 失败统计。

### 校验规则

解析阶段会做结构与清单校验，不计算图片摘要。任一项不通过就**禁止导入**，且不产生任何数据变更：

| 校验项 | 结果 |
| --- | --- |
| 缺少 `manifest.json` 或 `data.json` | 拒绝 |
| 条目路径包含 `..`、`\`、`:` 或以 `/` 开头 | 拒绝 |
| `format` 不是 `ammds-backup` | 拒绝 |
| `formatVersion` 低于 1 或高于当前支持版本 | 拒绝 |
| `type` 不在允许的类型内 | 拒绝 |
| `count` 与 `data.json` 实际条目数不一致 | 拒绝 |
| 图片清单路径不在 `images/` 下或文件不存在 | 拒绝 |
| `includeImages` 与图片清单不一致、引用未出现在数据中、存在未识别条目 | 仅提示 |

单文件 `data.json` 模式属于兼容模式，缺少清单时以提示方式放行，类型按首个条目推断。

### 匹配依据与冲突策略

| 类型 | 匹配依据 |
| --- | --- |
| 影视 | `uniqueid`（番号）有交集即视为同一条；合并策略下再按标题匹配 |
| 演员 | 姓名完全一致 |
| 漫画 | 优先 ISBN，其次相册名称 |
| 小说 | 书名或 ISBN 一致 |
| 剧集 | 依次按 TMDB、Bangumi、TVDB 站点 ID 匹配 |

| 策略 | 行为 |
| --- | --- |
| 跳过已存在 | 命中即跳过，不写入、不更新 |
| 覆盖更新 | 命中则覆盖；漫画、小说、剧集会删除后重建章节/季/集，未命中则新增 |
| 合并更新 | 只补缺失字段、列表去重并集；不删除已有数据（小说与覆盖等效） |

单条失败不会中断整包导入，失败条目会计入「失败」并记录原因，详情最多展示前 50 条。

## 分享导入

在其他实例的媒体、演员、系列页面生成分享链接后，可在这里导入：

1. 填入分享链接或短码；分享设置了密码时填写访问密码。
2. 选择导入方案（与数据导入一致）。
3. 点「预览分享」，确认类型、标题与条目数。
4. 点「导入分享」。

若分享主人未开放导入权限，页面会提示「该分享不允许导入」，可以填写申请原因提交申请；提交前需要在个人中心补全用户 ID、昵称与邮箱。

「链接记录」标签页可以切换两个视图：**记录**展示链接类型、标题、导入时间与结果（成功 / 无权限导入 / 链接无效 / 已过期 / 失败）；**申请记录**展示目标分享、申请原因、申请时间与状态，待处理的申请可以取消。

## 云备份（配置备份）

上面的备份包只覆盖媒体元数据，**不包含系统配置、插件密钥与订阅规则**。需要异地保存配置时使用插件集成里的云端同步：

- 入口：**插件集成 → 云端同步 → WebDAV / S3**，说明见[云存储](/docs/integration/auxiliary/cloud-storage)。
- 只备份「配置类」数据，不含图片与影片条目，因此包体很小。
- 备份包使用 AES-256-GCM 加密，口令丢失则无法恢复，务必单独保存。
- 恢复时可选择合并更新、本地优先或远端优先；WebDAV / S3 插件自身的连接配置不参与恢复，避免恢复后连不上远端。
- WebDAV 只承担配置备份；需要把图片等资源放到远端时用 S3 插件，两者互相独立。

## 建议的备份习惯

1. 元数据按类型分别导出，需要图片时再勾选「同时导出图像文件」。
2. 配置单独用云备份，加密口令与备份文件分开保管。
3. 恢复前先在同版本实例上「解析预览」，确认校验通过再导入。
4. 大版本升级前做一次完整导出，升级后用「系统检查」复查。
