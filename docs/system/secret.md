# 密钥管理

「密钥」在 AMMDS 里指三样不同的东西：页面上可自助创建的 **API 密钥**、系统启动时生成的 **RSA 密钥对**，以及只落在磁盘上的 **一次性恢复密钥**。它们都由本文覆盖，但操作入口不同。

{/* truncate */}

## 密钥管理页

进入 **系统管理 → 密钥管理**。页面顶部有「创建密钥」与「接口文档」两个按钮，下方是当前账号的密钥列表。

| 列 | 说明 |
| --- | --- |
| 名称 | 创建时填写的用途说明，右侧标签显示「正常」或「已过期」 |
| 密钥 | 点击标签即复制完整密钥 |
| 类型 | AMMDS 助手 / X-API-KEY / Mihon 扩展 |
| 过期时间 | 到点后自动失效，标签转红 |
| 操作 | 删除（二次确认，删除后不可恢复） |

### 创建密钥

1. 点「创建密钥」。
2. 填写名称（必填）。
3. 选择类型（必填）。
4. 选择过期时间，可留空表示长期有效；填写时必须晚于当前时间至少 10 分钟。
5. 点「创建」，成功后列表刷新，密钥可随时复制。

### 三种类型的用途

| 类型 | 适用协议 | 用法 |
| --- | --- | --- |
| AMMDS 助手 | 浏览器插件 | 在插件里填入该密钥完成配对 |
| X-API-KEY | `/api/v1/**` | 请求头携带 `x-api-key`，用于第三方程序调用开放接口 |
| Mihon 扩展 | `/api/mihon` | 供 Mihon / Tachiyomi 等漫画阅读器使用 |

:::warning[类型不能混用]
`x-api-key` 只在 `/api/v1` 前缀下生效，不会放行管理端接口；Mihon 授权码只用于 `/api/mihon`。用错类型会得到未授权响应。开放 API 还需在[系统配置](/docs/system/config)里打开「开放 API」开关。
:::

「接口文档」按钮会在新标签页打开内置的 Swagger 文档，可直接在页面里试调接口。

## RSA 密钥对

这是系统自身的加密基础，不出现在密钥管理页，也没有查看或轮换入口：

| 项目 | 说明 |
| --- | --- |
| 生成时机 | 首次启动时生成，公钥/私钥任一缺失会重新生成一对 |
| 存放位置 | 系统配置表（公钥与私钥各一条配置项） |
| 用途一 | 签发与校验登录令牌（JWT 签名） |
| 用途二 | 密码加密传输：登录页、修改密码、重置密码都会先取公钥加密再提交 |

生成失败时进程会打印错误并退出，而不是以无密钥状态对外提供服务。因此**不要手工删除**这两条配置，否则所有已签发的登录令牌立即失效，需要重新登录。

## 恢复密钥与重置密码

恢复密钥用于「唯一管理员忘记密码」这一场景，不依赖邮件或短信：

| 项目 | 说明 |
| --- | --- |
| 存放位置 | `data/secret/recovery.key`，单行 Base64 文本 |
| 生成时机 | 服务启动时检查，文件不存在则生成；已存在不覆盖 |
| 长度 | 32 字节随机数的 Base64 编码，44 个字符 |
| 可见性 | 只在磁盘上；不在页面展示、不打印到日志（日志只输出路径）、没有读取接口 |
| 有效性 | 重置成功即删除文件，成为一次性凭据 |

### 重置流程

1. 登录服务器，读取密钥文件：

   ```bash
   cat data/secret/recovery.key
   ```

   文件不存在时重启服务即可重新生成，启动日志会打印 `已生成恢复密钥，文件位置: ...`。

2. 打开登录页，点「忘记密码」。
3. 填入恢复密钥与新密码并提交。前端自动取 RSA 公钥加密新密码，再调用重置接口。
4. 返回成功后密钥文件被销毁，用新密码正常登录。

新密码需满足强度要求：6–22 位，同时包含大写与小写字母，且至少包含一个数字或一个符号。

### 失败提示对照

| 提示 | 原因 |
| --- | --- |
| 恢复密钥不存在，请重启服务后重试 | 密钥已用过，或文件尚未生成 |
| 恢复密钥错误 | 读取失败、内容为空或与文件不一致 |
| 密码解析失败 | 新密码密文无法解密 |
| 密码过于简单 | 不满足强度要求 |
| 管理员账户异常 | 系统中管理员账户数不等于 1 |
| 恢复密钥文件销毁失败 | 密码已保存，但密钥文件删除失败，请手工删除 |

:::tip[日常改密走另一条路径]
已登录时在**个人中心**头部点「修改密码」，需要同时提供当前密码与新密码，成功后会自动登出，详见[个人信息](/docs/account/profile)。它与「忘记密码」是两条独立路径。
:::

## 维护建议

- API 密钥按用途分开创建，一个程序一个密钥，便于单独撤销。
- 长期不用的密钥直接删除，而不是依赖过期时间。
- `data/secret` 目录只对运行账户可读，恢复密钥不要复制到聊天工具或笔记里。
- 重置密码成功后如果没重启服务，系统会处于「无恢复密钥」状态，这是预期行为；需要时重启即可重新生成。
