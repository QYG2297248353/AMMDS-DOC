# 系统检查

系统检查是一个诊断工具：先列出当前运行环境与关键配置，再由你触发一次全量扫描，把配置缺失、依赖未下载、服务连不通与运行压力逐条列出来，并标注会影响哪些功能。

{/* truncate */}

## 打开方式

点击右上角头像，在下拉菜单里选择 **系统检查**。这个页面不在侧边菜单中，属于随用随开的自检入口。

## 扫描前的环境信息

进入页面先展示只读快照，不发起任何网络请求：

| 项目 | 说明 |
| --- | --- |
| AMMDS / Java / SpringBoot | 版本号 |
| 操作系统 | 系统名与架构，容器中运行会标注 Docker |
| JVM 内存 | 已用 / 上限 |
| 系统内存 | 可用 / 总量 |
| 磁盘空间 | 数据目录所在卷的剩余 / 总量 |
| 服务端口 | 当前 `server.port` |
| 数据库 | 类型与连接串（密码脱敏） |
| 运行时长 | 进程已运行时间 |
| 数据目录 / 服务器时间 / 时区 | 便于与宿主环境对照 |

## 执行扫描

1. 点击「开始扫描」。
2. 扫描在服务端同步执行，前端进度条平滑推进（最多到 92%），整体至少展示 8 秒，避免一闪而过。
3. 完成后顶部显示正常、警告、异常、未启用与检查项总数，以及本次扫描耗时。
4. 点击「重新扫描」会重置结果并再跑一次。

:::info[只读诊断]
扫描不会修改任何配置，也不会自动修复。它只读取配置、探测服务与统计资源。
:::

## 四类检查项

结果按固定顺序分组展示：

| 分组 | 关注点 |
| --- | --- |
| 基础信息 | 版本、操作系统、内存、磁盘、系统时间、外网连接 |
| 软件配置 | 依赖程序是否就绪、代理是否完整、各集成插件是否可用 |
| 系统配置 | 服务端口、数据库连接、域名绑定、通知渠道、许可证 |
| 运行状态 | 日志错误量、CPU / 堆 / 磁盘压力 |

### 基础信息

| 检查项 | 正常条件 | 异常时的提示方向 |
| --- | --- | --- |
| 系统版本 | 始终正常，仅回显版本 | — |
| 操作系统 | 非 32 位架构 | 32 位系统不受支持，影响依赖资源下载与使用 |
| 内存 | JVM 堆使用率 ≤ 90% 且系统可用内存 ≥ 10% | 大量刮削、下载任务时可能内存不足 |
| 硬盘空间 | 数据目录剩余 ≥ 1GB 且使用率 ≤ 90% | 影视存储、缓存、日志写入受限 |
| 系统时间 | 与网络时间源相差 ≤ 5 分钟 | 许可证校验、定时任务、订阅与下载时间判断都会受影响 |
| 网络连接 | 多个目标并行探测，全部可达 | 部分可达为警告，全部失败为异常 |

网络连接会用短超时并行探测一批业务域名、CDN 与资源地址，任一目标失败不代表网络整体异常，所以按成功率分级结论，并在详情中列出每个目标的结果。

### 软件配置

**依赖资源**逐个检查是否就绪，未下载或不可用时给出「警告」：

| 依赖 | 缺失后受影响的功能 |
| --- | --- |
| FFmpeg | 视频处理、截图、封面裁剪、缩略图生成 |
| FFprobe | 媒体信息解析、时长与分辨率检测 |
| VideoHashes | 感知哈希计算、重复影片识别 |
| WinRAR | 压缩/解压归档（文件浏览器、漫画归档） |
| VibeVoice 推理程序 | 本地字幕识别 |
| MetaTube 程序 | MetaTube 元数据刮削与检索 |

**代理配置**：未开启代理时记为「未启用」；已开启但主机或端口为空、端口不在 1–65535，记为「异常」。

**集成插件**按三步判断，逐个检查已启用的插件：

| 判断顺序 | 结果 |
| --- | --- |
| 插件未启用 | 未启用（不算问题） |
| 已启用但缺少必需配置 | 警告，提示缺少哪些配置键 |
| 有服务地址且连接失败 | 异常，提示失败原因 |
| 配置齐全且服务可达 | 正常 |

常见插件启用后需要的配置：MetaTube 需要服务地址；TMDB 需要服务地址与 Token；Jellyfin / Emby 需要服务地址与 API Key；qBittorrent / Transmission 需要服务地址；IYUU 需要 Token；Prowlarr 需要服务地址与 API Key；Telegram 需要 Bot Token 与 Chat ID；Bark 需要设备密钥；DeepSeek 需要 API Key；Rousi / M-Team / FSM 需要 Passkey；S3 需要 Endpoint；WebDAV 需要服务地址。NexusPHP 这类没有固定服务地址的插件只校验配置完整性。

### 系统配置

| 检查项 | 说明 |
| --- | --- |
| 服务端口 | 仅回显 `server.port` |
| 数据库连接 | 执行一次 `SELECT 1`，3 秒查询超时 |
| 域名绑定 | 未绑定记为未启用；已绑定但回显校验失败记为异常 |
| 系统通知 | 总开关关闭记为未启用；开启但没有任何推送渠道记为警告；渠道缺必需配置记为警告 |
| 许可证 | 有效为正常；宽限期、无授权为警告；套餐缺少基础授权为异常 |

### 运行状态

- **系统日志**：日志文件缺失为警告；最近 500 行中 `ERROR` 超过 50 条为警告，建议导出日志排查。
- **系统性能**：CPU 负载高于核数、JVM 堆使用率超过 90%、磁盘使用率超过 90%，任一命中即为警告。

## 结果怎么读

| 状态 | 含义 | 要不要动手 |
| --- | --- | --- |
| 正常 | 符合预期 | 不用 |
| 警告 | 可用但存在隐患，功能可能受限 | 按提示处理 |
| 异常 | 功能已不可用或配置明显错误 | 必须处理 |
| 未启用 | 检查对象本身没开 | 不用，除非你需要它 |

除状态外，部分条目会附带标签：

| 标签 | 含义 |
| --- | --- |
| 需要配置 | 去对应配置页补齐参数 |
| 需要重启 | 改动后要重启服务才生效 |
| 受影响功能 | 指出这条问题会波及的具体能力 |

## 常见告警怎么修

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 系统时间相差超过 5 分钟 | 宿主时间未同步、时区错误、代理劫持了时间校验域名 | 校准宿主时间后重启；检查免代理名单是否仍包含时间校验域名 |
| 网络连接只有部分成功 | 部分域名被链路限制 | 在 **系统配置 → 网络配置** 启用代理后重新扫描 |
| 依赖资源未下载 | 首次启动下载未完成或网络失败 | 在对应插件页重新下载资源，完成后重启 |
| 插件显示已启用但连接失败 | 地址写错、服务未启动、防火墙拦截 | 先用插件页自带的连通性测试，再看该插件容器日志 |
| 内存或性能告警 | 并发任务过多、堆上限偏小 | 降低并发、调大堆上限、清理磁盘 |
| 许可证异常 | 套餐缺少 `ammds.license.base_access` | 见[许可证](/docs/system/license) |
| 数据库连接失败 | 库文件损坏、连接串或账号错误 | 见[备份与恢复](/docs/system/backup-restore) |

## 与其他页面的关系

- 只关心外网通不通：用[网络与连通性](/docs/dashboard/network)，它按域名逐个探测。
- 修完配置后复查：回到本页点「重新扫描」。
- 需要具体报错内容：[日志](/docs/system/logs)。
