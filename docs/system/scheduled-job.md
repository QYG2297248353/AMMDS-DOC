# 定时任务

计划任务页把系统内部的调度任务摊开给你看：每个任务多久跑一次、上次跑成功没有、现在是不是正在跑，并允许你手动补跑一次。

{/* truncate */}

## 打开方式

进入 **系统管理 → 计划任务**。工具栏显示总开关状态、执行中的任务数、自动刷新开关与刷新按钮。

## 任务清单从哪来

清单不是手工维护的：服务启动时会扫描容器里所有带 `@Scheduled` 的方法，按「类名#方法名」生成唯一标识；任务名称与说明取自 `@ScheduledJob` 注解，没标注时回退为方法名。因此新增任务不需要改页面，重启后自动出现。

## 列表字段

| 列 | 说明 |
| --- | --- |
| 任务名称 | 主标题为可读名称，副标题为所属类名，便于对照日志 |
| 执行周期 | 人话描述；鼠标悬浮可看原始表达式（Cron 或 `fixedDelay=xxxms`） |
| 运行状态 | 执行中 / 空闲，下方显示上次结果摘要 |
| 上次执行 | 开始时间；失败时带红色「失败」标签，从未执行时显示「从未执行」 |
| 操作 | 执行（手动触发一次） |

## 执行周期怎么读

页面把两类调度都翻译成人话：

| 原始写法 | 展示 |
| --- | --- |
| Cron 表达式 | 按表达式翻译，如「每天 04:45」「每 5 分钟」；无法识别时直接回退显示原文 |
| `fixedRate` | 每 N 分钟（按固定频率，不管上次是否跑完） |
| `fixedDelay` | 启动后 N 开始，每 N 分钟（上次结束后计时）；周期较长的任务多是这种写法 |

### Cron 表达式

Spring 的 Cron 是**六段**格式，从左到右依次为：

```text
秒 分 时 日 月 周
```

| 表达式 | 含义 |
| --- | --- |
| `0 0 4 * * *` | 每天 04:00:00 |
| `0 */5 * * * *` | 每 5 分钟 |
| `0 30 2 * * MON` | 每周一 02:30 |
| `0 0 3 1 * *` | 每月 1 日 03:00 |

`*` 表示任意值，`*/n` 表示每 n 个单位，`?` 只用于「日」或「周」表示不指定。

## 手动执行

1. 找到目标任务，点「执行」。
2. 请求会立即返回，任务在后台开始跑；按钮进入加载态，执行中不能重复触发。
3. 有任务在跑时列表每 3 秒静默刷新，任务结束后自动停止；也可以关掉「自动刷新」手动刷新。
4. 执行结果（完成或失败原因）会显示在「运行状态」下方，失败时同时写入运行日志。

手动执行使用独立线程池，并发上限很小，避免连点把系统拖垮。同一任务在执行中再次点击会被拒绝。

:::warning[总开关关闭后到底停了什么]
计划任务总开关 `AMMDS_SCHEDULER_ENABLE`（配置项 `ammds.scheduler.enable`，默认开启）关闭后：

- 页面顶部显示「计划任务已关闭」，**手动执行会被拒绝**；
- 由数据库配置注册的 Cron 任务（任务级 Cron 扫描、IYUU 自动辅种）不再注册，因此不再按计划触发；
- 代码中直接标注 `@Scheduled` 的内置任务仍由 Spring 调度器执行，**不受该开关影响**。

所以「关闭总开关」不等于「停止全部后台定时逻辑」。要彻底停掉某类自动行为，还需要同时停用对应的功能配置（例如任务级 Cron、自动刮削开关、订阅检测）。
:::

## 任务都在做什么

清单随版本变化，常见任务按用途大致分为几类：

| 分类 | 典型任务 |
| --- | --- |
| 媒体库维护 | 执行系列库同步、补全媒体库演员数据、感知哈希计算、厂牌规则收纳作品、修复章节序号、清理扫描脏数据 |
| 订阅与下载 | 更新 FSM 订阅、更新 MTeam 订阅、更新未匹配的订阅元数据、批量下载待订阅影视、更新订阅下载进度 |
| RSS 与资讯 | 更新 RSS 文章、更新 RSS 离线缓存、RSS 自动归档、刷新热门订阅、校验热门订阅可用性 |
| 媒体服务器 | 同步 JellyFin / Emby 媒体库与播放记录 |
| 站点与数据 | 执行 PT 站点认证、同步全部 PT 站点用户数据、检查 PT 站点账户安全状态、抓取榜单 |
| 系统运维 | 系统时间检查、磁盘容量检查、清理文件浏览器临时文件、清理过期缓存、统计存储占用、部署许可证后台校验 |
| 商城与对象存储 | 官方商城商品同步、同步本地资源到 S3、搜索索引更新 |

## 执行记录去哪看

本页只保留每个任务**最近一次**的执行时间与结果，不提供历史记录列表。需要完整过程时：

1. 打开 **系统管理 → 日志审计 → 任务日志**。
2. 按任务类型或状态筛选，或直接搜索关键词。
3. 点「详情」查看逐条执行明细与失败原因。

过程记录见[日志](/docs/system/logs)；扫描与刮削任务的执行逻辑见[扫描任务](/docs/task/scan)与[刮削任务](/docs/task/scrape)。

## 排查建议

| 现象 | 处理 |
| --- | --- |
| 任务长时间不执行 | 先确认总开关为开启状态，再看运行日志是否有调度线程异常 |
| 任务一直显示执行中 | 查看任务日志是否卡在同一进度，必要时取消后重跑 |
| 上次结果为失败 | 打开任务日志看执行明细的第一条错误，再对照[系统检查](/docs/system/system-check) |
| 时间相关任务总是跑偏 | 系统时间与网络时间相差过大，先用系统检查校准 |
| 手动执行提示任务不存在 | 任务清单在启动时生成，版本变更后请重启服务 |
