# 存储管理

存储管理回答一个问题：**空间被谁占用了**。它把数据目录按一级子目录拆开统计大小与文件数，再把图片目录按二级分类细分，最后列出数据库目录里的每个文件。

{/* truncate */}

## 打开方式

进入 **系统管理 → 存储管理**。卡片右上角显示「最后统计：时间」与「刷新」按钮。

## 数据目录在哪

| 目录 | 内容 |
| --- | --- |
| `data` | 图片、缓存、字幕、日志、插件运行时等全部业务数据 |
| `db` | 数据库文件（H2 默认，也可切换到 PostgreSQL） |

两个路径都相对于应用工作目录，容器部署时随数据卷持久化。需要确认 `data` 目录的绝对路径时，看[系统检查](/docs/system/system-check)里的「数据目录」一项。

:::warning[不要手工改动目录]
`data/secret` 保存恢复密钥等凭据，`db` 保存数据库文件。运行中直接移动或删除文件可能造成数据损坏，清理请走下文列出的页面入口。
:::

## 统计口径

- 统计由后端定时执行：启动时做一次，之后每 5 分钟一次；页面进入时读取缓存结果，并每 30 秒静默刷新。
- 「磁盘总空间 / 已用 / 可用」来自 `data` 目录所在的卷，不是容器内部分区的单独额度。
- 文件数为递归统计的真实文件数，单文件读取失败时跳过，不影响整体结果。
- 占比为该分类大小除以 `data` 目录总大小，保留两位小数。
- 统计失败时保留上一次结果，并在运行日志里记录错误。

## 顶部四个数字

| 指标 | 说明 |
| --- | --- |
| 磁盘总空间 | 数据目录所在卷的总容量 |
| 磁盘已用 | 该卷已被使用的容量（包含非 AMMDS 的文件） |
| 磁盘可用 | 该卷剩余容量 |
| data 目录占用 | AMMDS 业务数据合计 |

因此「磁盘已用」与「data 目录占用」的差值，通常是影片原文件、系统占用与其他程序。

## data 目录占用分布

左侧环形图与右侧明细一一对应，勾选配色一致；悬浮扇区会显示该分类的占用与文件数，同时隐藏图表中心的汇总文字以避免重叠。常见分类：

| 分类 | 内容 |
| --- | --- |
| images | 媒体、演员、图库等图片资源 |
| cache | 缓存文件，含转码缓存 |
| ffmpeg | FFmpeg 二进制与资源 |
| subtitles | 媒体字幕文件 |
| metatube | MetaTube 插件缓存 |
| secret | 密钥与凭证文件 |
| logs | 系统日志 |
| temp | 临时文件 |

未登记的子目录显示为「其他数据」；直接放在 `data` 根下的零散文件会单独汇总为「(根目录文件)」。

## 图片资源细分

`images` 还有一块独立的二级细分：环形图加明细列表，按子目录（演员、影视等）统计，占比是**相对 images 目录**而不是相对整个 `data`。根目录下的散落图片会汇总为一条。

## db 目录

右侧展示数据库目录占用、文件数量与逐个文件的大小。数据库文件通常不大，如果它增长异常，优先检查任务日志里是否有大量失败重试。

## 空间不够时怎么腾

本页面是只读的，不提供删除按钮。已实现的清理入口分散在各业务页面：

| 想清理什么 | 入口 | 注意 |
| --- | --- | --- |
| 任务日志 | 系统管理 → 日志审计 → 任务日志 → 清理已完成 | 只清理已结束的任务，执行中的需先取消 |
| 备份导出产物 | 系统管理 → 备份与恢复 → 数据导出 → 导出记录 → 删除 | 删除后无法再下载该次导出 |
| RSS 离线缓存 | 信息中心 → RSS → 缓存面板 → 清理缓存 | 清理后需要重新缓存才有离线内容 |
| 无用影片、临时文件 | 工具箱 → 文件浏览器 → 删除 | 会产生文件删除任务日志，可追溯 |
| 插件下载的资源 | 对应插件页的资源下载卡片 | 删除后该功能需要重新下载资源 |

:::tip[先备份再删]
删除操作不可撤销。清理媒体文件前先确认已有元数据备份，清理数据库或配置前先在[备份与恢复](/docs/system/backup-restore)里做一次导出。
:::

## 空间不足会怎样

- 系统检查的「硬盘空间」在剩余不足 1GB 或使用率超过 90% 时给出警告，影响「影视文件存储、缓存、日志写入」。
- 开启 **系统配置 → 基础配置 → 磁盘监测** 后，空间不足会主动推送通知。
- 刮削、下载、转码都依赖临时空间，空间耗尽时这些任务会失败并写进任务日志。
