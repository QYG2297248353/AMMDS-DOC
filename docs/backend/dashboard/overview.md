# 工作台：一开门看到什么

登录后默认落在工作台，一屏里放着磁盘、影片数量、天气、网络、系统版本这些状态卡片；往下还有三个榜单，帮你回顾观影、发现新片、查看各站点账号。这一页帮你看懂每块数字在说什么、数据从哪来，以及哪里不对劲时先查哪里。

## 先说清楚

> **工作台**：登录后台后默认打开的首页，把常看的信息集中放一屏，省得一个个菜单去翻。

> **榜单**：按某个口径排出来的排行或统计。本页有三种，数据各来自不同地方，互不牵连。

> **静默刷新**：不用你点，页面自己隔一阵重新取一次数，数字会悄悄更新。

卡片顺序固定：存储空间、媒体统计、天气、网络信息、系统信息、AMMDS 服务状态、支持一下。屏幕窄时会自动上下堆叠成整行。

## 看懂一屏里的卡片

### 存储空间

左边一个圆环，右边两个统计值。

| 看到的东西 | 意思 |
| --- | --- |
| 总空间 | 装 AMMDS 那台机器的磁盘总容量。Linux 和容器按数据目录所在的那块盘算，Windows 把各盘符加起来 |
| 影视空间 | 已经入库的影视文件加起来多大。不含漫画、小说，也不含还在下载的文件 |
| 已使用 / 剩余空间 | 磁盘层面用了多少、还能用多少，圆环画的就是这两段 |

每 10 秒静默刷新一次。

### 媒体统计

一行五个数：收藏影视、收藏演员、订阅影视、漫画（按相册数）、小说。同样每 10 秒静默刷新。数字是 0 不代表坏了，只说明还没有这类数据。

### 天气

显示图标、温度、天气现象、风向风力，以及省份与城市。

- 城市先取你在「集成应用 → 高德地图」里填的城市代码（`adcode`，3–6 位数字，就是城市的编号）。
- 没填城市代码时，程序先查本机公网 IP，再换算成城市。
- 没启用自己的高德配置时，用程序内置的一把钥匙，天气照样能显示。

> **代理**：程序不直接连目标网站，而是让装 AMMDS 的服务器替它把请求转发一次。直连连不上时会自动改走这条路。

加载不出来时，卡片显示「天气信息加载失败」和一个「重试」按钮。

:::note[天气要联网]
天气靠高德地图提供的数据。直连失败会自动改走服务器转发；两条路都不通才显示失败。这时先去看本栏目的《上不了网？先查这里》。
:::

### 网络信息

显示服务器看到的公网地址、用的是哪种网络连接、地理位置、有没有走代理；点开弹窗还有「连通性」标签页，能把程序用到的公共网站一个一个测过去。判定标准和排查方法单独一页，见[上不了网？先查这里](./network.md)。

### 系统信息

默认只给四行，方便快速核对版本。

| 这一行 | 说什么 |
| --- | --- |
| Java 版本、Spring Boot | 程序运行所依赖的基础软件版本，平时不用管 |
| AMMDS 内核版本 | AMMDS 自己的版本号，判断是不是最新就看它 |
| 运行系统 | 操作系统和架构；装在容器里时统一显示 `Docker` |

> **容器**：把程序和它要用的东西打包在一个隔离盒子里运行的一种装法。盒子里看到的系统统一记作 `Docker`。

点卡片任意位置打开「系统信息详情」，分两块：

- **服务端信息**：应用名称与描述、三个版本、底层运行环境与供应商、系统与架构、处理器核心数、内存占用、运行时长、服务端时间与时区、监听地址（程序对外服务的地址）、开发方与官网、联系邮箱。
- **浏览器信息**：浏览器标识、运行平台、语言、时区、屏幕与窗口尺寸、设备像素比、逻辑核心数、设备内存、网络状态、是否支持 Cookie、当前地址。

这份数据进工作台时取一次，打开详情复用同一份，不会一直刷新。

### AMMDS 服务状态

六个数字，都是最近 24 小时的口径：

| 指标 | 意思 |
| --- | --- |
| 在线人数 | 当前在线访问者数量 |
| 浏览量 | 最近 24 小时的页面浏览量 |
| 独立访客 | 最近 24 小时的独立访客数 |
| 访客 | 最近 24 小时的访问次数 |
| 跳出率 | 最近 24 小时的跳出率 |
| 平均访问时长 | 总访问时长除以访问次数，按天 / 时 / 分 / 秒显示 |

:::warning[这不是你机器的状态]
这些数字来自 AMMDS 官方统计服务，反映的是**官方网站**的访问情况，不是你本机 AMMDS 的运行指标。每 10 秒刷新一次，统计服务连不上时可能全是 0。想看本机的 CPU、内存、磁盘、数据库连接和插件状态，去「系统检查」；想看本机的端口、版本和监听地址，看上面的「系统信息」卡片。
:::

### 支持一下

一张能点的图片，点了在新标签页打开官方商城的购买页。它不参与任何统计，也不影响功能。

## 三个榜单，各看各的

三个榜单都在仪表盘下，数据来源完全不同，可以只启用其中一部分。

### 想回顾自己看了多少 —— 巅峰榜单

> **媒体服务器**：Jellyfin、Emby 这类负责放片、再给电视和手机播放的软件。

播放记录来自 Jellyfin 和 Emby 集成：启用插件、绑定用户后，后台每 5 分钟同步一次播放记录，写进本地；榜单只统计**绑定用户**的记录，不读媒体服务器自己的报表。

| 区域 | 内容 |
| --- | --- |
| 顶部统计 | 播放次数、总观影时长（分钟）、日均观影（分钟 / 天）、覆盖天数 |
| 播放趋势 / 观影时长 | 按天看各客户端播放时长和总量的柱状图、折线图 |
| 播放来源分布 | 按播放来源（客户端）汇总时长的饼图 |
| 月度播放日历 | 本月每天的播放热度，颜色越深表示当天看得越久 |

右上角的「7 天 / 14 天 / 30 天」按钮同时改变顶部统计和趋势图，默认 14 天。

几个容易看错的口径：

- 日期按播放记录的**开始时间**归到某天，统一写成 `yyyy-MM-dd`。
- 结束时间为空的记录算没看完，不计入按天统计。
- 没有播放记录的日期也会列出来（数值为 0），所以「覆盖天数」就等于你选的天数。
- 顶部「播放次数」是拿观看时长换算的：每满 10 分钟算 1 次、向上取整，不是记录条数。
- 月度日历里的「播放次数」是记录条数，和顶部不是一个算法；鼠标悬浮会把两种都显示出来。

:::note[全是空的先查绑定]
页面一片空白时，先到「集成应用 → Jellyfin / Emby」确认插件已启用、服务地址和密钥能连通、并且已经选好绑定用户。「系统检查」里也能看到对应插件的启用和配置状态。
:::

### 想找最近的新片 —— 电影榜单

> **元数据**：一部片子的封面、简介、演员、标签这些描述信息。

> **番号**：写在文件名里的影片识别编号，程序靠它认片子。

数据由后台定时任务从集成插件采集后存到本地，页面只读本地，打开时不会临时上网去抓。

| 榜单来源 | 从哪来 | 要满足什么才采集 |
| --- | --- | --- |
| ThePornDB | ThePornDB 的「最近更新」列表 | 「启用状态」和「榜单采集」都打开，且服务地址、API Key 都填全 |
| Fanza DMM | FANZA DMM 的日期榜单 | 「启用状态」和「榜单采集」都打开 |

采集都是后台自动跑，不用你点：

- ThePornDB：启动后约 8 分钟第一次，之后每 6 小时 10 分钟一次；每次最多翻 10 页、每页 20 条，按「来源那边的编号 + 榜单类型」去重，同一条不会重复进库。
- Fanza DMM 今日新作：启动后约 10 分钟第一次，之后每 6 小时 15 分钟一次；同一天已有数据就跳过。
- Fanza DMM 即将上映：启动后约 10 分钟第一次，之后每 13 小时 30 分钟一次，只补采未来 3 天里还没有记录的日期。

页面怎么用：

1. 顶部先选榜单来源：**ThePornDB** 或 **Fanza DMM**。
2. 再选分类：ThePornDB 有「Jav即将上映」「欧美即将上映」；Fanza DMM 有「今日上新」「即将上映」。
3. 卡片按发布日期倒序排，最多 30 条。每张有封面、番号、发布日期、标题、演员和剧照数量。
4. 卡片右上角是状态按钮：

| 按钮 | 意思 |
| --- | --- |
| 完成 | 这个番号已经入库，按钮点不动 |
| 订阅 | 还没订阅，点一下就提交订阅，后台会去补齐影片信息 |
| 已订阅 | 已经有订阅记录，按钮点不动 |

:::tip[点了订阅之后]
订阅会建一条订阅记录，并在后台慢慢补齐影片信息，之后由订阅和下载流程去匹配资源。很久没动静，先看下载器插件和站点配置，再看订阅状态。
:::

### 想看各站点账号状态 —— PT 站点榜单

> **PT 站点**：要注册账号、按上传下载量计分的资源站。

> **做种**：下载完成后继续开着、把文件传给别人的行为。

> **分享率**：上传量除以下载量的比值，站点一般要求它不低于某个数。

> **魔力值**：站点按做种等贡献给的积分。

数据来自已经配好的 PT 站点账号，按站点类型分别去取：M-Team、Rousi、FSM 和 NexusPHP 系站点。不要求先做「站点认证」，只要站点配好并同步过数据就会显示。

| 指标 | 口径 |
| --- | --- |
| 站点总数 | 有数据的站点数量 |
| 总上传量 / 总下载量 | 各站点上传、下载字节数相加 |
| 总做种数 / 总下载数 | 各站点做种、下载任务数相加 |
| 平均分享率 | 只算有分享率的站点，取平均 |
| 总魔力值 | 各站点魔力值相加 |
| 活跃站点 | 最近 30 天内有过登录记录的站点数 |

每张站点卡片有 Logo、名称、框架标签，还有分享率、魔力值、上传量、下载量、做种数、下载数、做种时长、下载时长、用户名与头像、警告 / 吸血 / 等级标签、注册时间与最后登录时间。卡片右上角两个按钮：**刷新**（只更这一个站点）和**打开主页**；刷新只更新这一个站点，NexusPHP 系站点按站点 ID 更新。

顶部还有两个操作：

| 按钮 | 作用 |
| --- | --- |
| 刷新数据 | 只把本地已有的站点数据重新读一遍，不去请求站点 |
| 更新所有站点 | 让后台逐个站点去拉最新数据，耗时较长 |

顶部提示条显示本页最近一次刷新或更新的时间，它只是页面上记下的时间，不代表服务器那边数据真正更新的时间。

:::warning[别一直点更新]
频繁点「更新所有站点」会连续去各站点取数据，可能被站点判定异常而临时封禁。不是非要实时数据时，保持默认节奏就好。
:::

### 三个榜单怎么选

| 你想看 | 用哪个榜单 |
| --- | --- |
| 自己的观影时长、习惯和设备分布 | 巅峰榜单 |
| 最近有哪些新片、是不是已入库 | 电影榜单 |
| 各 PT 站点的分享率、魔力值和做种情况 | PT 站点榜单 |

看观影要媒体服务器插件，看上新要元数据插件，看站点数据要站点配置。三套互相独立，只开一部分也能用。

## 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 天气城市代码（`adcode`） | 3–6 位数字的城市编号，在「集成应用 → 高德地图」里填 | 不填就按本机公网 IP 猜城市；填错城市，天气就显示别的地方 |
| 高德地图自定义配置 | 是否启用自己的高德配置 | 不启用就用程序内置的钥匙，天气照样能看 |
| 绑定用户（媒体服务器） | 在 Jellyfin / Emby 集成里选要统计的用户 | 不选或选错，巅峰榜单没有数据或数据不对 |
| 时间范围（7 / 14 / 30 天） | 巅峰榜单右上角选看多少天，默认 14 天 | 只影响顶部统计和趋势图，选错不会弄坏数据 |
| 榜单采集开关 | 电影榜单对应插件里，把「启用状态」和「榜单采集」都打开 | 有一个没开，该来源的榜单就不采集，页面没有新数据 |
| 服务地址、API Key | 采集 ThePornDB 榜单时要填全 | 少任一项，ThePornDB 榜单不采集 |
| 状态按钮「订阅」 | 在尚未订阅的卡片上点它 | 「完成」「已订阅」本来就点不动；订阅后要等后台补齐信息 |

## 出问题了怎么办

- 存储空间和「存储管理」页的数字对不上：两处口径不同。这里算整块磁盘总量加影视文件合计；「存储管理」按 `data/`、`db/` 下的一级子目录分开算。
- 媒体统计一直是 0：先确认是不是已有收藏、订阅、漫画或小说数据；刚装好还没有这些，0 是正常的。
- 天气城市不对：去「集成应用 → 高德地图」填对城市代码，或关掉自定义城市，让它按公网 IP 定位。
- 「AMMDS 服务状态」全是 0：那是官方统计服务连不上，跟你本机的功能无关，不用处理。
- 榜单空白：巅峰榜单查绑定用户，电影榜单查采集开关与插件配置，PT 榜单查站点是否配好并同步过。
