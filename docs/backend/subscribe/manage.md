# 订阅管理

订阅以番号为唯一键保存一条记录：先匹配影视元数据，再按配置的站点顺序检索资源，命中后自动提交 qBittorrent 下载，并按下载器状态回写「下载中 / 已完成」。

{/* truncate */}

## 打开方式

在 **订阅检索 → 订阅管理** 打开页面。页面按订阅状态分为六个页签，切换页签会重新拉取对应状态的数据。

## 订阅从哪里来

| 入口 | 说明 |
| --- | --- |
| 影视在线搜索 | 在 [影视](/docs/backend/media/movie) 的在线搜索结果中点击「订阅」，系统先保存影视元数据，再创建订阅 |
| 热门榜单 | 在仪表盘的热门榜单卡片上点击「订阅」 |
| 影视编辑器 | 在编辑器中「添加并订阅」 |
| 番号与识别码 | 订阅记录的 `uniqueid` 就是番号；同一番号（忽略大小写）已存在时会跳过，不会重复创建 |

:::note[订阅前先配好下载器]
自动下载依赖已启用的 qBittorrent 插件。未启用时订阅仍可创建和匹配，但提交下载会失败，并在站内通知中提示「未启用下载插件」。
:::

## 状态页签

| 页签 | 对应状态 | 含义 |
| --- | --- | --- |
| 全部 | `all` | 不按状态过滤 |
| 订阅 | `subscribe` | 已订阅，等待匹配或等待下一轮检索 |
| 暂停 | `paused` | 连续匹配失败达到上限或被暂停，不再自动下载 |
| 取消 | `cancel` | 已取消，记录保留，可恢复 |
| 下载 | `download` | 已提交下载器，正在下载 |
| 完成 | `finish` | 下载器报告已完成 |

列表每 10 秒轮询一次，订阅状态变化会自动反映到当前页；页面不可见时轮询暂停。

## 卡片字段

| 字段 | 说明 |
| --- | --- |
| 番号 | 蓝色标签，取自订阅记录的 `uniqueid` |
| 标题 | 匹配成功后显示影视标题；未匹配时显示「识别中」 |
| 上映时间 | 匹配成功后回填，缺失时显示「未知」 |
| 订阅时间 | 创建订阅的时间 |
| 海报 | 匹配后取影视海报首张；无海报时显示占位图标 |

只有带 `uniqueid` 的记录才会渲染卡片，缺少番号的记录视为尚未识别完成。

## 卡片操作

右下角的浮动按钮会随页签变化：

| 操作 | 出现页签 | 行为 |
| --- | --- | --- |
| 立即搜索 | 订阅、全部 | 提交一次该订阅的检索与下载任务，后台异步执行 |
| 恢复订阅 | 取消 | 把状态恢复为「订阅」，保留原记录 |
| 取消订阅 | 订阅、暂停、全部 | 把状态置为「取消」，保留记录以便恢复 |
| 删除订阅 | 取消、下载、完成、全部 | 物理删除该条订阅记录，不可恢复 |

「立即搜索」只负责提交，不会等待检索完成；提交后列表会刷新，实际进度看状态与站内通知。

## 匹配与下载流程

1. **匹配元数据**：按番号调用元数据服务检索，命中后写入 `matchId`、标题、海报与上映日期，并把连续失败计数清零。
2. **检查前置条件**：qBittorrent 已启用、订阅记录存在、已匹配到影视、影视带有识别码，任一缺失都会终止本次下载。
3. **按识别码检索**：遍历影视的识别码列表，逐个作为关键词检索站点资源；前一个番号没有结果时继续尝试下一个。
4. **排序资源**：Prowlarr 聚合结果永远排在最后；其余平台按「订阅规则配置 → 搜索顺序」中的关键词匹配，命中越靠前越优先。
5. **提交下载**：下载目录优先取订阅配置中的「下载目录」，未配置时回退 qBittorrent 默认保存路径；提交时写入标签 `AMMDS订阅` 与 `subscribe-<订阅ID>`。
6. **回查哈希**：提交后按标签回查下载器中的任务，最多重试 3 次，每次随机等待 2~8 秒；查到后记录下载哈希，状态转为「下载」。
7. **完成回写**：定时任务回查下载进度，下载器报告完成后把订阅置为「完成」，并推送完成通知。

:::tip[为什么有时显示「尚无资源」]
资源检索成功但没有任何站点返回可下载地址时，订阅会保持「订阅」状态并写入「尚无资源」通知，等待下一轮自动重试。
:::

## 匹配失败与重试

- 元数据匹配失败时 `matched=false`，连续失败计数加 1；**连续 10 次**失败会自动把订阅转为「暂停」，避免无意义地反复请求。
- 未匹配的订阅由定时任务「更新未匹配的订阅元数据」处理：启动后 10 分钟首跑，之后每 300 分钟一次。
- 处于「订阅」状态的记录由「批量下载待订阅影视」处理：每 20 分钟一次，单轮最多取 10 条，按订阅时间倒序。
- 想立刻重试时，在「订阅」或「全部」页签点击卡片上的「立即搜索」。
- 想停止重试时，点击「取消订阅」；之后可在「取消」页签恢复。

## 订阅规则配置

订阅相关的全局配置位于 **任务管理 → 任务配置 → 订阅规则配置**，由配置面板统一读写：

| 配置项 | 说明 |
| --- | --- |
| 中字优先 | 布尔配置项；当前版本仅保存该偏好，未参与自动下载的检索排序 |
| 搜索顺序 | 逗号分隔的平台关键词，默认 `M-Team,NexusPHP,Rousi,Prowlarr`；决定同一番号下各站点资源的尝试顺序 |
| 下载目录 | 提交下载时使用的保存路径；留空则使用 qBittorrent 默认保存路径 |

修改后无需重启，下一轮订阅任务会读取新值。配置入口与其它规则见 [任务配置](/docs/backend/task/config)。

## 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 卡片一直显示「识别中」 | 元数据源未匹配到番号 | 检查元数据插件，或在影视库中手动绑定后再试 |
| 状态停在「订阅」 | 站点无资源、站点未启用或下载器未启用 | 查看站内通知，确认插件与站点状态 |
| 提交后没有出现在下载器 | 下载目录无效或 qBittorrent 连接失败 | 在 [下载器使用](/docs/backend/subscribe/downloader) 中检查连接与保存路径 |
| 自动暂停 | 连续 10 次匹配失败 | 修正番号或元数据后，恢复订阅 |
| 下载完成但订阅未完成 | 下载器尚未回查或任务被移除 | 等待下一轮进度回查，必要时重新提交 |

站点资源本身的筛选与手动下载见 [站点资源检索](/docs/backend/subscribe/search)；下载器任务的查看与操作见 [下载器使用](/docs/backend/subscribe/downloader)。
