# 定时任务

「计划任务」页面汇总系统内全部定时作业：订阅轮询、站点认证、媒体服务器同步、RSS 更新、数据清理、榜单抓取等。它展示的是应用内置的 `@Scheduled` 作业，不是单个扫描任务的 Cron。

{/* truncate */}

## 打开方式

进入 **系统管理 → 计划任务**。页面顶部是总开关状态、运行中数量、自动刷新与刷新按钮，下方是任务表格。

## 列表字段

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 主标题为作业名称，副行显示 `类名#方法名`，便于与代码对照 |
| 执行周期 | 人类可读的周期文本；悬浮可看原始 Cron 或 fixedRate/fixedDelay 表达式 |
| 运行状态 | 本页手动执行中 / 空闲；下方附带上次手动执行结果摘要 |
| 上次执行 | 上次手动执行的开始时间；失败时追加红色「失败」标签，从未手动执行显示「从未执行」 |
| 操作 | 执行按钮；运行中或总开关关闭时置灰 |

:::note[运行状态的来源]
表格里的「运行状态」与「上次执行」记录的是从本页手动触发的执行；自动调度触发不会回写这两个字段。自动任务的执行情况请到 [运行日志](/docs/backend/system/logs) 查看。
:::

:::note[周期文本可能显示原始表达式]
页面只把常见的「每天定点」「每 N 分钟」「每 N 小时」「每 N 天定点」翻译成中文；无法识别的 Cron 会原样显示表达式，这是有意为之，避免猜测导致误读。
:::

## 总开关

总开关由环境变量 `AMMDS_SCHEDULER_ENABLE`（配置项 `ammds.scheduler.enable`）控制，默认开启。

- 关闭后页面顶部显示「计划任务已关闭」，并给出说明提示。
- 手动执行会被后端拒绝，按钮同时置灰。
- 应用启动时会跳过「任务级 Cron」与「IYUU 自动辅种」的注册，这两类计划不再生效。
- 内置 `@Scheduled` 作业仍由 Spring 调度器管理，页面会继续列出并按各自周期执行；该开关不会卸载它们。需要彻底停止全部后台作业时，应停止实例或在部署层处理。

修改该开关需要重启应用生效，具体配置方式见 [系统配置](/docs/backend/system/config)。

## 手动执行

点击某一行的「执行」按钮只提交一次执行，不改变原有调度周期：

1. 后端把任务放进独立的手动执行线程池，接口立即返回。
2. 同一任务已有执行中的实例时，再次点击会被拒绝，提示「任务正在执行中」。
3. 页面立刻把该行标记为执行中，并开始按 3 秒间隔轮询；全部任务结束后自动停止轮询。
4. 执行完成后，「上次执行」更新时间，结果摘要写入运行状态下方；失败时摘要为异常类名与消息（超长会截断）。

「自动刷新」开关控制是否在有任务运行时轮询，关闭后需要手动点「刷新」才能看到最新状态。

## Cron 与执行周期

应用使用 Spring 六段式 Cron：`秒 分 时 日 月 周`。

| 表达式 | 含义 |
| --- | --- |
| `0 0/20 * * * ?` | 每 20 分钟 |
| `0 0/2 * * * ?` | 每 2 分钟 |
| `0 0 9 * * ?` | 每天 09:00 |
| `0 30 4 * * ?` | 每天 04:30 |
| `0 10 */6 * * ?` | 每 6 小时的第 10 分钟 |
| `0 0 3 1/13 * ?` | 每 13 天的 03:00 |

除了 Cron，部分作业使用 `fixedRate`（固定频率）或 `fixedDelay`（上次结束后再计时）。页面会把它们换算成「每 N 分钟 / 小时」，并标注初始延迟。

## 执行范围

任务清单在应用启动时扫描容器中所有 `@Scheduled` 方法自动生成，不需要手工维护。常见分组：

| 分组 | 代表作业 |
| --- | --- |
| 订阅与下载 | 批量下载待订阅影视（每 20 分钟）、更新订阅下载进度（每 2 分钟）、更新未匹配的订阅元数据（每 300 分钟） |
| 站点与账号 | 执行 PT 站点认证、同步全部 PT 站点用户数据、检查 PT 站点账户安全状态 |
| 媒体服务器 | 同步 JellyFin / Emby 播放记录与媒体库、补全媒体库演员数据 |
| 信息中心 | 更新 RSS 文章、RSS 离线缓存、RSS 自动归档、刷新热门订阅、校验热门订阅可用性 |
| 榜单 | 抓取 ThePornDB 最近更新、FANZA DMM 当日榜单与未来 3 天榜单 |
| 维护 | 清理扫描脏数据、修复章节序号、清理文件浏览器临时文件、感知哈希计算、磁盘容量检查、存储统计、许可证校验、MeiliSearch 自动索引 |
| 其它 | 系列库同步、厂牌规则收纳、官方商城同步、本地资源同步到 S3 |

具体作业以页面实际列表为准；新增内置作业只要标注 `@Scheduled`，重启后就会自动出现，无需改页面。

## 与任务配置的关系

「计划任务」页与任务配置里的 Cron 是两套机制：

| 机制 | 配置位置 | 是否出现在计划任务页 |
| --- | --- | --- |
| 内置定时作业 | 代码中的 `@Scheduled` | 是 |
| 扫描任务 Cron | 任务配置 → 编辑任务 → 计划任务 | 否，由任务调度器单独注册 |
| 自动刮削间隔 | 任务配置 → 刮削规则 | 否，按间隔自调度，不受总开关控制 |
| IYUU 自动辅种 | 工具箱 → PT 辅种 → 辅种计划 | 否，由任务调度器单独注册 |

扫描任务开启目录监控后不再使用 Cron；关闭监控且填写 Cron 时，任务会在应用启动或配置变更后注册到调度器。任务级 Cron 与 IYUU 自动辅种受总开关约束，内置 `@Scheduled` 作业不受该开关控制。

:::warning[不要重复配置]
同一个扫描任务既填 Cron 又开目录监控没有意义：保存时只会保留其中一种触发方式。需要「新文件立即处理」用目录监控，需要「固定时间全量扫描」用 Cron。
:::

## 排查建议

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 页面提示计划任务已关闭 | 总开关为 false | 修改 `AMMDS_SCHEDULER_ENABLE` 并重启 |
| 执行按钮置灰 | 任务正在执行或总开关关闭 | 等待当前执行结束，或检查总开关 |
| 上次执行显示失败 | 上游服务不可用、凭据失效或网络异常 | 查看结果摘要与 [运行日志](/docs/backend/system/logs)，修复后手动执行一次 |
| 到点没有触发 | Cron 写错、时区不符或总开关关闭 | 核对六段式表达式与应用时区 |
| 任务列表为空 | 应用尚未完成启动扫描，或没有可发现的作业 | 刷新页面；仍为空时查看启动日志 |

任务本身的运行记录见 [任务记录与日志](/docs/backend/task/record)；扫描任务的 Cron 配置见 [扫描任务](/docs/backend/task/scan)。
