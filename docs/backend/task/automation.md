# 定时自动跑、任务记录与失败重试

不想每次都手动点「立即扫描」？这一页讲怎么让任务按点自己跑、那个控制全局的总开关在哪、时间表怎么写、跑完的记录去哪看，以及失败之后怎么重试、日志怎么清理。

## 先说清楚

> **刮削**：程序自动去资料网站查这部片子的封面、简介、演员，并填回来。

> **元数据**：一部片子的封面、简介、演员、标签这些描述信息。

> **番号 / 识别码**：影片的识别编号，通常写在文件名里，程序靠它认片子。

> **NFO**：和视频放在一起的小说明文件，播放器能读它。

> **Cron**：一串用数字和符号写成的「什么时候跑」的时间表，比如每天几点、每隔几分钟。

> **定时作业**：程序自己按点去做的一件活，比如同步播放记录、抓榜单、清理临时文件。

> **调度器**：程序里负责「到点就叫醒对应作业」的那一层，你不用手工一个个去启动。

> **环境变量**：软件启动前在系统里设的一个开关值。普通装法下不用碰，改它一般要重启程序才生效。

> **并发**：好几件事同时抢着做。

> **日志**：程序把「什么时候做了什么、成没成」记下来的流水账，出问题时靠它回溯。

## 让任务按点自己跑

### 打开「计划任务」页

进入 **系统管理 → 计划任务**。页面顶部显示总开关状态、正在运行的数量、「自动刷新」开关和「刷新」按钮，下面是作业表格。

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 主标题是作业名，下面一行是内部标识 `类名#方法名`，方便对照 |
| 执行周期 | 一句人话写清多久跑一次；鼠标悬浮能看到原始 Cron 或固定间隔表达式 |
| 运行状态 | 本页手动触发的执行中是 / 空闲，下面附上次手动执行的结果摘要 |
| 上次执行 | 上次手动执行的开始时间；失败时追加红色「失败」标签，从没手动跑过显示「从未执行」 |
| 操作 | 「执行」按钮；运行中或总开关关闭时会置灰 |

:::note[这两个字段只记手动跑的]
表格里的「运行状态」和「上次执行」只记录**从本页手动触发**的执行。自动调度触发的不会写回这两个字段，自动任务跑得怎么样要到「系统管理 → 运行日志」里看。
:::

:::note[周期文字看不懂时]
页面只把常见的「每天定点」「每 N 分钟」「每 N 小时」「每 N 天定点」翻成中文。认不出来的 Cron 会原样显示表达式，这是故意的，免得猜错让人误读。
:::

### 总开关：一关，一批计划就停

全局总开关由环境变量 `AMMDS_SCHEDULER_ENABLE`（配置项 `ammds.scheduler.enable`）控制，**默认开启**。

- 关掉后页面顶部显示「计划任务已关闭」，并给出说明提示。
- 手动「执行」会被拒绝，按钮同时置灰。
- 应用启动时会跳过「任务级 Cron」和「IYUU 自动辅种」的注册，这两类计划不再生效。
- 程序内置的定时作业不受这个开关影响，页面照样列出、照常按各自周期跑。想彻底停掉全部后台作业，得停掉整个实例或在部署层处理。

**改这个开关要重启应用才生效。** 具体改法在系统设置栏目里找系统配置那一页。

### 手动执行一次

点某一行的「执行」只提交一次执行，不改原来的调度周期：

1. 提交后页面马上返回，活儿在后台排队跑，不用守在页面上等。
2. 同一个作业已经在跑时，再点会被拒绝，提示「任务正在执行中」。
3. 页面会立刻把这一行标成执行中，并每 3 秒看一眼结果；全部跑完就自动停下来。
4. 跑完后「上次执行」会更新时间，结果摘要写在运行状态下面；失败时摘要显示错误类型和消息，太长会截断。

「自动刷新」开关控制有任务在跑时要不要轮询；关掉后得手动点「刷新」才看得到最新状态。

### Cron 怎么写

程序用六段式 Cron，顺序是 `秒 分 时 日 月 周`：

| 表达式 | 意思 |
| --- | --- |
| `0 0/20 * * * ?` | 每 20 分钟 |
| `0 0/2 * * * ?` | 每 2 分钟 |
| `0 0 9 * * ?` | 每天 09:00 |
| `0 30 4 * * ?` | 每天 04:30 |
| `0 10 */6 * * ?` | 每 6 小时的第 10 分钟 |
| `0 0 3 1/13 * ?` | 每 13 天的 03:00 |

有些作业不是按时间点跑，而是「隔多久跑一次」或者「上次跑完再等一会儿」。页面会把这几种都换算成「每 N 分钟 / 小时」，并标出第一次要等多久才开始。

### 都有哪些自动作业

清单在应用启动时自动扫出来，不用手工维护。常见几组：

| 分组 | 代表作业 |
| --- | --- |
| 订阅与下载 | 批量下载待订阅影视（每 20 分钟）、更新订阅下载进度（每 2 分钟）、更新未匹配的订阅元数据（每 300 分钟） |
| 站点与账号 | 执行 PT 站点认证、同步全部 PT 站点用户数据、检查 PT 站点账户安全状态 |
| 媒体服务器 | 同步 Jellyfin / Emby 播放记录与媒体库、补全媒体库演员数据 |
| 信息中心 | 更新 RSS 文章、RSS 离线缓存、RSS 自动归档、刷新热门订阅、校验热门订阅可用性 |
| 榜单 | 抓取 ThePornDB 最近更新、FANZA DMM 当日榜单与未来 3 天榜单 |
| 维护 | 清理扫描脏数据、修复章节序号、清理文件浏览器临时文件、感知哈希计算、磁盘容量检查、存储统计、许可证校验、MeiliSearch 自动索引 |
| 其它 | 系列库同步、厂牌规则收纳、官方商城同步、本地资源同步到 S3 |

具体以页面实际列表为准。以后新增内置作业，重启后会自动出现，不用改页面。

### 两套机制别搞混

「计划任务」页和任务配置里的 Cron 是两回事：

| 机制 | 在哪配 | 会出现在「计划任务」页吗 |
| --- | --- | --- |
| 内置定时作业 | 程序自带 | 会 |
| 扫描任务 Cron | 任务配置 → 编辑任务 → 计划任务 | 不会，由调度器单独注册 |
| 自动刮削间隔 | 任务配置 → 刮削规则 | 不会，按间隔自己跑，不受总开关控制 |
| IYUU 自动辅种 | 工具箱 → PT 辅种 → 辅种计划 | 不会，由调度器单独注册 |

扫描任务开了目录监控就不再用 Cron；关掉监控且填了 Cron，任务会在应用启动或配置改动后交给调度器安排。任务级 Cron 和 IYUU 自动辅种受总开关约束，内置定时作业不受它管。

:::warning[别给同一个任务配两种触发]
同一个扫描任务既填 Cron 又开目录监控没有意义，保存时只会保留其中一种。想「新文件一到就处理」用目录监控，想「固定时间全量扫一遍」用 Cron，详见[扫描：让 AMMDS 认识你的文件](./scan.md)。
:::

## 任务跑完去哪看记录

### 三类记录

| 记录 | 位置 | 记的是什么 |
| --- | --- | --- |
| 扫描日志 | 任务管理 → 扫描日志 | 扫描任务每次运行 |
| 刮削日志 | 任务管理 → 刮削日志 | 刮削任务的每个批次 |
| 任务日志 | 系统管理 → 日志审计 → 任务日志 | 文件操作、备份、RSS、漫画 / 小说整理等后台任务 |

### 扫描日志

点「查询」按条件刷新，点「重置」恢复默认。从任务卡片点「记录」进来时，会自动带上该任务过滤。

| 检索条件 | 可选项 |
| --- | --- |
| 任务类型 | 全部 / 影视 / 剧集 |
| 任务选择 | 按任务名称筛，可选全部 |
| 运行类型 | 手动执行、定时任务、实时监控、初始化 |
| 任务状态 | 创建、扫描中、监控中、等待扫描、扫描完成、取消扫描、扫描异常 |

| 列表字段 | 说明 |
| --- | --- |
| 任务名称 | 这次扫描属于哪个任务 |
| 类型 | 运行类型，对应触发来源 |
| 开始时间 | 开始执行的时间 |
| 任务耗时 | 有耗时就显示；扫描中显示「扫描中」，其它没有耗时的状态显示「扫描中断」 |
| 任务状态 | 扫描完成是绿色圆点，其余灰色 |
| 识别媒体数量 | 这次扫到的视频文件数 |
| 新增媒体数量 | 新登记入库的文件数 |
| 更新媒体数量 | 已存在、重新绑到这次扫描的记录数 |
| 操作 | 「取消」；只有「扫描中」且运行类型不是「实时监控」「初始化」时能取消 |

页面底部能翻页、改每页条数、调表格密度和列的显隐。顶部「清理日志」会清空全部扫描记录，**不可恢复**。

:::note[扫描日志没有单条详情]
扫描日志只记整批的信息。想看某个文件的识别番号、刮削状态和步骤，到 **任务管理 → 刮削入库**；单个媒体的步骤时间线在「查看步骤」里。
:::

### 刮削日志

| 检索条件 | 可选项 |
| --- | --- |
| 任务类型 | 全部 / 影视 / 剧集 |
| 运行类型 | 手动执行、定时任务等 |
| 任务状态 | 刮削中、刮削完成、等待、取消、异常 |

| 列表字段 | 说明 |
| --- | --- |
| 任务名称 | 本批次任务名；多线程时会带线程后缀 |
| 开始时间 | 批次开始时间 |
| 刮削结果 | 批次结果摘要 |
| 任务耗时 | 刮削中显示「刮削中」，其它没有耗时的状态显示「刮削中断」 |
| 任务状态 | 完成显示绿色，其余橙色 |
| 刮削媒体数量 | 本批次计划处理多少个 |
| 刮削成功数量 / 失败数量 | 本批次成功与失败计数 |
| 操作 | 「取消」；只有「刮削中」且运行类型不是实时刮削 / 初始化时能取消 |

「清理日志」只清可删除的历史记录。正在跑的任务不会被清掉；要停它先点「取消」。

### 系统任务日志

文件上传、下载、复制、移动、压缩，备份导入导出，RSS 更新，漫画 / 小说整理等操作都会写进这里：

- 能按关键字、任务类型、状态筛选。
- 列表显示类型、标题、状态、进度、消息、开始时间与耗时。
- 点「详情」打开抽屉，能看状态、进度、完成数 / 总数、消息、错误、开始和结束时间，以及一行行的执行日志，其中 `ERROR` 和 `WARN` 会高亮。
- 只有「执行中」、并且系统允许取消的任务，才会显示「取消」按钮。
- 执行中的任务不能删；已结束的可单条删，也能用「清理」批量删已结束的。
- 开启「自动刷新」后每 5 秒刷新一次列表。

### 状态对照

| 链路 | 会出现的状态 |
| --- | --- |
| 扫描任务 | 创建、扫描中、监控中、等待扫描、扫描完成、取消扫描、扫描异常、任务删除 |
| 刮削任务 | 刮削中、刮削完成、等待、取消、异常、删除 |
| 系统任务 | 执行中、已完成、失败、已取消 |

「等待」是任务建好了但还没轮到它跑；「异常」是跑的过程中冒出没处理掉的错误，要结合日志和步骤一起看。

## 失败之后怎么重试

记录页本身**没有「重试」按钮**，重试都回到对应的业务页面去做：

| 场景 | 怎么重试 |
| --- | --- |
| 扫描失败或想重扫 | 在任务配置再点一次「立即扫描」；正在扫描的要先取消 |
| 单个媒体刮削失败 | 在「刮削入库」点「刮削整理」，失败的会重新进待办，见[刮削：自动补齐影片信息](./scrape.md) |
| 识别番号错了 | 在「刮削入库」点识别番号标签改，再重新刮削 |
| 元数据匹配不到 | 用「绑定」手工绑到影视库记录，再刮削 |
| 图片或 NFO 缺失 | 对任务用「查漏补缺」，只补附属文件 |
| 订阅下载失败 | 在订阅管理点「立即搜索」，或等下一轮自动任务 |
| 文件操作失败 | 在系统任务日志看错误，把路径 / 权限修好再重新发起 |

:::tip[先看步骤，再看日志]
刮削失败时，先到「刮削入库 → 查看步骤」定位是文件校验、番号识别、数据源检索，还是图片 / NFO 生成出了问题；步骤里的错误信息通常比整批日志更具体。
:::

## 清理日志前先看

- 清理日志**不会删除媒体记录**，也不会把已经整理好的文件退回去。
- 扫描日志清掉后，历史批次就再也查不到了；要留排查依据，先导出或截图。
- 刮削日志只删允许删的历史记录，运行中的任务不会被清掉。
- 系统任务日志的「清理」只删已结束的，执行中的会保留。

## 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 全局计划任务总开关 `AMMDS_SCHEDULER_ENABLE` | 默认开启；在系统配置里改，改完要重启应用 | 关掉后「计划任务已关闭」、执行按钮置灰、任务级 Cron 与 IYUU 自动辅种不再注册；内置定时作业仍照常跑 |
| 扫描任务的计划任务（Cron） | 六段式表达式 `秒 分 时 日 月 周`，关掉目录监控时才显示 | 不填就只手动跑；写错或时区不符会到点不触发；还要确认总开关没关 |
| 目录监控 | 和 Cron 二选一 | 两个都填只会保留一种；开了监控就不参与 Cron 调度 |
| 自动刮削间隔 | 影视 / 剧集各自的开关与间隔，默认每 3 分钟检查一次待办 | 关闭就只能手动触发；间隔太短会频繁跑；它不受总开关控制 |
| 手动「执行」 | 在「计划任务」点某一行的执行按钮 | 运行中或总开关关闭时按钮置灰；同一作业已在执行会提示「任务正在执行中」 |
| 自动刷新（计划任务页） | 有任务在跑时要不要按 3 秒轮询 | 关掉就得手动点「刷新」才看得到最新状态 |
| 自动刷新（系统任务日志） | 开或关，开启后每 5 秒刷新一次 | 关掉不会自动更新列表 |
| 扫描 / 刮削日志的检索条件 | 任务类型、任务选择、运行类型、任务状态 | 条件选错会查不到想要的记录；点「重置」回到默认 |
| 清理日志 | 三类日志各自的「清理日志 / 清理」按钮 | 不可恢复：清掉后历史批次无法追溯；运行中的任务不会被清掉 |
| 保存配置 / 刷新配置（规则面板） | 改完点「保存配置」逐项提交 | 不保存不生效；点「刷新配置」会丢掉未保存改动 |

## 出问题了怎么办

| 现象 | 可能原因 | 怎么处理 |
| --- | --- | --- |
| 页面提示「计划任务已关闭」 | 总开关被关了 | 改 `AMMDS_SCHEDULER_ENABLE` 并重启应用 |
| 「执行」按钮置灰 | 任务正在执行，或总开关关闭 | 等当前这次跑完，或去检查总开关 |
| 「上次执行」显示失败 | 上游服务不可用、凭据失效或网络异常 | 看结果摘要和「系统管理 → 运行日志」，修好后手动执行一次 |
| 到点没有触发 | Cron 写错、时区不符或总开关关闭 | 核对六段式表达式和应用时区 |
| 「计划任务」列表是空的 | 应用还没完成启动扫描，或没有可发现的作业 | 先刷新页面；还是空的就看启动日志 |
| 自动任务跑了，但「上次执行」没变 | 那两个字段只记手动执行 | 到「系统管理 → 运行日志」看自动调度的情况 |
| 扫描 / 刮削记录里找不到单个文件 | 日志只记整批 | 到「任务管理 → 刮削入库」看单个文件和「查看步骤」 |

- 想让扫描按点跑，除了填 Cron，还要确认全局总开关没关，见[扫描：让 AMMDS 认识你的文件](./scan.md)。
- 刮削相关的触发方式、自动刮削间隔和查漏补缺，见[刮削：自动补齐影片信息](./scrape.md)。
- 清日志前先截图或导出：清掉就找不回来了。
