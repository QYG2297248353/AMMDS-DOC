# 网络与连通性

工作台的「网络信息」卡片展示服务端视角的公网地址与代理状态，并提供**连通性**标签页，按表格顺序逐个检测后端使用到的全部公共域名。

{/* truncate */}

## 打开方式

在 **仪表盘 → 工作台** 找到「网络信息」卡片，点击卡片任意位置打开弹窗。弹窗内有两个标签页：

| 标签页 | 内容 |
| --- | --- |
| 网络详情 | 公网 IPv4 / IPv6、当前连接协议族、地理位置、代理情况 |
| 连通性 | 公共域名清单与逐个检测结果 |

## 网络详情

### 数据来源

标签页顶部可切换数据来源：

- **当前网页**：由浏览器直接请求 `ip.sb`，反映你当前访问设备的出口地址
- **后台服务**：由后端代理转发请求，反映**服务器**的出口地址

两者不一致通常意味着服务器走了代理，或者你的浏览器与服务器不在同一网络。

### 展示项

| 项目 | 说明 |
| --- | --- |
| IPv4 / IPv6 | 分别探测，任一不可用显示「暂不支持」 |
| 网络优先级 | 双栈可用时按当前连接实际使用的协议族标注优先项 |
| 地理位置 | 国家/地区、城市、ISP、ASN、时区、经纬度 |
| 代理情况 | 系统配置中的代理开关、协议、地址、认证用户名（不回显密码） |

:::tip[缓存]
同一来源的详情结果会缓存 5 分钟，切换来源或点击「刷新」才会重新请求；网络信息卡片本身也会缓存 5 分钟，避免每次进入工作台都重新探测。
:::

## 连通性

### 判定标准

- **可访问**：后端拿到了目标服务器的任意 HTTP 响应（包括 401、403、404）。这说明网络链路是通的，接口需要鉴权或路径不存在不影响结论。
- **不可访问**：域名解析失败、连接超时、连接被重置、TLS 握手失败等。

因此「可访问」不等于「功能可用」。例如 TMDB 显示可访问但刮削仍失败，通常是 API Key 或配额问题，而不是网络问题。

### 表格字段

| 字段 | 说明 |
| --- | --- |
| 测试对象 | 站点图标 + 域名，副标题为名称与分组 |
| 连通性 | 待测试 / 测试中 / 可访问 / 不可访问，悬浮可看状态码或失败原因 |
| 耗时 | 从后端发起请求到收到响应头的时间 |

### 执行顺序

点击「开始测试」后，系统会**按表格顺序逐行串行测试**，每测完一行立即回显结果，不会并发抢占带宽。全部结束后顶部汇总显示总数、可访问数、不可访问数与总耗时。

- 中途关闭弹窗会立即中止后续测试
- 已加载的清单会复用，切回标签页不会重复拉取
- 「重新测试」会重置所有行后重新按顺序执行

### 检测对象

清单按分组维护，覆盖后端实际访问的公共域名：

| 分组 | 包含 |
| --- | --- |
| 元数据源 | DMM、FANZA、DMM 图片、R18.dev、TMDB、TMDB 图片、TheTVDB、Bangumi、ThePornDB、TheJavDB、MGS、JavBus、JAV321、AV-Legue、麻豆、MetaTube |
| 站点索引 | M-Team、M-Team API、Rousi、FSM、IYUU、KamePT |
| 通知服务 | Telegram、Bark、高德地图 |
| AI 与翻译 | DeepSeek、Gemini、百度翻译、DeepL、新译、彩云小译、Google 翻译、微软翻译、腾讯翻译 |
| 基础设施 | GitHub、GitHub 加速、HuggingFace、HF 镜像、官方资源、官方 S3、许可证服务、官方商城、统计服务 |
| DNS 与基础 | Cloudflare DoH、Google DoH、DNSPod DoH、IP 查询（ip-api / ipw.cn）、时间校验（苏宁 / 淘宝） |

:::info[新增域名]
清单由后端登记表统一维护，新增一项即可出现在本页，无需改动前端。自建服务（Jellyfin、qBittorrent、本地 MetaTube 等）不在此列，它们的连通性在各自的插件配置页测试。
:::

## 排查建议

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 大面积不可访问，耗时接近 4 秒 | 服务器无法出网 | 检查主机 DNS、防火墙与上游网络 |
| 仅境外域名不可访问 | 跨境链路受限 | 在 **系统配置 → 网络代理** 中启用代理后重测 |
| 全部域名可访问但刮削失败 | 鉴权、配额或站点风控 | 检查插件配置与站点账号状态 |
| DNS 分组整体失败 | DoH 端口被拦截 | 属于网络策略限制，通常不影响其他功能 |

需要更完整的体检（数据库、磁盘、依赖程序、插件配置）时，使用 **系统 → 系统检查**，详见[系统检查](/docs/system/system-check)。
