# 用 Telegram 遥控 AMMDS

除了收通知，Telegram 还能当遥控器：在手机或群里发指令，让 AMMDS 检索影片、订阅番号、看媒体库和下载任务、跑扫描、登录 115。

这一页讲怎么把机器人接上、怎么绑定自己、有哪些指令、哪些需要管理员、危险操作怎么确认。

## 先配好机器人

1. 在 Telegram 里找 `@BotFather`，新建一个机器人，拿到 **Bot Token**。
2. 打开后台「集成应用 → 推送通知 → Telegram」，填好 Bot Token，并把「启用状态」打开。
3. 到「系统配置 → 通知」确认**启用通知推送**是打开的。这是总开关，关掉后系统不会处理你发来的指令，机器人只收不回。
4. **不要注册 Webhook**。指令依赖系统定时向 Telegram 拉取消息；注册 Webhook 后系统会停止拉取，指令就不会响应了。家庭内网部署本来也不需要 Webhook。

服务地址默认是官方地址，用自建反代时再改。

## 绑定账号

第一次用的时候，系统还不知道你是谁。

1. 私聊机器人，发 `/whoami`。
2. 机器人会回复你的 **Chat ID**、**From ID**、昵称和当前角色。
3. 把 From ID 填进后台「用户白名单」，格式是 `FromID:角色`，多个账号用逗号分隔，例如：

```text
123456789:OWNER,987654321:ADMIN,555555555:GUEST
```

4. 保存后重新发一次 `/whoami`，角色就会变过来。

也可以不填白名单，直接把你的私聊 Chat ID 填到 `Chat ID` 配置项：私聊时 Chat ID 与 From ID 相同，这个账号会被当作所有者（OWNER）。群组场景建议用白名单，按人分配角色更清楚。

## 角色和权限

角色级别从高到低是 OWNER、ADMIN、GUEST、NONE，级别高的能用低级别的全部指令。

| 角色 | 能做什么 |
| --- | --- |
| OWNER（所有者） | 全部指令 |
| ADMIN（管理员） | 只读指令，加上扫描、刮削、重启、115 删除、下载器操作等 |
| GUEST（访客） | 检索、订阅、收藏、查看状态、跑体检摘要等只读或普通操作 |
| NONE（未绑定） | 只能用 `/start` 和 `/whoami` |

## 指令一览

### 基础

| 指令 | 作用 | 权限 |
| --- | --- | --- |
| `/ammds` | 查看 Bot 信息 | GUEST |
| `/start` | 启用 Bot，返回欢迎信息 | 未绑定也能用 |
| `/stop` | 停用 Bot，停止接收指令 | ADMIN，需确认 |
| `/help [指令]` | 查看帮助；带指令名时显示该指令的用法、所需角色和风险 | GUEST |
| `/version` | 查看 AMMDS 版本 | GUEST |
| `/whoami` | 查看自己的 Chat ID、From ID 和角色 | 未绑定也能用 |

| 指令 | 作用 | 权限 |
| --- | --- | --- |
| `/movie <关键词>` | 按关键词检索影片元数据 | GUEST |
| `/actor <关键词>` | 按关键词检索演员元数据 | GUEST |

`/deepseek` 需要先启用 DeepSeek 插件，否则会提示「请先启用 DeepSeek 插件」。会话闲置 20 分钟后自动过期，过期后再发就是新会话。

### 磁力推送

磁力链接除了检索，还能直接推给下载器，这组指令的区别只在「推到哪里」：

| 指令 | 推送到 | 权限 |
| --- | --- | --- |
| `/115 <磁力链接>` | 115 云下载 | ADMIN |
| `/magnet <磁力链接>` | 当前默认下载器 | ADMIN |
| `/qb <磁力链接>` | qBittorrent | ADMIN |
| `/tr <磁力链接>` | Transmission | ADMIN |

`/115 <磁力链接>` 会先校验链接，再依次确认 115 插件是否启用、是否已授权、是否已绑定，最后看云下载的剩余配额。**配额为 0 时会直接拒绝，不会提交任务。** 成功回执只显示任务名（取磁力里的 `dn` 名称，没有就用哈希前 8 位）、目标「115 云下载」、哈希前缀和剩余配额；失败会说明原因，比如配额不足、任务已存在、授权失效或创建失败。

`/magnet` 后跟磁力链接时走当前默认下载器，带关键词时仍是磁力检索。`/qb` 和 `/tr` 分别指定 qBittorrent 和 Transmission，没有可用的下载器时会提示去后台启用并配置。

几条规则：

- 只接受 `magnet:?xt=urn:btih:` 后接 40 位十六进制或 32 位 Base32 的链接，整条链接不超过 2048 字符
- 同一个 infohash 在 60 秒内重复提交会被拦截，回执会提示刚刚已提交
- 这些推送都是写操作，只有 OWNER 和 ADMIN 能执行，访客会被拒绝

### 授权与试用

| 指令 | 作用 | 权限 |
| --- | --- | --- |
| `/license` | 查看授权状态：状态、授权方式与套餐、到期时间与宽限截止、本实例是否已绑定、试用是否用过；未授权时给出下一步 | GUEST |
| `/license <密钥>` | 激活许可证 | ADMIN，需确认 |
| `/license <密钥> replace` | 已有许可证时更换，会释放旧实例占用的席位 | ADMIN，需确认 |

`/license` 不带参数时只读，不会改动授权，回执里能看到这些信息：

- 状态，以及对应的授权方式、套餐和脱敏密钥
- 到期时间和剩余天数；永久授权显示「永久」
- 本实例是否已绑定，以及占用的席位
- 试用有没有用过、试用截止时间
- 未授权时的诊断码

几种需要留意的显示：

- **已过期但还在宽限期**：会出现到期告警和宽限截止时间，宽限内仍可使用，但应尽快续期
- **还剩 0~15 天**：只有在这个区间才会提示「即将到期」
- **未授权**：管理员会看到「发送 `/license <密钥>` 激活，或到后台『系统设置 → 许可证』操作」；没试用过的话，还会提示可以在后台启动 7 天试用。访客看到的是联系管理员的说明

激活只允许 ADMIN 和 OWNER。发送 `/license <密钥>` 后不会立刻生效，机器人先回一张确认卡片：

> 即将激活许可证：ABC123…7890
> 确认后将占用 1 个激活席位，有效期以授权服务返回为准。

卡片上的密钥只保留**前 6 位与后 4 位**，密钥不足 10 位时只显示尾号；日志里也不会记录完整密钥。点「✅ 确认激活」才会真正激活。

失败时会直接说明原因，常见的有：密钥格式不正确、许可证已过期或被暂停/撤销、激活席位已满、许可证服务暂时不可用、上一次激活还在处理中。已经有许可证时，会提示改用 `/license <密钥> replace` 更换。

## 危险操作怎么确认

下面这些动作不会立刻执行，机器人会先回一条带「✅ 确认」和「取消」按钮的消息：

- `/stop`、`/restart`、`/scan`、`/scrape`
- `/system restart`、`/system stop`
- `/115_del <序号>`
- `/unsubscribe <编号>`
- `/dl pause`、`/dl del`
- `/license <密钥>`

点「确认」才会执行，点「取消」就放弃。确认按钮 **120 秒内有效**；超时、或者这条确认已经在别的会话被点过，就需要重新发一次指令。点按钮时系统会再核一次你的角色，权限不够不会执行。

## 未绑定的用户会看到什么

没进白名单、也没匹配到 Chat ID 的账号，只会收到一条固定提示：

> 当前账号未绑定 AMMDS，无法使用该指令。请将你的 Telegram ID 发送给管理员完成绑定，发送 /whoami 可查看自身 ID。

除此之外只能使用 `/start` 和 `/whoami`，其余指令一律拒绝。为了避免陌生会话刷屏，同一个人 10 分钟内只会收到一次这条提示。

权限不够但已绑定的账号，会收到单独的「权限不足」提示，不会暴露任何内部数据。

## 帮助和未知指令也按角色分层

`/help` 只列出你当前角色能用的指令，并按分类分组，不会把管理指令一起摆出来。

- 访客能看到 `/jellyfin`、`/emby`、`/check`、`/system`、`/tasks` 这些自己可用的指令，看不到 `/115_del`、`/dl pause` 一类管理指令
- 用 `/help <指令>` 查看某条管理指令的详情，会被直接拒绝
- 发了一个不存在的指令，机器人会回「未识别该指令」，并列出你当前可用的一小部分指令，末尾提示用 `/help` 看完整列表

所以同一句 `/help`，管理员和访客看到的条目数量不一样，这是正常的。

## 指令菜单怎么更新

在 Telegram 配置页点「注册指令」，系统会把上表中的指令整体注册到机器人的指令菜单。

- 如果这些指令都已经存在，会直接跳过，不会覆盖你手动加过的同名指令
- 只要有任意一条缺失，就会把整套重新提交；此时你自定义过的同名指令会被覆盖

新增或调整指令后，记得再点一次。

## 常见问题

| 现象 | 说明 |
| --- | --- |
| 发指令没反应 | 先确认「启用状态」和「启用通知推送」都打开；再看是否注册过 Webhook，注册了要删掉才能恢复轮询 |
| 一直提示未绑定 | `/whoami` 拿到 From ID，填进用户白名单并保存；改完重新发指令 |
| 管理员指令提示无权限 | 白名单里的角色写成了 GUEST，改成 ADMIN 或 OWNER |
| 点了确认没执行 | 超过 120 秒，或确认按钮已被使用，重新发一次指令 |
| `/deepseek` 提示启用插件 | 先到集成应用里启用 DeepSeek |
| `/library` 里看不到媒体服务器 | 对应 Jellyfin / Emby 没启用，或没配置好 |
| 发 `/license <密钥>` 提示无权限 | 激活只允许 ADMIN 和 OWNER，让管理员来发 |
| `/license` 说已有许可证 | 换绑要加 `replace`：`/license <密钥> replace`，会释放旧席位 |
| `/license` 显示宽限截止 | 授权已过期但还在宽限期，尽快续期；宽限结束后功能会受限 |
| 推送磁力提示无权限 | 磁力推送只允许 OWNER 和 ADMIN，访客只能检索 |
| `/115 <磁力链接>` 提示配额不足 | 云下载剩余配额为 0，本次不会提交任务，等配额恢复再试 |
| 推送提示刚刚已提交 | 同一个 infohash 60 秒内只能提交一次，稍等再试 |
| 指令菜单是旧的 | 到 Telegram 配置页点一次「注册指令」 |
