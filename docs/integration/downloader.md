# 让资源自动下载

找到资源之后，还得有个软件真的把它下载下来。这一页讲三件事：用 qBittorrent 承接下载、用 Transmission 登记下载器、用 IYUU 给已有种子做辅种。

> **下载器**：真正负责下载的软件。AMMDS 只负责「找到并把任务交给它」，下载过程由它自己完成。

> **辅种**：同一个资源在另一个站点也有一份。把你已经在做的种子「补」到那些站点继续做种，可以增加你的上传量。

> **做种**：下载完成后不删除、继续把文件分给其他人下载的行为。多数 PT 站按这个记录你的贡献。

> **端口**：一台机器上区分不同服务的号码，写在地址末尾，例如 `8080`。写错就会连到别的服务上。

## 先看清分工

这一点很重要，配错了会白忙一场：

| 能力 | 由谁承担 |
| --- | --- |
| 订阅自动下载推送 | **qBittorrent** |
| IYUU 自动辅种 | **qBittorrent** |
| 下载器登记与连通性验证 | qBittorrent 与 Transmission 都支持 |
| 系统检查里的插件体检 | qBittorrent 与 Transmission 都支持 |

也就是说：**只有 Transmission 的话，订阅自动下载不会由它执行**。想要自动下载，必须配 qBittorrent。

## qBittorrent

qBittorrent 是下载链路的终点。订阅匹配到资源后由它真正存到硬盘，IYUU 辅种补下的种子也交给它。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 下载器 → qBittorrent |
| 连接方式 | 通过 qBittorrent 的网页管理界面连接 |
| 登录方式 | 网页管理界面的登录用户名与密码 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 关闭后所有下载操作都会提示「qBittorrent 未启用」 |
| 服务地址 | 默认 `http://127.0.0.1:8080`，要带协议；容器部署请用宿主地址或服务名 | 装在容器里却写 `127.0.0.1`，会连到 AMMDS 自己 |
| 接入点 RPC | 默认 `/`；网页界面挂在 `/qbittorrent` 这类子路径下时要改成同样的值 | 不匹配时登录会失败（提示 404），表现为「测试连接通过、获取信息失败」 |
| 用户名 | 默认 `admin` | 填错获取不到应用信息 |
| 密码 | 网页管理界面的登录密码 | 同上 |

:::warning[反向代理前缀要对齐]
如果 qBittorrent 挂在子路径下，「接入点 RPC」必须与之匹配，否则登录会 404。
:::

### 按钮与检查

| 按钮 | 输出 |
| --- | --- |
| 测试连接 | 只确认服务地址能连上 |
| 获取应用信息 | 显示用户名、地址、默认保存路径、程序版本、种子数量 |

「获取应用信息」是检查账号密码最直接的方式：能拿到默认保存路径和种子数量，说明登录成功、版本也对得上。

### 保存路径与标签

| 项目 | 行为 |
| --- | --- |
| 保存路径 | 优先取订阅配置里的**下载目录**；没配置时回退到 qBittorrent 的默认保存路径 |
| 分类 | 添加种子时可以带一个分类，订阅推送默认不带 |
| 标签 | 订阅推送会打上 `AMMDS订阅` 加来源站点标签；需要事后暂停的种子会追加 `AMMDS暂停` |
| 路径归属 | 保存路径是**下载器所在主机**的路径，不是 AMMDS 容器的路径 |

:::tip[路径该怎么写]
AMMDS 与 qBittorrent 不在同一个容器时，填 qBittorrent 那一端看到的路径（例如 `/downloads`），而不是 AMMDS 容器里的路径。
:::

### 一条完整的下载链路

1. **订阅检索**在站点侧匹配到资源。
2. **推送下载**：把换到的种子地址交给 qBittorrent 添加任务，带上保存路径与订阅标签。
3. **回查状态**：系统按标签回查任务，任务完成就标记订阅完成并推送通知；任务消失记为失败。
4. **辅种**：IYUU 补下的种子同样由 qBittorrent 承接，当前版本自动辅种仅支持 qBittorrent。

日常的暂停、开始、删除与批量操作在**工具箱 → 下载器 → 任务管理**中进行。

## Transmission

Transmission 是一款轻量的下载软件。AMMDS 会把它的地址记下来，并试一下能不能连上，同时把它纳入系统检查的体检清单。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 下载器 → Transmission |
| RPC 路径 | 默认 `/transmission/rpc`，需与下载器配置一致 |
| 登录信息 | 下载器的用户名与密码（若启用了认证） |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 关闭后不参与系统检查里的插件体检 |
| 服务地址 | 默认 `http://127.0.0.1:8080`，**请按实际端口修改** | 不改就会连到 qBittorrent 的端口上 |
| 接入点 RPC | 默认 `/transmission/rpc`；反代改写过路径时要同步修改 | 路径不符会取不到数据 |
| 用户名 | 默认 `admin` | 认证开启时填错会连不上 |
| 密码 | 下载器认证密码 | 同上 |

:::warning[默认端口一定要改]
Transmission 常用端口是 `9091`，而这里的默认值是 `8080`（与 qBittorrent 默认端口一致）。两个下载器同时部署时务必改成 Transmission 的真实端口。
:::

点击「连接测试」只会试着访问服务地址，拿到任何回应都算连通。要注意：Transmission 在没带会话标识时会回一个 409，**409 也属于「有响应」**，所以测试通过只代表地址和端口正确，不代表用户名和密码正确。

:::note[系统检查怎么用它]
系统检查会读取本插件的「启用状态」与「服务地址」：启用后若地址为空或不可访问，会在插件体检中标记异常，并提示受影响的功能是「种子下载推送」。
:::

## IYUU

IYUU 是一个按种子特征做交叉比对的服务：拿你已经在做种的种子去比对其它站点，命中后把同一个资源补到那些站点继续做种。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 下载器 → IYUU |
| 令牌来源 | 登录 IYUU 官网，进入用户中心复制账号令牌 |
| 分工 | IYUU 只负责**找**，实际把种子加入下载器由 qBittorrent 完成 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 关闭后辅种和推送测试都会失败 |
| API 服务地址 | 默认 `https://2025.iyuu.cn` | 改错会连不上 |
| 服务地址 | 默认 `https://iyuu.cn`，用于页面跳转与控制台入口 | 改错只影响跳转 |
| 密钥 | IYUU 账号令牌，用来证明这是你的账号 | 为空时辅种与推送都失败；换账号要同步换令牌 |
| 隐藏图像 | 默认**开启**；开启后生成的消息不带图片 | 关掉会让推送消息带图 |

### 按钮

| 按钮 | 检查内容 |
| --- | --- |
| 测试连接 | 只确认「API 服务地址」能连上，不检查令牌 |
| 推送测试 | 用内置测试模板真实发一条消息，验证令牌与通知链路 |

### 辅种计划

在**工具箱 → PT辅种 → 站点管理**中，点「辅种计划」打开配置弹窗：

| 项目 | 说明 |
| --- | --- |
| 启用 | 是否开启自动辅种 |
| 执行周期 | 定时表达式（例如每隔几小时跑一次）；留空表示不定时自动跑，只能手动执行 |
| 辅种客户端 | 选择承载辅种的下载器；**当前版本仅 qBittorrent 生效** |
| 通知 | 辅种完成后是否推送通知 |

提交前会检查定时表达式，写错了会被直接拒绝保存。

### 辅种流程

1. 系统按计划触发，或点「立即辅种」手动触发。
2. 启动时随机延时 30～300 秒，避免多个实例同时去请求 IYUU。
3. 每轮取最多 100 条「等待辅种」记录，逐条向 IYUU 查询可辅种的站点。
4. 按站点要求选择添加方式：需要授权的站点先换取种子文件；需要 Cookie 的站点带上站点 Cookie；其余直接提交种子地址。
5. 每个站点的处理结果马上记录下来，状态为 `未辅种`、`等待辅种`、`辅种完成` 或 `辅种失败`。

:::warning[前置条件在 IYUU 账号里]
自动辅种要求 IYUU 账号已开启辅种，并把辅种客户端设为 qBittorrent。这些开关在 IYUU 账号里，不在 AMMDS 里；账号侧没开，这边触发也不会有结果。
:::

### 站点与记录

| 页面 | 用途 |
| --- | --- |
| 工具箱 → PT辅种 → 站点管理 | 查看支持辅种的站点卡片、修改站点设置、**导入站点**（JSON 配置文件）、执行「立即辅种」 |
| 工具箱 → PT辅种 → 辅种记录 | 任务级记录：自动 / 手动、辅种结果、数量、时间与原因 |
| 工具箱 → PT辅种 → 辅种任务 | 种子级明细：状态、辅种时间、命中的站点种子、失败原因 |

记录与任务列表都支持清空，**清空不可撤销**。

## 出问题了怎么办

- **提示下载器未启用**：打开对应插件的「启用状态」并保存。
- **测试连接通过但获取信息失败**：用户名密码错误，或者「接入点 RPC」与实际路径不符。
- **添加种子失败**：保存路径在下载器所在主机上不存在，改用下载器视角的有效路径。
- **订阅一直不完成**：不要手动改动 `AMMDS订阅` 标签，改了系统就回查不到任务。
- **下载完成但没有入库**：扫描目录与保存路径不一致，检查扫描任务的目录配置。
- **立即辅种返回 0**：没有「等待辅种」记录，或 IYUU 账号侧没开启辅种。
- **辅种提示暂不支持的客户端**：辅种客户端选了 Transmission，改为 qBittorrent。
- **大量「辅种失败」**：站点需要 Cookie，或授权信息过期，在站点卡片更新设置后重试。
- **推送测试收不到消息**：令牌错误，或系统级通知开关关闭。
