# NexusPHP

NexusPHP 是一套广泛使用的 PT 建站程序。这个插件不是「一站一插件」，而是**一个插件管多个站点**：添加站点条目、做健康检查、同步用户信息，并把站点资源并入订阅检索。

## 站点定位

| 项目 | 说明 |
| --- | --- |
| 页面入口 | **集成应用 → 站点资源 → NexusPHP** |
| 集成版本 | 页面顶部标注 `1.9.0+`，类型为「PT站点」 |
| 站点要求 | NexusPHP 站点版本需在 1.9.0 以上（站点页脚 `Powered by NexusPHP` 可查看） |
| 通信方式 | 站点自带 `/api/v1` 接口，统一使用 `Bearer` 令牌 |
| 覆盖站点 | KamePT、Rousi（NexusPHP 站群）、Kelu、NicePT、ilolicon 等，也可添加自定义站点 |

## 配置项

| 配置键 | 界面名称 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `nexusphp_enabled` | 启用状态 | 布尔 | `false` | 关闭后除站点列表查询外的接口都会被拒绝 |
| `nexusphp_search` | 检索功能 | 布尔 | `false` | 开启后站点参与订阅检索 |
| `nexusphp_sync_user` | 同步用户信息 | 布尔 | `false` | 关闭时单个或全量同步都会被后端拒绝 |
| `nexusphp_notice` | 告警通知 | 布尔 | `false` | 站点异常、账号风险等场景推送通知 |

## 管理站点

站点卡片右上角有三个按钮：**刷新**（重新拉取列表）、**同步用户信息**（全量同步）、**添加站点**。

### 添加站点

1. 点「添加站点」打开弹窗。
2. 「站点名称」既可直接输入，也可从官方预设中选择；选中预设会自动填好地址与 Logo。
3. 填写 **站点令牌**，确认「是否启用」为开启。
4. 点「健康检查」验证地址与令牌，通过后点「添加」。

| 字段 | 界面名称 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | 站点名称 | 是 | 展示名，出现在检索结果与告警里 |
| `url` | 站点地址 | 是 | 站点首页完整地址，需含协议 |
| `logo` | 站点Logo | 否 | 仅用于界面展示 |
| `token` | 站点令牌 | 是 | `/api/v1` 接口令牌；编辑时留空表示保留原令牌 |
| `enable` | 是否启用 | 是 | 禁用后不参与辅种与用户信息同步 |

### 获取站点令牌

1. 登录站点，进入 **控制面板 → 設定首頁**。
2. 找到「访问令牌」，点创建并复制。
3. 权限至少包含：获取种子列表、查看种子详情、查看用户基本信息。

:::warning[预设站点仍要填令牌]
官方预设只帮你填名称、地址与 Logo。令牌必须自己在站点侧生成，预设里不会包含，也无法由系统代填。
:::

## 连接测试

| 时机 | 方式 | 检查内容 |
| --- | --- | --- |
| 添加前 | 弹窗内「健康检查」 | 先校验表单，再按填写的地址与令牌请求站点 |
| 添加后 | 站点卡片「刷新」 | 用库中已保存的地址与令牌复查，异常站点保持未就绪 |

检查会访问 `/api/v1/sections` 与 `/api/v1/profile`，分别验证「能否读取分区与种子」和「能否读取账号信息」。权限不足时日志会明确提示，不需要靠猜。

## 同步用户信息

- **单个站点**：在站点卡片上对目标站点执行同步。
- **全量同步**：点卡片右上角「同步用户信息」，对所有已启用站点依次同步。
- 同步在后台异步执行，接口立即返回「任务已提交」，进度看运行日志。
- 前置条件：`nexusphp_enabled` 与 `nexusphp_sync_user` 都为开启。

## 在订阅检索中的作用

- **平台标识**：所有 NexusPHP 站点的结果统一标记为 `NexusPHP`；订阅配置默认搜索顺序中排第二。
- **多分区汇总**：先查主接口 `/api/v1/torrents`，再按站点配置的每个分区各查一次，结果合并后返回；单个分区失败不影响其他分区。
- **权限提示**：站点返回权限不足时，日志会标注具体站点，便于单独排查。
- **缓存**：结果非空才写入缓存，避免空结果污染后续检索。
- **禁用即退出**：被禁用的站点不参与检索、辅种与用户信息同步。

:::tip[告警通知]
开启「告警通知」后，站点异常等事件会通过已配置的通知渠道推送。通知渠道本身还受系统级开关与夜间免打扰约束，见[Telegram](/docs/integration/notification/telegram)。
:::

## 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 健康检查失败 | 站点版本过低、地址错误或令牌无权限 | 确认版本 ≥ 1.9.0，重发令牌 |
| 同步被拒绝 | 插件或「同步用户信息」未开启 | 打开两个开关后重试 |
| 检索结果缺少某站点 | 站点被禁用，或未开启「检索功能」 | 检查站点启用状态与检索开关 |
| 站点列表为空但插件已启用 | 尚未添加任何站点 | 添加站点后再试 |
