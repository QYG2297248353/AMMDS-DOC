# 影片资料从哪里来

影片的封面、简介、演员表、标签这些资料，AMMDS 自己不生产，是从外部资料网站查回来的。这一页把全部资料来源放在一起，告诉你每个源能给你什么、要准备什么、怎么开，以及同时开好几个时按什么顺序取。

> **元数据源**：提供影片资料的外部网站。AMMDS 拿着文件名里的编号去问它，它把封面、简介、演员等回给你。

> **刮削**：AMMDS 自动去资料网站查这部片子的资料、并填回自己库里的过程。

> **番号 / 编号**：影片的识别编号，通常写在文件名里，例如 `SSIS-001`。AMMDS 主要靠它认片子。

## 先选一个源开始

:::tip[不用全开]
十个源不是都要开。挑一个你访问得通的先配好、跑通，再考虑加第二个。开得越多命中率越高，但配置和维护成本也越高。
:::

| 资料来源 | 能给你什么 | 要准备什么 | 默认状态 |
| --- | --- | --- | --- |
| MetaTube | 番号类影片的标题、简介、发行日期、时长、评分、演员、导演、制作商、系列、类型、剧照；演员资料 | 可选：用本机内置服务，或填远程服务地址与令牌 | 默认关闭 |
| TMDB | 电影、剧集、演员的标题、简介、剧照与演职员 | 授权码（可点按钮授权自动写入），可选填账户 ID | 默认关闭 |
| TheTVDB | 剧集的季与集结构，也能查电影 | API 密钥（必填），订阅 PIN（部分密钥需要） | 默认关闭 |
| Bangumi | 动画、番剧的条目标题、简介、章节、角色声优、制作人员 | 免密钥即可检索；涉及账号的功能需授权 | 默认关闭 |
| ThePornDB | 影片与演员资料；还能接自建或公共 Stash-Box 实例 | API 密钥；Stash 客户端另填端点与密钥 | 默认关闭 |
| TheJavDB | 按番号查标题、发行信息、演员、分类与示例图 | 不需要密钥，服务地址能访问即可 | 默认关闭 |
| R18.dev | 在线查番号，也能导入官方数据包做离线查询 | 在线查要地址可达；离线用要下载数据包 | 默认关闭 |
| FANZA DMM | 影片检索与榜单（今日新作、即将上映） | 不需要账号和密钥 | 默认关闭 |
| 麻豆 | 整批同步影视与演员资料 | 服务地址；页面公告提示该源已停止对外服务 | 默认关闭 |
| M-Team DMM | 通过 M-Team 站点的 DMM 服务查影片资料，并可直接导入 | M-Team 的存取令牌（与站点资源共用同一页配置） | 默认关闭 |

## 通用三步

不管配哪一个，流程都一样，细节见[接外部服务，一共三步](./overview.md)：

1. 打开「启用状态」，把要用的子开关（影视检索、剧集搜索等）一并打开。
2. 填好地址、密钥等资料，点**保存配置**。
3. 点**测试连接**确认地址可达，再点**检索 / 搜索测试**确认真能拿到数据。

:::warning[两个开关都要开]
多数源除了「启用状态」还有「影视检索」「剧集搜索」「元数据检索」这类子开关。只开总闸不会参与检索，也不会采集榜单。
:::

## MetaTube

MetaTube 是一个聚合了多家影片与演员网站的服务，一次配置就能覆盖很多站点，还能顺手把标题与简介翻成中文。AMMDS 可以用本机内置的那个进程，也可以连你自己部署的远程服务。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → MetaTube |
| 内置服务 | 本机自带的 MetaTube 程序；打开「内置服务优先」并且它正在运行时就用它，默认监听 18080 端口 |
| 远程服务 | 关掉「内置服务优先」，或内置进程没跑起来时用「远程服务地址」 |
| 能给什么 | 标题、番号、发行日期、时长、评分、演员、导演、制作商、厂商、系列、类型、简介、剧照；演员的生日、国籍、身高、三围、血型 |
| 要准备什么 | 远程模式要地址与令牌；内置模式在程序缺失时会自动下载，也可手动下载 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开就不参与刮削 |
| 内置服务优先 | 默认开启；想用远程服务就关掉 | 内置进程没跑起来时会退回远程地址，可能连的是另一个实例 |
| 远程服务地址 | 默认 `https://metatube.lifebus.fun`，必须带 `http(s)://`，不能以 `/` 结尾 | 格式不对，「测试连接」会失败 |
| 开启鉴权 | 远程服务设置了 TOKEN 时才打开 | 开了却不填令牌，请求会被远程服务拒绝 |
| 令牌 | 与远程服务的 TOKEN 一致 | 填错表现为连接正常但检索为空 |
| 优先级 | 数据源的尝试顺序，越靠前越优先。默认顺序为 `Caribbeancom,AVBASE,Pcolle,DUGA,MYWIFE,1Pondo,JAV321,FC2,TOKYO-HOT,JavBus,Getchu,fc2hub,Gcolle,HeyDouga,FALENO,FANZA,H0930,DAHLIA,H4610,HEYZO,SOD,10musume,KIN8,ThePornDBScene,C0930,AVE,PACOPACOMAMA,MGS,ThePornDBMovie,JAVFREE,CaribbeancomPR,MURAMURA`，多个值用英文逗号分隔 | 目标站排得太靠后，可能还没轮到就返回结果了 |
| 开启翻译 | 默认关闭；打开后刮削时翻译标题、简介等内容 | 不开就是原文 |
| 翻译服务 | 候选 `GoogleFree,Google,OpenAI,DeepL,Baidu,Microsoft`，实际生效的是你保存的那一个，首次默认是 `GoogleFree` | 选了需要密钥的引擎却没填密钥，翻译不生效 |
| Google / DeepL / OpenAI 的密钥与地址 | 选择对应引擎时必填密钥；地址留空用默认地址 | 缺密钥时翻译失败，只记日志不影响入库 |
| OpenAI Model / Prompt | 模型名与自定义翻译提示词 | 留空由服务端决定 |
| Baidu 应用 ID / 密钥 | 选择百度翻译时必填 | 缺了翻译不生效 |

配置卡片右上角的按钮：**启动内置服务**、**停止内置服务**、**重启内置服务**、**刷新配置**、**保存配置**。「资源下载」卡片用于 MetaTube 程序本身，缺失时会在启动后自动在后台下载。

:::note[测试连接测的是远程地址]
「测试连接」只测「远程服务地址」，不测内置进程。内置服务是否就绪要看「内置应用信息」；提示获取失败时，先确认程序已下载并点「启动内置服务」。
:::

## TMDB

TMDB（The Movie Database）是电影与剧集的通用资料库。接入后能参与影视、演员与剧集检索。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → TMDB |
| 能给什么 | 影视详情、剧照与演职员；演员资料；剧集的季与集 |
| 要准备什么 | 在 TMDB 开发者站点创建一个应用，就能拿到授权码；也可以点「获取授权」让页面自动填好 |
| 页面 | 「配置信息」「连接测试」「资源检索」三张卡片 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与任何检索 |
| 服务地址 | 默认 `https://api.themoviedb.org`，一般不用改 | 改错会连不上 |
| 授权码 | TMDB 的 API Read Access Token | 不填或填错，验密钥时会返回 401（表示没通过） |
| 账户ID | 用于「获取账户信息」，OAuth 授权成功后自动填好 | 为空时账户信息获取失败 |
| 影视搜索 | 默认开启 | 关掉后 TMDB 不参与影视检索 |
| 剧集搜索 | 默认**关闭** | 不开时搜剧集会一律提示「未检索到相关剧集」 |
| 演员搜索 | 默认开启 | 关掉后不参与演员检索 |
| 图像地址 | 默认 `https://image.tmdb.org/t/p/`，留空时系统会自动补上 | 地址被挡住图片就显示不出来 |
| 图像尺寸 | 默认 `original`，与图像地址拼接 | 尺寸写错图片 404 |
| 检索语言 | 默认 `zh-CN` | 填错不会报错，只是取不到对应翻译 |

### 按钮与检索

| 按钮 | 检查内容 |
| --- | --- |
| 获取授权 | 打开 TMDB 授权页，同意后自动跳回本站，并把授权码和账户 ID 填好 |
| 测试连通性 | 判断服务是否可达 |
| 校验密钥 | 确认授权码有效 |
| 获取账户信息 | 展示头像与账户资料，依赖账户 ID |

「资源检索」有三个标签页：TMDB 影视（点结果查看详情与演职员，点「导入」写入影视库）、TMDB 演员（点「导入」写入演员库）、TMDB 剧集（可先看「导入预览」，再点「导入全部季」或「导入本季」）。季号 `0` 表示特别篇；「导入预览」只生成草稿，不写库。

## TheTVDB

TheTVDB 主要提供剧集的季与集结构，同一套服务也能查电影。它现在的查询都要先用密钥换一次登录，所以密钥是必填的。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → TheTVDB |
| 能给什么 | 剧集基本信息、角色与演职员、季列表、集列表；影视的海报、描述、类型、制作公司、简介 |
| 要准备什么 | API 密钥（必填）；「用户支持型」密钥还要填订阅 PIN |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与刮削 |
| 服务地址 | 默认 `https://api4.thetvdb.com`，写不写 `/v4` 都行，插件会统一处理 | 写错会连不上 |
| API 密钥 | 必填 | 不填时插件视为不可用 |
| 订阅 PIN | 只有「用户支持型」密钥需要，其它留空 | 该填没填会登录失败 |
| 语言 | 三字母语言码，默认 `zho`（简体中文）；`eng` 英语、`jpn` 日语 | 填错不报错，只是取不到对应翻译，回退原文 |
| 剧集搜索 | 默认关闭，控制是否参与剧集检索 | 不开时剧集检索不到（影视没有独立开关） |
| 请求间隔 | 默认 `1000` 毫秒，同一进程内发往 TheTVDB 的请求共用 | 太小会触发限速 |

检索时可选剧集或影视，填关键词、首播年份与返回条数（默认 10，单页上限 50）后点「检索」；点「查看详情」加载扩展详情，点「导入」入库。导入剧集时季号留空表示全季导入。

:::note[测连通性与验密钥要分开看]
「测试连通性」只代表网络能到 TheTVDB；密钥无效仍然会登录失败。两者都过才算配好。
:::

## Bangumi

Bangumi（bgm.tv）是动画、番剧的资料库，强项是章节、角色声优与制作人员。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → Bangumi |
| 能给什么 | 条目标题、简介、章节、角色与声优、制作人员、关联条目 |
| 要准备什么 | 检索与查看不需要令牌；涉及账号的功能点「获取授权」即可 |
| 特别之处 | 应用的密钥已内置，页面上看不到客户端 ID、密钥、回调地址与 User-Agent |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与检索 |
| 授权地址 | 默认 `https://bgm.tv` | 改错会导致授权打不开 |
| API 地址 | 默认 `https://api.bgm.tv` | 改错会导致检索失败 |
| 授权 Token / 刷新 Token | 授权成功后自动填好 | 没授权时连接照样可能通过，但验令牌会失败 |
| 刷新有效期 | 默认 `604800` 秒（7 天） | 一般不用改 |
| 剧集搜索 | 默认关闭，控制是否参与剧集 / 动漫检索 | 不开时番剧检索不到 |
| 请求间隔 | 默认 `1000` 毫秒 | 太小会触发限速 |
| 语言 | 默认 `zh-CN` | 影响返回文本的语言偏好 |
| 授权有效期 | 存令牌的过期时刻，默认 `0` 表示未知 | 无需手工填 |

检索时可以输入关键词，也可以「按 ID 查询」直接填 Bangumi 条目 ID。在详情底部选季号（`0` 表示特别篇）后点「导入剧集库」，可先点「映射预览」看看整理后的结果。

:::warning[换账号只能覆盖]
系统里没有「撤销令牌」的按钮。要换账号就重新点「获取授权」，新令牌会覆盖旧的。
:::

## ThePornDB / StashBox

ThePornDB 提供影片与演员资料。除官方 API 外，还能接你自己搭建或公共的 Stash-Box 实例，两类来源在同一页管理。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → ThePornDB |
| 能给什么 | 影片（可切场景 / 影片类型）与演员资料；Stash 客户端里的同类数据 |
| 要准备什么 | 在 ThePornDB 账户里生成的 API Token；Stash 客户端要另填名称、端点（形如 `http://主机:9999/graphql`）与密钥 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与检索 |
| 服务地址 | 默认 `https://api.theporndb.net` | 改错会连不上 |
| 密钥 | 在 ThePornDB 用户设置里生成的 API Token | 不填时「获取用户信息」失败 |
| 感知哈希计算 | 默认关闭；开启后计算图片感知哈希用于相似度比对，依赖 VideoHashes 程序 | 程序缺失时该功能不可用 |
| 模糊匹配 | 默认关闭；开启后允许按标题模糊匹配 | 不开就只按精确条件找 |
| 榜单采集 | 默认关闭；开启后定时采集「最近更新」榜单 | 只影响榜单任务，不影响检索 |

:::warning[两套密钥不要混填]
主配置里的密钥只用于官方 API。Stash 客户端的密钥随客户端保存，填到主配置里不生效。
:::

检索分四个标签页：ThePornDB 影视、ThePornDB 演员、Stash 影视、Stash 演员，命中后可点「导入影视库」或「导入演员库」。没有可用客户端时会提示检查 Stash 客户端配置。

## TheJavDB

TheJavDB 以番号为入口返回影片资料，适合作为番号类影片的补充源。不需要申请密钥。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → TheJavDB |
| 能给什么 | 封面、番号、发行日期、时长、分类标签、制作公司、标签、系列、导演、演员、来源链接、简介与示例图 |
| 要准备什么 | 只要服务地址能访问；自建或镜像服务改地址即可 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与检索 |
| 服务地址 | 默认 `https://api.thejavdb.net`，要带 `http(s)://`，不要附加多余路径 | 改错会连不上 |
| 影视检索 | 默认关闭；开启后才参与自动刮削 | 不开时页面上的番号检索仍能用，但自动刮削不会用它 |

:::note[检索测试与自动刮削是两条路]
页面上的「番号检索」直接去资料源查，用于核对地址与数据，不受「影视检索」开关限制。要让它参与自动刮削，必须打开「影视检索」并保存。该页面没有导入按钮，入库发生在刮削任务里。
:::

## R18.dev

R18.dev 既能在线查，也提供可以下载下来离线用的数据包。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → R18.dev |
| 能给什么 | 封面、番号、发行日期、时长、女优、男优、导演、分类、制作商、标签、系列、作者、预告片、简介与预览图 |
| 要准备什么 | 在线查要服务地址可达；离线查要先导入官方数据包（`.sql`、`.sql.gz` 或 `.sql.zip`） |
| 页面 | 「配置信息」「数据统计」「数据导入」「番号检索」「连接测试」 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与检索 |
| 服务地址 | 默认 `https://r18.dev` | 纯离线模式下不可达也不影响本地检索 |
| 影视检索 | 默认关闭；开启后才参与自动刮削 | 不开就不会自动用它 |
| 在线检索 | 默认关闭；打开表示刮削时优先在线查，关闭则只查本地库 | 关闭且本地没导入数据，就什么都查不到 |

导入数据包的步骤：点「下载页面」或「获取最新数据包」去官方下载页 → 把文件拖进上传区或点选文件 → 点「开始导入」（上传中可点「取消上传」）→ 提示「文件上传成功，正在后台导入数据...」。

:::warning[导入很吃资源]
解压和写入数据库会占用较多 CPU、磁盘和数据库连接，建议在空闲时段做，导入期间不要重复上传同一个文件。
:::

「数据统计」卡片展示各表的记录数与增量，点「刷新」重新统计。「番号检索」可选在线或离线：在线先在线查、没命中再查本地库；离线只查本地库，不对外发请求。

## FANZA DMM

FANZA（DMM）提供影片检索与榜单，不需要账号和密钥。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 元数据 → FANZA DMM |
| 能给什么 | 关键词 / 番号检索、按日期检索、在线聚合检索、榜单（今日新作与未来 3 天的即将上映） |
| 要准备什么 | 无。查询地址由系统固定（默认 `https://api.video.dmm.co.jp/graphql`），页面上不能改 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开完全不参与 |

## 麻豆

麻豆会一批批地从官方服务拉取影视和演员资料，存进本地。页面不提供关键词检索，只能用「同步」整批采集。

:::warning[服务公告]
页面顶部显示「自 2026年4月3日 起，我们有缘江湖再见🪁」，表示该数据源已停止对外服务。配置与采集入口仍然保留，但对方可能已经不再返回数据，是否继续启用请自行判断。
:::

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与采集 |
| 服务地址 | 默认 `https://api.modelmediaasia.com` | 改错会连不上 |
| 影视采集 | 默认关闭；是「同步影视」的前置条件 | 不开就点同步会被拒绝，提示先启用对应采集功能 |
| 演员采集 | 默认关闭；是「同步演员」的前置条件 | 同上 |

「连接测试」卡片右上角三个按钮：**同步影视**（在后台一批批拉取影视，按发布时间排序后存进本地）、**同步演员**（在后台一批批拉取演员资料）、**测试连接**（用当前表单里的地址试一下能不能访问）。点完马上提示「同步任务已提交」，实际采集在后台跑；同一类同步正在跑时再点会被拒绝，提示「同步进行中，请勿频繁操作」。

:::tip[先保存再测试]
「测试连接」用的是表单里当前填的地址。改完地址先「保存配置」，再测试和同步，避免测的和实际跑的不是同一个地址。
:::

M-Team 站点的 DMM 资料能力挂在「站点资源 → M-Team」页面里，不在「元数据」分组，但同样参与影片检索与导入。

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |

| 服务地址 | 默认 `https://api.m-team.io/api` | 改错会连不上 |

## 多个源一起开时怎么取

- **优先级**：MetaTube 内部按「优先级」里的数据源顺序逐个尝试；其它源之间，由刮削和识别规则挑一条最合适的。
- **子开关决定参与范围**：影视检索、剧集搜索、元数据检索分别控制该源是否参与对应类型的检索。
- **回填不会自动发生**：改了优先级、语言、图片地址或开关之后，只对**以后**的任务生效。想让已入库的片子用上新设置，需要重新跑一次刮削任务。
- **翻译是可选步骤**：标题与简介的中文由翻译通道补齐，失败只记日志，不影响已经匹配到的资料。

> **回填**：把新设置套用到已经整理过的片子上。AMMDS 不会自动做这件事，需要你重新跑一次刮削。

## 保管好你的钥匙

TMDB 授权码、TheTVDB 密钥与订阅 PIN、Bangumi 令牌、ThePornDB 与 Stash 的密钥、MetaTube 令牌、M-Team 的 PassKey 与令牌都属于凭据（也就是你的「钥匙」）。

- 不要在截图、问题反馈、群聊或日志里粘贴明文密钥。
- 怀疑泄露时先去对应网站吊销，再生成新的填回来。
- 长期不用的源建议关掉并清空密钥。

## 出问题了怎么办

- **保存了却不参与刮削**：检查「启用状态」和「影视检索 / 剧集搜索 / 元数据检索」是不是都打开并保存了。
- **连接测试失败**：检查服务地址的协议与端口；装在容器里时别写 `127.0.0.1`；再确认这台机器能出网。
- **连接测试通过但检索为空**：查密钥是否有效、额度是否用完、子开关是否打开，以及关键词是不是该源能识别的编号格式。
- **返回 401 / 403**：令牌过期或权限不足，去对方站点重新生成。
- **返回 429 或经常超时**：被限速了，把请求间隔调大。
- **图片显示不出来**：图片地址被网络挡住，或站点有防盗链。
- **麻豆 / 某个源一直空**：先确认对方服务本身还在不在（麻豆页面顶部有停止服务的公告）。
