# 去哪里找资源

想让 AMMDS 帮你找片子，就要告诉它「去哪些站点找」。这一页把全部站点资源接入放在一起，说明每个站点是什么、要不要账号、配置项怎么填。

> **站点资源**：AMMDS 去搜索资源的来源。多数是需要邀请注册的 PT 站，也有你自己搭建的搜索服务。

> **PT 站**：一种靠上传量维持运转的资源站。你下载时也在给别人上传，站点按这个记录你的分享情况；长期不登录可能被注销账号。

> **种子**：一个记录了「文件在哪里、有哪些人手里有」的小文件或链接，下载软件靠它开始下载。

> **磁力**：一串可以直接交给下载软件的文字，作用等同于种子文件，但不依赖某个站点保存文件。

> **RSS**：网站把最新内容按固定格式列出来的一份清单，别的程序可以定时来读。

> **认证**：向对方证明「我是这个账号本人」，通常靠一串只有你和站点知道的密钥完成。

## 先看清两件事

1. **站点账号你自己要有**。AMMDS 不提供任何站点的账号、邀请或注册入口，只负责拿着你给的密钥去搜。
2. **搜索顺序有默认值**。订阅的搜索顺序默认是 `M-Team,NexusPHP,Rousi,Prowlarr`：命中越靠前的结果越优先；没写进顺序的平台排在命中平台之后。**Prowlarr 是唯一例外，它永远排在最后**。

| 站点 / 服务 | 是什么 | 要不要账号 | 主要用途 |
| --- | --- | --- | --- |
| M-Team（馒头） | 综合类 PT 站，需要邀请注册 | 要：PassKey（站点给你的下载凭证）+ 存取令牌 | 订阅检索与下载，另外还能提供 DMM 影片资料 |
| NexusPHP | 一套建站程序，**一个插件管多个站点** | 要：每个站点一枚站点令牌 | 订阅检索、同步用户信息、告警 |
| KamePT（龟站） | NexusPHP 架构的 PT 站，没有独立插件页 | 要：站点令牌；可选做站点认证 | 通过 NexusPHP 插件添加后参与检索 |
| Rousi（肉丝） | 综合类 PT 站，需要邀请注册 | 要：PassKey（临时授权码可选） | 订阅检索、种子详情补全、下载链接 |
| FSM | 自研框架的站点 | 要：PassKey + API TOKEN | 订阅检索与下载 |
| Prowlarr | 你自己搭建的索引聚合服务 | 要：Prowlarr 的鉴权密钥 | 一次请求覆盖它背后的多个索引器 |
| BitMagnet | 你自己搭建的种子搜索服务 | 不需要站点账号，但要自建服务 | 磁力检索、文件列表与目录树 |

## M-Team

M-Team（馒头）同时承担两件事：作为站点资源参与订阅检索并换取下载地址；还能通过站点自带的 DMM 查询服务提供影片资料。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 站点资源 → M-Team |
| 网络要求 | 站点网页域名与 API 域名不同，启用前先确认两个都能访问 |
| 密钥在哪拿 | PassKey：控制台 → 設置 → 主頁，在「密匙」区域发送到邮箱；存取令牌：控制台 → 設置 → 實驗室，创建后复制（只显示一次，先存好） |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开就不参与检索、资料检索与账户保护检查 |
| 服务地址 | 默认 `https://api.m-team.io/api`，可改为 `https://api.m-team.cc/api` 或 `https://api2.m-team.cc/api` | 改错会连不上 |
| 密钥 (PassKey) | 站点给你的下载凭证，下载时用它换取种子文件 | 缺失时**检索正常、下载失败** |
| 存取令牌 | 搜索时证明身份的另一把钥匙，检索和资料检索都要它 | 缺失时检索不到结果 |
| 临时授权码 | 少数情况下站点会额外发一个，只在需要时填写 | 需要时才填 |
| 账户保护通知 | 默认关闭；定时检查登录状态并推送提醒 | 站点对长期不登录账号会做封号注销处理 |
| 元数据检索 | 默认关闭；开启后 DMM 资料才会参与在线检索与刮削 | 不开时搜索测试会提示先开启 |

:::warning[两把钥匙不能互相替代]
存取令牌用于**检索**，PassKey 用来**取下载链接**。只填一个会出现「能搜到但下载失败」或「能下载但搜不到」。
:::

页面上有两个测试：「测试连接」只确认地址能连上，不检查密钥对不对；「搜索测试」需要先开启「元数据检索」，可选按 `DMM 元数据`、`女优 / 企划`、`合集`、`关键词` 检索。

:::tip[资料能力不影响下载]
元数据检索只影响识别与刮削这条链路，不影响站点资源检索。关掉它不会让订阅下载失效。
:::

## NexusPHP

NexusPHP 是一套被广泛使用的建站程序。这个插件不是「一站一插件」，而是**一个插件管多个站点**：KamePT、Rousi 的 NexusPHP 站群、Kelu、NicePT、ilolicon 等都能挂进来，也可以自己添加站点。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 站点资源 → NexusPHP |
| 站点版本 | 页面标注兼容 NexusPHP 1.9.0+（站点页脚 `Powered by NexusPHP` 可查看）。程序不会自动校验站点版本，这一点仅作参考；老版本站点若接口不兼容，需自行确认 |
| 站点令牌 | 在站点「控制面板 → 設定首頁」的「访问令牌」里创建，权限至少要有：获取种子列表、查看种子详情、查看用户基本信息 |

### 设置项说明（插件级）

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 关闭后只剩站点列表能看，其它功能都用不了 |
| 检索功能 | 默认关闭；开启后站点参与订阅检索 | 不开就搜不到这些站点的资源 |
| 同步用户信息 | 默认关闭 | 关闭后点同步会被直接拒绝 |
| 告警通知 | 默认关闭；站点异常、账号风险时推送通知 | 不开就不会收到告警 |

### 添加站点

1. 点「添加站点」打开弹窗。
2. 「站点名称」可以直接输入，也可以从官方预设里选；选中预设会自动填好地址与 Logo。
3. 填写**站点令牌**，确认「是否启用」为开启。
4. 点「健康检查」验证地址与令牌，通过后再点「添加」。

下表左列是配置项在系统里的名字，你在界面上看到的是「界面名称」那一列，照着界面填即可。

| 配置项 | 界面名称 | 必填 | 不填 / 填错会怎样 |
| --- | --- | --- | --- |
| `name` | 站点名称 | 是 | 展示名，出现在检索结果与告警里 |
| `url` | 站点地址 | 是 | 站点首页完整地址，要带 `http://` 或 `https://`；写错健康检查失败 |
| `logo` | 站点Logo | 否 | 只用于界面展示 |
| `token` | 站点令牌 | 是 | 编辑时留空表示保留原令牌；令牌无权限会提示「权限不足」 |
| `enable` | 是否启用 | 是 | 禁用后不参与辅种与用户信息同步 |

站点卡片右上角三个按钮：**刷新**（重新拉取列表）、**同步用户信息**（对所有已启用站点依次同步）、**添加站点**。点完会马上提示「任务已提交」，实际同步在后台慢慢跑。

:::warning[预设站点也要自己填令牌]
官方预设只帮你填名称、地址与 Logo。令牌必须由你在站点侧生成，预设里没有，系统也不能代填。
:::

健康检查会依次访问站点的 `/api/v1/sections` 与 `/api/v1/profile`，也就是先试着读取分区与种子，再试着读取账号信息。权限不足时日志会写明原因。

## KamePT

KamePT（龟站）是 NexusPHP 架构的站点，**没有独立插件页**，检索能力由 NexusPHP 插件提供；另有一条独立的「站点认证」通道。

| 项目 | 说明 |
| --- | --- |
| 站点地址 | `https://kamept.com` |
| 检索入口 | 集成应用 → 站点资源 → NexusPHP，添加站点时在「站点名称」里选 **KamePT (龟站)**，系统会自动带出地址与 Logo |
| 认证入口 | 头像菜单 → 站点认证，选择 KamePT |

### 接入步骤

1. 打开 NexusPHP 插件，把「启用状态」打开并保存。
2. 在「NexusPHP 站点」卡片点「添加站点」。
3. 站点名称选 **KamePT (龟站)**。
4. 填「站点令牌」（在站点「控制面板 → 設定首頁」的「访问令牌」里创建），保持「是否启用」开启。
5. 先点「健康检查」，通过后再点「添加」。

### 站点认证（可选）

站点认证与插件配置是两条独立链路：

1. 打开右上角头像菜单，进入**站点认证**。
2. 在站点列表里选择 **KamePT (龟站)**。
3. 填写你在站点的 **UID** 与 **PassKey**，提交认证。
4. 认证通过后，依赖认证结果的站点功能才可用；**每次服务重启都需要重新认证**。

:::note[检索结果怎么标记]
KamePT 的结果标记为 `NexusPHP`，订阅默认搜索顺序里已包含 NexusPHP，所以不用额外加。检索时先查站点总列表，再按站点配置的分区逐个查询汇总；单个分区失败不影响其它分区。
:::

## Rousi

Rousi（肉丝）把 RSS 服务（更新清单）与 API 服务（检索）分成两个地址分别配置，因为两者可能指向不同域名。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 站点资源 → Rousi |
| 默认域名 | RSS `https://rousi.pro`，API `https://rousi.pro/api` |
| 密钥在哪拿 | 登录站点 → 右上角头像 → 账户设置 → Passkey，复制后填入 |

:::note[站群域名差异]
系统里登记了两个 Rousi 条目：`rousi.pro` 与 `rousi.zip`（站点公告为即将闭站）。插件默认指向 `rousi.pro`；如果你实际用的是另一个域名，请按站点现状修改两个服务地址。
:::

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与检索、下载与账户保护检查 |
| RSS服务地址 | 默认 `https://rousi.pro`；用于 RSS 链路，也用于把相对路径的封面拼成完整地址 | 填错会导致封面裂图 |
| API服务地址 | 默认 `https://rousi.pro/api`；检索时会在这个地址后面自动接上 `/v1/search` | 填错会搜不到东西 |
| 密钥 (PassKey) | 搜索时用它证明身份，下载时也用它换取种子 | 缺失时检索正常、下载失败 |
| 临时授权码 | 少数情况下站点会额外发一个 | 检索只依赖 PassKey，不需要时可留空 |
| 账户保护通知 | 默认关闭；定时检查登录状态并推送提醒 | 站点对长期未登录账号会做封号注销处理 |

配置页两个测试按钮：**测试RSS连接**（验证 RSS 服务地址）、**测试API连接**（验证 API 服务地址，订阅检索依赖它）。两个都只确认地址能连上，不检查 PassKey 对不对。

## FSM

FSM 是自研框架的站点，**不属于 NexusPHP**，也不参与站点认证流程，只用插件配置。它的检索地址和 RSS 地址分属两个域名：检索用 API TOKEN，下载链接用 PassKey。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 站点资源 → FSM |
| 密钥在哪拿 | 登录站点，在账号设置里查看 PassKey 与 API TOKEN |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与检索与下载 |
| API 服务地址 | 默认 `https://fsm.name/api`，检索时会在这个地址后面自动接上 `/Torrents/listTorrents` | 写成站点首页会连不上 |
| RSS 服务地址 | 默认 `https://api.fsm.name`，与 API 不同域 | 只填其一会导致对应功能不可用 |
| 密钥 (PassKey) | 用于换取种子下载链接 | 缺失时能检索、下载失败 |
| 授权码 (API TOKEN) | 搜索时证明身份的另一把钥匙，由站点生成 | 无效时检索结果为空 |

:::warning[两把钥匙各管一段]
API TOKEN 决定能不能检索，PassKey 决定能不能下载。两个都填对，链路才完整。
:::

两个测试按钮：**测试连接 RSS**、**测试连接 API**，都只确认域名能连上，不检查密钥对不对。

:::tip[想让 FSM 优先就要加进搜索顺序]
订阅默认搜索顺序 `M-Team,NexusPHP,Rousi,Prowlarr` 里没有 FSM。没写进顺序的平台不会被优先，但也不会被排除；想让 FSM 结果优先，就在订阅配置的搜索顺序里补上 `FSM`。
:::

## Prowlarr

Prowlarr 是你自己搭建的索引聚合服务：它把多个站点的搜索能力合在一起，AMMDS 只问它一家，由它去分发。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 站点资源 → Prowlarr |
| 部署形态 | 自建服务，AMMDS 只要能访问它的地址 |
| 与直连站点的区别 | 直连插件只搜一个站；Prowlarr 一次搜索就能覆盖它里面配置的全部索引器（也就是你逐个添加进去的站点） |
| 密钥在哪拿 | Prowlarr 管理界面 → Settings → General → API Key |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 不打开不参与检索 |
| 服务地址 | Prowlarr 访问地址，需带协议，例如 `http://127.0.0.1:9696` | 为空时检索直接返回空结果，日志提示「索引器配置不完整」 |
| 鉴权密钥 | Prowlarr 的 API Key（它后台生成的一串密码） | 填错时连接正常但检索始终为空 |

:::warning[两个必填项]
服务地址和鉴权密钥缺一不可。任一为空不会报错打断流程，只是检索一直空。
:::

搜索时只查成人分类。如果你在 Prowlarr 侧没有配置支持该分类的索引器，结果会是空的。Prowlarr 返回的结果自带下载地址，提交下载时不用再换一次。

:::tip[当兜底用最合适]
直连站点搜不到的番号，再让 Prowlarr 去覆盖它背后的全部索引器。它永远排在最后，不影响直连站点优先。
:::

## BitMagnet

BitMagnet 是开源、可自托管的种子搜索服务：它自己持续在网上发现种子并分类。接进来之后，可以在磁力检索里查公开的种子，而不只限于已配置的 PT 站。

| 项目 | 说明 |
| --- | --- |
| 入口 | 集成应用 → 站点资源 → BitMagnet |
| 部署形态 | **必须自建**，AMMDS 不内置搜索爬虫 |
| 端口 | 至少需要网页端口 `3333` 与爬虫端口 `3334`（TCP/UDP），还要一个数据库 |
| 定位 | 不在订阅的搜索顺序里，独立服务于磁力检索 |

### 设置项说明

| 设置项 | 要填什么 | 不填 / 填错会怎样 |
| --- | --- | --- |
| 启用状态 | 打开开关 | 关闭后搜磁力和查看文件列表都会提示「BitMagnet 集成插件未启用」 |
| 服务地址 | 默认 `http://127.0.0.1:3333`；容器部署时不要填 `127.0.0.1`，要填宿主地址或容器服务名，例如 `http://bitmagnet:3333` | 填成 `127.0.0.1` 会连到 AMMDS 自己身上 |

:::warning[容器里的地址坑]
Docker 部署时 `127.0.0.1` 指向容器自身。请改填宿主地址或容器服务名。
:::

配置页两个按钮：**测试连接**（只确认地址能连上）、**获取应用状态**（会显示「基本信息」与「服务状态」两个页签）。应用状态里能看到 DHT 服务、数据库、TMDB 三个组件是否健康。

:::tip[先看状态再排查]
检索为空时先点「获取应用状态」。如果爬虫服务显示异常，说明它还没发现种子，问题在 BitMagnet 侧而不是 AMMDS。
:::

:::note[不参与订阅排序]
BitMagnet 不在订阅配置的搜索顺序里，订阅自动下载不会走它。它服务的是磁力检索页面，适合按关键词找冷门资源。
:::

## 出问题了怎么办

- **保存了还是搜不到**：检查「启用状态」是否打开并保存；NexusPHP 还要检查「检索功能」是否打开、站点是否「启用」。
- **连接测试失败**：检查服务地址的协议与端口；装在容器里的 AMMDS 别写 `127.0.0.1`；再确认这台机器能出网。
- **能检索但下载失败**：多数是 PassKey 为空或失效，去站点重新获取。
- **提示配置丢失**：服务地址或令牌为空，补齐后保存再检索一次。
- **健康检查失败 / 权限不足**：站点地址写错、令牌复制不完整、令牌权限不够。回到站点重新生成令牌，不要反复重试同一枚。
- **总是搜不到 FSM 的结果**：FSM 不在默认搜索顺序里，需要时在订阅配置的搜索顺序中补上 `FSM`。
- **账户保护通知频繁提醒**：用浏览器登录一次站点；不需要时可以关掉提醒。
