# FFmpeg

FFmpeg 是音视频处理的基础组件。AMMDS 用 FFmpeg 完成视频处理、截图、封面裁剪与缩略图生成，用 FFprobe 解析媒体信息、探测视频时长与分辨率；插件页负责这两个组件的下载、状态查看与删除，并集中管理转码与格式转换的默认参数。

## 组件与安装位置

| 组件 | 用途 |
| --- | --- |
| FFmpeg | 视频处理、截图、封面裁剪、缩略图生成、转码与格式转换 |
| FFprobe | 媒体信息解析、视频时长与分辨率检测 |

- 安装目录为 `data/ffmpeg`，按操作系统与 CPU 架构选择对应可执行文件。
- 后端启动后会检查组件，缺失时自动异步下载，并每分钟重试。
- 不支持 32 位系统；此类环境相关能力不可用。
- 下载地址由后台按平台维护，包含 GitHub、官方镜像与官方 S3 备份等多个来源，失败会自动换源重试。

## 资源下载

「资源下载」卡片以表格列出两个组件的文件名、状态、下载进度、路径，并提供：

- **下载缺失组件**：只提交缺失项，下载在后台执行
- **刷新状态**：手动查询；存在下载中的组件时页面每 3 秒自动轮询
- **删除**：删除本地文件并清理状态，删除后可重新下载

:::note[状态说明]
下载状态包含未开始、下载中、已完成、失败等；中断的组件可删除后重新下载，不会影响另一组件。
:::

## 配置项

| 配置键 | 界面名称 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `ffmpeg_enabled` | 启用状态 | 布尔 | `true` | 只控制工具箱的「视频转码 / 格式转换」；关闭后不能创建新任务，已有任务不受影响 |
| `ffmpeg_max_concurrent` | 任务数量 | 数字 | `2` | 每种任务类型的同时任务数（1–5），视频转码与格式转换各算一类 |
| `ffmpeg_transcode_output_mode` | 转码输出方式 | 单选 | `suffix`（候选 `suffix`、`unified`） | `suffix` 源目录同名加后缀，`unified` 输出到统一目录 |
| `ffmpeg_transcode_output_dir` | 转码统一输出目录 | 文本 | 空 | 输出方式为 `unified` 时使用 |
| `ffmpeg_transcode_suffix` | 转码默认后缀 | 文本 | `transcode` | 输出方式为 `suffix` 时拼在文件名后 |
| `ffmpeg_convert_output_mode` | 格式转换输出方式 | 单选 | `source`（候选 `source`、`unified`） | `source` 源目录同名输出，`unified` 输出到统一目录 |
| `ffmpeg_convert_output_dir` | 格式转换统一输出目录 | 文本 | 空 | 输出方式为 `unified` 时使用 |
| `ffmpeg_video_codec` | 转码默认视频编码 | 单选 | `libx264`（候选 `libx264`、`libx265`） | 新建转码任务的默认编码 |
| `ffmpeg_preset` | 转码默认预设 | 单选 | `veryfast` | 速度与体积的权衡，候选从 `ultrafast` 到 `veryslow` |
| `ffmpeg_crf` | 转码默认质量 (CRF) | 数字 | `23` | 越小画质越高、体积越大，建议 18–28 |
| `ffmpeg_queue_enabled` | 排队等待 | 布尔 | `true` | 批量添加超出任务数量的任务自动排队；关闭后超出部分直接失败 |
| `ffmpeg_resume_enabled` | 任务恢复 | 布尔 | `true` | 服务重启后自动恢复未完成任务；关闭后标记失败并可手动重试 |

枚举中多项默认值以英文逗号登记候选，单选配置取首项生效，因此表中默认值为实际生效项。

## 视频转码

入口在 **工具箱 → 视频转码**，页面按全部 / 进行中 / 已完成分页签，列表展示视频文件、目标格式、方式、状态、进度与创建时间。

创建任务时可以选择单个视频或整个目录，并按需覆盖默认参数：

| 参数 | 说明 |
| --- | --- |
| 目标格式 | 输出容器格式 |
| 视频编码 | `libx264` / `libx265` |
| 编码预设 | 速度与压缩率的权衡 |
| 质量 (CRF) | 数值越小画质越高 |
| 输出方式 | 同名加后缀或统一目录 |
| 输出后缀、统一输出目录 | 随输出方式显示 |

任务详情包含视频路径、输出路径、视频编码、预设、CRF、帧率、实际执行命令与最近输出，便于定位失败原因。

## 格式转换

入口在 **工具箱 → 格式转换**，用于在不重新编码的前提下更换封装格式；创建时可选择「无损转换」，任务详情会展示目标格式、输出路径、帧率与速度。

格式转换的默认输出方式为「源目录同名输出」，也可改为加后缀或输出到统一目录；统一输出目录按需选择。

## 排队与恢复

- 超出「任务数量」的任务在开启「排队等待」时进入队列，按顺序执行。
- 服务在转码过程中重启时，开启「任务恢复」会自动续跑或重新排队；关闭后任务标记失败，可在列表手动重试。
- 任务恢复同时解决重启后任务显示「进行中」但实际进程已不存在、进度不同步的问题。

## 常见问题

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 无法创建任务 | 启用状态被关闭 | 打开开关并保存 |
| 组件一直下载失败 | 服务器无法访问下载源 | 检查网络与代理，或手动放置组件后刷新状态 |
| 转码报编码器不存在 | 组件缺失或损坏 | 在资源下载中删除后重新下载 |
| 任务全部失败 | 关闭了排队等待且并发已满 | 打开排队等待后重试 |
| 重启后任务状态异常 | 未开启任务恢复 | 打开任务恢复，并手动重试失败任务 |

需要调整播放兼容性或体积时，优先改「转码默认预设」与「CRF」，两项对结果影响最大。
