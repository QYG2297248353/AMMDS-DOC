## Introduction

AMMDS v1.1.0 was released in 2025, the first major feature update since the v1.0.0 public beta in March. This article takes a hands-on perspective, offering an in-depth look at the new features of v1.1.0 and sharing genuine configuration advice and usage tips.

## 1. The AMMDS Assistant Management Page

### Feature Overview

The most eye-catching new feature in v1.1.0 is the **AMMDS Assistant** management page. This is a system-level management panel provided by AMMDS for administrators, integrating a number of operational functions.

### Core Capabilities

**System health check**: the assistant page has a built-in health check that detects the status of the following with one click:

- Database connection status (SQLite)
- API connectivity of each scraping plugin
- Reachability of authenticated sites
- Disk space usage
- System uptime

**Running Status Overview**:

```
System status
├── Service uptime: 15 days 7 hours 32 minutes
├── Database: ✅ Normal (37.2 MB)
├── TMDB plugin: ✅ Connected
├── JavBus plugin: ✅ Connected
├── M-Team site: ✅ Authenticated
├── KamePT site: ✅ Authenticated
├── Rousi site: ⚠️ Cookie expiring soon
└── Disk usage: 42% (128 GB remaining)
```

### Real-World Impression

The assistant page's design philosophy is very practical — it brings together system information that was previously scattered across different menu items, letting administrators grasp the overall system state at a glance. The cookie expiry reminder for the Rousi site is especially thoughtful. PT site cookies are usually valid for only 30 days; if not renewed in time, authentication expires, and this reminder helps avoid a lot of trouble.

**Suggestion for improvement**: we hope future versions will allow customizing the health check interval and notification thresholds, and support monitoring more system metrics (such as CPU load and memory usage).

## 2. The 3D Logo Login Page

### Visual Upgrade

v1.1.0 gave the login page a major visual overhaul, introducing a **3D Logo animation effect**. Previously the AMMDS login page used a standard flat logo — clean but lacking distinctiveness. The new 3D Logo animates with a rotating effect when the page loads, complemented by dynamic background lighting, bringing the overall look in line with modern SaaS products.

### Front-End Technology

Based on observation, the 3D Logo is implemented with Three.js or CSS 3D Transforms (depending on the version), taking advantage of GPU hardware acceleration. It runs smoothly in mainstream browsers with no noticeable performance overhead, and the login page's load speed has not declined noticeably compared with the previous version.

### User Feedback

In actual use, the 3D Logo's visual effect is indeed impressive, especially when opening the login page for the first time after deployment. It conveys an image of a "professional, modern" product and helps strengthen users' brand recognition of AMMDS.

**Note**: in environments with tight server resources (such as a low-spec NAS), the 3D animation may increase CPU load. It is recommended to keep a "Disable 3D Animation" option in system settings to accommodate hardware of different performance levels.

## 3. Scraping Results with JavBus Site Support

### Background

JavBus is a Japanese film and TV resource database commonly used by film enthusiasts in China, offering rich metadata. In v1.1.0, AMMDS officially integrated JavBus as a scraping data source.

### Scraping Results in Testing

We used a typical resource file to test JavBus scraping:

**Test file**: `FC2-PPV-1234567.mp4`

**Scraping results**:

- Film title: ✅ accurately recognized Japanese and Chinese titles
- Cover poster: ✅ high-resolution poster downloaded
- Actor information: ✅ complete actor list and avatars
- Release date: ✅ accurate to the day
- Film ID: ✅ automatically recognized and linked
- Plot synopsis: ✅ Japanese synopsis + Chinese translation
- Series information: ✅ series name and number within the series

### Multi-Source Aggregation Performance

AMMDS's intelligent matching algorithm fetches information from JavBus and other available data sources simultaneously, then aggregates the data. For example, when JavBus provides actor information and TMDB provides rating data, AMMDS automatically merges the two to produce the most complete metadata record.

### Configuration Details

The JavBus plugin is very simple to configure:

1. Enable the JavBus plugin on the Plugin Management page
2. No extra API key needed (JavBus is a public data source)
3. Set the request interval (1–2 seconds recommended, to avoid triggering anti-scraping measures)
4. Configure priority (a medium setting is recommended, so TMDB takes priority for Western content)

## 5. Summary of the Actual Experience

### Deployment and Upgrades

Upgrading from v1.0.x to v1.1.0 was very smooth:

```bash
docker compose pull
docker compose up -d
```

After the upgrade, the database migration completed automatically and all existing settings (site authentication, plugin settings and user accounts) were preserved intact, with no compatibility issues.

### Performance

Data from one week of running on a DS920+ (J4125, 8 GB RAM):

| Metric | v1.0.x | v1.1.0 |
|:----|:------:|:------:|
| Memory usage | ~180 MB | ~210 MB |
| CPU idle usage | < 1% | < 2% |
| Scraping speed (single file) | ~8 seconds | ~7 seconds |
| Page load time | ~1.2 seconds | ~1.5 seconds |

The new features' use of system resources is within reasonable limits, and overall performance is satisfactory.

### Recommended Configurations

Based on hands-on testing, here are configuration recommendations for different usage scenarios:

**Light users** (home media, 2–3 people):

- Docker parameters: no special adjustments needed
- Plugins to enable: TMDB + JavBus
- Authenticated sites: 1–2

**Advanced users** (multi-site management, large collections):

- Docker parameters: add `AMMDS__MaxConcurrentScrapes=3`
- Plugins to enable: TMDB + JavBus + FANZA DMM
- Authenticated sites: 3–5
- Telegram notifications are recommended

## 6. Outlook

v1.1.0 has laid a solid foundation for AMMDS's future development. This update shows the project team has clear plans in three areas:

1. **Operational tooling**: reducing operational complexity through the assistant page
2. **Visual branding**: designs such as the 3D Logo enhance the product's quality feel
3. **Ecosystem diversification**: continuously expanding scraping data sources and site support

We look forward to seeing more innovative features in future versions, and welcome more users to join the AMMDS community to build a better private data platform together.
