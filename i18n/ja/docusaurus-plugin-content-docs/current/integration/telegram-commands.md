# Telegram で AMMDS を操作する

通知を受け取るだけでなく、Telegram はリモコンとしても使えます。スマートフォンやグループでコマンドを送ると、AMMDS に作品の検索、番号の購読、メディアライブラリとダウンロードタスクの確認、スキャンの実行、115 へのログインを行わせられます。

このページでは、ボットの接続方法、自分のアカウントの紐付け方法、コマンドの一覧、管理者権限が必要なもの、危険な操作の確認方法を説明します。

## まずボットを設定する

1. Telegram で `@BotFather` を見つけて新しいボットを作成し、**Bot Token** を取得します。
2. 管理画面の「連携アプリ → プッシュ通知 → Telegram」を開き、Bot Token を入力して「有効状態」をオンにします。
3. 「システム設定 → 通知」で**通知プッシュを有効化**がオンになっていることを確認します。これはマスタースイッチで、オフにするとシステムは送信されたコマンドを処理せず、ボットは受信するだけで応答しなくなります。
4. **Webhook は登録しないでください**。コマンドはシステムが定期的に Telegram からメッセージを取得することに依存しています。Webhook を登録するとシステムが取得を停止し、コマンドが応答しなくなります。家庭内ネットワークへの導入では元々 Webhook は不要です。

サービスアドレスは既定では公式アドレスです。独自のリバースプロキシを使う場合にのみ変更します。

## アカウントの紐付け

初回利用時、システムはあなたが誰かをまだ知りません。

1. ボットにプライベートメッセージで `/whoami` を送信します。
2. ボットが **Chat ID**、**From ID**、ニックネーム、現在の役割を返信します。
3. From ID を管理画面の「ユーザーホワイトリスト」に入力します。形式は `FromID:役割` で、複数のアカウントはカンマで区切ります。例：

```text
123456789:OWNER,987654321:ADMIN,555555555:GUEST
```

4. 保存後にもう一度 `/whoami` を送信すると、役割が切り替わります。

ホワイトリストに入力せず、プライベートチャットの Chat ID を `Chat ID` 設定項目に直接入力することもできます。プライベートチャットでは Chat ID と From ID が同じであり、このアカウントは所有者（OWNER）として扱われます。グループでの利用ではホワイトリストを使い、人ごとに役割を割り当てる方が明確です。

## 役割と権限

役割のレベルは高い順に OWNER、ADMIN、GUEST、NONE で、上位の役割は下位の役割のすべてのコマンドを使用できます。

| 役割 | できること |
| --- | --- |
| OWNER（所有者） | すべてのコマンド |
| ADMIN（管理者） | 読み取り専用コマンドに加え、スキャン、スクレイピング、再起動、115 の削除、ダウンローダー操作など |
| GUEST（ゲスト） | 検索、購読、お気に入り、状態確認、ヘルスチェック概要の実行などの読み取り専用・通常操作 |
| NONE（未紐付け） | `/start` と `/whoami` のみ |

## コマンド一覧

| コマンド | 役割 | 権限 |
| --- | --- | --- |
| `/ammds` | ボット情報を表示 | GUEST |

| `/version` | AMMDS のバージョンを表示 | GUEST |
| `/whoami` | 自分の Chat ID、From ID、役割を表示 | 未紐付けでも使用可 |

### マグネットの送信

マグネットリンクは検索だけでなく、ダウンローダーへ直接送信することもできます。このグループのコマンドの違いは「どこへ送信するか」だけです：

| コマンド | 送信先 | 権限 |
| --- | --- | --- |
| `/115 <マグネットリンク>` | 115 クラウドダウンロード | ADMIN |
| `/magnet <マグネットリンク>` | 現在の既定ダウンローダー | ADMIN |
| `/qb <マグネットリンク>` | qBittorrent | ADMIN |
| `/tr <マグネットリンク>` | Transmission | ADMIN |

`/115 <マグネットリンク>` はまずリンクを検証し、次に 115 プラグインが有効か、認可済みか、紐付け済みかを順に確認し、最後にクラウドダウンロードの残り割当を確認します。**割当が 0 の場合はタスクを投入せず、直接拒否します。** 成功時の返信には、タスク名（マグネット内の `dn` 名。なければハッシュの先頭 8 桁）、送信先「115 クラウドダウンロード」、ハッシュの接頭辞、残り割当のみが表示されます。失敗時は、割当不足、タスクの重複、認可の失効、作成失敗などの理由が示されます。

`/magnet` の後にマグネットリンクを付けると現在の既定ダウンローダーへ送信し、キーワードを付けるとマグネット検索のままになります。`/qb` と `/tr` はそれぞれ qBittorrent と Transmission を指定します。利用できるダウンローダーがない場合は、管理画面で有効化・設定するよう案内されます。

いくつかのルール：

- `magnet:?xt=urn:btih:` の後に 40 桁の 16 進数または 32 桁の Base32 が続くリンクのみを受け付けます。リンク全体は 2048 文字以内です
- 同じ infohash が 60 秒以内に再送信されるとブロックされ、「たった今送信済みです」と返信されます
- これらの送信は書き込み操作であり、実行できるのは OWNER と ADMIN だけです。ゲストは拒否されます

### ライセンスとお試し

| コマンド | 役割 | 権限 |
| --- | --- | --- |
| `/license` | ライセンス状態を表示。状態、認可方式とプラン、有効期限と猶予期限、このインスタンスの紐付け有無、お試しの利用有無。未認可の場合は次の手順を案内 | GUEST |
| `/license <キー>` | ライセンスを有効化 | ADMIN、確認要 |
| `/license <キー> replace` | 既存ライセンスを交換。旧インスタンスが占有していた席を解放 | ADMIN、確認要 |

`/license` を引数なしで送信すると読み取り専用で、認可は変更されません。返信には次の情報が表示されます：

- 状態、および対応する認可方式、プラン、マスキングされたキー
- 有効期限と残り日数。永久認可の場合は「永久」と表示
- このインスタンスが紐付け済みか、および占有している席
- お試しを利用済みか、お試しの期限
- 未認可の場合の診断コード

特に注意したい表示：

- **期限切れだが猶予期間内**：期限切れの警告と猶予期限が表示されます。猶予期間内は利用できますが、できるだけ早く更新してください
- **残り 0〜15 日**：この期間でのみ「まもなく期限切れ」と表示されます
- **未認可**：管理者には「`/license <キー>` を送信して有効化するか、管理画面の『システム設定 → ライセンス』で操作してください」と表示されます。お試し未利用の場合は、管理画面で 7 日間の試用を開始できることも案内されます。ゲストには管理者に連絡する旨の説明が表示されます

有効化は ADMIN と OWNER のみ可能です。`/license <キー>` を送信してもすぐには反映されず、ボットがまず確認カードを返します：

> ライセンスを有効化します：ABC123…7890
> 確認すると有効化席を 1 つ占有します。有効期間は認可サービスの応答に従います。

カード上のキーは**先頭 6 桁と末尾 4 桁**のみが表示され、キーが 10 桁未満の場合は末尾のみが表示されます。ログにも完全なキーは記録されません。「✅ 有効化を確認」をクリックすると実際に有効化されます。

失敗時は理由が直接説明され、よくあるものとして、キーの形式が正しくない、ライセンスの期限切れまたは停止・取り消し、有効化席が満杯、ライセンスサービスが一時的に利用不可、前回の有効化がまだ処理中、などがあります。すでにライセンスがある場合は、`/license <キー> replace` による交換を案内されます。

## 危険な操作の確認方法

次の操作はすぐには実行されず、ボットがまず「✅ 確認」と「キャンセル」のボタン付きメッセージを返します：

- `/stop`、`/restart`、`/scan`、`/scrape`
- `/system restart`、`/system stop`
- `/115_del <番号>`
- `/unsubscribe <番号>`
- `/dl pause`、`/dl del`
- `/license <キー>`

「確認」をクリックすると実行され、「キャンセル」をクリックすると中止します。確認ボタンは **120 秒間有効** です。時間切れ、またはその確認が別の会話ですでにクリックされている場合は、コマンドを再度送信する必要があります。ボタンをクリックするとシステムは役割を再確認し、権限が不足している場合は実行しません。

## 未紐付けのユーザーに表示されるもの

ホワイトリストになく、Chat ID にも一致しないアカウントには、固定の案内のみが送信されます：

> 現在のアカウントは AMMDS に紐付けられていないため、このコマンドは使用できません。管理者にあなたの Telegram ID を送って紐付けを完了してください。/whoami を送信すると自身の ID を確認できます。

これ以外は `/start` と `/whoami` のみ使用でき、他のコマンドはすべて拒否されます。知らない会話での連投を避けるため、同じ人には 10 分間に一度だけこの案内が送信されます。

権限が不足しているが紐付け済みのアカウントには、専用の「権限不足」案内が送信され、内部データは一切開示されません。

## ヘルプと不明なコマンドも役割で階層化

`/help` は現在の役割で使用できるコマンドのみを一覧表示し、分類ごとにまとめます。管理用コマンドを一緒に表示することはありません。

- ゲストは `/jellyfin`、`/emby`、`/check`、`/system`、`/tasks` など自分が使えるコマンドを見られますが、`/115_del`、`/dl pause` のような管理コマンドは見えません
- `/help <コマンド>` で管理コマンドの詳細を見ようとすると、直接拒否されます
- 存在しないコマンドを送信すると、ボットは「そのコマンドは認識できません」と返し、現在利用できるコマンドの一部を列挙し、最後に `/help` で完全な一覧を見るよう案内します

そのため、同じ `/help` でも管理者とゲストでは表示される項目数が異なります。これは正常です。

## コマンドメニューの更新方法

Telegram 設定ページで「コマンドを登録」をクリックすると、上記の表のコマンドがまとめてボットのコマンドメニューに登録されます。

- すべてのコマンドがすでに存在する場合はスキップされ、手動で追加した同名コマンドは上書きされません
- 一つでも欠けているものがあれば、一式が再送信されます。このときカスタマイズした同名コマンドは上書きされます

コマンドを追加または調整したら、もう一度クリックすることをお忘れください。

## よくある質問

| 現象 | 説明 |
| --- | --- |
| コマンドを送信しても反応がない | まず「有効状態」と「通知プッシュを有効化」が両方オンか確認してください。次に Webhook が登録されていないか確認し、登録されていれば削除してポーリングを復旧させる必要があります |
| ずっと未紐付けと案内される | `/whoami` で From ID を取得し、ユーザーホワイトリストに入力して保存してください。変更後にコマンドを再送信します |
| 管理者コマンドで権限なしと表示される | ホワイトリストの役割が GUEST になっています。ADMIN または OWNER に変更してください |
| 確認をクリックしても実行されない | 120 秒を過ぎた、または確認ボタンがすでに使用されています。コマンドを再度送信してください |
| `/deepseek` でプラグイン有効化を案内される | 先に連携アプリで DeepSeek を有効化してください |
| `/library` にメディアサーバーが表示されない | 対応する Jellyfin / Emby が無効、または設定が不十分です |
| `/license <キー>` で権限なしと表示される | 有効化は ADMIN と OWNER のみ可能です。管理者に送信してもらってください |
| `/license` でライセンス既存と言われる | 交換には `replace` を付けます：`/license <キー> replace`。古い席が解放されます |
| `/license` に猶予期限が表示される | 認可は期限切れですが猶予期間内です。できるだけ早く更新してください。猶予終了後は機能が制限されます |
| マグネット送信で権限なしと表示される | マグネット送信は OWNER と ADMIN のみ可能です。ゲストは検索のみです |
| `/115 <マグネットリンク>` で割当不足と表示される | クラウドダウンロードの残り割当が 0 のため、今回はタスクを投入しません。割当が回復してから再試行してください |
| 送信するとたった今送信済みと表示される | 同じ infohash は 60 秒に一度しか送信できません。少し待ってから再試行してください |
| コマンドメニューが古い | Telegram 設定ページで一度「コマンドを登録」をクリックしてください |
