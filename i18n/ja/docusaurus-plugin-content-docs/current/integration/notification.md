# スマートフォンに通知を送る

走査が終わった、購読が一致した、作品が登録された——こうしたことを管理画面で見張る必要はありません。通知の経路を一つつなげば、AMMDS がそのときに知らせてくれます。

> **プッシュ通知**：AMMDS から能動的にスマートフォンや別のプログラムへメッセージを届けることです。見に行く必要はありません。

> **Webhook**：「何か起きたら決まった住所へ一言送る」という仕組みです。ネットワークのメッセージを受け取れるものなら、AMMDS の通知を受け止められます。

> **ボット（Bot）**：チャットソフトの中に作る自動のアカウントです。命令を送ると、その通りに動きます。

## まず経路を一つ選ぶ

| 経路 | 向いている人 | 準備するもの | 特徴 |
| --- | --- | --- | --- |
| Bark | iPhone を使っていて、いちばん手間を省きたい人 | Bark アプリを入れ、端末キーをコピー | キー一つで受信できます |
| Telegram | スマートフォンから指令で操作したい人 | `@BotFather` でボットを作り、トークンと Chat ID を取得 | **逆方向の操作に唯一対応**。検索・購読・処理実行ができます |
| Webhook | 自前のサービスや自動化の流れに流し込みたい人 | ネットワークのメッセージを受け取れる住所 | 複数の戻り先を同時に設定でき、送信内容を完全に作り込めます |

:::warning[まだ三つの元スイッチがある]
経路の設定は第一歩です。メッセージが本当に出るかは、システム側のスイッチ（後述の「三つのシステム側スイッチ」）も通る必要があります。一通も来ないときは、まずそこを見てください。
:::

## Bark

Bark は iOS 向けの軽い通知道具です。端末キー一つで受け取れます。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → 通知 → Bark |
| 対象 | iOS（Bark アプリ） |
| サービス形態 | 公式 `api.day.app`、または自前で建てたサーバー |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと送信テストが「Bark プラグインを有効にしてください」を返し、通知もこの経路を通りません |
| サービス住所 | 既定 `https://api.day.app`。自前なら自分の住所に | 住所とキーの出所が違うと拒否されます |
| 端末キー | Bark アプリのトップに出る送信住所のうち、`api.day.app/` より後ろの部分 | 空欄や間違いで送信テストが失敗します |
| 通知アイコン | 既定は AMMDS のアイコン。別の画像住所にも変更可 | 住所に届かないとアイコンが出ません |
| 通知グループ | 既定 `AMMDS`。同じグループは通知センターでまとめて折りたたまれます | 空にするとグループ分けされません |
| Markdown 優先 | 既定オフ。オンで本文を Markdown として描画 | 古いアプリでは崩れることがあります。そうしたらオフに戻します |

### ボタン

| ボタン | 内容 |
| --- | --- |
| 接続テスト | サービス住所に届くかだけを確認。端末キーは確認しません |
| 送信テスト | 雛形で実際に一通を送り、キーとサーバーを確認 |

この経路は状態の照会もあり、サーバーの版、ビルド情報、**登録済み端末数**が返ります。サーバーが正常かどうかの判断に使えます。

:::tip[自前サーバーの注意]
自前サーバーを使うなら、「サービス住所」をその住所に変え、キーもそのサーバーが表示するものを使ってください。出所が違うと拒否されます。
:::

## Telegram

Telegram は主力の通知経路であり、逆方向の操作に対応する唯一の経路です。通知を受けるだけでなく、指令で仕事もできます。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → 通知 → Telegram |
| メッセージの形 | 文字 + 画像。画像にはネタバレ隠しを付けられます |
| 双方向 | 通知 + ボット指令での操作 |
| 資格情報 | Telegram で `@BotFather` を探し、案内に従ってボットを作成してトークンをコピー |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと Telegram の口がすべて「Telegram プラグインを有効にしてください」を返します |
| サービス住所 | 既定 `https://api.telegram.org`。自前の反転プロキシにも変更可 | 間違えるとつながりません |
| Bot トークン | `@BotFather` が発行するトークン | 空だと Chat ID も取れず、送信もできません |
| Chat ID | 受信する個人チャット、グループ、チャンネルの ID。個人は正の数、グループとチャンネルはふつう負の数 | 間違いは「送信テストは成功するのに届かない」として現れます。グループでは先にボットを入れてください |
| Webhook URL | 戻り先の住所。空なら戻り先を登録しません | 登録前にシステム設定でドメインの紐づけが必要です。無いと口が拒否します |
| ネタバレ隠し | 既定オフ。オンで画像に隠しを付けます | オフなら画像がそのまま出ます |

### ボタン

| ボタン | 働き | 前提条件 |
| --- | --- | --- |
| Chat ID を取得 | ボットの直近の会話から Chat ID を読みます | Bot トークンが入っていること、ボットに一度メッセージを送っていること |
| 指令を登録 | ボットに指令の一覧を登録します | サービス住所と Bot トークンが入っていること |
| Webhook を登録 | 戻り先住所を Telegram に登録します | システム設定で**ドメインの紐づけ**が済んでいること |
| 送信テスト | 雛形で一通を送ります | Bot トークンと Chat ID が入っていること |
| 接続テスト | 口の住所に届くかを確認 | なし |

指令の登録はやり直しても安全です。必須の指令（`ammds`、`movie`、`actor`、`resource`、`deepseek`、`system`）が既にあれば重ねて送信しないため、自分で足した指令が上書きされることはありません。

使える指令：`/start`、`/stop`、`/help`、`/version`、`/movie`、`/actor`、`/resource`、`/magnet`、`/search`、`/deepseek`、`/system`、`/subscribe`、`/unsubscribe`、`/favorite`、`/unfavorite`、`/scan`、`/scrape`、`/media_sync`、`/restart`。

:::warning[Webhook には外から届く必要がある]
Webhook の登録前に、システム設定でドメインの紐づけを済ませてください。無いと口が直接拒否します。家庭内のネットワークでは登録せず、既定の受け方で指令を受けるのがおすすめです。
:::

## Webhook

Webhook はもっとも汎用的な出口です。特定のアプリに縛られず、ネットワークのメッセージを受け取れれば何でも受け止められます。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → 通知 → Webhook |
| 特徴 | 複数の戻り先を同時に、送信内容を完全に作り込み、失敗時に再送 |
| 向いている先 | 社内のシステム、自動化の流れ、自前のメッセージ中継 |

### 設定項目の説明（プラグイン側）

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだとすべての戻り先への送信が止まります |
| 再試行回数 | 既定 `3`。失敗後の再送回数。最小は 1 | 相手がときどき失敗するなら増やすと効果があります |
| 再試行間隔 | 既定 `5` 秒。再送の間に待つ秒数。最小は 1 | 相手の制限が厳しいなら、回数より間隔を延ばすほうが効きます |

### 設定項目の説明（戻り先ごと）

「Webhook サービス管理」カードの「新規」で戻り先を作ります。複数を同時に置いて、必要なものだけ有効にできます。

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| サービス名 | 一覧での表示と見分けに使います | 必須。空だと見分けがつきません |
| 要求方式 | `POST` や `GET` など | 必須。相手の指定と違うと拒否されます |
| Webhook URL | 通知を受け取る完全な住所 | 必須。届かないと送信が失敗し再送されます |
| 説明 | 用途のメモ | 任意 |
| 有効状態 | オフでも設定は残りますが送信しません | オフなら届きません |
| ヘッダ | JSON の配列形式。例 `[{"key":"Content-Type","value":"application/json"}]` | 正しい JSON 配列でないと効きません |
| 本文 | JSON 形式。通知の差し込み変数が使えます | 間違えてもエラーにはならず、相手に変な内容が届きます |
| 検査タイプ | `ステータスコード` または `応答本文`。空なら検査しません | 判定が実際と合わないとずっと失敗表示になります |
| 検査値 | 期待するステータスコード、または応答本文に必ず含まれる文字 | 同上 |

一覧から直接、有効・無効の切替、編集、削除ができ、戻り先ごとに「送信テスト」もできます。

### 使える変数

ヘッダと本文の両方で次の差し込み記号が使え、送信時に置き換わります。

| 変数 | 意味 |
| --- | --- |
| `{{sign}}` | 署名。通知の出所を確認するために使います |
| `{{title}}` | 通知の題名 |
| `{{subTitle}}` | 通知の副題 |
| `{{logo}}` | ロゴ画像の住所 |
| `{{image}}` | 内容画像の住所 |
| `{{message}}` | 本文 |
| `{{time}}` | 送信時刻 |
| `{{type}}` | 出来事の種類 |

本文の例：

```json
{
  "event": "{{type}}",
  "title": "{{title}}",
  "text": "{{message}}",
  "timestamp": "{{time}}",
  "image": "{{image}}"
}
```

:::warning[「送信済み」は「届いた」ではない]
送信テストが「プッシュ要求を送信しました」と返すのは、要求を出したという意味であり、相手が処理できたという意味ではありません。実際の結果は相手側のログで確認してください。「検査タイプ」をステータスコードか応答本文にすれば、システムが規則に従って判定します。
:::

## 三つのシステム側スイッチ

送信の前には、次の三つが順に検査されます（**システム設定 → 通知**）。

| 設定項目 | 何を設定するか | 設定しない・間違ったとき |
| --- | --- | --- |
| 通知送信を有効化 | 既定**オン**。元スイッチ | オフならどの経路も黙り、一通も出ません |
| メッセージ種類 | 種類の許可一覧。複数はコンマ区切り。既定 `system,subscription,download,library,certification,vip,scrape,actor_scrape` | 選んでいない種類は送信されません |
| 夜間おやすみ | 既定オフ。オンなら 22:00 から翌 08:00 まで送信しません | この時間帯の通知は「送信不要」として飛ばされ、**後から送り直されることはありません** |

:::note[飛ばされても失敗ではない]
夜間おやすみの時間や、選んでいない種類の場合、システムは「送信不要」として記録に残すだけで、エラーにも後送にもなりません。
:::

## どんなときに通知が出るか

三つの経路は同じ通知の中身を共有しています。

| 種類 | 起きる場面 |
| --- | --- |
| システム | サービスの開始 / 停止、ディスク残量不足、アカウントの長期未ログイン |
| 購読 | 購読が資源に一致、購読の失敗 |
| ダウンロード | ダウンロードを送信、ダウンロード完了 |
| 登録 | 作品の登録完了 |
| 認証 | サイト認証の結果 |
| 作品の情報取得 | 取得成功 |
| 出演者の情報取得 | 取得成功 |
| テスト | 手動の送信テスト |

## 困ったときは

- **一通も来ない**：システム設定の「通知送信を有効化」がオンか、夜間おやすみの時間帯でないか、そして種類が許可一覧に入っているかを順に確認します。
- **送信テストが失敗する**：Bark は端末キーと住所の出所を確認。Telegram はトークンと Chat ID を確認。Webhook は住所に届くかを確認します。
- **Telegram は成功するのに届かない**：Chat ID が別の会話のもの、またはボットがグループから外されています。ボットに一度メッセージを送ってから「Chat ID を取得」をやり直してください。
- **Chat ID が取れない**：まだボットにメッセージを送っていません。一度送ってから押してください。
- **Webhook の登録が拒否される**：システム設定でドメインの紐づけが済んでいません。
- **Webhook がいつも失敗判定**：検査タイプ・検査値が実際の応答と合っていません。ステータスコードにして `200` を入れるか、検査を空にしてください。
- **変数が置き換わらない**：書き間違いです。変数の表と一字ずつ見比べてください。波括弧が二組である点にも注意。
- **同じ通知が重なる**：相手が時間切れになり再送されています。相手の処理を短くするか、再試行回数を減らしてください。
- **指令の一覧が古い**：以前に一部の指令が登録されています。削除してから登録し直してください。
