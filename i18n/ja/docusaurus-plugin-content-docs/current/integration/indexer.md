# 資源はどこで探すか

AMMDS に作品を探してほしければ、「どのサイトを探すか」を教える必要があります。このページではサイト資源の連携をまとめて、それぞれが何で、アカウントが要るか、設定をどう書くかを説明します。

> **サイト資源**：AMMDS が資源を探しに行く先です。多くは招待制の共有サイトですが、自分で建てる検索サービスもあります。

> **PT サイト（共有サイト）**：アップロード量で成り立つ資源サイトです。ダウンロードしながら他の人にもアップロードし、サイトはそれを記録します。長くログインしないとアカウントが削除されることがあります。

> **トレント**：ファイルがどこにあり、誰が持っているかを記録した小さなファイル、またはリンクです。ダウンロードソフトはこれを使って開始します。

> **マグネット**：ダウンロードソフトにそのまま渡せる一行の文字です。トレントファイルと同じ働きをしますが、サイトにファイルを預ける必要がありません。

> **RSS**：サイトが新しい内容を決まった書式で並べた一覧です。他のプログラムが定期的に読みに来ます。

> **認証**：相手に「私はこのアカウントの本人です」と示すことです。ふつうは本人とサイトだけが知っている文字列で行います。

## まず二つ確認

1. **サイトのアカウントは自分で用意します**。AMMDS はどのサイトのアカウントも招待も登録口も提供しません。渡された資格情報で検索するだけです。
2. **検索順序には既定値があります**。購読の検索順序は既定で `M-Team,NexusPHP,Rousi,Prowlarr` です。前に並ぶほど結果が優先され、順序に無い場所は一致した場所の後に回ります。**Prowlarr は唯一の例外で、必ず最後になります**。

| サイト / サービス | 何か | アカウント | 主な用途 |
| --- | --- | --- | --- |
| M-Team（饅頭） | 総合型の共有サイト。招待登録が必要 | 要：パスキー + アクセストークン | 購読検索とダウンロード。さらに DMM の作品情報も提供 |
| NexusPHP | サイト構築プログラム。**一つのプラグインで複数サイトを管理** | 要：サイトごとにサイトトークン | 購読検索、ユーザー情報同期、警告 |
| KamePT（亀サイト） | NexusPHP 構成のサイト。独立したプラグイン画面は無し | 要：サイトトークン。サイト認証は任意 | NexusPHP プラグインに追加すると検索に参加 |
| Rousi（肉絲） | 総合型の共有サイト。招待登録が必要 | 要：パスキー（臨時認証コードは任意） | 購読検索、トレント詳細の補完、ダウンロードリンク |
| FSM | 独自フレームワークのサイト | 要：パスキー + API トークン | 購読検索とダウンロード |
| Prowlarr | 自分で建てる索引まとめサービス | 要：Prowlarr の認証キー | 一度の要求で背後の複数の索引をまとめて検索 |
| BitMagnet | 自分で建てるトレント検索サービス | サイトのアカウントは不要だが、自分で建てる必要 | マグネット検索、ファイル一覧とディレクトリ表示 |

## M-Team

M-Team（饅頭）は二つの役割を同時に持ちます。購読検索に参加してダウンロード住所を作ることと、サイト付属の DMM 口で作品情報を提供することです。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → サイト資源 → M-Team |
| ネットワーク | サイトのページのドメインと API のドメインは別です。有効化前に両方へ届くか確認してください |
| 資格情報 | パスキー：管理画面 → 設定 → メイン，「密匙」からメールへ送信。アクセストークン：管理画面 → 設定 → 実験室で作成してコピー（一度だけ表示） |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと検索も情報検索もアカウント保護確認も行いません |
| サービス住所 | 既定 `https://api.m-team.io/api`。`https://api.m-team.cc/api` や `https://api2.m-team.cc/api` にも変更可 | 間違えるとつながりません |
| キー（パスキー） | トレントのダウンロードリンクを組み立てるために使用 | 無いと**検索はできるがダウンロードが失敗**します |
| アクセストークン | サイトの口を呼ぶための証明。検索も情報検索もこれに依存 | 無いと結果が出ません |
| 臨時認証コード | ヘッダ `Authorization` として送信。一部の口で必要 | 必要なときだけ |
| アカウント保護通知 | 既定オフ。ログイン状態を定期確認して通知 | 長期未ログインのアカウントはサイト側で凍結・削除されます |
| メタデータ検索 | 既定オフ。オンで DMM の口がオンライン検索と情報取得に参加 | オフだと検索テストが先に有効化するよう促します |

:::warning[二つの資格情報は代用できません]
アクセストークンは**検索**用、パスキーは**ダウンロードリンクの作成**用です。どちらか一方だけだと「見つかるのに落とせない」か「落とせるのに見つからない」になります。
:::

画面には二つのテストがあります。「接続テスト」は届くかだけを見て資格情報は確認しません。「検索テスト」は「メタデータ検索」を先にオンにする必要があり、`DMM メタデータ`、`女優 / 企画`、`合集`、`キーワード` を選んで検索できます。

:::tip[情報の機能はダウンロードに影響しない]
メタデータ検索が影響するのは判別と情報取得の道筋だけです。オフにしても購読のダウンロードは動きます。
:::

## NexusPHP

NexusPHP は広く使われているサイト構築プログラムです。このプラグインは「一サイト一プラグイン」ではなく、**一つのプラグインで複数サイトを管理**します。KamePT、Rousi の NexusPHP 系サイト、Kelu、NicePT、ilolicon などをまとめて登録でき、自分でサイトを追加することもできます。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → サイト資源 → NexusPHP |
| サイトバージョン | 画面には NexusPHP 1.9.0+ との互換性を表示しています（フッターの `Powered by NexusPHP` で確認できます）。プログラムはサイトのバージョンを自動確認しないため、あくまで参考情報です。古いサイトは互換性がない場合があるのでご自身で確認してください。 |
| サイトトークン | サイトの「コントロールパネル → 設定」で作成。権限は少なくとも「トレント一覧の取得」「トレント詳細の閲覧」「ユーザー基本情報の閲覧」が必要 |

### 設定項目の説明（プラグイン側）

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだとサイト一覧の取得以外の口がすべて拒否されます |
| 検索機能 | 既定オフ。オンでサイトが購読検索に参加 | オフだとこれらのサイトは検索されません |
| ユーザー情報を同期 | 既定オフ | オフだと単一も全量も同期が拒否されます |
| 警告通知 | 既定オフ。サイトの異常やアカウントの危険を通知 | オフだと警告が来ません |

### サイトの追加

1. 「サイトを追加」を押して画面を開きます。
2. 「サイト名称」は直接入力も、公式プリセットからの選択もできます。プリセットを選ぶと住所とロゴが自動で入ります。
3. **サイトトークン**を入力し、「有効にする」がオンであることを確認します。
4. 「健康診断」で住所とトークンを確認し、通ってから「追加」を押します。

| 項目 | 画面の名称 | 必須 | 空欄・間違いのとき |
| --- | --- | --- | --- |
| `name` | サイト名称 | はい | 検索結果と警告に出る表示名です |
| `url` | サイト住所 | はい | トップページの完全な住所。プロトコルが必要。間違えると健康診断が失敗 |
| `logo` | サイトロゴ | いいえ | 画面表示のみ |
| `token` | サイトトークン | はい | 編集時に空なら既存のトークンを保持。権限不足は「権限不足」と記録されます |
| `enable` | 有効にする | はい | 無効だと補植とユーザー情報同期に参加しません |

サイトカードの右上に三つのボタン：**更新**（一覧を再取得）、**ユーザー情報を同期**（有効な全サイトを順に同期）、**サイトを追加**。同期は裏で非同期に進み、口はすぐ「タスクを送信しました」を返します。

:::warning[プリセットでもトークンは自分で]
公式プリセットが埋めてくれるのは名称・住所・ロゴだけです。トークンは必ずサイト側で発行してください。プリセットには入っていませんし、システムが代わりに埋めることもできません。
:::

健康診断はサイトの `/api/v1/sections` と `/api/v1/profile` を訪れ、「分区とトレントが読めるか」「アカウント情報が読めるか」を確認します。権限不足はログにはっきり記録されます。

## KamePT

KamePT（亀サイト）は NexusPHP 構成のサイトで、**独立したプラグイン画面はありません**。検索は NexusPHP プラグインが担い、別に「サイト認証」という独立した道があります。

| 項目 | 内容 |
| --- | --- |
| サイト住所 | `https://kamept.com` |
| 検索の入口 | 連携アプリ → サイト資源 → NexusPHP。サイト追加時に「サイト名称」で **KamePT（亀サイト）** を選ぶと、住所とロゴが自動で入ります |
| 認証の入口 | 右上のアイコンメニュー → サイト認証 → KamePT を選択 |

### 手順

1. NexusPHP プラグインを開き、「有効状態」をオンにして保存します。
2. 「NexusPHP サイト」カードで「サイトを追加」を押します。
3. サイト名称で **KamePT（亀サイト）** を選びます。
4. **サイトトークン**を入力（サイトの「コントロールパネル → 設定」の「アクセストークン」で作成）。「有効にする」はオンのまま。
5. 先に「健康診断」を押し、通ってから「追加」を押します。

### サイト認証（任意）

サイト認証はプラグイン設定とは別の道です。

1. 右上のアイコンメニューから**サイト認証**を開きます。
2. サイト一覧で **KamePT（亀サイト）** を選びます。
3. サイトの **UID** と **パスキー**を入力して送信します。
4. 認証が通ってから、その結果に依存する機能が使えます。**サービスを再起動するたびに再認証が必要**です。

:::note[検索結果の名前]
KamePT の結果は `NexusPHP` と記録されます。購読の既定順序には NexusPHP が入っているため、追加の設定は不要です。検索では先にサイトの主口を問い合わせ、次に設定された分区を一つずつ調べてまとめます。一つの分区が失敗しても他には影響しません。
:::

## Rousi

Rousi（肉絲）は **RSS サービス**と **API サービス**を別々の住所として設定します。ドメインが違うことがあるためです。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → サイト資源 → Rousi |
| 既定ドメイン | RSS `https://rousi.pro`、API `https://rousi.pro/api` |
| 資格情報 | ログイン → 右上のアイコン → アカウント設定 → パスキー、をコピーして入力 |

:::note[サイト群のドメイン差]
システムには二つの Rousi が登録されています。`rousi.pro` と `rousi.zip`（閉鎖予定の告知あり）です。プラグインの既定は `rousi.pro` です。別のドメインを使っている場合は、サイトの現状に合わせて二つの住所を変更してください。
:::

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと検索もダウンロードもアカウント保護確認も行いません |
| RSS サービス住所 | 既定 `https://rousi.pro`。RSS の道筋と、相対パスの表紙を完全な住所にする際に使用 | 間違えると表紙の画像が壊れます |
| API サービス住所 | 既定 `https://rousi.pro/api`。検索の口はこれに `/v1/search` を足したもの | 間違えると何も見つかりません |
| キー（パスキー） | 検索時に `Bearer` トークンとして使用。ダウンロードリンクの作成にも使用 | 無いと検索はできてダウンロードが失敗 |
| 臨時認証コード | ヘッダ `Authorization` として送信 | 検索の本筋はパスキーだけで動きます。不要なら空欄で構いません |
| アカウント保護通知 | 既定オフ。ログイン状態を定期確認して通知 | 長期未ログインのアカウントは凍結・削除されます |

テストのボタンは二つ：**RSS 接続をテスト**（RSS サービス住所を確認）、**API 接続をテスト**（API サービス住所を確認。購読検索が依存）。どちらも届くかだけを調べ、パスキーは確認しません。

## FSM

FSM は独自フレームワークのサイトで、**NexusPHP ではありません**。サイト認証の流れにも参加せず、プラグイン設定だけを使います。口と RSS は別ドメインで、検索は API トークン、ダウンロードリンクはパスキーを使います。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → サイト資源 → FSM |
| 資格情報 | ログインして、アカウント設定でパスキーと API トークンを確認 |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと検索もダウンロードもしません |
| API サービス住所 | 既定 `https://fsm.name/api`。検索の道筋はこれに `/Torrents/listTorrents` を足したもの | サイトのトップページを書くとつながりません |
| RSS サービス住所 | 既定 `https://api.fsm.name`。API とは別ドメイン | どちらか片方だけだと対応する機能が使えません |
| キー（パスキー） | トレントのダウンロード住所の取得に使用 | 無いと検索はできてダウンロードが失敗 |
| 認証コード（API トークン） | 検索時の証明。ヘッダ `APITOKEN` として送信 | 無効だと検索結果が空になります |

:::warning[二つで半分ずつ]
API トークンは検索できるか、パスキーはダウンロードできるかを決めます。両方正しくて初めて道筋が完結します。
:::

テストのボタンは二つ：**RSS 接続をテスト**と**API 接続をテスト**。どちらもドメインに届くかだけを見て、資格情報は確認しません。

:::tip[FSM を優先したいら順序に足す]
購読の既定順序 `M-Team,NexusPHP,Rousi,Prowlarr` には FSM がありません。順序に無い場所は優先されませんが、除外もされません。FSM の結果を優先したいなら、購読設定の検索順序に `FSM` を追加してください。
:::

## Prowlarr

Prowlarr は自分で建てる索引まとめサービスです。複数のサイトの検索を一つの口にまとめるため、AMMDS は Prowlarr だけに尋ね、あとは Prowlarr が配ります。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → サイト資源 → Prowlarr |
| 運用形態 | 自前で用意。AMMDS はその住所に届けばよい |
| 直結サイトとの違い | 直結プラグインは一サイトだけ。Prowlarr は一度の要求で配下の全索引を覆います |
| 資格情報 | Prowlarr の管理画面 → Settings → General → API Key |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと検索しません |
| サービス住所 | Prowlarr の住所。プロトコルが必要。例：`http://127.0.0.1:9696` | 空だと検索結果が空になり、ログに「索引の設定が不完全」と出ます |
| 認証キー | Prowlarr の API キー。ヘッダ `X-Api-Key` として送信 | 間違いは「つながるのに検索がずっと空」として現れます |

:::warning[二つとも必須]
サービス住所と認証キーはどちらも必要です。どちらが空でも処理は止まりませんが、検索はずっと空のままです。
:::

検索の条件は成人向け分類に固定されます。Prowlarr 側にその分類に対応する索引が無ければ結果は空です。Prowlarr の結果には直接リンクが付いているため、ダウンロード時に住所を引き直す必要はありません。

:::tip[控えとして使うのが一番]
直結サイトで見つからない番号を、Prowlarr に配下の全索引で探させます。Prowlarr は常に最後に並ぶため、直結サイトの優先は保たれます。
:::

## BitMagnet

BitMagnet はオープンソースで自前運用できるトレント検索サービスです。自分で絶えずトレントを見つけて分類します。つなぐと、設定済みの PT サイトに限らず、公開されたトレントをマグネット検索で探せます。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → サイト資源 → BitMagnet |
| 運用形態 | **自前で用意が必須**。AMMDS に探索の仕組みは内蔵されていません |
| ポート | 少なくとも画面用 `3333` と探索用 `3334`（TCP/UDP）、さらにデータベースが必要 |
| 位置づけ | 購読の検索順序には入らず、マグネット検索に専念 |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと検索とファイル照会の口が「BitMagnet 連携プラグインが未使用」を返します |
| サービス住所 | 既定 `http://127.0.0.1:3333`。コンテナなら `127.0.0.1` ではなく、ホストの住所かサービス名（例 `http://bitmagnet:3333`）を書く | `127.0.0.1` を書くと AMMDS 自身につながります |

:::warning[コンテナの住所の落とし穴]
Docker では `127.0.0.1` はコンテナ自身を指します。ホストの住所かサービス名を使ってください。
:::

ボタンは二つ：**接続テスト**（住所に届くかだけ）、**アプリ状態を取得**（「基本情報」と「サービス状態」の二つのタブ）。状態では探索サービス、データベース、TMDB の三つが健康かを確認できます。

:::tip[まず状態を見る]
検索が空なら先に「アプリ状態を取得」を押してください。探索サービスが異常なら、まだトレントを見つけていないということです。原因は AMMDS ではなく BitMagnet 側にあります。
:::

:::note[購読の順序には入らない]
BitMagnet は購読設定の検索順序に含まれないため、購読の自動ダウンロードはこれを使いません。マグネット検索の画面を担うもので、キーワードで珍しい資源を探すのに向いています。
:::

## 困ったときは

- **保存したのに見つからない**：「有効状態」がオンになって保存されているかを確認。NexusPHP なら「検索機能」がオンか、サイト自体が「有効」かも確認します。
- **接続テストが失敗する**：サービス住所のプロトコルとポートを確認。コンテナの AMMDS で `127.0.0.1` を使わないこと。そのうえで外に出られるかを確認します。
- **見つかるのにダウンロードできない**：たいていパスキーが空か失効しています。サイトで取り直してください。
- **「設定が失われた」と出る**：サービス住所かトークンが空です。埋めて保存し、もう一度検索します。
- **健康診断が失敗 / 権限不足**：サイト住所の間違い、トークンのコピー漏れ、権限不足です。同じトークンで繰り返さず、サイトで作り直してください。
- **FSM の結果がいつも出ない**：FSM は既定の順序にありません。必要なら購読設定の検索順序に `FSM` を足します。
- **アカウント保護の通知が頻繁**：ブラウザで一度サイトにログインしてください。不要なら通知をオフにできます。
