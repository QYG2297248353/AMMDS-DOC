# 資源を自動でダウンロードする

資源が見つかっても、実際に落とすのは別のソフトです。このページでは三つを扱います。qBittorrent にダウンロードを担わせること、Transmission をダウンローダーとして登録すること、そして IYUU で既存のトレントを補植することです。

> **ダウンローダー**：実際にダウンロードするソフトです。AMMDS がするのは「見つけて仕事を渡す」ことで、ダウンロードそのものはダウンローダーが行います。

> **補植（クロスシード）**：同じ資源が別のサイトにもあるとき、すでに持っているトレントをそのサイトにも足して、そこでも種を維持することです。アップロード量を増やせます。

> **種を維持する（シード）**：ダウンロード後もファイルを消さず、他の人に配り続けることです。多くの PT サイトはこれを貢献として記録します。

> **ポート**：一台の機械で複数のサービスを見分けるための番号です。住所の末尾に書きます。例：`8080`。間違えると別のサービスにつながります。

## まず役割分担を確認

ここを間違えると時間を無駄にします。

| 能力 | 担当 |
| --- | --- |
| 購読の自動ダウンロード | **qBittorrent** |
| IYUU の自動補植 | **qBittorrent** |
| ダウンローダーの登録と接続確認 | qBittorrent と Transmission の両方 |
| システム診断のプラグイン健診 | qBittorrent と Transmission の両方 |

つまり、**Transmission だけでは購読の自動ダウンロードは実行されません**。自動ダウンロードには qBittorrent が必要です。

---

## qBittorrent

qBittorrent はダウンロードの道筋の終点です。購読が一致した資源はここが書き込み、IYUU の補植で足されたトレントもここが受けます。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → ダウンローダー → qBittorrent |
| 通信 | qBittorrent のウェブ管理画面の口 |
| 認証 | ウェブ管理画面のログイン名とパスワード |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだとダウンロード関連の口がすべて「qBittorrent が未使用」を返します |
| サービス住所 | 既定 `http://127.0.0.1:8080`。プロトコルが必要。コンテナならホストの住所かサービス名 | コンテナで `127.0.0.1` を書くと AMMDS 自身につながります |
| 接入点 RPC | 既定 `/`。ウェブ画面が `/qbittorrent` のような下の階層にあるなら同じ値に | 合わないとログインが 404 になり「接続テストは通るのに情報取得が失敗」します |
| ユーザー名 | 既定 `admin` | 間違えるとアプリ情報が取れません |
| パスワード | ウェブ管理画面のログインパスワード | 同上 |

:::warning[反転プロキシの前置きを合わせる]
qBittorrent が下の階層にあるなら、「接入点 RPC」をそれに合わせてください。合わないとログインが 404 になります。
:::

### ボタン

| ボタン | 出力 |
| --- | --- |
| 接続テスト | サービス住所への到達確認 |
| アプリ情報を取得 | ユーザー名、住所、既定の保存先、口のバージョン、プログラムのバージョン、トレント数 |

「アプリ情報を取得」は資格情報の確認にいちばん確実です。既定の保存先とトレント数が取れれば、ログイン成功かつ口のバージョンも合っています。

### 保存先とタグ

| 項目 | 動作 |
| --- | --- |
| 保存先 | 購読設定の**ダウンロード先**を優先。無ければ qBittorrent の既定の保存先に戻ります |
| 分類 | 追加時に分類を渡せます。購読からの送信では既定で指定しません |
| タグ | 購読からの送信では `AMMDS订阅` と配信元サイトのタグが付きます。後で停止したいトレントには `AMMDS暂停` も追加されます |
| 住所の帰属 | 保存先は**ダウンローダーが動く機械**の住所であり、AMMDS コンテナの住所ではありません |

:::tip[住所の書き方]
AMMDS と qBittorrent が別のコンテナなら、qBittorrent から見た住所（例 `/downloads`）を書きます。AMMDS 側で割り当てる前の住所ではありません。
:::

### ダウンロードの流れ

1. **購読検索**がサイト側で資源に一致します。
2. **ダウンロードを送信**：取得したトレントの住所で qBittorrent に追加し、保存先と購読タグを付けます。
3. **状態を見返す**：タグで処理を探し、完了していれば購読を完了として通知を送ります。処理が消えていれば失敗として記録します。
4. **補植**：IYUU が足したトレントも qBittorrent が受けます。現行版の自動補植は qBittorrent のみ対応です。

日常の停止・開始・削除・一括操作は**ツールボックス → ダウンローダー → タスク管理**で行います。

## Transmission

Transmission は軽量なダウンロードソフトです。AMMDS はその口を通じてインスタンスを登録し、到達を確認します。あわせてシステム診断の健診対象にもなります。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → ダウンローダー → Transmission |
| 口の道筋 | 既定 `/transmission/rpc`。ダウンローダーの設定と一致させる必要があります |
| 認証 | 口のユーザー名とパスワード（認証が有効な場合） |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだとシステム診断のプラグイン健診に参加しません |
| サービス住所 | 既定 `http://127.0.0.1:8080`。**実際のポートに必ず変更してください** | 変更しないと qBittorrent のポートにつながります |
| 接入点 RPC | 既定 `/transmission/rpc`。反転プロキシで道筋を書き換えたなら同期して変更 | 合わないとデータが取れません |
| ユーザー名 | 既定 `admin` | 認証が有効なときに間違えるとつながりません |
| パスワード | 口の認証パスワード | 同上 |

:::warning[既定のポートは必ず変更]
Transmission のよく使われるポートは `9091` ですが、ここでの既定値は `8080`（qBittorrent の既定と同じ）です。二つを同時に動かすなら、Transmission の本当のポートに変えてください。
:::

「接続テスト」は住所を調べ、何か応答があれば成功とします。注意点として、Transmission の口は識別子が無いと 409 を返しますが、**409 も「応答あり」**です。したがってテストが通るのは住所とポートが正しいという意味であり、ユーザー名とパスワードが正しいという意味ではありません。

:::note[システム診断での使われ方]
システム診断はこのプラグインの「有効状態」と「サービス住所」を読みます。有効なのに住所が空、または届かない場合、プラグイン健診で異常として印が付き、影響する機能は「トレントのダウンロード送信」と表示されます。
:::

## IYUU

IYUU はトレントの特徴を手がかりに他のサイトを探すサービスです。すでに種を維持しているトレントを他のサイトと突き合わせ、一致すれば同じ資源をそのサイトにも足して種を維持します。

| 項目 | 内容 |
| --- | --- |
| 入口 | 連携アプリ → ダウンローダー → IYUU |
| トークン | IYUU 公式サイトにログインし、ユーザーセンターでアカウントトークンをコピー |
| 分担 | IYUU は**探す**だけです。実際にダウンローダーへ足すのは qBittorrent です |

### 設定項目の説明

| 設定項目 | 何を入力するか | 空欄・間違いのとき |
| --- | --- | --- |
| 有効状態 | スイッチをオン | オフだと補植の口も送信テストもすべて失敗します |
| API サービス住所 | 既定 `https://2025.iyuu.cn` | 間違えるとつながりません |
| サービス住所 | 既定 `https://iyuu.cn`。画面の移動と管理画面の入口に使用 | 間違えても移動先が変わるだけ |
| キー | IYUU のアカウントトークン。口の中の身分を示す印 | 空だと補植も送信も失敗。アカウントを替えたらトークンも替えます |
| 画像を隠す | 既定**オン**。オンなら生成されるメッセージに画像が付きません | オフならメッセージに画像が付きます |

### ボタン

| ボタン | 内容 |
| --- | --- |
| 接続テスト | 「API サービス住所」への到達確認。トークンは確認しません |
| 送信テスト | 内蔵の雛形で実際に一通を送り、トークンと通知の道筋を確認 |

### 補植の予定

**ツールボックス → PT補植 → サイト管理**で「補植予定」を押すと設定画面が開きます。

| 項目 | 内容 |
| --- | --- |
| 有効 | 自動補植を行うか |
| 実行周期 | 定时の式。空なら定期処理を登録せず、手動のみになります |
| 補植クライアント | 補植を担うダウンローダー。**現行版では qBittorrent のみ有効** |
| 通知 | 補植完了後に通知を送るか |

送信前に定时の式を検査し、正しくない式は保存を拒否されます。

### 補植の流れ

1. 予定どおりに起動するか、「今すぐ補植」で手動起動します。
2. 起動時に 30〜300 秒のランダムな待ち時間を入れ、複数が同時に IYUU を叩かないようにします。
3. 一回につき最大 100 件の「補植待ち」を取り出し、一件ずつ IYUU に補植可能なサイトを尋ねます。
4. サイトの要件に合わせて追加方法を選びます。認証が要るサイトは先にトレントファイルを取得、Cookie が要るサイトはサイトの Cookie を添付、それ以外は直接トレントの住所を送信します。
5. サイトごとの結果はすぐ記録され、状態は `未補植`、`補植待ち`、`補植完了`、`補植失敗` のいずれかになります。

:::warning[前提条件は IYUU アカウント側]
自動補植には、IYUU アカウントで補植が有効で、補植クライアントが qBittorrent に設定されていることが必要です。これらのスイッチは IYUU にあり、AMMDS にはありません。アカウント側がオフなら、こちらで起動しても何も起きません。
:::

### サイトと記録

| 画面 | 用途 |
| --- | --- |
| ツールボックス → PT補植 → サイト管理 | 補植対応サイトのカード表示、サイト設定の変更、**サイト取込**（JSON 設定ファイル）、「今すぐ補植」 |
| ツールボックス → PT補植 → 補植記録 | 処理単位の記録：自動 / 手動、結果、件数、時刻、理由 |
| ツールボックス → PT補植 → 補植タスク | トレント単位の明細：状態、補植時刻、一致したサイトのトレント、失敗理由 |

記録とタスク一覧はどちらも消去できますが、**消去は取り消せません**。

## 困ったときは

- **「ダウンローダーが未使用」と出る**：該当プラグインの「有効状態」をオンにして保存します。
- **接続テストは通るのに情報取得が失敗**：ユーザー名かパスワードが違う、または「接入点 RPC」が実際の道筋と合っていません。
- **トレントの追加が失敗**：保存先がダウンローダーの機械に存在しません。ダウンローダーから見て有効な住所を使ってください。
- **購読がいつまでも完了しない**：`AMMDS订阅` タグを手で変えないでください。変えると見返すときに見つかりません。
- **ダウンロード完了なのに登録されない**：スキャンの場所と保存先が一致していません。スキャン処理の場所設定を確認します。
- **「今すぐ補植」が 0 を返す**：「補植待ち」の記録が無い、または IYUU アカウント側で補植がオフです。
- **「対応していないクライアント」と出る**：補植クライアントに Transmission が選ばれています。qBittorrent に変更してください。
- **「補植失敗」が多い**：サイトが Cookie を要する、または認証情報が期限切れです。サイトカードで設定を更新して再実行します。
- **送信テストが届かない**：トークンが違う、またはシステム側の通知スイッチがオフです。
