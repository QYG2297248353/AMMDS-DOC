# ライブラリヘルスチェック

ライブラリヘルスチェックは、「何かおかしい」と思われる箇所をまとめて検出します。購読が停止している、再生進捗が削除済みの作品を指している、ストレージディレクトリが開けない、ポスターが欠けている、といった問題です。チェックのみを行い、データは自動では変更しません。どれを修正するかは、手動でクリックして決めます。

## 入口

右上のアバターをクリックし、ドロップダウンメニューから「ライブラリヘルスチェック」を選択します。

:::note[メディア管理メニューにない理由]
これは意図的な設計です。ヘルスチェックの入口はアバターメニューにのみ残され、メディア管理のサイドバーには表示されません。日常のメディア管理操作と混同しないようにするためです。直接アクセスするアドレスは `/admin/media/health` です。
:::

## ヘルスチェックは読み取り専用です

ページ上部に「ヘルスチェック自体は読み取り専用で、データを変更しません。修正操作は手動で実行してください」と表示されています。つまり：

- ページを開く、絞り込みを切り替える、「チェック開始」をクリックする、といった操作では何も削除・変更されません
- 実際に変更が実行されるのは、問題の行にある修正ボタンをクリックしたときだけです
- 削除を伴う操作では確認ダイアログが表示され、中には「取り消し不可」と明記されたものもあります

## 検出できる問題

| 分類 | わかりやすく言うと |
| --- | --- |
| 無効なファイル紐付け | データベースには記録されているが、ディスク上に見つからない、または利用不可とマークされたファイル |
| ポスター / 背景画像の欠落 | 作品はあるが、ローカルにポスターや背景画像がない |
| カバー画像の比率異常 | カバー画像のサイズ比率が規格に合っていない |
| 重複ファイル | 同じスキャンパス、同じ番号、または同じファイルが複数回記録されている |
| 未照合の番号 / メタデータ | ファイルはスキャンされたが、どの作品か認識されていない |
| スキャンの残骸 / 孤立 | スキャンで残った無効なレコード、またはどのファイルにも対応しないメタデータ |
| 漫画ページの消失 | 章の記録は残っているが、ディスク上の漫画画像が削除されたか、ディスクが利用不可 |
| 購読の異常 | RSS 購読が無効化された、長期間更新がない、映画・ドラマの購読が一時停止中、または長期間マッチしない |
| 再生進捗の異常 | 再生進捗が削除済みの動画やファイルを指している、またはファイルが利用不可 |
| ストレージディレクトリの異常 | データディレクトリが存在しない、または書き込み権限がない |
| メタデータが不完全 | 公開日、上映時間、あらすじなどの主要情報が欠けている |

「スキャンの残骸 / 孤立」には「ファイルのないメタデータ」という種類があります。これは意図的に残した純粋なデータ項目である可能性があるため、システムは既定で削除ボタンを表示しません。

## 重大度の見方

| レベル | 意味 | 推奨対応 |
| --- | --- | --- |
| 重大 | 再生、スクレイピング、データセキュリティに直接影響する | 優先して対応 |
| 警告 | 機能は使えるが、状態が正しくない | 時間があるときに修正 |
| 通知 | 見た目が整っていないだけ、使用には影響しない | 無視しても構わない |

## 絞り込みと検索

- **ライブラリ種別**：映画、ドラマ、漫画、購読、システム
- **重大度**：重大、警告、通知
- **キーワード**：タイトル、パス、番号を検索

一覧の各行には、カバー画像、項目、主要情報、状態、実行可能な操作が表示されます。実行できる操作がない項目には「読み取り専用」と表示されます。

## ワンクリックで修正できるもの

| ボタン | 実際の動作 | 注意点 |
| --- | --- | --- |
| 再検出 | ディスク上のファイルがまだ存在するかを再確認し、利用可否を更新 | 安全 |
| 再スクレイピング | バックグラウンドのスクレイピングタスクを投入し、メタデータと画像を再取得 | 即座には完了せず、タスク完了を待つ必要があります |
| 無視 | 無視としてマークし、今後のスキャンでこの項目を表示しない | 安全 |
| マークを消去 | 「カバー画像の比率異常」のマークだけを消し、カバー画像ファイルは変更しない | 安全 |
| 紐付けを削除 | データベース内のファイル紐付け記録のみを削除し、**ディスク上のファイルは削除しない** | 安全 |
| 参照を解除 | 無効なメタデータ参照を解除し、項目を未照合の状態に戻す | 安全 |
| 重複を統合 | 既存のルールに従って最も古い一条を残し、残りを削除または統合 | **取り消し不可** |
| 今すぐ取得 | この RSS 購読の最新内容をすぐに一度取得 | 安全 |
| 購読を有効化 | 無効化された RSS 購読を再度有効にし、以降はスケジュールどおり取得 | 安全 |
| 再マッチング | マッチング回数をクリアし、購読状態を復元して、再びマッチング待ち行列に入れる | 安全 |
| 進捗を削除 | 無効な動画やファイルを指す再生進捗記録を削除 | 動画やファイル自体には影響しません |
| ストレージ管理 | ストレージ管理ページに移動してディスクとディレクトリの状態を確認 | 画面遷移のみ |

## 一括修正

1. 複数の問題にチェックを入れます。
2. 下部に「N 件を選択」と表示されるので、「一括修正」をクリックします。
3. 選択したすべての項目が対応する修正操作だけが選択肢に表示されます。共通の操作がない場合は「選択した項目に共通して利用できる修正操作がありません」と表示されます。
4. ダイアログに今回影響する件数が表示され、確認後に実行されます。

実行後は「N 件を処理しました」、または「成功 X 件、失敗 Y 件」と集計結果が表示されます。

## チェック履歴

- 「チェック開始」をクリックすると新しい記録が生成され、完了後に統計と一覧が自動更新されます
- 「履歴」では開始時刻、状態、結果、所要時間、トリガー方法を確認できます
- トリガー方法は「手動」と「定時」があり、状態は「実行中」「完了」「失敗」です
- 「表示」をクリックすると、その回のチェックの分類別詳細を確認できます

## よくある質問

| 現象 | 説明 |
| --- | --- |
| 修正をクリックしても反応がない | その項目が読み取り専用か、チェックを入れてから一括修正する必要がある可能性があります |
| 修正後も一覧が変わらない | 再検出系の操作は即座に更新されます。スクレイピングや取得はバックグラウンドタスクのため、完了を待ってから確認してください |
| 紐付けを削除してもファイルが残っている | 正常です。紐付けの削除はデータベースの記録だけを消します |
| ストレージディレクトリの異常を修正できない | この種の問題は手動対応が必要です。案内に従って「ストレージ管理」でマウントと権限を確認してください |
