# バックアップと復元

このページは二つの別の作業を扱います。**データの引っ越し**（整理した情報を書き出し、別の場所で復元すること）と、**設定のオフサイト保存**です。文字と画像だけを対象とし、システム設定やプラグインの鍵は含みません。

> **メタデータ**：項目を説明する情報のことです。タイトル、出演者、あらすじ、表紙、章などが該当します。バックアップに入るのはこれらで、動画ファイル自体は入りません。

## 1. データを書き出す

**システム管理 → バックアップと復元 → データ書き出し** を開きます。四つのカードがあり、それぞれ画像を同梱するかを個別に決められます。

| 種類 | 書き出されるもの | 「画像も同時に書き出す」を選ぶと増えるもの |
| --- | --- | --- |
| 作品 | 作品の情報、ファイル情報、紐づく出演者・シリーズ・磁力・字幕 | ポスター、背景、サムネイル、場面写真、高解像度画像 |
| 出演者 | 出演者の情報（体格、タグ、SNS など） | 顔写真とポスター |
| 漫画 | アルバムの情報、章、章ページの記録 | 表紙、裏表紙、すべての章ページ画像 |
| 小説 | 小説の情報と章の本文 | 表紙と裏表紙 |

書き出しは裏で実行されるので、終わるのを待たずにページを離れて構いません。「書き出し履歴」で種類、ファイル名、状態（書き出し中 / 完了 / 失敗）、サイズ、作成日時を確認し、ダウンロードや削除ができます。同じ種類が書き出し中の間はボタンが読み込み中表示になり、二重に開始できません。

:::tip[同梱されるのはローカルの画像だけです]
データディレクトリに保存され、実際に存在する画像だけが入ります。外部のリンクは入りません。引っ越し後に元のデータディレクトリを残していれば、以前のパスがそのまま使えます。外部リンクは配信元が見られるかどうかに依存します。
:::

## 2. バックアップの中身

標準的なバックアップは圧縮ファイルで、最上位に `manifest.json` と `data.json` が必須、画像フォルダは任意です。

| ファイル | 役割 |
| --- | --- |
| `manifest.json` | 明細。形式の印、バージョン、種類、件数、画像の一覧 |
| `data.json` | データ本体。1 件ずつ記録されます |
| `images/` | 画像を書き出したときだけ存在し、項目ごとにフォルダが分かれます |

1 つのバックアップに入るのは 1 種類だけです。明細の件数と `data.json` の実際の件数は一致している必要があり、一致しないと取り込みは拒否されます。

## 3. データを復元する

1. **データ取り込み** を開き、圧縮ファイル、または単体の `data.json` をドラッグします。
2. 取り込み方法を選びます（下の表）。
3. 「解析プレビュー」を押し、件数、同梱画像数、サイズ、ファイル数を確認します。
4. 検証が通ったら「取り込み開始」を押します。完了時に、成功・スキップ・更新・失敗の件数が表示されます。

解析時点で次のことを確認します。明細またはデータファイルの欠落、項目パスの不正、形式の印の不一致、未対応バージョン、許可されない種類、明細と実際の件数の不一致、画像のパスが `images/` 外またはファイル不在。一つでも引っかかると**取り込みは禁止**され、データは一切変わりません。

1 件の失敗で全体が止まることはありません。理由は記録され、詳細には最大 50 件まで表示されます。

### 設定項目：三つの取り込み方法

| 方法 | 動作 | 向いている場面 |
| --- | --- | --- |
| 既存をスキップ | 一致するものは何も書き込まず、更新もしません | 欠けている分だけ補いたく、今ある情報を壊したくないとき |
| 上書き更新 | 一致するものを上書き。漫画・小説・ドラマは章や季・話を作り直します | バックアップの内容を現在の状態にしたいとき |
| マージ更新 | 足りない項目だけを補い、一覧は重複を除いて統合。削除はしません | 両方の情報を合わせたいとき |

「同じ項目」の判定：作品は作品番号の重なり（マージ時はタイトルでも照合）、出演者は氏名の完全一致、漫画は ISBN を優先し次にアルバム名、小説は書名または ISBN、ドラマは外部サイトの ID を順に照合します。

## 4. 共有リンクから取り込む

**共有取り込み** タブで行います。

| 設定項目 | 何を決めるか / 入力方法 | 未設定の場合 |
| --- | --- | --- |
| 共有リンクまたは短縮コード | 相手から受け取った公開アドレス、または末尾の短縮コード | プレビューできません |
| アクセスパスワード | 相手が設定しているときだけ入力 | パスワードを求められ、取り込みできません |
| 取り込み方法 | 既存をスキップ / 上書き更新 / マージ更新 | 既定は「既存をスキップ」です |

入力して「共有をプレビュー」で種類・タイトル・件数を確認し、「共有を取り込み」を押します。取り込みが許可されていない場合は「この共有は取り込みできません」と表示されるので、理由を書いて申請できます（事前にユーザー ID、ニックネーム、メールアドレスの登録が必要です）。

同じページの下で「リンク記録」（成功、権限なし、リンク無効、期限切れ、失敗）と「申請記録」（対象、理由、状態。保留中は取消可）を切り替えられます。記録を消しても、取り込み済みのデータには影響しません。

## 5. 設定は別にオフサイトへ

上のバックアップには**システム設定、プラグインの鍵、購読ルールは含まれません**。設定を別の場所に残したいときは、**統合アプリ → クラウド同期** のネットワークディスクまたはオブジェクトストレージを使います。

- 対象は「設定類」だけで、画像や作品の項目は入らないため、容量はごく小さいです。
- バックアップは暗号化されます。**合言葉を失うと復元できません**。ファイルとは別に保管してください。
- 復元時は、マージ更新、ローカル優先、リモート優先から選べます。
- それらのサービス自身の接続設定は復元対象外です。復元後にリモートへつながらなくなるのを防ぐためです。
- ネットワークディスクは設定のバックアップ専用です。画像などの資源をリモートへ置きたいときはオブジェクトストレージを、と使い分けてください。両者は独立しています。

> **合言葉**：バックアップの暗号化と復号に使う、自分で決めた文字列です。システムは保管してくれないので、忘れたら新しく作り直すしかありません。

## 習慣にしておきたいこと

1. データは種類ごとに書き出し、画像が必要なときだけ「画像も同時に書き出す」を選びます。
2. 設定はクラウドへ別に保存し、合言葉はバックアップと分けて保管します。
3. 復元前に同じバージョンの環境で「解析プレビュー」を実行し、検証が通るか確認します。
4. 大きなバージョン更新の前に一度すべてを書き出し、更新後にシステム診断を実行します。

## 困ったときは

- **取り込みが拒否される**：バックアップが不完全か、明細と件数が合っていないことが多いです。書き出しをやり直し、中のファイルを手で編集しないでください。
- **取り込んでも変わらない**：「既存をスキップ」を選んでいないか確認してください。置き換えたいなら「上書き更新」です。
- **画像が復元されない**：書き出し時に画像を選んでいないか、画像が外部リンクです。画像を付けて書き出し直してください。
- **書き出し履歴が失敗**：タスクログで理由を確認してください。空き容量不足がよくある原因です。
- **クラウドの設定が復元できない**：合言葉が正しいか、リモートのファイルが壊れていないかを確認してください。接続設定自体は復元されないので、手で入力します。
- **復元後に問題がないか確認したい**：[システム診断、ログ、ストレージ、ライセンスとユーザー](./maintenance.md)で全体診断を実行してください。
