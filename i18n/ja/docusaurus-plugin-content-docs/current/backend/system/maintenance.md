# システム診断、ログ、ストレージ、ライセンスとユーザー

「まずここを見る」ためのページです。全体診断を実行し、ログと容量を確認し、ついでにライセンス、アカウントの安全、裏のタスクも処理します。各節は独立しています。

## 1. システム診断：まず一度実行する

> **システム診断**：内蔵の点検ツールです。設定と状態を読むだけで、変更も自動修復もしません。

右上のアイコン → **システム診断** を開きます。最初に読み取り専用の概要が出ます。バージョン、OS、メモリ、ディスクの空き、ポート、データベース、稼働時間、データディレクトリ、サーバー時刻、タイムゾーンです。

「診断開始」を押すとサーバー側で実行され、完了時に正常・警告・異常・未使用の件数と所要時間が上部に出ます。

### 何を点検するか

| グループ | 着目点 |
| --- | --- |
| 基本情報 | バージョン、OS、メモリ、ディスク、システム時刻、外部への接続 |
| ソフトウェア設定 | 補助プログラムの準備状況、中継設定の過不足、各統合サービスの応答 |
| システム設定 | ポート、データベース接続、ドメインの紐付け、通知経路、ライセンス |
| 稼働状態 | ログ内のエラー数、CPU とメモリの負荷、ディスクの負荷 |

主な判定基準です。

- **メモリ**：使用率が 90% を超える、またはシステムの空きメモリが 10% 未満で警告。
- **ディスク**：データディレクトリの空きが 1GB 未満、または使用率 90% 超で警告。
- **システム時刻**：ネットワーク時刻との差が 5 分を超えると警告。ライセンス確認、定期タスク、時刻判定に影響します。
- **ネットワーク接続**：複数の宛先を並行して確認し、すべて到達で正常、一部のみで警告、全部失敗で異常。
- **補助プログラム**：無い場合は警告が出て、影響する機能も示されます（動画処理プログラムが無いと、動画処理、画面キャプチャ、ポスター切り抜き、サムネイル作成に影響）。
- **中継設定**：未使用は「未使用」として記録。使用中でホストかポートが空、またはポートが 1〜65535 外なら異常。
- **統合サービス**：未使用は問題なし。使用中で必須設定が不足なら警告。アドレスが入っているのに応答しないなら異常。

### 結果の読み方

| 状態 | 意味 | 対応は必要か |
| --- | --- | --- |
| 正常 | 想定どおり | 不要 |
| 警告 | 使えるが不安あり。機能が制限される可能性 | 表示に従って対応 |
| 異常 | すでに使えない、または明らかな設定誤り | 必須 |
| 未使用 | 対象自体がオフ | 不要（必要なら別） |

一部の項目には印が付きます。「設定が必要」は対応する設定画面へ、「再起動が必要」は再起動後に有効、「影響する機能」はその問題が及ぶ範囲を示します。

## 2. ログ：三種類で役割が違う

**システム管理 → ログ監査** に三つのページがあります。

| ページ | 内容 | 向いている調査 |
| --- | --- | --- |
| ログインログ | 誰がいつログインしたか。成功も失敗も記録 | パスワード誤り、無効化アカウント、身に覚えのない接続元 |
| 動作ログ | サーバーで何が起きたか | 画面のエラー、サービスの異常 |
| タスクログ | 裏のタスクがどこまで進み、なぜ失敗したか | スキャン、情報取得、整理、同期、書き出しと取り込みの失敗 |

### ログインログ

項目は順に、ユーザー名、接続元、場所、日時、端末情報（OS / 端末 / ブラウザ）、状態、理由です。キーワードと状態で絞り込み、1 ページ 10 件、新しい順です。失敗の理由は検証段階のもので、「ユーザーが存在しません」「アカウントは無効です」「パスワードが違います」などがあります。成功は「ログイン成功」です。

### 動作ログ

項目は日時、スレッド、レベル、出力元、メッセージです。レベルは四段階で、エラー（赤）、警告（橙）、情報（青）、デバッグまたは通常です。画面は最近の分（既定 300 件）を読み、8 秒ごとに更新されます。

右上で「最近 1 日 / 7 日 / 30 日」を選んで書き出せます。サーバーが主ログと日付で分かれたログを日付順に一枚のテキストにまとめ、合計が 100MB を超えると古い分を切り捨てます。ログはデータディレクトリにあり、主ファイルは日付で回転し、エラーは別に保存されます。

### タスクログ

ツールバーに実行中の件数が出て、タスク名、種類、状態で絞り込めます。自動更新も切り替えられます。列はタスク、種類、状態、進捗、完了 / 総数、所要時間です。「詳細」を押すと、失敗理由、開始と終了時刻、そして**実行明細**（時刻、レベル、メッセージの並び）が見られます。失敗の原因を突き止める最短の材料です。

操作は次のとおりです。詳細（いつでも）、中止（実行中で、かつ対応しているものだけ）、削除（実行中以外）、完了分をクリア（終了済みをすべて消す。実行中は残ります）。

### 調べる順番のおすすめ

1. まず**タスクログ**で失敗した回を探し、実行明細の最初のエラーを読みます。
2. 時刻を覚えて、**動作ログ**で同じ時刻の前後を確認します。
3. サービスのアドレス、鍵、ネットワークが絡むときは**システム診断**で確認します。
4. ログインや権限の疑いがあれば**ログインログ**を見ます。

## 3. ストレージ：容量を使っているのは誰か

**システム管理 → ストレージ管理** を開くと四つの数字が出ます。ディスク総容量、使用中、空き、データディレクトリの使用量です。「使用中」と「データディレクトリの使用量」の差は、たいてい動画の元ファイル、OS、他のプログラムです。

集計は裏で行われます（起動時に 1 回、その後 5 分ごと）。画面は 30 秒ごとに更新されます。データディレクトリは第 1 階層のフォルダごとにサイズとファイル数が分かり、画像はさらに第 2 階層まで内訳が出ます。多い分類は、画像、キャッシュ、動画処理プログラム、字幕、メタデータサービス、鍵、ログ、一時ファイルです。登録のないフォルダは「その他のデータ」にまとめられます。

:::warning[フォルダを手で消さないでください]
データディレクトリの鍵フォルダとデータベースフォルダには、証明書とすべてのデータが入っています。動作中に移動や削除をすると破損する恐れがあります。整理は下の入口から行ってください。
:::

この画面は閲覧専用で、整理の入口は別の場所にあります。

| 整理したいもの | 場所 |
| --- | --- |
| タスクログ | ログ監査 → タスクログ → 完了分をクリア |
| 書き出したバックアップ | バックアップと復元 → データ書き出し → 書き出し履歴 → 削除 |
| フィードのオフラインキャッシュ | インフォメーションセンター → フィード → キャッシュ画面 → キャッシュを削除 |
| 不要なファイルと一時ファイル | ツールボックス → ファイルブラウザ → 削除 |
| サービスがダウンロードした資源 | そのサービスのページの資源カード |

容量が足りなくなるとどうなるか：システム診断のディスク項目は空き 1GB 未満または使用率 90% 超で警告します。「システム設定 → 基本設定」のディスク監視をオンにしていれば、不足時に通知が届きます。情報取得、ダウンロード、変換はいずれも一時領域を必要とするため、容量が尽きると失敗してタスクログに記録されます。

## 4. ライセンスと透かし

> **透かし**：ページに重ねて表示される半透明の文字です。有効なライセンスがないとき全画面に出ますが、**機能はすべてそのまま使えます**。ログイン、システム設定、サイト認証、バックアップも影響を受けません。

> **鍵**：ここでは、この導入環境のライセンスを示す文字列のことです。

右上のアイコン → **ユーザーセンター** を開き、一番下の「ライセンス」カードがこの節の内容です。状態と権利の一覧はどのアカウントでも見られますが、**有効化、更新、試用、停止、クリアができるのは管理者だけ**です。

### 状態の読み方

画面には、ライセンス状態（有効 / 無効）、有効化の方法、プラン、有効期限、鍵（一部伏せ字）、直近の検証成功時刻、試用状態、導入環境の識別子が出ます。上部のバナーが現在の状況を説明します。

| バナー | 意味 | すべきこと |
| --- | --- | --- |
| 試用中（残り時間） | 7 日間の試用期間内。終了すると透かしが戻ります | 期限前に有効化 |
| 試用終了済みで再試用不可 | 1 つのデータにつき 1 回のみ | ライセンスを有効化 |
| ライセンスサービスに接続できず、検証済みのライセンスで動作中（オフライン猶予の期限） | オフラインだが猶予期間内 | ネットワークを復旧して更新 |
| サービスに接続できず、猶予期間も超過 | ネットワークが必要 | 復旧して更新 |
| ライセンスが現在使えない | 期限切れ、取り消し、停止、未設定などの可能性 | ライセンスの管理画面で確認 |
| プランに基本権利が無い | プラン設定の問題 | 管理者に連絡 |

### 三つの有効化方法

| 方法 | 手順 |
| --- | --- |
| オンライン有効化 | `AMMDS-XXXX-XXXX-XXXX-XXXX` の形の鍵を入力して「有効化」を押します。サーバー側が直接処理し、透かしが消えます |
| オフライン有効化 | サーバーからライセンスサービスへ届かないときに使います。「オフライン有効化」を押すと製品 ID、識別子、コピー可能なコマンドが出るので、別のネット接続端末で実行し、返ってきた JSON をファイル（64 KiB まで）としてアップロードします |
| 7 日間の試用 | 鍵は不要です。押すとすぐに連続したカウントダウンが始まり、停止中も進みます |

有効化済みの環境では、既定で有効化エリアは隠れており、右上の「ライセンスを変更」で開きます。変更は現在のライセンスを置き換え、試用中に有効化すると試用はすぐ終了します。

### いくつかの規則

| 操作 | 規則 |
| --- | --- |
| 7 日間の試用を開始 | 導入データ 1 つにつき 1 回のみ。完全なライセンスがある、または試用済みならボタンは押せません |
| オンライン更新 | 一度検証します。サービスが使えないときは、保存されている状態を返します |
| オンラインのライセンスを停止 | リモートが枠の解放を確認してから、ローカルの情報を消します |
| ローカルのみクリア | この端末の鍵とトークンだけを消します。リモートの枠は解放されず、試用の記録も残ります |

停止とクリアはどちらも確認が必要で、元に戻せません。会員はアカウントの印、ライセンスは導入環境の権利で、別物です。プラン名、価格、権利の範囲は購入ページとライセンス画面の表示に従ってください。

## 5. ユーザーとログインの安全

AMMDS は自分で運用する管理者 1 人のアプリです。導入環境に管理者は 1 人だけなので、重点は**唯一の入口を守ること**です。

| 役割 | 説明 |
| --- | --- |
| 管理者 | 導入環境のライセンス変更と、慎重な操作ができる唯一のアカウント |
| ユーザー | ログインして機能を使えるが、導入環境の権限は変更できない |
| ゲスト | 未ログインで公開ページを見る。公開 API の回数制限の対象 |

最初の管理者は初回起動時に作られ、ユーザー名は固定で、初期パスワードは導入時の環境変数（既定は公開されている値）です。**導入後、まずパスワードを変更してください。**

### ログインの検証の流れ

パスワードは送信前に暗号化され、平文がブラウザから出ることはありません。ユーザー名、パスワード、アカウント状態が確認され、二段階認証が有効なら数字も確認されます。

> **ログイントークン**：ログイン後に受け取る通行証です。以後の操作はこれを添えるだけで、パスワードの再入力は不要になります。アクセストークンは 120 分、更新トークンは 30 日です。

試行は成功・失敗を問わずログインログに残ります。

パスワードの規則（ログイン、変更、リセットで共通）：**6〜22 文字、英大文字と小文字を含み、数字または記号を少なくとも一つ**です。

### 安全点検の四つの手順

1. **ログインログ**を開き、状態「失敗」で連続の試行がないか、接続元や場所で身に覚えのないログインがないかを確認します。
2. 異常があれば、まずパスワードを変更し、次に二段階認証かパスキーを有効にします。
3. 無効化されたアカウントはログインできず、理由が記録されます。
4. パスワードを忘れたときは、後述の回復キーでリセットします。

### 二段階認証

> **二段階認証**：パスワードに加えて、スマートフォンの 6 桁の数字を入力します。パスワードが漏れても入られません。

**システム設定 → セキュリティ設定 → 二段階認証** にあります。

1. 総スイッチをオンにします。
2. 「有効にする」を押し、四つの手順を進みます。説明を読む → QR を読み取る（手入力も可）→ 認証アプリの 6 桁を入力 → 完了。
3. 完了時に **8 個の一回限りの回復コード**が発行されます。コピーまたはダウンロードで保存し、それぞれ一度だけ使えます。
4. オフにするときも検証が必要です。認証アプリの現在の 6 桁、または未使用の回復コードを入力します。

回復コードを使い切ったら、一度オフにして再度有効化すると 8 個が再発行されます。数字が通らないときは端末の時刻を合わせてください。この仕組みは時刻の同期に依存します。

### パスキー

**システム設定 → セキュリティ設定 → パスキー** にあります。指紋、顔、端末の暗証番号でログインします。有効にするには三つの条件がすべて必要です。

| 条件 | 満たさないとき |
| --- | --- |
| ドメインでアクセスしている（アドレスとポート、ローカルではない） | ドメインを紐付けて、ドメインでアクセスするよう促されます |
| 暗号化された接続（アドレスが暗号化方式で始まる） | ブラウザが認証器を提供しないと表示されます |
| ブラウザがこの認証方式に対応している | 新しいブラウザへ変更するよう促されます |

条件を満たしたら「作成」を押すと、端末の認証機能（OS の生体認証、スマートフォンなど）が呼び出され、登録された証明が一覧に出ます。名前（変更可）、作成日時、最終利用が表示され、操作は名前変更と削除です。削除すると、その端末ではこの方法でログインできなくなります。パスキーと外部アカウントのログインでは、追加の数字入力は**不要**です。

### シングルサインオン

**システム設定 → セキュリティ設定 → シングルサインオン** で、外部アカウントでのログインを設定します。

1. 画面に出たコールバック URL をコピーし、相手側の許可リストに登録します。
2. 「アプリを作成」を押し、名前、アイコン、ボタン文言、クライアント ID と秘密、対応づけ項目（既定は識別子）を入力します。
3. 保存後、自分の外部アカウントを紐付けできます。解除や停止もいつでも可能です。
4. ログイン画面に対応するボタンが出ます。

クライアントの秘密はローカルのデータベースにだけ保存され、画面には戻りません。アプリを削除すると、その入口はすぐに使えなくなります。

### セキュリティの設定項目

| 設定項目 | 何を決めるか / 入力方法 | 未設定の場合 |
| --- | --- | --- |
| パスキーの総スイッチ | 指紋や顔などでのログインを許可するか | 既定はオフ |
| 二段階認証の総スイッチ | 追加の数字入力を求めるか | 既定はオフで、パスワードのみ |
| ゲストの回数制限 | 未ログインの公開 API 利用の上限（回/分、既定 100） | システムが直接読み、画面に入口はありません |

## 6. 鍵とパスワードの再設定

**システム管理 → 鍵管理** で扱うのは**外部プログラム用の鍵**です。

| 列 | 説明 |
| --- | --- |
| 名称 | 作成時に書いた用途。隣に「正常」または「期限切れ」 |
| 鍵 | 印をクリックすると全体がコピーされます |
| 種類 | ブラウザ拡張 / API 呼び出し / 漫画リーダー |
| 有効期限 | その時点で自動的に無効になり、印が赤くなる |
| 操作 | 削除（確認あり、元に戻せません） |

> **API キー**：他のプログラムに渡す文字列です。これを添えて要求すれば「許可された呼び出し」と証明でき、アカウントのパスワードは不要です。

作成時に入力するのは、名称（必須）、種類（必須）、有効期限（空なら無期限。入れる場合は現在より 10 分以上後）です。

:::warning[種類は混用できません]
三つの種類はそれぞれの用途にだけ効きます。API の鍵は公開 API だけで有効で、管理画面の操作は許可しません。漫画リーダーの鍵はその入口専用です。使い間違えると「未認証」になります。公開 API は[システム設定項目の一覧と説明](./config.md)で「API を公開」もオンにする必要があります。
:::

**管理者パスワードの再設定**は別の道で、一回限りの回復キーを使います。データディレクトリ内のファイルにだけ存在し、画面にもログにも出ません。ログイン画面の「パスワードを忘れた」から、回復キーと新しいパスワードを入力して送信すると、成功時にファイルが消去され、一回限りの証明になります。ファイルが無いときは、再起動すれば新しく生成されます。

新しいパスワードも同じ強度の規則に従います。よくある表示は次のとおりです。「回復キーが存在しません」は使い済みか未生成、「回復キーが違います」は内容の不一致、「パスワードが簡単すぎます」は規則不足、「管理者アカウントが異常です」は管理者が 1 人ではない状態です。

日常的な変更はユーザーセンター（現在のパスワードが必要）から行います。「パスワードを忘れた」とは別の経路です。

## 7. 裏の定期タスク

**システム管理 → スケジュールタスク** を開くと、システム内蔵の定期タスクがすべて見られます。どのくらいの間隔で動くか、前回が成功したか、いま動いているかが分かり、一度だけ手動で実行もできます。

一覧にはタスク名（下に所属が出る）、実行間隔（人が読む形。元の式はホバーで表示）、実行状態、前回の実行時刻、そして「実行」があります。「実行」を押すと即座に戻り、裏で開始します。実行中は同じタスクを二重に開始できません。

> **Cron**：「いつ実行するか」を一行で書いた式です。「毎日 04:45」「5 分ごと」など。画面は人が読む形に訳し、分からないときはそのまま表示します。

このページが保持するのは各タスクの**直近 1 回**の実行時刻と結果だけで、履歴の一覧はありません。全体の流れを見るときは**タスクログ**で種類や状態を絞り込み、「詳細」で明細を確認してください。

:::warning[総スイッチを切っても全部は止まりません]
総スイッチ（導入時の環境変数、既定はオン）を切ると、画面に「スケジュールタスクは停止中」と出て手動実行も拒否され、設定から登録される周期タスク（追加シードの自動実行など）は登録されなくなります。ただし、プログラム内に直接書かれた内蔵タスクはそのまま動きます。ある種の自動動作を完全に止めるには、対応する機能のスイッチも一緒に切ってください。
:::

## 困ったときは

- **警告がたくさん出た**：まず「異常」を直し、次に「設定が必要」の印があるものを処理し、「再診断」で確認します。
- **システム時刻が大きくずれている**：ホストの時刻を合わせて再起動し、中継の対象外リストに時刻確認用ドメインが残っているかも確認します。
- **タスクが「実行中」のまま**：タスクログで同じ進捗で止まっていないか確認し、必要なら中止してやり直します。
- **ディスクの警告**：第 3 節の入口から整理してください。データディレクトリのファイルを手で消さないでください。
- **透かしが消えない**：ライセンスの状態とバナーを見て、表示に従ってください。機能は止まらないので、そのまま使い続けて構いません。
- **ログインできない**：ログインログで理由を確認します。管理者のパスワード忘れなら回復キーで再設定します。
