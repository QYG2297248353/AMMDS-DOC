# ホーム画面：開いてすぐ見えるもの

ログインすると既定で工作台（ホーム画面）が開きます。一枚の画面にディスク容量・作品数・天気・ネットワーク・バージョンのカードが並び、その下に三つのランキングがあり、視聴の振り返り・新作の発見・各サイトのアカウント状態を確認できます。このページでは、それぞれの数字の意味、データの出どころ、様子がおかしいときに最初に見る場所を説明します。

## はじめに

> **ホーム画面**：ログイン後に既定で開くページです。よく確認する情報を一枚にまとめ、メニューをあちこち開かずに済ませます。

> **ランキング**：ある基準で並べた順位や統計です。ここには三つあり、それぞれ別のデータを使うため互いに影響しません。

> **自動更新**：こちらが操作しなくても、ページが定期的に数字を取り直し、表示が静かに更新されます。

カードの順番は固定です。ストレージ、メディア統計、天気、ネットワーク情報、システム情報、AMMDS サービス状態、応援する。画面が狭いと縦に積み重なり、全体幅の行になります。

## カードの読み方

### ストレージ

左に円グラフ、右に二つの数値です。

| 表示 | 意味 |
| --- | --- |
| 総容量 | AMMDS を動かす機器のディスク総容量です。Linux とコンテナはデータフォルダがあるファイルシステム単位、Windows は各ドライブを合計します |
| 映像容量 | 登録済みの映像ファイルの合計サイズです。漫画・小説、ダウンロード中のファイルは含みません |
| 使用済み / 空き | ディスク全体の使用量と残量で、円グラフの二つの区間になります |

10 秒ごとに自動更新されます。

### メディア統計

一行に五つ：お気に入り映像、お気に入り俳優、購読映像、漫画（アルバム数）、小説です。同じく 10 秒ごとに自動更新されます。0 でも故障ではなく、まだ該当データがないだけです。

### 天気

アイコン、気温、天候、風向きと風力、省と都市を表示します。

- 都市はまず集成应用 → 高德地图（連携アプリ → 高徳地図）で設定した都市コード（`adcode`、3〜6 桁の都市番号）を使います。
- 未設定なら、まずグローバル IP を調べて都市に換算します。
- 独自の高徳地図設定を有効にしていない場合は、プログラム内蔵のキーを使い、天気はそのまま表示されます。

> **プロキシ**：目的のサイトに直接つながず、バックエンドのサーバーに代わりにリクエストを転送してもらうことです。直接接続が失敗すると、自動でこちらに切り替わります。

失敗するとカードに「天气信息加载失败（天気情報の読み込みに失敗）」と重试（再試行）ボタンが出ます。

:::note[天気にはインターネットが必要です]
天気は高徳地図のサービスに依存します。直接接続が失敗するとバックエンド経由の転送に切り替わり、両方だめなときだけ失敗と表示します。その場合は、まずこの欄の[ネットにつながらない？まずここを](./network.md)をご覧ください。
:::

### ネットワーク情報

サーバー側から見た公衆アドレス、使っている接続の種類、地理位置、プロキシの有無を表示します。ポップアップには连通性（接続性）タブもあり、プログラムが使う公共サイトを一つずつ検査できます。判定基準と対処は別ページ、[ネットにつながらない？まずここを](./network.md)にあります。

### システム情報

既定では四行だけで、バージョンをすばやく確認できます。

| 行 | 内容 |
| --- | --- |
| Java バージョン、Spring Boot | プログラムが依存する下位の実行環境のバージョンです。普段は気にしなくてかまいません |
| AMMDS コアバージョン | AMMDS 自身のバージョンです。最新版かどうかはこれで判断します |
| 稼働システム | OS とアーキテクチャです。コンテナ内では一律 `Docker` と表示されます |

> **コンテナ**：プログラムと必要なものを隔離された箱にまとめて動かす導入方法です。箱内のシステムは一律 `Docker` と記録されます。

カードのどこかをクリックすると「系统信息详情（システム情報の詳細）」が開き、二つに分かれます。

- **サーバー情報**：アプリ名と説明、三つのバージョン、実行環境と提供元、システムとアーキテクチャ、プロセッサのコア数、メモリ使用量、稼働時間、サーバーの時刻とタイムゾーン、待ち受けアドレス、開発元と公式サイト、連絡先メール。
- **ブラウザ情報**：ブラウザ識別子、稼働プラットフォーム、言語、タイムゾーン、画面とウィンドウのサイズ、デバイスピクセル比、論理コア数、デバイスメモリ、ネットワーク状態、Cookie 対応、現在のアドレス。

この情報はホーム画面を開いたときに一度取得し、詳細でも同じものを使います。この四行は定期更新されません。

### AMMDS サービス状態

六つの数字で、いずれも直近 24 時間の集計です。

| 指標 | 意味 |
| --- | --- |
| オンライン人数 | 現在オンラインの訪問者数 |
| 閲覧数 | 直近 24 時間のページ閲覧数 |
| ユニーク訪問者 | 直近 24 時間のユニーク訪問者数 |
| 訪問 | 直近 24 時間の訪問回数 |
| 離脱率 | 直近 24 時間の離脱率 |
| 平均滞在時間 | 総滞在時間を訪問回数で割った値で、日 / 時 / 分 / 秒で表示します |

:::warning[これはあなたの機器の状態ではありません]
これらの数字は AMMDS 公式の統計サービスから来ており、**公式サイト**の利用状況を示すもので、手元の AMMDS の稼働指標ではありません。10 秒ごとに更新され、統計サービスに届かないとすべて 0 になることがあります。手元の CPU・メモリ・ディスク・データベース接続・プラグイン状態は「系统检查（システム診断）」を、手元のポート・バージョン・待ち受けアドレスは上の「系统信息（システム情報）」カードをご覧ください。
:::

### 応援する

クリックできる画像で、押すと公式ショップの購入ページを新しいタブで開きます。どの統計にも数えられず、機能にも影響しません。

## 三つのランキング、それぞれの役割

三つともダッシュボード配下にあり、データの出どころはまったく別です。一部だけ有効にすることもできます。

### 自分がどれだけ見たか振り返る —— 巅峰榜单（ピークランキング）

> **メディアサーバー**：Jellyfin や Emby など、ファイルを置いてテレビやスマホに配信するソフトです。

再生履歴は Jellyfin と Emby の連携から来ます。プラグインを有効にしてユーザーを紐づけると、バックエンドが 5 分ごとに再生履歴を同期してローカルに保存します。ランキングは**紐づけたユーザー**だけを集計し、メディアサーバー自身のレポートは読みません。

| 領域 | 内容 |
| --- | --- |
| 上部の統計 | 再生回数、総視聴時間（分）、一日あたり平均（分 / 日）、対象日数 |
| 再生推移 / 視聴時間 | クライアント別の視聴時間と合計を日ごとに示す棒グラフ・折れ線グラフ |
| 再生元の分布 | クライアント別に視聴時間をまとめた円グラフ |
| 月間カレンダー | 今月の各日の視聴熱量で、色が濃いほどその日よく見ています |

右上の「7 天 / 14 天 / 30 天（7 / 14 / 30 日）」ボタンは上部の統計と推移グラフの両方に効き、既定は 14 日です。

誤解しやすい集計ルール：

- 日付は再生履歴の**開始時刻**でまとめ、`yyyy-MM-dd` に統一します。
- 終了時刻が空の履歴は未完了とみなし、日ごとの集計に入れません。
- 再生履歴がない日も結果に並ぶ（値は 0）ため、「対象日数」は選んだ日数と一致します。
- 上部の「再生回数」は視聴時間から換算したもので、10 分ごとに 1 回、切り上げです。履歴の件数ではありません。
- 月間カレンダーの「再生回数」は履歴の件数で、上部とは別基準です。マウスを重ねると両方が表示されます。

:::note[空ならまず紐づけを確認]
ページが空のときは、集成应用 → Jellyfin / Emby（連携アプリ → Jellyfin / Emby）で、プラグインが有効か、アドレスとキーがつながるか、ユーザーが紐づいているかを確認します。「系统检查（システム診断）」でもプラグインの有効・設定状態を見られます。
:::

### 最近の新作を探す —— 电影榜单（映画ランキング）

> **メタデータ**：作品の表紙・あらすじ・出演者・タグなどの説明情報です。

> **作品番号**：ファイル名に含まれる識別番号で、AMMDS はこれで作品を判別します。

データはバックエンドの定時タスクが連携プラグインから集めてローカルに保存したもので、ページはローカルを読むだけです。開いたときに上流へ取りに行くことはありません。

| ランキング元 | 出どころ | 収集に必要な条件 |
| --- | --- | --- |
| ThePornDB | ThePornDB の「最近更新」 | 「启用状态（有効）」と「榜单采集（ランキング収集）」が両方オンで、サービスアドレスと API Key がそろっていること |
| Fanza DMM | FANZA DMM の日付ランキング | 「启用状态（有効）」と「榜单采集（ランキング収集）」が両方オン |

収集はすべてバックエンドで自動実行され、操作は不要です。

- ThePornDB：起動の約 8 分後に初回、以降 6 時間 10 分ごと。1 回につき最大 10 ページ・各 20 件で、「上流の ID + ランキング種別」で重複を除き、同じものは二重に入りません。
- Fanza DMM 本日の新作：起動の約 10 分後に初回、以降 6 時間 15 分ごと。その日にすでにデータがあればスキップします。
- Fanza DMM 公開予定：起動の約 10 分後に初回、以降 13 時間 30 分ごと。今後 3 日のうち記録がない日だけ補います。

ページの使い方：

1. 上部でランキング元を選びます。**ThePornDB** または **Fanza DMM**。
2. 分類を選びます。ThePornDB は「Jav即将上映（JAV 公開予定）」「欧美即将上映（欧米公開予定）」、Fanza DMM は「今日上新（本日の新作）」「即将上映（公開予定）」。
3. カードは公開日の新しい順で最大 30 件です。表紙、作品番号、公開日、タイトル、出演者、スチール写真の点数が載ります。
4. カード右上が状態ボタンです。

| ボタン | 意味 |
| --- | --- |
| 完成（完了） | この作品番号は登録済みで、ボタンは押せません |
| 订阅（購読） | 未購読です。押すと購読を登録し、バックエンドが作品情報を補います |
| 已订阅（購読済み） | すでに購読記録があり、ボタンは押せません |

:::tip[購読したあと]
購読すると購読記録ができ、バックエンドで作品情報が補われ、その後、購読とダウンロードの流れで資源が照合されます。長く進まないときは、まずダウンローダーのプラグインとサイト設定を、次に購読状態を確認します。
:::

### 各サイトのアカウント状態を見る —— PT 站点榜单（PT サイトランキング）

> **PT サイト**：アカウント登録が必要で、アップロード・ダウンロード量で評価される資源サイトです。

> **シーディング（做种）**：ダウンロード完了後も公開を続け、他の人にファイルを渡す行為です。

> **レシオ（分享率）**：アップロード量をダウンロード量で割った値で、サイトは一定以上を求めるのが普通です。

> **ボーナスポイント（魔力值）**：シーディングなどの貢献に対してサイトが与えるポイントです。

データは設定済みの PT サイトのアカウントから、サイトの枠組みごとに取得します。M-Team、Rousi、FSM、NexusPHP 系のサイトです。先に「站点认证（サイト認証）」を済ませる必要はなく、サイトが設定されデータを同期していれば表示されます。

| 指標 | 集計方法 |
| --- | --- |
| サイト総数 | データがあるサイトの数 |
| 総アップロード / 総ダウンロード | 各サイトのアップロード・ダウンロードのバイト数を合計 |
| 総シード数 / 総ダウンロード数 | 各サイトのシード・ダウンロードのタスク数を合計 |
| 平均レシオ | レシオがあるサイトだけを平均 |
| 総ボーナスポイント | 各サイトのポイントを合計 |
| アクティブサイト | 直近 30 日にログイン記録があるサイト数 |

各サイトのカードにはロゴ、名称、枠組みタグのほか、レシオ、ボーナスポイント、アップロード量、ダウンロード量、シード数、ダウンロード数、シード時間、ダウンロード時間、ユーザー名とアイコン、警告 / 吸血 / 等級タグ、登録日時と最終ログインが並びます。右上に二つのボタン、刷新（更新、このサイトのみ）と打开主页（ホームを開く）があります。更新は枠組みに応じたインターフェースを呼び、NexusPHP 系はサイト ID で更新します。

上部にはもう二つ操作があります。

| ボタン | 作用 |
| --- | --- |
| 刷新数据（データを更新） | ローカルにあるサイトデータを読み直すだけで、サイトへはリクエストしません |
| 更新所有站点（全サイトを更新） | バックエンドに各サイトへ最新データを取りに行かせます。時間がかかります |

上部の通知バーには、このページで最後に更新した時刻が出ます。これはページ内のタイムスタンプで、サーバー側でデータが実際に更新された時刻ではありません。

:::warning[更新を連打しないでください]
「更新所有站点（全サイトを更新）」を頻繁に押すと各サイトへ連続してリクエストが飛び、異常と判定されて一時的に禁止されることがあります。リアルタイム性が不要なら既定の間隔のままにしてください。
:::

### どれを使うか

| 見たいもの | ランキング |
| --- | --- |
| 自分の視聴時間・習慣・端末の分布 | 巅峰榜单（ピークランキング） |
| 最近の新作と、登録済みかどうか | 电影榜单（映画ランキング） |
| 各 PT サイトのレシオ・ポイント・シード状況 | PT 站点榜单（PT サイトランキング） |

視聴統計はメディアサーバーのプラグイン、新作はメタデータのプラグイン、サイトデータはサイト設定に依存します。三つは独立しており、一部だけ有効でも使えます。

## 設定項目の説明

| 設定項目 | 入力するもの | 未入力 / 間違えた場合 |
| --- | --- | --- |
| 天気の都市コード（`adcode`） | 3〜6 桁の都市番号。集成应用 → 高德地图（連携アプリ → 高徳地図）で設定します | 未設定ならグローバル IP から都市を推測します。間違えると別の地域の天気になります |
| 高徳地図の独自設定 | 自分用の設定を有効にするか | オフならプログラム内蔵のキーを使い、天気はそのまま見られます |
| 紐づけるユーザー（メディアサーバー） | Jellyfin / Emby 連携で集計するユーザーを選びます | 未選択・誤りだと、巅峰榜单（ピークランキング）にデータが出ない、または誤ったデータになります |
| 期間（7 / 14 / 30 日） | 巅峰榜单（ピークランキング）右上で日数を選択。既定は 14 日 | 上部の統計と推移にだけ影響し、選び間違えてもデータは壊れません |
| ランキング収集スイッチ | 映画ランキング側のプラグインで「启用状态（有効）」と「榜单采集（ランキング収集）」を両方オンにします | どちらかがオフだとその元は収集せず、ページに新着が出ません |
| サービスアドレス、API Key | ThePornDB の収集に必要です | どちらか欠けると ThePornDB のランキングを収集しません |
| 「订阅（購読）」ボタン | 未購読のカードで押します | 「完成（完了）」「已订阅（購読済み）」は元々押せません。購読後はバックエンドの補完を待ちます |

## 困ったときは

- ストレージが「存储管理（ストレージ管理）」の数字と合わない：基準が違います。こちらはディスク全体と映像ファイルの合計、「存储管理」は `data/`・`db/` 直下の一段目のフォルダ別に数えます。
- メディア統計がずっと 0：お気に入り・購読・漫画・小説のデータが実際にあるか確認します。入れたばかりなら 0 は正常です。
- 天気の都市が違う：集成应用 → 高德地图（連携アプリ → 高徳地図）で都市コードを直すか、独自都市をオフにしてグローバル IP での定位に任せます。
- 「AMMDS サービス状態」がすべて 0：公式の統計サービスに届いていないだけです。手元の機能とは無関係で、対応は不要です。
- ランキングが空：巅峰榜单（ピークランキング）は紐づけユーザー、电影榜单（映画ランキング）は収集スイッチとプラグイン設定、PT 站点榜单（PT サイトランキング）はサイトの設定と同期済みかを確認します。
