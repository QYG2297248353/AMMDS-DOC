# 定時実行・タスク履歴・失敗時の再実行

毎回「立即扫描（今すぐスキャン）」を押すのは面倒ですよね。このページでは、タスクを決まった時刻に自動で動かす方法、全体を制御するスイッチの場所、時間割の書き方、実行後の記録の見場所、そして失敗時の再実行とログの整理を扱います。

## はじめに

> **スクレイピング**：情報サイトから作品の表紙・あらすじ・出演者を調べて自動で埋めることです。

> **メタデータ**：作品の表紙・あらすじ・出演者・タグなどの説明情報です。

> **作品番号 / 識別コード**：ファイル名に含まれる識別番号で、AMMDS はこれで作品を判別します。

> **NFO**：動画と同じ場所に置く小さな説明ファイルで、プレイヤーも読みます。

> **Cron**：「いつ実行するか」を数字と記号で書いた短い文字列です。毎日の時刻や何分ごとかを指定します。

> **定時ジョブ**：再生履歴の同期、ランキング取得、一時ファイルの削除など、プログラムが決まった時刻に自分でこなす一仕事です。

> **スケジューラ**：時刻が来たら対応するジョブを起こす、プログラム内の仕組みです。一つずつ手で起動する必要はありません。

> **環境変数**：アプリを起動する前にシステムで設定するスイッチの値です。普通の導入方法では触らず、変更にはたいてい再起動が必要です。

> **並列処理**：複数のことを同時に進めることです。

> **ログ**：「いつ何をして、うまくいったか」を書き残した記録で、不調のときにさかのぼって確認します。

## 決まった時刻に自動で動かす

### 「计划任务（定時タスク）」ページを開く

系统管理 → 计划任务（システム管理 → 定時タスク）へ進みます。上部に全体スイッチの状態、実行中の数、「自动刷新（自動更新）」スイッチ、「刷新（更新）」ボタンがあり、下にジョブの表があります。

| 項目 | 内容 |
| --- | --- |
| 任务名称（ジョブ名） | 主見出しがジョブ名で、下の行は内部の識別子 `类名#方法名` です。照合用です |
| 执行周期（実行周期） | 人が読める周期の文です。マウスを重ねると元の Cron や固定間隔の式が見られます |
| 运行状态（実行状態） | このページから手動で起動した実行が「実行中 / 空き」かどうかで、下に前回の手動実行の結果概要が付きます |
| 上次执行（前回実行） | 前回の手動実行の開始時刻です。失敗なら赤い「失败（失敗）」ラベルが付き、一度も手動実行していなければ「从未执行（未実行）」と出ます |
| 操作（操作） | 「执行（実行）」ボタン。実行中または全体スイッチがオフのときは灰色になります |

:::note[この二つは手動実行だけを記録します]
「运行状态（実行状態）」と「上次执行（前回実行）」は**このページから手動で起動した実行**だけを記録します。自動スケジュールで動いた分はこの二つに書き戻されません。自動タスクの様子は「系统管理 → 运行日志（システム管理 → 実行ログ）」で確認します。
:::

:::note[周期の文が読めないとき]
画面が読みやすい文に直すのは「毎日定時」「N 分ごと」「N 時間ごと」「N 日ごとの定時」といった一般的な形だけです。判別できない Cron は式をそのまま表示します。推測による誤読を避けるための、意図した動作です。
:::

### 全体スイッチ：オフにすると一連の計画が止まる

全体スイッチは環境変数 `AMMDS_SCHEDULER_ENABLE`（設定項目 `ammds.scheduler.enable`）で制御され、**既定はオン**です。

- オフにすると上部に「计划任务已关闭（定時タスクは無効です）」と表示され、説明も出ます。
- 手動の「执行（実行）」はバックエンドに拒否され、ボタンも灰色になります。
- 起動時に「任务级 Cron（タスク単位の Cron）」と「IYUU 自动辅种（IYUU 自動補種）」の登録を飛ばし、この二つは無効になります。
- プログラム内蔵の定時ジョブはこのスイッチの影響を受けません。ページに引き続き並び、各自の周期で動き続けます。バックグラウンド作業をすべて止めたいなら、インスタンスごと止めるか導入側で対処します。

**このスイッチの変更はアプリの再起動後に有効になります。** 変更方法はシステム設定欄のシステム設定ページにあります。

### 一度だけ手動で実行する

ある行の「执行（実行）」は一度だけ実行を投入し、元の周期は変えません。

1. バックエンドは今回の実行を専用の待ち行列へ入れ、完了を待たずに即座に戻ります。
2. 同じジョブがすでに実行中なら、再度押すと拒否され「任务正在执行中（タスク実行中）」と出ます。
3. 画面はただちにその行を実行中と表示し、3 秒ごとに結果を問い合わせます。全部終わると自動的に問い合わせを止めます。
4. 完了すると「上次执行（前回実行）」が更新され、結果概要が実行状態の下に書かれます。失敗時はエラーの種類とメッセージで、長すぎると切り詰められます。

「自动刷新（自動更新）」スイッチは、実行中に問い合わせを続けるかを制御します。オフなら「刷新（更新）」を手で押すまで最新状態が見られません。

### Cron の書き方

アプリは 6 項目の Cron を使い、並びは `秒 分 时 日 月 周` です。

| 式 | 意味 |
| --- | --- |
| `0 0/20 * * * ?` | 20 分ごと |
| `0 0/2 * * * ?` | 2 分ごと |
| `0 0 9 * * ?` | 毎日 09:00 |
| `0 30 4 * * ?` | 毎日 04:30 |
| `0 10 */6 * * ?` | 6 時間ごとの 10 分目 |
| `0 0 3 1/13 * ?` | 13 日ごとの 03:00 |

Cron のほか、`fixedRate`（固定間隔）や `fixedDelay`（前回終了から計時）を使うジョブもあります。画面はこれらを「N 分 / 時間ごと」に換算し、初期遅延も表示します。

### どんな自動ジョブがあるか

一覧は起動時に自動的に走査して作られるため、手で管理する必要はありません。よくあるグループです。

| グループ | 代表的なジョブ |
| --- | --- |
| 購読とダウンロード | 購読待ち作品の一括ダウンロード（20 分ごと）、購読のダウンロード進捗更新（2 分ごと）、未照合の購読メタデータ更新（300 分ごと） |
| サイトとアカウント | PT サイト認証の実行、全 PT サイトのユーザーデータ同期、PT アカウントの安全状態チェック |
| メディアサーバー | Jellyfin / Emby の再生履歴とライブラリ同期、ライブラリの出演者データ補完 |
| 情報センター | RSS 記事の更新、RSS オフラインキャッシュ、RSS 自動アーカイブ、人気購読の更新、人気購読の有効性確認 |
| ランキング | ThePornDB の最近更新、FANZA DMM 当日ランキングと今後 3 日のランキング取得 |
| 保守 | スキャンの不要データ削除、章番号の修復、ファイルブラウザの一時ファイル削除、知覚ハッシュ計算、ディスク容量チェック、ストレージ統計、ライセンス確認、MeiliSearch の自動インデックス |
| その他 | シリーズライブラリ同期、厂牌规则（メーカー規則）の取り込み、公式ショップ同期、ローカルリソースの S3 同期 |

実際のページの一覧が基準です。今後内蔵ジョブが増えても、再起動すれば自動的に現れ、画面の改修は不要です。

### 二つの仕組みを混同しない

「计划任务（定時タスク）」ページと、タスク設定の Cron は別物です。

| 仕組み | 設定場所 | 「定時タスク」ページに出るか |
| --- | --- | --- |
| 内蔵の定時ジョブ | アプリに最初から同梱 | 出る |
| スキャンタスクの Cron | 任务配置 → 编辑任务 → 计划任务（タスク設定 → タスク編集 → スケジュール） | 出ない。スケジューラが別に登録します |
| 自動スクレイピング間隔 | 任务配置 → 刮削规则（タスク設定 → スクレイピング規則） | 出ない。間隔で自己スケジュールし、全体スイッチの影響を受けません |
| IYUU 自動補種 | 工具箱 → PT 辅种 → 辅种计划（ツールボックス → PT 補種 → 補種計画） | 出ない。スケジューラが別に登録します |

スキャンタスクでフォルダ監視をオンにすると Cron は使われなくなります。監視をオフにして Cron を書くと、起動時または設定変更後にスケジューラへ登録されます。タスク単位の Cron と IYUU 自動補種は全体スイッチに従い、内蔵ジョブは従いません。

:::warning[一つのタスクに二つの起動方法を入れない]
同じスキャンタスクに Cron とフォルダ監視の両方を入れても意味がなく、保存時にどちらか一方だけが残ります。「新しいファイルをすぐ処理」したいならフォルダ監視、「決まった時刻に全件スキャン」なら Cron です。[スキャン：AMMDS にファイルを覚えさせる](./scan.md)参照。
:::

## 実行後の記録はどこで見るか

### 三種類の記録

| 記録 | 場所 | 記録するもの |
| --- | --- | --- |
| 扫描日志（スキャンログ） | 任务管理 → 扫描日志（タスク管理 → スキャンログ） | スキャンタスクの毎回の実行 |
| 刮削日志（スクレイピングログ） | 任务管理 → 刮削日志（タスク管理 → スクレイピングログ） | スクレイピングタスクの各バッチ |
| 任务日志（タスクログ） | 系统管理 → 日志审计 → 任务日志（システム管理 → ログ監査 → タスクログ） | ファイル操作、バックアップ、RSS、漫画 / 小説の整理などのバックグラウンド作業 |

### スキャンログ

「查询（検索）」で条件に沿って更新し、「重置（リセット）」で既定に戻します。タスクカードの「记录（記録）」から入ると、そのタスクで自動的に絞り込まれます。

| 検索条件 | 選択肢 |
| --- | --- |
| 任务类型（タスク種別） | 全部 / 影视（映像）/ 剧集（ドラマ） |
| 任务选择（タスク選択） | タスク名で絞り込み、全部も可 |
| 运行类型（実行種別） | 手動実行、定時タスク、リアルタイム監視、初期化 |
| 任务状态（タスク状態） | 作成、スキャン中、監視中、スキャン待ち、スキャン完了、スキャン取消、スキャン異常 |

| 一覧の項目 | 内容 |
| --- | --- |
| 任务名称（タスク名） | 今回のスキャンが属するタスク |
| 类型（種別） | 実行種別、つまり起動元 |
| 开始时间（開始時刻） | 実行を始めた時刻 |
| 任务耗时（所要時間） | あれば表示。スキャン中は「扫描中（スキャン中）」、それ以外で所要時間がなければ「扫描中断（中断）」 |
| 任务状态（状態） | 完了は緑の丸、それ以外は灰色 |
| 识别媒体数量（判定メディア数） | 今回見つけた動画ファイル数 |
| 新增媒体数量（追加メディア数） | 新たに登録したファイル数 |
| 更新媒体数量（更新メディア数） | 既存で、今回のスキャンに結び直した記録数 |
| 操作 | 「取消（取り消し）」。「スキャン中」かつ実行種別がリアルタイム監視・初期化以外のときだけ可能 |

下部ではページ送り、1 ページ件数、表の密度、列の表示 / 非表示を変えられます。上部の「清理日志（ログ消去）」はスキャン記録をすべて消し、**元に戻せません**。

:::note[スキャンログに個別の詳細はありません]
スキャンログはバッチ単位の情報だけです。ファイルごとの識別番号、スクレイピング状態、手順を見たいなら **任务管理 → 刮削入库（タスク管理 → 取り込み）** へ。媒体ごとの手順タイムラインは「查看步骤（手順を見る）」にあります。
:::

### スクレイピングログ

| 検索条件 | 選択肢 |
| --- | --- |
| 任务类型（タスク種別） | 全部 / 影视（映像）/ 剧集（ドラマ） |
| 运行类型（実行種別） | 手動実行、定時タスクなど |
| 任务状态（状態） | スクレイピング中、完了、待機、取消、異常 |

| 一覧の項目 | 内容 |
| --- | --- |
| 任务名称（タスク名） | このバッチのタスク名。マルチスレッド時はスレッド接尾辞が付きます |
| 开始时间（開始時刻） | バッチの開始時刻 |
| 刮削结果（結果） | バッチの結果概要 |
| 任务耗时（所要時間） | 実行中は「刮削中（スクレイピング中）」、それ以外で所要時間がなければ「刮削中断（中断）」 |
| 任务状态（状態） | 完了は緑、それ以外はオレンジ |
| 刮削媒体数量（対象メディア数） | このバッチで処理予定の数 |
| 刮削成功数量 / 失败数量（成功 / 失敗数） | このバッチの成功と失敗の数 |
| 操作 | 「取消（取り消し）」。「スクレイピング中」かつ実行種別がリアルタイム / 初期化以外のときだけ可能 |

「清理日志（ログ消去）」が消すのは削除可能な過去の記録だけです。実行中は消せません。止めたいときは先に「取消（取り消し）」を押します。

### システムタスクログ

ファイルのアップロード・ダウンロード・複製・移動・圧縮、バックアップの読み込み / 書き出し、RSS 更新、漫画 / 小説の整理などはここに書かれます。

- キーワード、タスク種別、状態で絞り込めます。
- 一覧は種別、タイトル、状態、進捗、メッセージ、開始時刻、所要時間を表示します。
- 「详情（詳細）」を押すと引き出しが開き、状態、進捗、完了数 / 総数、メッセージ、エラー、開始 / 終了時刻、行ごとの実行ログを確認できます。`ERROR` と `WARN` は強調されます。
- 「取消（取り消し）」が出るのは、実行中でバックエンドが取消可と印を付けたタスクだけです。
- 実行中のタスクは削除できません。終了したものは 1 件ずつ削除でき、「清理（消去）」で一括削除もできます。
- 「自动刷新（自動更新）」をオンにすると 5 秒ごとに一覧を更新します。

### 状態の対応

| 経路 | 出てくる状態 |
| --- | --- |
| スキャンタスク | 作成、スキャン中、監視中、スキャン待ち、スキャン完了、スキャン取消、スキャン異常、タスク削除 |
| スクレイピングタスク | スクレイピング中、完了、待機、取消、異常、削除 |
| システムタスク | 実行中、完了、失敗、取消済み |

「等待（待機）」はタスクが作られたがまだ順番が来ていない状態、「异常（異常）」は実行中に未処理のエラーが出た状態で、ログと手順を合わせて特定します。

## 失敗したあとどう再実行するか

記録ページ自体には**「再実行」ボタンがありません**。再実行は対応する業務ページに戻って行います。

| 場面 | 再実行の方法 |
| --- | --- |
| スキャン失敗、または再スキャンしたい | タスク設定でもう一度「立即扫描（今すぐスキャン）」。実行中なら先に取消を |
| 媒体が一つだけ失敗 | 「刮削入库（取り込み）」で「刮削整理（スクレイピング＋整理）」を押すと、失敗分が再度待ちに入ります。[スクレイピング：作品情報を自動で補う](./scrape.md)参照 |
| 作品番号の誤認 | 「刮削入库（取り込み）」で識別番号タグを押して直し、再度スクレイピング |
| メタデータが照合できない | 「绑定（紐付け）」でライブラリの記録に手動で結び、それからスクレイピング |
| 画像や NFO が欠けている | タスクに「查漏补缺（不足補完）」を使い、付属ファイルだけ補う |
| 購読ダウンロード失敗 | 購読管理で「立即搜索（今すぐ検索）」を押すか、次の自動実行を待つ |
| ファイル操作失敗 | システムタスクログでエラーを見て、パス / 権限を直してからやり直す |

:::tip[まず手順、それからログ]
スクレイピング失敗時は、まず「刮削入库 → 查看步骤（取り込み → 手順を見る）」で、ファイル検証・番号判定・情報源検索・画像や NFO 生成のどこで失敗したかを特定します。手順のエラーはたいていバッチログより具体的です。
:::

## ログを消す前に

- ログ消去は**媒体記録を削除せず**、整理済みファイルを元に戻すこともありません。
- スキャンログを消すと過去のバッチは二度と追えません。根拠を残したいなら先に書き出すか画面を保存してください。
- スクレイピングログが消すのは削除可能な過去の記録だけです。実行中は消えません。
- システムタスクログの「清理（消去）」が消すのは終了済みだけで、実行中は残ります。

## 設定項目の説明

| 設定項目 | 入力するもの | 未入力 / 間違えた場合 |
| --- | --- | --- |
| 全体の定時タスクスイッチ `AMMDS_SCHEDULER_ENABLE` | 既定はオン。システム設定で変更し、変更後はアプリを再起動します | オフだと「计划任务已关闭」と表示され、実行ボタンが灰色になり、タスク単位の Cron と IYUU 自動補種が登録されません。内蔵ジョブは動き続けます |
| スキャンタスクの「计划任务（スケジュール）」の Cron | 6 項目の式 `秒 分 时 日 月 周`。フォルダ監視オフのときだけ表示 | 空なら手動のみ。書き間違いやタイムゾーン違いで発火しません。全体スイッチがオンかも確認を |
| 目录监控（フォルダ監視） | Cron とどちらか一方 | 両方入れても一方だけ残ります。監視オンなら Cron スケジュールには参加しません |
| 自动刮削（自動スクレイピング）間隔 | 映像 / ドラマ別のスイッチと間隔。既定は 3 分ごとに未処理を確認 | オフなら手動のみ。短すぎると頻繁に走ります。全体スイッチの影響は受けません |
| 手動の「执行（実行）」 | 「定時タスク」ページで該当行のボタンを押します | 実行中または全体スイッチオフで灰色。すでに実行中なら「任务正在执行中」と出ます |
| 自动刷新（自動更新・定時タスクページ） | 実行中に 3 秒ごとに問い合わせるか | オフなら「刷新（更新）」を押すまで最新状態が見られません |
| 自动刷新（自動更新・システムタスクログ） | オン / オフ。オンなら 5 秒ごとに更新 | オフだと一覧は自動更新されません |
| 扫描 / 刮削日志（スキャン / スクレイピングログ）の検索条件 | タスク種別、タスク選択、実行種別、状態 | 条件が違うと欲しい記録が出ません。「重置（リセット）」で既定に戻ります |
| 清理日志（ログ消去） | 三種類それぞれの消去ボタン | 元に戻せません。消すと過去のバッチを追えなくなります。実行中は消えません |
| 保存配置 / 刷新配置（規則パネル） | 変更後「保存配置」で項目ごとに送信 | 保存しないと反映されません。「刷新配置」は未保存の変更を捨てます |

## 困ったときは

| 現象 | 考えられる原因 | 対処 |
| --- | --- | --- |
| 「计划任务已关闭（定時タスクは無効）」と出る | 全体スイッチがオフ | `AMMDS_SCHEDULER_ENABLE` を変更してアプリを再起動します |
| 「执行（実行）」が灰色 | 実行中、または全体スイッチがオフ | 現在の実行が終わるのを待つか、全体スイッチを確認します |
| 「上次执行（前回実行）」が失敗 | 上流サービス不通、認証情報の失効、ネットワーク異常 | 結果概要と「系统管理 → 运行日志（システム管理 → 実行ログ）」を見て直し、手動で一度実行します |
| 時刻になっても動かない | Cron の書き間違い、タイムゾーン違い、全体スイッチオフ | 6 項目の式とアプリのタイムゾーンを照合します |
| 「定時タスク」一覧が空 | 起動時の走査が未完了、または見つかるジョブがない | まず更新します。それでも空なら起動ログを確認します |
| 自動実行は動いているのに「上次执行」が変わらない | この二つは手動実行だけを記録します | 「系统管理 → 运行日志（システム管理 → 実行ログ）」で自動スケジュールの様子を確認します |
| スキャン / スクレイピング記録にファイル単位が出てこない | ログはバッチ単位だけ | 「任务管理 → 刮削入库（タスク管理 → 取り込み）」と「查看步骤（手順を見る）」で個別に確認します |

- スキャンを定時で動かすには、Cron を書くだけでなく全体スイッチがオンかも確認してください。[スキャン：AMMDS にファイルを覚えさせる](./scan.md)参照。
- スクレイピングの起動方法、自動間隔、不足補完は[スクレイピング：作品情報を自動で補う](./scrape.md)にあります。
- ログを消す前に画面を保存するか書き出してください。消すと戻せません。
