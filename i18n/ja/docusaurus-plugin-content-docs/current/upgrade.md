# アップグレードガイド

現在 1.x をご利用で、2.x への乗り換えをお考えの場合は、まずこのページを最後までお読みになってから、どう進めるかを決めてください。**v1 と v2 のデータには互換性がありません**。プログラムを直接差し替えても古いデータは引き継がれず、操作を誤ると古いデータが「消えた」ように見えることもあります。

:::warning[まず次の三つを覚えてください]
1. v1 と v2 は**互換性がなく**、上書きアップグレードはできません。
2. 強制アップグレードはおすすめしません。まずは価値があるかを見極めてください。
3. 現在可能な方法は、**v1 からデータを書き出し、v2 に取り込む**ことです。より安心なのは、**真っ新しい v2 をインストールして最初からやり直す**ことです。
:::

## 直接アップグレードできない理由

v2 はデータの保存方法と内部構造が再設計されており、v1 のデータベースファイルを v2 で読み込むことはできず、その逆も同様です。これは「アップグレードすれば互換性ができる」という関係ではなく、二つの独立したシステムです。

そのため、次のような方法はすべて**不可**です：

- v1 の `db/`、`data/` ディレクトリをそのまま v2 にマウントして起動する。
- v2 のプログラムファイルで v1 のインストールディレクトリを上書きし、古いデータをそのまま使い続けようとする。
- 同じデータディレクトリでバージョンを繰り返し切り替えて起動し、「運任せ」で試す。

このような操作の結果は、通常 v2 が古いデータを読み取れずに空の状態で再初期化されるか、さまざまなエラーが発生します。動画ファイル自体は失われません（これらはハードディスク上の単なるファイルです）。しかし、整理済みのデータは読み出せなくなります。

## 二つの実行可能なルート

| ルート | 対象者 | おおまかな作業 |
| --- | --- | --- |
| エクスポート → インポート | v1 で大量のデータを整理済みで、項目が多くて再スクレイピングしたくない人 | v1 でバックアップパッケージを書き出し、v2 をインストールしてから読み込む |
| 新規やり直し | データが少ない人、またはバージョン変更を機に整理し直したい人 | v2 を新規インストールし、初期設定をやり直して、プログラムに再認識・再スクレイピングさせる |

### ルート一：エクスポート・インポート

これは現在 v1 のデータを v2 に移せる唯一の方法で、三つの手順に分かれます：

1. **v1 で書き出す**。v1 の「バックアップと復元」ページに進み、映画・俳優・漫画・小説の各種データを個別にバックアップパッケージとして書き出します。画像が必要な場合は「画像ファイルも一緒に書き出す」にチェックを入れます。詳細は[バックアップと復元](./backend/system/backup-restore.md)をご覧ください。
2. **v2 を新規インストールする**。v1 のデータディレクトリは再利用せず、[インストール方法を選ぶ](./getting-started/overview.md)に従って通常どおりインストールし、初回起動時の初期設定を最後まで進めます。
3. **v2 で読み込む**。v2 の「バックアップと復元」ページに進み、手順 1 で書き出したバックアップパッケージを一つずつ取り込みます。

取り込みの前に、以下にご注意ください：

- 取り込みで移されるのは**データ**（テキストと画像）だけです。システム設定、プラグインのキー、ダウンローダーやメディアサーバーの接続設定は移されないため、v2 で改めて設定する必要があります。
- 取り込み後は、スキャンとスクレイピングを一度実行し、ファイル情報やタスク履歴のような移せなかった内容を補うことをおすすめします。
- v1 のバックアップパッケージ形式と v2 の検証ルールは[バックアップと復元](./backend/system/backup-restore.md)ページを基準にしてください。取り込みが拒否された場合は、まず「解析プレビュー」で具体的な原因を確認してください。

### ルート二：新規やり直し（こちらを推奨）

率直に言うと、多くの人にとってこのルートの方が**手間がかかりません**：

- バックアップパッケージの形式、検証ルール、画像パスといった詳細を気にする必要がありません。
- v2 の認識とスクレイピングは v1 より改善されており、新しく実行した方が古いデータを移すより良い結果になるのが一般的です。
- 設定を最初から v2 の方式で行えるため、まず v1 を学んでから v2 を学ぶ必要がありません。

方法は簡単です。v2 を新規インストールし、動画ディレクトリを指定して、プログラムに再スキャン・再認識・再スクレイピングさせます。動画ファイルを触る必要はなく、移すのは「ファイル」ではなく「プログラム」だけです。

v1 のデータ量がどうしても多く、再スクレイピングの負担が大きすぎる場合にのみ、ルート一を検討してください。

## どちらを選んでも、まずバックアップ

アップグレードにはバージョン変更が伴うため、作業前に v1 の `db/` と `data/` を完全にコピーして控えを取ってください。こうすれば、取り込み中に問題が起きても古い環境にいつでも戻って使い続けられ、行き詰まることがありません。

古いインスタンスは **v2 がすべて正常に動くまで**残しておき、その後でアンインストールすることをおすすめします。停止前に「個人情報 → ライセンス」でオンラインライセンスを停止し、枠を新しいインスタンスに譲ることをお忘れください。[ライセンスと透かし](./faq.md#ライセンスと透かし)をご覧ください。

## Docker 以外のインストール：2.0 を入れる前にデータディレクトリを処理する

Docker のデータはマウントディレクトリ内にあるため、イメージを差し替えてコンテナを作り直しても影響はありません。しかし、**インストールパッケージ、バイナリ、NAS アプリパッケージでは事情が異なります**。データディレクトリがプログラムディレクトリのすぐ隣にあり、古いバージョンをアンインストールして新しいバージョンを入れる際に、データディレクトリも一緒に削除される可能性があります。そのため 2.0 をインストールする前に、データディレクトリを**移動またはバックアップ**しておくことをおすすめします：

- 「エクスポート・インポート」ルートの場合：バックアップパッケージがすべてダウンロード済みであることを確認してから、古い環境を触ってください。
- 「新規やり直し」ルートの場合：データが不要でも、`db/` と `data/` をコピーして控えを取ることをおすすめします。気が変わったときに何も残らない事態を避けられます。

Windows インストールパッケージを例にすると、順序は次のとおりです：

1. **サービスを停止する**：トレイアイコンを右クリックし、AMMDS を停止します。
2. **データディレクトリを見つける**：トレイアイコンの右クリックメニューにある「ログを見る」やデータディレクトリの入口から、データディレクトリの場所をたどって確認できます。
3. **データディレクトリを移動する**：プログラムディレクトリの外（別のドライブなど）へまるごとコピーします。これが上記のバックアップにあたります。
4. **古いバージョンをアンインストールする**：OS の通常のアンインストール手順を実行します。
5. **新しいバージョンをインストールする**：2.0 をインストールし、新規インストールと同じように初期設定を進めます。

他のインストーラー（NAS アプリパッケージなど）も基本的に同じです。**まずサービスを停止し、データを外へ移してから、アンインストールします**。アンインストーラーの動作は製品によって異なり、データディレクトリを自動で削除するものもあれば、アンインストール時にデータを保持するか尋ねるものもあります。どちらの場合もアンインストーラーの案内だけに頼らず、事前に手動でデータを移動させるのが最も確実です。
