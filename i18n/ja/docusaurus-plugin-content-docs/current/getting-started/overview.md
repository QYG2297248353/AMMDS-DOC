# インストール方法を選ぶ

AMMDS がお届けしているのは**二つ**だけです。どちらも中身は同じプログラムです。

1. **Docker イメージ** —— 実行環境を整えたコンテナのパッケージです。
2. **バイナリープログラム** —— そのまま実行できるファイルです。

どちらも GraalVM Native Image という技術で作られています。配布する前に、プログラムを単独で動く実行ファイルに変換してあるため、動かすときに**Java を入れる必要はなく、JAR / WAR といったファイルもありません**。手に入るのはプログラムのファイル、またはそれを収めた Docker イメージです。動かすだけで使えます。

> **GraalVM Native Image**：梱包の技術です。プログラムをあらかじめ単独で動く実行ファイルに変換しておくため、受け取った方は実行環境を用意せずに、ダブルクリックやコマンドで起動できます。仕組みを知る必要はありません。覚えておくのは二つだけです。**Java は要らない**、**JAR のファイルは無い**。

> **バイナリープログラム**：実行ファイルとも呼ばれます。Windows ではふつう `.exe` で終わるファイル、Linux では拡張子の無いファイルです。AMMDS の配布パッケージではこのプログラムは `ammds`（Windows では `ammds.exe`）という名前です。実際の名前は、入手した配布パッケージのとおりです。

ですから「どの Java を入れるか」「JAR をどこに置くか」といった案内を探す必要はありません。それは自分でソースを組み立てるときの話であり、AMMDS を導入するときの話ではありません。

まだ決められないなら、まずひとつだけ答えてください。**お使いの機器に Docker はありますか？** あるなら Docker、ないならバイナリープログラムを入手してそのまま動かします。

## 始める前の三つの条件

| 項目 | 説明 |
| --- | --- |
| システム | 64 ビットが必要です。システム診断は 32 ビットを警告として表示し、FFmpeg などの依存プログラムが使えない可能性を知らせます |
| 実行環境 | どちらの形式も、Java や他の実行環境を別に用意する必要はありません。プログラムに含まれています |
| バイナリープログラムは機器に合わせる | 実行ファイルは機器ごとに作られています。Windows 用と Linux 用があり、入手するときに自分の機器を確認してください |
| ネットワーク | 情報の自動補完、資源の検索、通知の送信にはインターネット接続が必要です。身内だけのネットワークでは、手元にある情報しか使えません |

> **Docker**：ソフトを、必要な環境ごとまとめて動かす仕組みです。Docker を一度入れれば、パッケージを取ってくるだけで動き、依存を一つずつ入れる必要はありません。

> **イメージ**：ソフトのパッケージファイルで、「インストールディスク」のようなものです。`qyg2297248353/ammds:latest` のように書き、コロンの後ろがバージョンのタグです。

> **コンテナ**：イメージを実際に動かしている本体です。

## 二つの比較

| 形式 | 動き方 | 向いている人 | 今後の更新 |
| --- | --- | --- | --- |
| Docker イメージ | コンテナの中で画面のサービスと本体が一緒に動き、外にはポートをひとつだけ出します | Docker が入った Linux サーバーや NAS | 新しいイメージを取ってコンテナを作り直します。データは外に出したディレクトリに残ります |
| バイナリープログラム | 実行ファイルをそのまま動かし、画面も受け口もそれが提供します | Docker が無い Windows / Linux の機器、または自分でひとつのプログラムを管理したい方 | 新しい版の実行ファイルに差し替えて再起動します |

### 選び方

| 状況 | おすすめ |
| --- | --- |
| サーバーに Docker が入っている、またはポートやディレクトリや自動起動をまとめて管理したい | Docker。[Docker でインストールする](./docker.md)をご覧ください |
| 機器が FnOS や QNAP で、アプリセンターでの管理に慣れている | NAS のアプリパッケージ。[NAS にインストールする](./nas.md)をご覧ください |
| Windows / Linux に Docker が無く、プログラムをそのまま動かしたい | バイナリープログラム。[Windows / Linux で直接動かす](./native.md)をご覧ください |
| サービスで管理し、ひとつのプログラムを自動起動させたい | バイナリープログラム。[Windows / Linux で直接動かす](./native.md)をご覧ください |

:::note[NAS のアプリパッケージは三つ目のプログラムではありません]
FnOS や QNAP の「アプリパッケージ」は、それらの機器がプログラムを導入して管理してくれる入口にすぎません。中身は上で説明したのと同じプログラムです。二つの形式と競合するものではなく、自分でコマンドを打つ手間が省けるだけです。
:::

## ポート：導入後にどこを開くか

| 形式 | ブラウザーで使うポート | 説明 |
| --- | --- | --- |
| Docker | コンテナ内は `80`。機器側のポートは自分で決めます | `8080:80` と対応付けたら `http://ホストIP:8080` で開きます |
| バイナリープログラム | `8080` | 「アクセスするポート」という設定で変えられます |
| NAS のアプリパッケージ | 導入時に自分で決めたもの | 導入後は `http://NASのIP:ポート` で開きます |

Docker のイメージは内部で `8080` も使いますが、コンテナの中で画面のサービスが中継するだけなので、機器側に対応付ける必要はありません。

:::note[スマホやクライアントに自動で見つけてほしい]
デスクトップのクライアントは、同じネットワークの中で二つの UDP ポート（`47823` が探索、`47824` が同報）を使って AMMDS を見つけます。Docker は TCP しか中継しないため、自動検出にはこの二つの UDP ポートを別に対応付ける必要があります。不要なら、クライアントに住所を手入力しても構いません。
:::

## データのディレクトリ：先に把握してください

どの形式でも、プログラムは**起動した場所**を基準に相対的な場所を読みます。必ず専用のディレクトリを作り、そこで起動してください。

| ディレクトリ | 中身 |
| --- | --- |
| `data/` | 画像、一時保存、字幕、ログ、回復キー、そして自動で取ってくる FFmpeg などの依存プログラム |
| `db/` | データベースのファイルです。作品、タスク、設定など、すべての大切なデータが入ります |
| `download/` | イメージがあらかじめ用意しているディレクトリです。ふつうはダウンローダーの保存先と共用します |
| `data/logs/` | 実行ログです。システム診断と「実行ログ」のページはここを読みます |

:::tip[バックアップの優先順位]
`db/` と `data/` は必ず残す二つです。前者がすべてのデータ、後者に画像と回復キーが入ります。作品のファイルは普段のやり方で構いません。
:::

## 設定項目

導入のときに決めるのはこの程度です。書き間違えたときの影響も確認してください。

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| アクセスするポート（`AMMDS_SERVER_PORT`） | ブラウザーで開くときの番号 | プログラムの既定値（`8080`）になります | 必要 |
| メディアディレクトリの場所 | 作品のファイルをどこから探すか | 探す対象が無くなります。書き間違いだと何も見つからず、「無くなった」ように見えます | 不要、いつでも変更できます |
| データのディレクトリ（`data/`、`db/`） | 画像、ログ、回復キー、データベースの置き場所 | Docker で外に出さないと、コンテナを消したときに一緒に消えます | 必要 |
| 時間帯（`TZ`） | ログの時刻と定時タスクが従う時間帯 | 既定の時間帯になり、タスクの時刻が生活とずれることがあります | 必要 |
| 実行する利用者（`PUID` / `PGID`） | どの利用者として読み書きするか（Docker の場合） | 既定の利用者で動きます。機器側の持ち主と違うと「書き込み失敗」や「権限が無い」が出ます | 必要 |

:::warning[作品をプログラムのディレクトリに入れない]
Docker では、機器側の作品ディレクトリを**同じ場所**としてコンテナに入れてください（例：`/mnt/media:/mnt/media`）。`/ammds` の下には置かないでください。プログラムのデータと混ざり、整理のときに消す恐れがあります。
:::

## 導入したあと

1. ブラウザーで住所を開き、既定の管理者アカウントで入ります。[初回起動：ログインと基本設定](./first-login.md)をご覧ください。
2. ポートやアップロード容量など起動時の設定を変えたいときは、[ポートやアップロード容量を変える](./settings.md)をご覧ください。
3. すぐに結果を見たいときは、[10 分で最初の作品を整理する](./first-library.md)を一通り試してください。

## 困ったときは

- **どれを選べばよいか分からない**：Docker があれば Docker、なければバイナリープログラムを入手してそのまま動かします。選び直しもできます。データのディレクトリを残しておけば大丈夫です。
- **バイナリープログラムをダブルクリックしても動かない、実行できないと出る**：ほかの機器向けの配布パッケージを入手した可能性が高いです（Windows と Linux では共用できません）。Linux では実行の許可も先に与えます。[Windows / Linux で直接動かす](./native.md)をご覧ください。
- **画面が開かない**：開いているポートと対応付けたポートが同じか確認し、ファイアウォールを確認します。初回起動は依存プログラムの取得も待つため、ログが増え続けているか見てください。
- **データが消えた**：起動した場所が変わり、別の場所に `data/` と `db/` が作られた可能性が高いです。元のディレクトリに戻って起動してください。
- **起動してすぐ終わる**：ログに `inotify` や CPU の命令に関する記述がないか見てください。どちらも[よくある質問](../faq.md)に手順があります。
