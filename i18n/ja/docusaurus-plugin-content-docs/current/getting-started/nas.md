# NAS にインストールする

NAS は AMMDS を動かす場所としてよく選ばれます。Docker のほかに、FnOS や QNAP には**アプリパッケージ**があります。NAS のアプリセンターが導入・停止・起動・更新を行うため、コンテナの管理は要りません。

このページでは二つの道のりの選び方、導入の手順、ディレクトリの計画を説明します。Docker の一般的な話は[Docker でインストールする](./docker.md)にあります。アプリパッケージは NAS がプログラムを導入してくれる入口にすぎません。中に入っているのは、同じく GraalVM Native Image で作られた同じプログラムであり、別の版ではありません。

> **NAS**：ファイルを置くためのネットワーク機器です（FnOS や QNAP など）。

> **アプリパッケージ**：NAS 専用の導入ファイルで、NAS のアプリセンターが管理します。

## まず道のりを選ぶ

| 道のり | 特徴 | 向いている人 |
| --- | --- | --- |
| アプリパッケージ | アプリセンターが導入し、案内の中でパスワードとポートを決めます。停止・起動・更新もそこで行います | 手間をかけたくない、NAS が主な利用機器の方 |
| Docker コンテナ | ポート、ディレクトリ、環境変数をすべて自分で決められます。更新はイメージの差し替えです | NAS が Docker に対応しており、コンテナに慣れている方 |

どちらもディレクトリの意味は同じです。`data/` に画像、一時保存、ログ、依存プログラム、`db/` にデータベース、作品のファイルは保存領域に別に置きます。

:::warning[導入ファイルは公式だけ]
導入ファイルは公式の配布ページからのみ取得してください。第三者が作り変えたものには余計な処理が混ざっている可能性があり、また現在の版とディレクトリの構成が違って更新時にデータを失うことがあります。
:::

## FnOS

### 取得

公式の配布ページから最新の導入ファイルを取得します：https://github.com/QYG2297248353/AMMDS-Offline-FnNas/releases

パソコンに保存してから送っても、機器で直接取得しても構いません。

### 導入

1. **アプリセンター**を開き、左下の**手動インストール**から、保存したファイルを選びます。
2. **インストール**を押し、案内に従って進みます。
3. 利用条件を読み、同意します。
4. 導入先を選びます。空きが十分で、**一時的な場所として自動的に消されない**保存領域を選んでください。
5. 管理画面のパスワードを決めます。強いものをおすすめします。
6. アクセスするポートを決め、控えておきます。導入後はそれを使います。
7. 内容を確認し、進み具合が終わるまで待ちます。

### 導入したあと

- `http://NASのIP:導入時に決めたポート` で開きます。
- 作品をスキャンするには、まず NAS 側で AMMDS に作品ディレクトリの読み取り権限を与え、それから AMMDS にディレクトリを追加します。
- 更新はアプリセンターで新しいパッケージを入れます。その前に導入ディレクトリの `db/` と `data/` をバックアップしてください。

## QNAP

### 取得

機器の種類（x86 か ARM）に合う導入ファイルを配布ページから取得します：https://github.com/QYG2297248353/AMMDS-Offline-QNAP/releases

### 導入

1. QNAP の管理画面に入り、**App Center** を開きます。
2. 手動インストール、またはローカルのパッケージ取り込みを選び、保存したファイルを指定します。
3. 案内に従って導入先の領域を選び、アクセスするポートを決めます。
4. 導入後、アプリの一覧から AMMDS を起動します。

Container Station が入っていれば Docker 方式にしても構いません。ディレクトリとポートは一般的な Docker と同じです。

### 導入したあと

- `http://NASのIP:ポート` で開きます。ポートは案内で決めたものです。
- 作品のディレクトリは同じ保存領域に置くと、領域をまたぐことによる権限の問題を避けられます。
- 更新前には同じように `db/` と `data/` をバックアップします。

## ディレクトリの計画

| 場所 | おすすめ |
| --- | --- |
| プログラムとデータのディレクトリ | 主となる保存領域の専用ディレクトリに置きます。システム領域や、自動的に消される一時的な場所は避けます |
| 作品のディレクトリ | 共有フォルダーを別に作り、AMMDS を動かすアカウントに読み取り（または読み書き）を許可します |
| ダウンロードのディレクトリ | ダウンローダーと同じディレクトリを共用し、両者が見る場所を同じにします |
| バックアップ | `db/` と `data/` を、別のディスクや離れた保存先に定期的に写します |

:::tip[どのアプリからも同じ場所に見せる]
NAS でダウンローダーやプレイヤーも動かしているなら、作品のディレクトリを**まったく同じ場所**に見せてください（同じ共有フォルダーの場所を使う等）。こうすると、AMMDS が送ったダウンロードが見つからなくなるのを防げます。
:::

## 設定項目

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| アクセスするポート | ブラウザーで開く番号です。導入の案内で決めます | 開く先が決まりません。忘れたときはアプリセンターの設定で確認できます | 必要 |
| 管理のパスワード | 管理画面に入るためのパスワードです。導入の案内で決めます | 決めないと既定のパスワードのままになり、そのポートに届く人なら誰でも入れます | 不要、ログイン後に変更できます |
| 導入先 | プログラムとデータを置く保存領域 | 空きが無い、または消される領域だと導入に失敗したりデータを失います | 必要（入れ直し） |
| 作品のディレクトリと権限 | どこを探すか、そして読み取れるか | 権限が無いとスキャンできず、「中が空」のように見えます | 不要、権限を直せばすぐ反映されます |
| 自動起動 | NAS を再起動したあと、サービスが自動で立ち上がるか | 設定しないと、再起動のたびに手で起動します | 必要 |

ログイン後に変えられる起動時の設定は、[ポートやアップロード容量を変える](./settings.md)にあります。

## NAS で多い症状

| 症状 | 考えられる原因 | 対応 |
| --- | --- | --- |
| 導入時に空きが足りないと出る | 選んだ保存領域の空きが足りません | 別の領域を選ぶか、空きを増やします |
| 画面は開くのにスキャンできない | アプリのアカウントに共有フォルダーの権限が無い | NAS の共有フォルダーの権限で許可します |
| NAS を再起動したら動いていない | 自動起動が設定されていない | アプリセンターで自動起動を有効にします |
| 更新後にデータが空 | 新しい版が別のディレクトリに入った、または古いディレクトリが残っていない | 更新前の `db/`、`data/` を戻し、導入先を確認します |
| スマホやクライアントが見つけない | NAS のネットワークで同報が止められている、または UDP のポートが許可されていない（Docker の場合） | クライアントに住所を手入力するか、Docker の説明どおり UDP を対応付けます |

## 困ったときは

- **導入できない**：空きが足りないか、機器の種類に合わないファイル（x86 か ARM）を選んでいないか確認します。
- **画面が開かない**：NAS のファイアウォールでそのポートが許可されているか、IP とポートが合っているかを確認します。
- **スキャンできない**：NAS でいちばん多い症状で、ほとんどは共有フォルダーの権限です。先に NAS 側で許可してから試してください。
- **更新後に不調**：まず `db/` と `data/` のバックアップを戻し、導入先が変わっていないか確認します。当てはまる症状が無ければ、[よくある質問](../faq.md)で探してください。
