# 初回起動：ログインと基本設定

導入が終わったら、まず既定の管理者アカウントで管理画面に入り、順に必要なことを行います。既定のパスワードを変える、回復キーを安全な場所に置く、必要ならドメインをひも付けてサイトの情報を入れる、です。全部で十分ほどです。

この順に終えてからスキャンや情報取得を始めると、あとで調べる手間が大きく減ります。

## 既定のアカウント

| 項目 | 既定値 |
| --- | --- |
| ユーザー名 | `ammds` |
| パスワード | `ammds` |

:::warning[ユーザー名は変えられません]
管理者のユーザー名は `ammds` に固定されています。起動時にこれ以外の値が見つかると、プログラムはそのまま終了します。パスワードは**データベースを初めて作るときだけ**指定できます。それ以降は個人情報のページで変更してください。
:::

## ログイン

1. ブラウザーで `http://ホストIP:ポート` を開きます。ポートは導入方法で違います。Docker は対応付けたポート、NAS は導入時に決めたポート、直接動かす場合は既定の `8080` です。
2. セットアップウィザードで作成したアカウント で入ります。
3. 既定では管理画面のワークベンチが開きます。以前に「最初に開くページ」を公開サイト側に変えていると、公開の最初のページが開きます。メニューから管理側に戻してください。

:::note[まず末永く使う住所で一度ログインする]
ログインに成功すると、そのときに開いていた住所が「サービスの住所」として自動的に記録され、ドキュメントや検出などで使われます。そのため、ドメインをひも付ける前に、**これから使い続ける住所で一度ログイン**してください。
:::

## 一、既定のパスワードを変える

1. 右上のアバターを押し、**ユーザーセンター**を選びます。
2. 個人情報のページの上部で**パスワードを変更**を押します。
3. **現在のパスワード**、**新しいパスワード**、**再入力**を順に入力します。
4. **変更を送信**を押します。成功すると自動的にログアウトします。新しいパスワードで入り直してください。

新しいパスワードは次の規則を満たす必要があります。

| 規則 | 説明 |
| --- | --- |
| 長さ | 6〜22 文字 |
| 中身 | 大文字と小文字の両方を含み、さらに数字か記号を含む |

## 二、回復キーを保管する

回復キーは初回起動時に作られ、プログラムのディレクトリの `data/secret/recovery.key` に保存されます。管理者のパスワードを忘れたときは、ログイン画面の**パスワードを忘れた**から回復キーを入力して再設定できます。

> **回復キー**：パスワードを忘れたときに再設定するための、ファイルに保存された鍵です。データベースには依存しません。

:::tip[今のうちにバックアップ]
`db/` だけを残して `data/secret/` を失うと、二度とパスワードを取り戻せません。このファイルはデータベースといっしょに、安全な場所に残してください。
:::

## 三、ドメインをひも付ける（任意）

ドメインで開きたいときは、まずドメインの管理元でドメインをこの機器に向けてから、**システム設定 → 基本設定 → ドメインのひも付け**に進みます。

1. **変更**を押し、ドメインを入力します。
2. 保存すると、表示が「未設定」から「設定済み」に変わります。
3. **システム診断**を開き、「ドメインのひも付け」が通っているか確認します。この項目は、ドメインが本当にこの機器を向いているかを実際に確認します。失敗するときは、設定がまだ有効でない、ポートが開いていない、途中の中継が正しく渡していない、のいずれかです。

身内だけで使うなら、この段は飛ばして IP のままで構いません。ドメインのひも付けは他の機能の前提ではありません。

## 四、サイトの情報を入れる

**システム設定 → サイト設定 → 基本設定**で、サイト名、サブタイトル、説明、会社名を入力します。これらは公開ページの題名、共有の要約、ページ下部に出ます。届出が必要な場合は、同じページに届出番号と確認先も書けます。

「システム設定」の他のタブには、見た目、通知、安全の設定があります。分からない項目は既定のままで構いません。あとからいつでも変えられます。

## 五、ネットワークを設定する（必要なとき）

サーバーから海外サイトが不安定なときは、**システム設定 → ネットワーク設定**に進みます。

1. **プロキシモードを有効にする**を入れます。
2. 方式（HTTP / SOCKS4 / SOCKS5）を選び、ホスト、ポート、認証の情報を入力します。
3. 必要に応じて「除外」の一覧を整え、身内の住所をプロキシから外します。
4. 保存したら、もう一度接続を確認します。

## 六、外部サービスと作品ディレクトリ

基本の設定が終わったら、必要に応じて外部サービスとディレクトリを追加します。

| 順番 | すること |
| --- | --- |
| 1 | 情報源、ダウンローダー、メディアサーバーなどを設定する |
| 2 | 作品のディレクトリを追加し、スキャンタスクを作る |
| 3 | スキャンの結果に対して情報取得を行う |
| 4 | 作品のライブラリを眺めて整理する |

手順は[10 分で最初の作品を整理する](./first-library.md)にまとめています。

## 七、システム診断を一度実行する

右上のアバターを押し、**システム診断**を選んで一度実行します。データベース、ディスク、ポート、機器の時刻、依存プログラム（FFmpeg など）、プロキシ、プラグインの設定を調べ、問題を分野別に出します。

:::tip[システム診断を確認表として使う]
初回の導入で出た黄色や赤の項目は、たいてい対応する設定ページで直せます。すべて通ってから、まとめてのスキャンと情報取得を始めてください。
:::

## 設定項目

| 設定項目 | 何を入力するか | 入力しない、間違えるとどうなるか |
| --- | --- | --- |
| ユーザー名 | `ammds` 固定で、入力は要りません | 他の値にすると起動に失敗します |
| 現在のパスワード / 新しいパスワード / 再入力 | 元のパスワードと、規則を満たす新しいパスワード（6〜22 文字、大文字と小文字を含み、数字か記号を含む） | 二つが一致しない、または規則に合わないと送信できません。元を忘れたら回復キーで再設定します |
| ドメインのひも付け | この機器に向けてあるドメイン | 無ければ IP でしか開けません。設定が有効でないとシステム診断のこの項目が通りません |
| サイト名 / サブタイトル / 説明 / 会社名 | 公開ページの題名、共有の要約、ページ下部に出る文 | 入れないと既定の文になり、機能には影響しません |
| 最初に開くページ | ログイン後に管理側か公開側か | 公開側を選ぶと、ログイン後にメニューから戻る必要があります |
| プロキシモードを有効にする | スイッチと、HTTP / SOCKS4 / SOCKS5 の選択 | 不要なら入りません。住所を間違えると広くつながらなくなります |
| プロキシのホスト / ポート / 認証 | プロキシの住所とポート、必要なら利用者名とパスワード | 間違えるとつながりません。SOCKS は利用者名とパスワードに対応していません |
| 除外の一覧 | プロキシを通さない住所（身内の範囲など） | 無いと身内の機器（NAS、プレイヤー）もプロキシを通り、つながらなくなります |

これらの変更は**ふつう再起動は要りません**。保存するとすぐ反映されます。

## 困ったときは

- **入れない**：ユーザー名が `ammds` か確認します。何度も失敗した、または忘れた場合は、ログイン画面で回復キーを使って再設定します。
- **パスワードの変更が通らない**：上の規則を見直してください。長さ、大文字と小文字、数字か記号の三つです。
- **回復キーが見つからない**：プログラムのディレクトリの `data/secret/` にある `recovery.key` を探します。写しも無く失った場合は、入れ直して整理からやり直すほかありません。
- **ドメインを設定したのに通らない**：設定が有効か、ポートが開いているか、途中の中継が正しいかを確認します。「ドメインのひも付け」の項目が結果を教えてくれます。
- **ログイン後に画面が崩れる**：強制的に読み込み直してください（`Ctrl` + `F5`）。更新後に特によくあります。
