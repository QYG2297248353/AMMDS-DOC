# ポートやアップロード容量を変える

AMMDS には**起動時の設定**があり、画面では変えられないポートやアップロード容量などを決めます。このページでは一つずつ、決めないとどうなるか、再起動が要るかを書いています。

既定のままで動くため、ほとんどの方は**ひとつも変える必要がありません**。ポートの競合、大きなファイルの失敗、ログが足りない、といったことが起きたときに、対応する項目を探しに来てください。

> **環境変数**：起動前にプログラムへ渡す設定です。Docker では設定ファイルの `environment` の欄に、直接動かすときは実行ファイルの起動コマンドの前に書きます。名前を間違えると設定されず、既定値のままになります。

> **ポート**：一台の機器の中でサービスを分けるための番号です。`http://ホストIP:8080` の 8080 がポートです。

## 変え方

三つの場面での書き方です。

| 導入方法 | 変え方 |
| --- | --- |
| Docker / Compose | `environment` の欄に書き、コンテナを作り直します |
| コマンドで直接動かす | 実行ファイルの起動コマンドの前に書きます（例：`AMMDS_SERVER_PORT=9090 ./ammds`、Windows では `ammds.exe`） |
| サービスで管理している | サービスの設定に環境変数を追加し、再起動します |

:::warning[変更後は必ず再起動]
起動時の設定は**起動するときに読まれます**。再起動しないと反映されません。画面のシステム設定で変える項目は保存するとすぐ反映され、ここでは扱いません。
:::

## サービスとネットワーク

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| サーバーのポート（`AMMDS_SERVER_PORT`） | ブラウザーで開くときの番号 | 既定の `8080` になります | 必要 |
| 待ち受ける住所（`AMMDS_SERVER_HOST`） | どの機器からの接続を許すか。既定はすべてです | 既定値になります。自分の機器だけに限定すると、他の機器からはつながりません | 必要 |
| 外に知らせる住所（`AMMDS_SERVICE_ADDRESS`） | プログラムが自分の住所として知らせるもので、受け口のドキュメントや検出に使われます | 既定値になります。ログインに成功したとき、そのときの住所が自動で書き込まれます | 必要 |
| 接続の待ち時間（`AMMDS_CONNECTION_TIMEOUT`） | ひとつの接続が待てる最長の時間（ミリ秒） | 既定値になり、ふつうは変更不要です | 必要 |
| アップロードの一時保存場所（`AMMDS_CACHE_PATH`） | アップロード時に一時的に置く場所 | `data/cache` になります。そのディスクが満杯だとアップロードが失敗します | 必要 |
| ひとつのファイルの上限（`AMMDS_MAX_FILE_SIZE`） | 一度に送れるファイルの大きさ | 既定値になります。大きなファイルが拒否されたら上げます | 必要 |
| 一回の依頼の上限（`AMMDS_MAX_REQUEST_SIZE`） | 一回の依頼（複数のファイルを含むことがあります）の合計 | 既定値になります。上の項目と一緒に上げ、それより小さくしないでください | 必要 |
| ログの詳しさ（`AMMDS_DEBUG`） | ログをどこまで細かく書くか | 既定の段階になります。調べるときだけ `DEBUG` にし、終わったら戻します | 必要 |

:::note[アップロード容量の落とし穴]
Docker のイメージに入っている画面のサービスにも、独自の上限（約 10G）があります。上の二つをそれより大きくしても、先にそちらで断られることがあります。手前に別の中継がある場合も同じです。
:::

## 機能のスイッチ

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| 定時タスクの元スイッチ（`AMMDS_SCHEDULER_ENABLE`） | 時刻で自動的に動くタスクを動かすか | 既定では有効です。切ると手動での実行も拒否されます | 必要 |
| ディレクトリ監視のスイッチ（`AMMDS_MONITOR_ENABLE`） | ファイルが変わったら自動でスキャンするか | 既定では有効です。切ると定時のスキャンだけになります | 必要 |
| 実行のモード（`AMMDS_SYSTEM_MODE`） | 全部 / 管理側だけ / 受け口だけ | 既定は全部です。範囲外の値は無視されます | 必要 |
| 外部への待ち時間（`AMMDS_NETWORK_TIMEOUT`） | 外部サイトを何秒まで待つか | 既定値（一分ほど）です。回線が遅いときは上げます | 必要 |
| 一度に扱う件数（`AMMDS_SCRAPE_LIMIT`） | まとめて情報取得するときの上限 | 既定値になります。多いときは数回に分かれます | 必要 |
| ディスクの警告の基準（`AMMDS_DISK_THRESHOLD`） | 空きがこれを下回ったら知らせる（単位はバイト） | 既定値になります。知らせを遅らせたいときは下げます | 必要 |
| ディスクの警告の割合（`AMMDS_DISK_RATIO`） | 空きの割合がこれを下回ったら知らせる | 既定値になります。上の項目と同時に働きます | 必要 |

## 同じネットワークでの自動検出

デスクトップのクライアントは、この組みの設定で同じネットワークの AMMDS を見つけます。

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| 検出のスイッチ（`AMMDS_DISCOVERY_ENABLED`） | 自動検出を使うか | 既定では有効です。切るとクライアントに手入力が必要です | 必要 |
| 探索のポート（`AMMDS_DISCOVERY_PORT`） | クライアントが探すときの番号。既定は `47823` | 既定の番号です。変えたらファイアウォールと対応付けも直します | 必要 |
| 同報のスイッチ（`AMMDS_DISCOVERY_ANNOUNCE_ENABLED`） | 自分の存在を定期的に知らせるか | 既定では有効です | 必要 |
| 同報のポート（`AMMDS_DISCOVERY_ANNOUNCE_PORT`） | 知らせるときの番号。既定は `47824` | 既定の番号です | 必要 |
| 同報の間隔（`AMMDS_DISCOVERY_ANNOUNCE_INTERVAL_SECONDS`） | 何秒ごとに知らせるか。既定は 15 秒 | 既定の間隔です。0 や負の数は 15 秒になります | 必要 |
| 同報の送り先（`AMMDS_DISCOVERY_ANNOUNCE_TARGETS`） | 誰に知らせるか。複数はカンマで区切ります | 空なら同報の住所と各回線の住所を自動で使います。間違えるとクライアントに届きません | 必要 |

:::note[Docker の方へ]
コンテナの中の画面のサービスは TCP しか扱いません。自動検出を使うには、この二つの UDP ポートを別に対応付ける必要があります。さもないとクライアントは見つけられません。
:::

## 管理者アカウント

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| 管理者のユーザー名（`ADMIN_USER`） | ログインに使う名前。**`ammds` に固定**です | `ammds` になります。**他の値にすると起動に失敗します** | 必要 |
| 管理者の最初のパスワード（`ADMIN_PASS`） | データベースを初めて作るときに使うパスワード | 既定のパスワードになります。すでに管理者がいる場合、これを変えても**効きません**。パスワードは個人情報のページで変えます | 必要（初めてのデータベース作成時のみ有効） |

## 外部サービス

これらに値を入れると、起動のたびに対応するサービスの設定として書き込まれ、そのサービスが有効になります。まとめて導入するときに向きます。一つ二つなら、画面で入力して接続テストをしたほうが分かりやすいです。

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| MetaTube の住所と認証コード（`AMMDS_METATUBE_URL` / `AMMDS_METATUBE_TOKEN`） | 作品情報のサービスの住所と認証コード | 有効になりません。間違えるとつながらず情報が入りません | 必要 |
| Prowlarr の住所とキー（`AMMDS_PROWLARR_URL` / `AMMDS_PROWLARR_TOKEN`） | 資源検索のサービスの住所とキー | 同上 | 必要 |
| IYUU の認証コード（`AMMDS_IYUU_TOKEN`） | 追加の種のサービスの認証コード | 有効になりません | 必要 |
| qBittorrent の住所とアカウント（`AMMDS_QBITTORRENT_URL` / `AMMDS_QBITTORRENT_USERNAME` / `AMMDS_QBITTORRENT_PASSWORD`） | ダウンローダーの住所とログイン情報 | 有効になりません。間違えると送っても何も起きません | 必要 |
| Telegram のロボット（`AMMDS_TELEGRAM_BOT_TOKEN` / `AMMDS_TELEGRAM_CHAT_ID`） | Telegram への通知に使う証明と宛先 | 有効になりません。間違えると届きません | 必要 |

:::tip[画面での変更は上書きされます]
この組みは**起動のたびに書き込まれます**。つまり、同じサービスを画面で変えても、再起動するとこちらの値が勝ちます。上書きされたくなければ、これらの環境変数を削除してください。
:::

## コンテナ専用

Docker で導入したときだけ関係します。

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| 時間帯（`TZ`） | ログの時刻と定時タスクが従う時間帯 | 既定の時間帯になり、時刻がずれることがあります | 必要 |
| 実行する利用者（`PUID` / `PGID`） | どの利用者として読み書きするか | 既定の利用者で動きます。持ち主と違うと「書き込み失敗」や「権限が無い」が出ます | 必要 |
| 作られるファイルの権限（`UMASK`） | 新しく作るファイルの権限 | 既定値になり、ふつうは変更不要です | 必要 |
| コンテナ内の画面のポート（`NGINX_PORT`） | コンテナ内の画面のサービスが待つ番号 | `80` になります。変えたら対応付けも直します | 必要 |
| メモリーの上限（`AMMDS_MAX_HEAP`） | プログラムが使えるメモリーの上限 | コンテナの上限から自動で決まります。負荷が高いと感じたら自分で設定します | 必要 |

## 高度な設定（ふつうは触らない）

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| 解凍ツールの場所（`AMMDS_RAR_TOOL`） | 外部の解凍プログラムの置き場所 | 空なら内蔵のものを優先し、見つからないときだけここを使います | 必要 |
| 開発用のデバッグ（`AMMDS_DEVELOP_DEBUG`） | 一部の実行時チェックを省きます（開発向け） | 既定は無効です。普段使いで有効にすると予期せぬ問題が起きます | 必要 |

## 変更が効いたか確認する

| 確認したいこと | 見る場所 |
| --- | --- |
| いまのポート | ワークベンチの「システム情報」の詳細にある待ち受け住所 |
| バージョンと実行環境 | ワークベンチの「システム情報」 |
| 外部サービスがつながるか | アバターメニュー → **システム診断** のプラグインの項目 |
| プロキシとネットワーク | システム設定 → ネットワーク設定、そしてシステム診断 |
| メモリーの上限が効いているか | 資源のページに出る現在の上限 |

## 困ったときは

- **ポートを変えたのに開かない**：新しい番号で開いているか確認します。他のプログラムが使っていないか、ファイアウォールが許可しているかも確認します。
- **容量を上げたのに送れない**：二つを一緒に上げ、依頼の上限をファイルの上限より小さくしないでください。Docker ではコンテナ内の画面のサービスの上限も確認します。
- **設定がまったく効かない**：まず名前の書き間違いがないか確認します（間違いは黙って無視されます）。そのうえで、再起動またはコンテナの作り直しをしたか確認します。
- **変えたあと起動しない**：その項目を削除して既定に戻し、ひとつずつ足して原因を絞ります。ユーザー名の項目は特に触らないでください。
- **それでも直らない**：[よくある質問](../faq.md)で症状から探すか、バージョンとログを添えて GitHub へご連絡ください：https://github.com/QYG2297248353/AMMDS-Docker/issues/new
