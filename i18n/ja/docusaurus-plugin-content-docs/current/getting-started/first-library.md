# 10 分で最初の作品を整理する

このページは、最初から最後まで通しで進める手順です。「入れたばかりで何も無い」状態から「ライブラリに表紙とあらすじの付いた作品が並ぶ」状態までを目指します。1、2、3 の順に進めてください。各段のあとに**終わったときに見えるもの**を書き、つまずいたときの確認点も添えています。

始める前に[初回起動：ログインと基本設定](./first-login.md)を終え、システム診断を一度実行しておいてください。

## まず準備

必要なものは三つだけです。

| 準備するもの | 説明 |
| --- | --- |
| 作品のファイルが入ったディレクトリ | まずは十本ほどで試してください。いきなり数万ファイルを投げないでください |
| ファイル名から作品番号が分かること | 作品番号は作品を見分ける識別番号です。ファイル名に入っていれば、判別が正確になります |
| 使える情報源 | 情報を補うには情報サイトを調べるため、連携アプリで設定し接続を確認しておきます。完全に身内だけの環境ではできません |

> **スキャン**：指定したディレクトリを一通り見て、どの作品があるかを調べさせることです。

> **情報取得（スクレイピング）**：情報サイトから表紙・あらすじ・出演者・タグを調べて自動で埋めることです。

> **作品番号**：作品を見分けるための識別番号で、ふつうファイル名に含まれます。読めないと情報は埋まりません。

## 一、ファイルの場所を教える

1. スキャンタスクのページを開き、作品ディレクトリを追加する場所を探します。
2. 作品を置いたディレクトリの場所を入力します。Docker の方は**コンテナから見た場所**を入力します。だからこそ、マウントは同じ場所にするのがおすすめです。
3. 保存します。

### 終わったときに見えるもの

ディレクトリが一覧に出て、プログラムが読める状態——保存のときに「場所が無い」や「権限が無い」が出ないことです。

### つまずいたときの確認点

- 場所の書き間違い：階層が一つ多い、少ないだけで読めません。場所を写して見比べてください。
- 権限が無い：NAS でいちばん多いです。NAS の共有フォルダーの権限で AMMDS に許可します（[NAS にインストールする](./nas.md)をご覧ください）。
- Docker で場所が無い：そのディレクトリをコンテナに入れているか確認します。

## 二、一度スキャンして覚えさせる

1. スキャンタスクのページでタスクを作り、さきほど追加したディレクトリを選びます。
2. 整理のモードを選びます。初回は**判別だけで、ファイルは動かさない**モードがおすすめです。すでに整っていて、足りない画像と情報ファイルだけを補いたいときは「不足分の補完」モードを使います。
3. 実行して、終わるまで待ちます。

### 終わったときに見えるもの

タスクが完了になり、判別された作品が一覧に出て、作品番号が正しそうに見えることです。

### つまずいたときの確認点

- タスクが失敗と出る：タスクログでそのタスクを開いてください。失敗の理由と、最後に成功した段階が書かれています。
- 一覧が空：ディレクトリに判別できるファイルが無いか、形式が対象外です。まず確実に判別できるファイルで試してください。
- 途中で進まない：ファイルが多いと時間がかかります。タスクが動いているかを確認し、それからログのエラーを見ます。

## 三、作品番号が合っているか確認する

1. スキャンの結果から何本か選び、プログラムが読み取った番号が自分の思う作品と同じかを見ます。
2. 間違っているものは、まずファイル名を直します（番号を先頭に、区切りをそろえる）。そしてスキャンをやり直します。

### 終わったときに見えるもの

ほとんどの番号が合っていることです。一部が読めないのは普通なので、一度で全部を完璧にする必要はありません。

### つまずいたときの確認点

- 番号の書き方が特殊：ファイル名に読める番号が無い、または珍しい書き方だと読み取れません。よくある書き方に直して再スキャンします。
- 同じ作品が何本も出る：ファイル名の書き方がそろっていないためです。書き方を一つに統一します。

## 四、表紙とあらすじを補う

1. 情報取得のタスクのページでタスクを作り、さきほどのスキャンの結果を選びます。
2. どの情報源を使うか選びます（複数あるなら、まず一つだけで試します）。
3. 実行して待ちます。一度に扱う数に上限があるため、多いときは数回に分けます。

### 終わったときに見えるもの

作品に表紙、あらすじ、出演者、タグが付き始め、空だった項目が埋まることです。

### つまずいたときの確認点

- 成功したのに中身が空：番号が合っていない、またはその情報源に作品がありません。第三段の確認に戻るか、別の情報源で試します。
- いつも失敗し、接続できないと出る：情報源の住所や認証コードが違う、または相手サイトに止められています。プラグイン設定で接続テストをし、システム診断で「異常」か「設定が不完全」かを見ます。
- 一部だけ失敗：よくあることです。失敗した分だけを選び直して実行します。

## 五、ライブラリで結果を見る

作品のメニューを開き、一覧を見ます。表紙とあらすじの付いた作品が並んでいます。詳細を開くと、ポスター、劇中の写真、出演者、タグも見られます。

ここまでで、最初の一批は完了です。続けて次のこともできます（すぐにやらなくても構いません）。

| やりたいこと | 場所 |
| --- | --- |
| シリーズ、レーベル、タグでまとめる | 作品メニューの整理ページ |
| これから自動でスキャン、自動で補う | スキャンタスクの「ディレクトリ監視」を入れる、または定時のスキャンを足す |
| テレビでポスター一覧を見る | 連携アプリでメディアサーバーをつなぐ |
| 新しい資源を見張り続ける | 購読のページで設定する |

## 六、これからは自動で動かす

1. スキャンタスクの**ディレクトリ監視**を入れます。ファイルが変わると自動でスキャンします。
2. または定時のスキャンタスクを作ります（毎日一度など）。
3. 定時タスクの元スイッチが入っているか確認します。切れていると手動の実行も拒否されます。

## 設定項目

| 設定項目 | 何を入力するか | 入力しない、間違えるとどうなるか |
| --- | --- | --- |
| 作品ディレクトリの場所 | 作品のファイルがあるディレクトリ | 書き間違いや権限不足でスキャンできません。Docker ではコンテナ内の場所を使います |
| 整理のモード | 初回は「判別だけで動かさない」。整ったディレクトリなら「不足分の補完」 | 移動や改名をするモードでは、ファイルの場所が変わります。使う前に考えましょう |
| ディレクトリ監視のスイッチ | ファイルが変わったら自動でスキャンするか | 切ると定時か手動だけになります |
| 定時タスクの時刻 | どのくらいごとに動かすか | 間違えてもエラーにはならず、動く時刻がずれるだけです |
| 情報源 | どのサイトを調べるか、その住所と認証コード | 設定が無い、または間違いだと情報が入りません。先にプラグインで接続テストをします |
| 一度に扱う件数の上限 | 一回で何件処理するか | 決めないと既定値です。多いときは数回に分かれます |

## 困ったときは

- **スキャンの結果がまったく空**：たいていは場所か権限です。第一段の確認点に戻ってください。
- **情報取得がいつも失敗**：その情報サイトに届くか確認します。システム診断のネットワークの項目で分かります。
- **表紙はあるのにあらすじが無い（または逆）**：その情報源のデータが欠けています。別の情報源で補ってください。
- **ログにエラーが無いのにタスクが失敗**：タスクログでそのタスクの「詳細」を開き、失敗の理由と最後に成功した段階を確認します。
- **どれも当てはまらない**：[よくある質問](../faq.md)で症状から探すか、バージョン、時刻、ログを添えて GitHub へご連絡ください：https://github.com/QYG2297248353/AMMDS-Docker/issues/new
