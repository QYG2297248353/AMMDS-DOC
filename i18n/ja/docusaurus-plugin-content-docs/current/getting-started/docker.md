# Docker でインストールする

これがいちばんよく使われる導入方法です。コンテナの中で画面のサービスと本体が一緒に動き、画面も受け口も同じポートから提供されます。このページでは、そのまま使える二つのコマンドと、ディレクトリと権限の決め方を説明します。

コンテナの中で動いているのは、配布パッケージに入っている GraalVM Native Image のバイナリープログラムそのものです。そのためコンテナに Java を入れる必要はなく、JAR / WAR を用意する必要もありません。

始める前に確認してください。Docker が入っていること、そして作品のファイルがどのディレクトリにあるか分かっていることです。まだ方法を決めていない場合は、[インストール方法を選ぶ](./overview.md)をご覧ください。

> **イメージ**：ソフトのパッケージファイルで、「インストールディスク」のようなものです。`qyg2297248353/ammds:latest` のように書き、コロンの後ろがバージョンのタグです。

> **コンテナ**：イメージを実際に動かしている本体です。

> **マウント**：機器上の実際のディレクトリをコンテナ内の場所につないで、読み書きできるようにすることです。「ホスト側:コンテナ側」と書きます。

## どのイメージを選ぶか

| イメージ | 説明 |
| --- | --- |
| `qyg2297248353/ammds:latest` | 最新バージョンです。まずはこれがおすすめです |
| `qyg2297248353/ammds:バージョン` | 特定のバージョンで固定します。更新の時期を自分で決めたいときに向きます |
| `qyg2297248353/ammds:latest-ol8` | 古いシステム向けの別版です。標準のイメージが動かない古い機器で使います |
| `ghcr.io/qyg2297248353/ammds:latest` | 別の配布元です。取得がうまくいかないときに替えてみてください |

イメージは 64 ビットの x86 と ARM の両方が用意されており、取得時に自動で合うものが選ばれます。

## コマンドひとつで動かす

```bash title="docker run"
docker run -d \
  --name AMMDS \
  -p 8080:80 \
  -v /opt/ammds/data:/ammds/data \
  -v /opt/ammds/db:/ammds/db \
  -v /opt/ammds/download:/ammds/download \
  -v /mnt/media:/mnt/media \
  -e TZ=Asia/Shanghai \
  -e PUID=1000 \
  -e PGID=1000 \
  --restart always \
  qyg2297248353/ammds:latest
```

起動したら `http://ホストIP:8080` で開きます。8080 が他のプログラムに使われているときは、コロンの左側だけを変えてください（例：`8090:80`）。

## 構成ファイルを使う（長く使うならおすすめ）

下を `docker-compose.yml` として、データを置きたいディレクトリに保存してください。

```yaml title="docker-compose.yml"
services:
  ammds:
    image: qyg2297248353/ammds:latest
    container_name: AMMDS
    ports:
      - "8080:80"          # 画面と受け口
      - "47823:47823/udp"  # 同じネットワークでの検出（任意）
      - "47824:47824/udp"  # 同じネットワークでの同報（任意）
    volumes:
      - ./data:/ammds/data
      - ./db:/ammds/db
      - ./download:/ammds/download
      - /mnt/media:/mnt/media
    environment:
      TZ: Asia/Shanghai
      PUID: "1000"
      PGID: "1000"
      UMASK: "022"
    restart: always
```

そして次を実行します。

```bash
docker compose up -d
```

:::note[二つの UDP ポートは必要ですか]
画面のサービスは TCP しか中継しません。スマホやクライアントに自動で見つけてほしくなければ、この二行を消して構いません。クライアントには住所を手入力します。
:::

## ポートの中身

| ポート | 使いみち | 外に対応付けるか |
| --- | --- | --- |
| `80` | コンテナ内の画面のサービスです。画面と受け口を提供します | 必要。外側の番号は自由です |
| `8080` | コンテナ内の本体です。コンテナの中から中継されるだけです | 不要 |
| `47823/udp` | クライアントがサービスを探すためのものです | 自動検出が要るときだけ |
| `47824/udp` | サービスが自分の存在を知らせるものです | 自動検出が要るときだけ |

## ディレクトリのつなぎ方

| コンテナ内の場所 | 中身 | おすすめ |
| --- | --- | --- |
| `/ammds/data` | 画像、一時保存、字幕、ログ、依存プログラム、回復キー | 必ず外に出して残す |
| `/ammds/db` | データベースのファイル | 必ず外に出し、バックアップに入れる |
| `/ammds/download` | ダウンロード用のディレクトリです。ふつうはダウンローダーと共用します | 外に出すのがおすすめ |
| 作品のディレクトリ | スキャンして整理する対象です | 機器側とコンテナ側で場所を同じにする |

:::warning[作品を /ammds に入れない]
`/ammds` はプログラムとデータの基準となるディレクトリです。作品は別にしてください（例：`/mnt/media:/mnt/media`）。さもないと、整理やコンテナの作り直しのときに一緒に消す恐れがあります。
:::

## 権限：「書き込み失敗」が出たらここ

コンテナは既定では最も権限の高い利用者で動きます。`PUID` と `PGID` に 0 以外を設定すると、起動時の処理がその利用者に切り替え、`UMASK`（既定は `022`）で作られるファイルの権限が決まります。

外に出したディレクトリで「書き込み失敗」や「権限が無い」が出るときは、まず `PUID` / `PGID` を、そのディレクトリの持ち主に合わせてください。

## 起動したかどうかの確認

```bash
docker logs -f AMMDS
```

ログに「サービスが起動しました」と出れば、画面のサービスと本体の両方が準備できています。画面に「起動中です。しばらくお待ちください」と出るときは、画面側は動いていますが本体が準備中です。少し待って読み込み直してください。

:::tip[初回の起動は少し時間がかかります]
初回の起動では FFmpeg などの依存プログラムを自動で取得します。時間は回線次第です。準備できたかは、アバターメニューの**システム診断**で項目ごとに確認できます。
:::

## 設定項目

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| アクセスするポート（機器側。コンテナ内は `NGINX_PORT`） | ブラウザーで開くときの番号 | コンテナ内の既定値になります。対応付けが無いと開けません | 必要（コンテナの作り直し） |
| 時間帯（`TZ`） | ログの時刻と定時タスクが従う時間帯 | 既定の時間帯になり、時刻がずれることがあります | 必要 |
| 実行する利用者（`PUID` / `PGID`） | どの利用者として読み書きするか | 既定の利用者で動きます。持ち主と違うと権限のエラーが出ます | 必要 |
| 作られるファイルの権限（`UMASK`） | 新しく作るファイルの権限 | 既定値になり、ふつうは変更不要です | 必要 |
| アップロード容量（`AMMDS_MAX_FILE_SIZE` / `AMMDS_MAX_REQUEST_SIZE`） | ひとつのファイル、一回の依頼の上限 | 既定値になります。大きなファイルが拒否されたら上げます | 必要 |
| 自動検出のスイッチとポート（`AMMDS_DISCOVERY_ENABLED` / `AMMDS_DISCOVERY_PORT` / `AMMDS_DISCOVERY_ANNOUNCE_ENABLED` / `AMMDS_DISCOVERY_ANNOUNCE_PORT`） | クライアントに自動で見つけてもらうか、どの二つの UDP ポートを使うか | 既定では有効です。UDP を対応付けないと見つからず、手入力になります | 必要 |
| メモリーの上限（`AMMDS_MAX_HEAP`） | プログラムが使えるメモリーの上限 | コンテナの上限から自動で決まります。負荷が高いと感じたら自分で設定します | 必要 |

起動時の設定はほかにもあります。[ポートやアップロード容量を変える](./settings.md)をご覧ください。

## 更新の手順

1. 外に出した `db/` と `data/` をバックアップします。
2. 新しいイメージを取ります：`docker compose pull`（または `docker pull qyg2297248353/ammds:latest`）。
3. コンテナを作り直します：`docker compose up -d`（または古いコンテナを消して `docker run` し直します）。
4. 画面でバージョンと「システム診断」の結果を確認します。

データは外に出したディレクトリにあるため、作り直しても消えません。ただし大きな版をまたぐ更新では、データベースの写しを残しておくことをおすすめします。

## 困ったときは

| 症状 | 考えられる原因 | 対応 |
| --- | --- | --- |
| 起動してすぐ終わる | 機器の種類とイメージが合っていない、またはディレクトリに書き込み権限が無い | `docker logs AMMDS` で内容を確認します。ARM の機器では arm64 のイメージか確認します |
| 画面が 502、または「起動中」と出る | 本体がまだ準備中です | 少し待ってログを確認し、ポートの競合やデータベースの破損がないか見ます |
| 作品のディレクトリに書き込めない | コンテナ内の利用者と機器側の持ち主が違う | `PUID` / `PGID` を合わせるか、ディレクトリの権限を直します |
| クライアントが見つけない | TCP のポートしか対応付けていない | 二つの UDP を追加するか、クライアントに住所を手入力します |

- **どれも当てはまらない**：まず `docker logs AMMDS` を見て、それから[よくある質問](../faq.md)で症状から探してください。
- **設定が効いたか確認したい**：ポートとバージョンはワークベンチの「システム情報」に、外部サービスの状態はアバターメニューの**システム診断**に出ています。
