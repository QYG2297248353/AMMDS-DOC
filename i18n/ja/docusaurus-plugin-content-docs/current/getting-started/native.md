# Windows / Linux で直接動かす

Docker が無い、または自分でプログラムを管理したい場合はこの方法です。配布パッケージに入っている実行ファイルを動かすだけで、画面も受け口もそれが提供し、既定では `8080` を使います。

始める前に必要なのはひとつだけです。**お使いの機器に対応する配布パッケージを入手してください**。Java を入れる必要も、他の実行環境を用意する必要もありません。まだ方法を決めていない場合は、[インストール方法を選ぶ](./overview.md)をご覧ください。

> **バイナリープログラム**：実行ファイルとも呼ばれます。Windows では `.exe` で終わるファイル、Linux では拡張子の無いファイルです。AMMDS は GraalVM Native Image という技術で、配布前にプログラムをこのファイルに変換しています。そのため動かすときに Java は要らず、JAR / WAR といったファイルの管理も不要です。

## 動作環境

| 項目 | 条件 |
| --- | --- |
| システム | 64 ビットの Windows または 64 ビットの Linux です。実行ファイルは機器ごとに作られているため、自分の機器に合うものを選んでください |
| 実行環境 | Java も、他の実行環境も必要ありません |
| ディスク | 作品のファイルとは別に、`data/` と `db/` の分が必要です。初回起動では依存プログラムも取得します |
| ネットワーク | 情報の自動補完や資源の検索にはインターネット接続が必要です |

## プログラムのファイルを用意する

公式の配布ページから、お使いの機器に対応する配布パッケージを入手して展開してください。中に入っているのは実行ファイルひとつです。Linux ではふつう `ammds`、Windows では `ammds.exe` という名前で、ファイル名に含まれるバージョンは配布版と一致します。実際の名前は、入手した配布パッケージのとおりです。

:::note[Windows にはインストーラーもあります]
公式から Windows 向けのオフラインインストーラーも配布されています。案内に従って導入したい方、自動起動させたい方は配布ページをご覧ください：https://github.com/QYG2297248353/AMMDS-Launcher/releases
:::

## Windows で動かす

1. 実行ファイルを固定のディレクトリに置きます（例：`C:\AMMDS\`）。
2. PowerShell かコマンドプロンプトを開き、**そのディレクトリに移動します**。
3. 起動します。

```powershell
cd C:\AMMDS
.\ammds.exe
```

4. ブラウザーで `http://127.0.0.1:8080` を開きます。

窓を閉じると止まります。長く動かすには、このコマンドをバッチファイルに書き、タスクスケジューラで起動時に実行させます。お好きな常駐管理の道具に任せても構いません。

## Linux で動かす

```bash
mkdir -p /opt/ammds
cd /opt/ammds
chmod +x ./ammds
./ammds
```

:::note[「権限が足りない」と出るとき]
Linux では、入手したばかりのファイルに実行の許可が無いことがあります。先に `chmod +x ./ammds` を一度実行してから起動してください。
:::

機器の起動と一緒に動かしたいときは、サービスに任せます。次は参考の設定です。

```ini title="/etc/systemd/system/ammds.service"
[Unit]
Description=AMMDS
After=network-online.target

[Service]
WorkingDirectory=/opt/ammds
ExecStart=/opt/ammds/ammds
Restart=on-failure
User=ammds

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now ammds
journalctl -u ammds -f
```

:::note[この設定の利用者について]
`User=ammds` は、その名前のアカウントが機器にあることを前提にしています。無ければ実際に動かすアカウントに変えるか、アカウントを作って `/opt/ammds` の持ち主を変更してください。
:::

## 作業ディレクトリとデータの場所

AMMDS は**起動した場所**を基準に `data/` や `db/` を読みます。必ずプログラムのディレクトリに移動してから起動してください。サービスに任せるときは作業ディレクトリを設定します。

| 場所 | 中身 |
| --- | --- |
| `data/` | 画像、一時保存、字幕、ログ、回復キー、そして自動で取ってくる FFmpeg などの依存プログラム |
| `data/logs/` | 実行ログです。日ごとに新しいファイルに移り、別にエラーだけのファイルもあります |
| `db/` | データベースのファイルです。作品、タスク、設定が入ります |
| `download/` | ダウンロード先として使えるディレクトリです。ダウンローダーと共用するなら場所を同じにします |

:::warning[一時的なディレクトリで起動しない]
ファイルを一時ディレクトリやダウンロードのディレクトリに置いてそのまま開くと、作業場所が意図せぬ場所になり、データが散らばります。専用のディレクトリを作り、そこで起動してください。
:::

## 初回起動で依存プログラムを取得します

起動後、FFmpeg などを必要に応じて自動で取得し、`data/` の下の対応するディレクトリに置きます。初回のログに進み具合が出ます。回線が遅いときは気長にお待ちください。準備できたかは、アバターメニューの**システム診断**で項目ごとに確認できます。

## 設定項目

これらは起動前に環境変数で指定します。変更したら**必ず再起動**が必要です。

| 設定項目 | 何を決めるものか | 決めないとどうなるか | 再起動は必要か |
| --- | --- | --- | --- |
| アクセスするポート（`AMMDS_SERVER_PORT`） | ブラウザーで開くときの番号 | 既定の `8080` になります | 必要 |
| 待ち受ける住所（`AMMDS_SERVER_HOST`） | どの機器からの接続を許すか。既定はすべてです | 既定値になります。自分の機器だけに限定すると、他の機器からはつながりません | 必要 |
| アップロード容量（`AMMDS_MAX_FILE_SIZE` / `AMMDS_MAX_REQUEST_SIZE`） | ひとつのファイル、一回の依頼の上限 | 既定値になります。大きなファイルが失敗したら、二つを一緒に上げます | 必要 |
| 一時保存のディレクトリ（`AMMDS_CACHE_PATH`） | アップロード時に一時的に置く場所 | `data/cache` になります。そのディスクが満杯だとアップロードが失敗します | 必要 |
| ログの詳しさ（`AMMDS_DEBUG`） | ログをどこまで細かく書くか | 既定の段階になります。調べるときだけ最も詳しくできます | 必要 |
| 自動検出のスイッチとポート（`AMMDS_DISCOVERY_ENABLED` / `AMMDS_DISCOVERY_PORT` / `AMMDS_DISCOVERY_ANNOUNCE_ENABLED` / `AMMDS_DISCOVERY_ANNOUNCE_PORT`） | クライアントに自動で見つけてもらうか、どの二つの UDP ポートを使うか | 既定では有効です。切るとクライアントに手入力が必要です | 必要 |
| 定時タスクの元スイッチ（`AMMDS_SCHEDULER_ENABLE`） | 時刻で自動的に動くタスクを動かすか | 既定では有効です。切ると手動での実行も拒否されます | 必要 |
| ディレクトリ監視のスイッチ（`AMMDS_MONITOR_ENABLE`） | ファイルが変わったら自動でスキャンするか | 既定では有効です。切ると定時のスキャンだけになります | 必要 |
| メモリーの上限（`-Xmx`、Docker では `AMMDS_MAX_HEAP`） | プログラムが使えるメモリーの上限 | プログラムの既定値になります。負荷が高いと感じたら自分で設定します | 必要 |

ポートを変える書き方です。

```bash
# Linux
AMMDS_SERVER_PORT=9090 ./ammds

# Windows PowerShell
$env:AMMDS_SERVER_PORT = "9090"
.\ammds.exe
```

:::tip[メモリーの使用量が多く見えるとき]
バイナリープログラムは、機器のメモリーに応じて上限を確保します。そのためスキャンや情報取得のあと、使用量が高いまま残ることがあります。`./ammds -Xmx2g` のように上限を自分で決め、Linux では環境変数 `MALLOC_ARENA_MAX=2` と併用すると、はっきり下がります。設定した値は資源のページで確認できます。
:::

起動時の設定の一覧は[ポートやアップロード容量を変える](./settings.md)にあります。

## 更新の手順

1. プログラムを止めます（サービスなら `systemctl stop ammds`、またはコンソールの窓を閉じます）。
2. `db/` と `data/` をバックアップします。
3. 古いファイルを新しい版の実行ファイルに差し替えます。
4. 起動し直し、画面のバージョンと「システム診断」の結果を確認します。

データベースの形は自動で更新されるため、普段の更新で手作業は要りません。ただし大きな版をまたぐときは、更新前の写しを残しておくことをおすすめします。

## 困ったときは

- **ダブルクリックしても動かない、実行できるプログラムでないと出る**：ほかの機器向けの配布パッケージを入手した可能性が高いです（Windows と Linux では共用できません）。自分の機器に合うものを取り直してください。Linux では `chmod +x ./ammds` を実行したかも確認します。
- **起動してすぐ CPU の命令に対応していないと出る**：入手したパッケージが機器に合っているか確認してください。古い機器なら古い CPU 向けの配布パッケージに替えるか、`ol8` の付いた Docker イメージをお使いください。
- **画面が開かない**：プログラムが動いているか、ポートが他のプログラムに使われていないか、ファイアウォールが許可しているかを確認します。初回は依存プログラムの取得も待ちます。
- **起動するが動きがおかしい**：`data/logs/` の実行ログを見て、システム診断を一度実行してください。
- **データが消えた**：起動した場所が変わり、別の場所にデータが作られた可能性が高いです。元のディレクトリに戻って起動してください。
- **それでも直らない**：[よくある質問](../faq.md)で症状から探してください。
