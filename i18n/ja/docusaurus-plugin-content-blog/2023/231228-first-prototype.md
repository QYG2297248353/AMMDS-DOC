2023 年の最後の週、AMMDS の初めて稼働するプロトタイプが生まれました。今の目から見ればあまりに粗末で、人に話すのも少し気恥ずかしいほどですが、まさにこのプロトタイプが、最も重要な一つのことを確認させてくれました。この道は通れる、ということです。

## プロトタイプができたのは三つのことだけ

当時の AMMDS にはインターフェースも、プラグインマーケットも、今のような派手な機能もありませんでした。できるのは三つのことだけです：

1. 単一のサイトからトレントの一覧を取得する；
2. トレントに含まれるメタデータを解析する；
3. 最低限の NFO ファイルを生成する。

たったこれだけです。しかし、一連の流れを最初から最後まで通しました——「ハードディスクの中の名前のめちゃくちゃなファイル」から、「メディアサーバーが認識できる一件のレコード」まで。

## なぜ最初に最も単純な一本の線を作ったのか

プロトタイプの段階で、私たちは「全部の機能を作りたい」という衝動をあえて抑えました。理由は現実的です：

- **中核の仮説を検証する**：サイトからのデータ取得、解析、NFO 書き出しという最も基本的な流れすら通らなければ、その後の壮大な計画はすべて空中楼閣です。
- **未知の問題をできるだけ早く露出させる**：サイトのページ構造、メタデータのフィールド、NFO 形式の細部といった、実際にコードを書いて初めて浮かび上がる問題は、早い段階でぶつかるほどよいものです。
- **アーキテクチャの検証場とする**：プラグイン化エンジン、パイプライン型のデータ処理、仮想スレッドによるスケジューリング——後に採用し続けたこれらの設計は、最初このプロトタイプの中で生み出されたものです。

## 書き直されたコード

今日振り返れば、プロトタイプのコードの多くはすでに何度も書き直されています：

| プロトタイプの段階 | 現在のやり方 |
| :--- | :--- |
| 単一サイトの解析をハードコード | 差し替え可能なサイトアダプター |
| 一度きりの処理フロー | パイプライン型のデータ処理 |
| 同期・順次実行 | 仮想スレッドによるスケジューリング |
| 固定の NFO テンプレート | 複数形式への自動対応 |

コードは入れ替わりましたが、**アーキテクチャの方向性は変わっていません**。これがプロトタイプが私たちに残してくれた最も価値あるものです。より多くのリソースを投じる前に、技術選定の正しさを確認させてくれました。

## 初めて通った瞬間の気持ち

プロトタイプが初めて完全に動いた日の夜、私たちは画面に生成されたその NFO ファイルを長いこと見つめていました。完璧ではなく、フィールドの欠落もあり、レイアウトが美しいとは言えません。しかし、それは自分たちが書いたプログラムが、ごちゃまぜのデータの中から一本の作品を見つけ出し、構造を持つ情報に整理してくれたものでした。

その瞬間、私たちは確信しました。このことは続ける価値がある、と。

その後に起きたすべてのこと——2024 年のアーキテクチャの熟成から、2025 年の v1.0.0 リリースまで——は、この目立たないプロトタイプから始まりました。
