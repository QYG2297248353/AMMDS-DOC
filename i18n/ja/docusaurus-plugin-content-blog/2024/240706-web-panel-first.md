AMMDS のメインインターフェースの形を決める際、私たちは真剣な議論を行いました。デスクトップクライアントにするか、Web パネルにするか。最終的に Web パネルが勝ちました。この記事では、当時の判断を振り返ります。

{/* truncate */}

## 避けて通れない前提：それはあなた自身の機器の上で動く

セルフホストソフトウェアには、SaaS とはまったく異なる利用シナリオがあります。プログラムは常時稼働している機器——自宅の NAS かもしれませんし、ミニ PC や古いコンピューターかもしれません——にインストールされます。あなたは必ずしもその前に座っているわけではありませんが、いつでも管理できる必要があります。

デスクトップクライアントにすれば、その機器の前に出向くか、リモートデスクトップを設定する必要があります。一方、Web パネルはこの問題を自然に解決します。ブラウザからその機器にアクセスできさえすれば、メディアライブラリを管理できるのです。

## どこにいても管理できる体験

Web 優先がもたらす最も直接的な利点は、デバイスに依存しないことです：

- **PC**：パソコンの前に座り、フル機能のパネルで一括整理；
- **タブレット／スマートフォン**：ソファに横になりながら、メタデータを一条補完したり、タスクの進捗を確認したり；
- **NAS**：NAS の管理画面のブラウザでそのまま開け、追加のクライアントインストールは不要。

AMMDS を NAS にインストールしている多くのユーザーにとって、「ブラウザを開けば使える」ことは、導入の敷居を越えられるかどうかのほぼ鍵となります。

## モバイルファーストはスローガンではない

私たちが言う「モバイルファースト」とは、デスクトップの画面を小さくすることではなく、最初から小さな画面でもレイアウトが成り立つようにすることです：

- よく使う操作を親指の届く位置に置く；
- 表は小さな画面では自動的にカード形式のレイアウトへ切り替わる；
- 重要な状態（タスクの進捗、スキャン結果）がひと目で分かる。

これらの細部は今では当たり前に見えますが、2024 年に設計上の判断を下した当時は、実際に数週間をかけて磨き込んだ箇所です。

## ローカルでの体験を捨てたわけではない

念のため申し添えると、Web 優先は「Web だけ」を意味するわけではありません。その後私たちは Windows ネイティブクライアント（Launcher）もリリースしました。「アドレスを覚えたくない、ワンクリックで開きたい」という場面に対応するためです。しかし、その本質は Web パネルの殻にすぎません——実際のインターフェースとロジックは、相変わらず同じ Web アプリケーションです。

この選択により保守コストは管理可能な範囲に保たれています。デスクトップ版と Web 版を別々に保守するのではなく、一つのインターフェースだけを保守すればよいからです。
