メディアサーバーを使ったことがあれば、おそらく「再生にトランスコードが必要です」という通知を見たことがあるでしょう。トランスコードはメディアライブラリの中で最もリソースを食う部分であり、その背後にあるエンジンが FFmpeg です。本稿では、トランスコードとは何か、そしてなぜハードウェアアクセラレーションに注目する価値があるのかを明確にします。

## まず区別する：トランスコード vs リマックス

多くの人がこの二つを混同しています：

- **リマックス（remux）**：動画ストリームをあるコンテナから別のコンテナへ移すだけ（たとえば MKV から MP4 へ）で、データ自体は再エンコードされず、ほぼ瞬時に完了し、画質も劣化しません；
- **トランスコード（transcode）**：文字どおり動画を再エンコードします。たとえば 4K の高ビットレートをスマートフォンで滑らかに再生できる形式に圧縮します。このステップが最も CPU を消費し、画質の劣化も最も起こりやすいものです。

メディアサーバーがトランスコードを行うのは、クライアントの能力が千差万別だからです。テレビがハードウェアデコードできる形式でも、スマートフォンのブラウザが対応しているとは限りません。そのためサーバーは、その場で対応した版を一時的に作るほかありません。

## ソフトウェアエンコードとハードウェアエンコード

FFmpeg は既定でソフトウェアエンコーダー（たとえば `libx264`）を使い、すべて CPU で計算します。品質は最良ですが、サーバーにとっては遅い方法です——同時に多数のトランスコードを実行すると、CPU がすぐにボトルネックになります。

ハードウェアエンコードはこの作業を、グラフィックカードや内蔵 GPU の専用回路に任せるため、はるかに高速です。一般的なものをいくつか挙げます：

| 方式 | 対応ハードウェア | FFmpeg エンコーダー |
| :--- | :--- | :--- |
| NVENC | NVIDIA グラフィックカード | `h264_nvenc` / `hevc_nvenc` |
| QSV | Intel 内蔵 GPU | `h264_qsv` / `hevc_qsv` |
| VAAPI | Linux の汎用インターフェース | ドライバーによる |
| AMF | AMD グラフィックカード | `h264_amf` |

どれを使うかはハードウェア次第です。`ffmpeg -hwaccels` で利用可能なアクセラレーション方式を一覧でき、`ffmpeg -encoders` で対応するエンコーダーを確認できます。典型的なハードウェアトランスコードのコマンドは次のようなものです：

```bash
ffmpeg -i input.mkv -c:v h264_nvenc -preset p4 -c:a aac output.mp4
```

## 知っておくべきトレードオフ

ハードウェアエンコードが追求するのは**速度**であり、極限の圧縮率ではありません。同じ画質では、より高いビットレートを必要とすることが多く——ファイルは少し大きくなりますが、その代わり処理速度がはるかに速くなります。これは十分に割に合う取引です。トランスコードの場面で求められるのは「今すぐ再生できること」であり、「最後の 10% の容量を節約すること」ではありません。

一括処理では、この差はさらに明確になります。ソフトウェアエンコードなら数時間かかるところ、ハードウェアエンコードなら数十分で完了します。

## FFmpeg のバージョンのリズム

特筆すべきは、FFmpeg がバージョン 6.0（コードネーム "Von Neumann"、2023 年 2 月リリース）から、**毎年ひとつのメジャーバージョン**というリズムを確立し、メジャーバージョンごとに ABI を上げ、三つ以上のバージョンにわたって非推奨となった API を削除していることです。6.0 では QSV と NVENC の AV1 エンコード対応も追加されました。一般ユーザーにとっては、新機能がより規則的にやってくることを意味しますが、アップグレード時には ABI の変化に注意する必要があることも思い起こさせてくれます。

## AMMDS との関係

AMMDS は内蔵の FFmpeg ツールチェーンを通じてメディアファイルを処理します——動画の前処理でも、関連する自動化フローでも、基盤としてそれに依存しています。ソフトウェアエンコードとハードウェアエンコードの違いを理解すれば、サーバーにどんなハードウェアを備えるべきか判断できます。整理と軽い負荷だけなら CPU で十分ですし、多数の同時トランスコードを実行するなら、NVENC 対応のグラフィックカードや QSV 対応の内蔵 GPU があれば格段に楽になります。

> 注：本稿のコマンドとパラメータは FFmpeg の公式ドキュメントに基づいてまとめたものです。実際に利用できるかどうかは、お使いの FFmpeg のビルドとハードウェアドライバーに依存します。
