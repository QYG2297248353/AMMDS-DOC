# リクエストとレスポンスの読み方

オープン API のインターフェースは、すべて同じ決まりに従います。先にこのページを読んでおくと、あとでの読み違えや判断違いのほとんどを避けられます。

## まず言葉を整理します

> **リクエスト**：プログラムが AMMDS に送る「これが欲しい」という問いかけです。

> **レスポンス**：AMMDS が返してくる中身のかたまりです。

> **JSON**：その中身の書式で、「項目名」と「値」の組み合わせです。例：`{"code": 200, "data": true}`。

> **ヘッダー**：本文とは別に、リクエストといっしょに送る小さな付加情報です。鍵や形式を伝えるのに使います。

> **ステータスコード**：答えの中の `code` という項目です。数字で、うまくいったか、そうでなければ何が原因かが分かります。

> **ページ送り（ページネーション）**：データが多いときに、ページ番号と 1 ページの件数で少しずつ渡すしくみです。

## 基本情報

| 項目 | 内容 |
| --- | --- |
| 住所 | `http://<ホスト>:<ポート>`。ポートは既定値 `8080` |
| 文字コード | UTF-8 |
| リクエストとレスポンスの形式 | `application/json`（ファイルを送るインターフェースは `multipart/form-data`） |
| 認証 | ヘッダーに `x-api-key` |

## 返ってくる中身の形

成功でも失敗でも、形は同じです。

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1753958400000
}
```

| 項目 | 意味 |
| --- | --- |
| `code` | 今回うまくいったかを示す数字 |
| `message` | 一言の説明です。失敗時には理由が書かれるので、そのまま利用者に見せてよい内容です |
| `data` | 本体のデータです。失敗時はたいてい `null` です |
| `timestamp` | サーバーが答えた時刻。ミリ秒の数字です |

:::warning[HTTP の状態だけを見ないでください]
漫画リーダー向けを除き、処理上の失敗も**HTTP としては成功で返ってくる**のがふつうです。本当の結果は中身の `code` に出ます。成功の判定は `200 <= code < 300` です。
:::

## ステータスコード

| `code` | 意味 | ありがちな原因 |
| --- | --- | --- |
| `200` | 成功 | `data` に求めたものが入ります |
| `400` | 送り方が正しくない | 検査に通らない、必須項目が抜けている |
| `401` | 権限がない | 鍵がない・無効、またはオープン API が OFF |
| `403` | 拒否 | 権限が足りない |
| `404` | 見つからない | 住所や対象が存在しない |
| `500` | サーバー側の異常 | 内部で失敗。`message` に原因の要約が入ります |

:::note[一部は data で失敗を表します]
取り込みなど一部のインターフェースは、失敗時に `code=500` かつ `data=false` を返します。一つの項目で結果が読めるようにするためです。各インターフェースの説明に従ってください。
:::

## 日時の書き方

| 場面 | 書式 | 例 |
| --- | --- | --- |
| レスポンス中の日時 | `yyyy-MM-dd HH:mm:ss`（日本時間より 1 時間遅い UTC+8） | `2025-10-16 20:30:00` |
| リクエストで送る日付 | `yyyy-MM-dd` | `2025-10-16` |
| タイムスタンプ | ミリ秒 | `1753958400000` |

## 値が複数ある項目

作品データのうち「番号・表紙・ジャンル・タグ・監督・制作会社」は**複数値の項目**です。

- **読むとき**：標準の JSON の配列で返ります。例：`"actors": ["演员A", "演员B"]`
- **書くとき**：かんたん取り込みは配列をそのまま受け取ります。フォーム送信（`multipart/form-data`）では配列を文字列にした形で受け取ります。

## ページ送り

オープン API 側の作品インターフェースは**ページ送りをしません**。検索結果は一度に全部返ります。

漫画リーダー向けは `page` と `pageSize` でページ送りをし、ページ番号は `1` から始まります。

## 二度呼んでも大丈夫か

- **検索・詳細・件数・照合**：読むだけなので、何度やり直しても安全です。
- **取り込み**：一意の番号で重複を判定するので、二度取り込んでも二件にはなりません。
- **翻訳**：まったく副作用がありません。

## 待ち時間の目安

| インターフェースの種類 | 推奨タイムアウト |
| --- | --- |
| 健康診断・件数取得 | 5 秒 |
| 詳細・ローカル照合 | 10 秒 |
| 複数ソース検索 | 60 秒以上（`waitTime` で調整可） |
| 翻訳 | 30 秒 |

## ヘッダー一覧

| 名前 | 値 | 対象 |
| --- | --- | --- |
| `x-api-key` | 自分の鍵 | `/api/v1/**` のみ |
| `Authorization` | `Bearer <認証コード>` | `/api/mihon/**` のみ |
| `Content-Type` | `application/json` または `multipart/form-data` | インターフェースの指定どおり |

> **User-Agent**：リクエストに添えられる一行で、「自分はどのプログラムか」を示します。記入も変更も不要です。

## 設定項目

一度の呼び出しで記入するのはこれだけです。

| 設定項目 | 何を入れるか | 入れない / 間違えた場合 |
| --- | --- | --- |
| ホストとポート | `http://<ホスト>:<ポート>`。ポートは既定値 `8080` | 間違えると何もつながりません |
| `x-api-key` | システムで作成した X-API-KEY の鍵 | なし、または間違いだと `code` が `401` |
| `Content-Type` | JSON の本文なら `application/json`、ファイル送信なら `multipart/form-data` | 間違えると本文を読み違えることがあります |
| 複数値の項目 | かんたん取り込みは JSON の配列、フォーム送信は配列の文字列 | 形が違うと検査で弾かれます |
| 日付の引数 | `yyyy-MM-dd` の形で書く | 別の形だと検査に通りません |

## うまくいかないときは

- **HTTP は成功なのに中身が違う**：HTTP の状態ではなく、中身の `code` と `message` を見てください。
- **`code` が `400`**：インターフェースの説明を見ながら必須の引数を確認してください。項目名と型が多い原因です。
- **`code` が `401`**：オープン API のスイッチが ON か、鍵の種別が X-API-KEY か、ヘッダー名が `x-api-key` かを確認してください。
- **時刻がずれる**：レスポンスの時刻は UTC+8 で、手元の時計と数時間ずれることがあります。異常ではありません。
- **ある項目が空**：取得元によって用意できる情報は違い、用意できないものは空で返ります。故障ではありません。
