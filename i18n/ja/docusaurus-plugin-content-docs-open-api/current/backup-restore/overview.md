# バックアップパッケージの中身

AMMDS は作品と演者のデータを圧縮書庫（バックアップパッケージ）に書き出し、あとでまた取り込めます。このページは、**自分でバックアップスクリプトを書きたい**方や、**書庫を開いて中身を確かめたい**方のためのものです。正しいパッケージがどんな形か、どこで間違えやすいかを説明します。

画面からバックアップと復元をするだけでよければ、管理機能の「バックアップと復元」で十分です。このページは読み飛ばしてかまいません。

## まず言葉を整理します

> **バックアップパッケージ**：書き出したデータを入れた zip 書庫です。二つの AMMDS の間でデータを移すときや、長期保存に使います。

> **JSON**：中のデータファイルの書式で、「項目名」と「値」の組み合わせです。人にもプログラムにも読めます。

> **マニフェスト**：書庫の中にある「この書庫は何か、何件あるか、画像はどこか」を書いたファイルです。取り込み時に AMMDS が最初に読みます。

> **一意の識別子**：作品の番号です。取り込み時に「このデータはすでに存在するか」を判断するのに使います。

## 書庫に何が入るか

| ファイル | 必須か | 中身 |
| --- | --- | --- |
| `manifest.json` | はい | マニフェスト。形式の識別子・バージョン・データ種別・生成時刻・件数・画像の対応表 |
| `data.json` | はい | 本体のデータ。JSON の配列で、要素ひとつが作品一件または演者一人 |
| `images/` | いいえ | 画像ディレクトリ。書き出し時に「画像ファイルも同時に書き出す」を選んだときだけ存在します |

必須の二つのファイルは、書庫の**ルート**に置きます。

:::warning[ひとつの書庫には一種類だけ]
書庫に入るのは**作品**か**演者**のどちらか一方だけで、混ぜられません。種別はマニフェストの `type` に書きます。作品は `movie`、演者は `actor` です。
:::

## マニフェストに書かれていること

| 項目 | 説明 |
| --- | --- |
| `format` | 形式の識別子。必ず `ammds-backup` |
| `formatVersion` | 形式のバージョン番号。現在は `1` |
| `type` | データ種別。`movie`（作品）または `actor`（演者） |
| `generatedAt` | 生成した時刻 |
| `appVersion` | この書庫を作った AMMDS のバージョン |
| `includeImages` | 画像ファイルが含まれるか |
| `count` | `data.json` の件数 |
| `imageFiles` | 画像の対応表。「元のパス → 書庫内のパス → ファイルのダイジェスト」を一件ずつ記録 |

「画像ファイルも同時に書き出す」を選ばなかった場合、`images/` は存在せず、`includeImages` は `false`、`imageFiles` は空のリストになります。

## 画像はどう扱われるか

書庫内の画像の項目は**元の参照形式**のままです。二通りあります。

| 形式 | 見た目 | 書き出し時に入るか | 取り込み時の扱い |
| --- | --- | --- | --- |
| 外部リンク | `http` または `https` で始まる完全な URL | **入りません** | 終始そのままで、書き換えられません |
| ローカルパス | `data` で始まる相対パス | ファイルが実際にあれば入ります | 保存後、項目は新しい `data` パスに書き換えられます |

両方が同じ項目の中に混在してもかまいません。

要点は二言です。外部リンクは書き出しでも取り込みでも一切触られません。ローカルパスはファイルが実在するときだけ書庫に入り、取り込み後に新しいパスへ書き換えられます。

:::note[取り込み時に画像は重複を除かれます]
画像入りの書庫を取り込むとき、ファイルの中身で重複を判定し、同じものは一つだけ保存します。同じ書庫を何度取り込んでもディスクを圧迫しません。
:::

## 取り込み時にどう同一判定するか

| データ種別 | 同じデータと見なす条件 |
| --- | --- |
| 作品（`movie`） | 識別子が重なること。既存の番号と、取り込むデータの番号がひとつでも一致すれば同じデータです |
| 演者（`actor`） | 氏名が完全に一致すること |

すでにあるデータに当たったときは、選んだ方針で処理されます。

| 方針 | 動作 |
| --- | --- |
| スキップ | 既存のものは触らず、新しいものだけを追加します |
| 上書き | 既存のものを書庫の内容で更新し、なければ新規作成します |

## どんな書庫が拒否されるか

次のいずれかに当てはまると、取り込みは丸ごと拒否され、**既存のデータは一切変更されません**。

- マニフェストの `format` が `ammds-backup` でない。
- 形式のバージョンが、その時点のプログラムが対応するより高い。
- `manifest.json` または `data.json` がない。
- 書庫内に、展開先のディレクトリから抜け出そうとする不審なファイルパスがある。

## 設定項目

| 設定項目 | 何を入れるか | 入れない / 間違えた場合 |
| --- | --- | --- |
| `format` | 必ず `ammds-backup` | 違うと書庫ごと拒否されます |
| `formatVersion` | 現在のバージョン `1` | 対応範囲より高いと拒否されます |
| `type` | `movie` または `actor` | ほかの値、または二種類の混在は不正になります |
| `data.json` | データの配列。項目は AMMDS の実体に合わせる | ファイル欠落で拒否、項目違いで取り込み失敗 |
| 画像の参照 | 外部画像は完全な URL、ローカルは `data` で始まる相対パス | パス違いだと取り込み後に画像がありません |
| 衝突時の方針 | 「スキップ」か「上書き」を選ぶ | 選ばないと重複時の動作が不定になります |

## うまくいかないときは

- **取り込みが拒否される**：`manifest.json` を開き、`format` が `ammds-backup` か、`type` が `movie` か `actor` かを確認してください。この二つが最も多い原因です。
- **取り込み後に画像が出ない**：外部リンクは処理されないので、その URL が今も開けるかを確認してください。ローカルパスの場合は、書き出し時に「画像ファイルも同時に書き出す」を選んだかを確認します。
- **取り込み後の件数が合わない**：作品は番号、演者は氏名の完全一致で照合します。番号の書き方が違う、氏名に余分な空白がある、といった場合は新規データとして扱われます。
- **書庫が改ざんされていないか確かめたい**：マニフェストに記録された各画像のダイジェストと、書庫内の実際のファイルのダイジェストを比べてください。
