# はじめての呼び出し

このページでは、AMMDS に問いを送り、答えを受け取り、その中の項目の意味を一つずつ理解するところまでを通して試します。例はそのまま写せます。住所と自分の鍵だけ置き換えてください。

始める前に、[まず鍵を手に入れる](./api-key.md)の二点をそろえておいてください。オープン API のスイッチが ON であること、X-API-KEY の鍵を手にしていることです。

## まず言葉を整理します

> **リクエスト**：プログラムが AMMDS に送る「これが欲しい」という問いかけです。

> **レスポンス**：AMMDS が返してくる中身のかたまりです。

> **JSON**：その中身の書式で、「項目名」と「値」の組み合わせです。例：`{"code": 200, "data": true}`。

> **ステータスコード**：答えの中の `code` という項目です。数字で、今回うまくいったかどうかがすぐ分かります。

## 用意するもの

| 項目 | 内容 |
| --- | --- |
| インスタンスの住所 | AMMDS が動く機器の住所。例：`http://192.168.1.10:8080` |
| 鍵 | システム → 鍵管理で作成。種別は X-API-KEY |
| オープン API のスイッチ | システム → システム設定で ON（設定キー `GLOBAL_OPEN_API`） |

以下の例では `http://192.168.1.10:8080` を使います。自分の住所に置き換えてください。

## 手順 1：ブラウザでサービスが動いているか確かめる

健康診断の住所は**鍵が不要**なので、ブラウザで直接開けます。次をアドレス欄に貼って Enter を押してください。

`http://192.168.1.10:8080/api/v1/health/check`

ブラウザには次のように表示されます。

```json
{
  "code": 200,
  "message": "success",
  "data": true,
  "timestamp": 1753958400000
}
```

`data` が `true` なら、サービスは動いていて住所も合っています。

:::note[ここで分からないこと]
健康診断は「プログラムが動いている」ことだけを証明します。データベース、ディスク、外部サービスは対象外です。それらは管理画面の「システム診断」で確認してください。
:::

## 手順 2：鍵を付けて作品の件数を尋ねる

ここは鍵が必要です。ブラウザのアドレス欄では鍵を送れないので、コマンドラインを使います。`<あなたの鍵>` を置き換えて実行してください。

```bash
curl -s -H "x-api-key: <あなたの鍵>" \
  http://192.168.1.10:8080/api/v1/movie/count
```

答えは次のとおりです。

```json
{ "code": 200, "message": "success", "data": 1286, "timestamp": 1753958400000 }
```

`data` の `1286` がライブラリ内の作品の件数です。`code` が `401` なら、[まず鍵を手に入れる](./api-key.md)を一つずつ確認してください。

## 手順 3：番号で作品を検索する

```bash
curl -s -X POST http://192.168.1.10:8080/api/v1/movie/search \
  -H "x-api-key: <あなたの鍵>" \
  -H "Content-Type: application/json" \
  -d '{"keyword":"ABC-123","waitTime":30}'
```

答えの `data` は一覧で、要素一つが一件分のデータです。

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "source": "metatube",
      "provider": "jav",
      "number": "ABC-123",
      "title": "示例标题",
      "summary": "示例简介",
      "cover": "https://example.com/cover.jpg",
      "actors": ["演员A"],
      "genres": ["类型A"],
      "score": 8.6,
      "runtime": 120,
      "release": "2025-10-16 00:00:00",
      "extras": {}
    }
  ],
  "timestamp": 1753958400000
}
```

### 各項目の意味

| 項目 | 意味 |
| --- | --- |
| `code` | 今回うまくいったか。`200` から `299` までが成功です |
| `message` | 一言の説明です。失敗時には理由が書かれるので、そのまま見せてよい内容です |
| `data` | 本体のデータです。失敗時はたいてい `null` です |
| `timestamp` | サーバーが答えた時刻。ミリ秒の数字です |
| `source` / `provider` | どの取得元か、およびその中の区分 |
| `number` / `title` / `summary` | 番号・題名・あらすじ |
| `cover` | 表紙画像の住所 |
| `actors` / `genres` | 出演者・ジャンル。角括弧の中に複数入ります |
| `score` / `runtime` / `release` | 評価（10 点満点）・長さ（分）・発売日 |
| `extras` | その取得元だけが持っている追加項目 |

:::note[項目は空になることがあります]
取得元によって用意できる情報は違い、用意できないものは空で返ります。異常ではありませんので、空を異常として扱わないでください。
:::

## 手順 4（省略可）：見つけたデータをライブラリに保存する

`source` と `id` が手に入れば、そのまま取り込めます。

```bash
curl -s -X POST http://192.168.1.10:8080/api/v1/movie/import/from-source \
  -H "x-api-key: <あなたの鍵>" \
  -H "Content-Type: application/json" \
  -d '{"source":"metatube","id":"12345","provider":"jav"}'
```

答えの `data` が、取り込み後の作品 ID です。

## 設定項目

| 設定項目 | 何を入れるか | 入れない / 間違えた場合 |
| --- | --- | --- |
| インスタンスの住所 | `http://<住所>:<ポート>`。ポートは既定値 `8080` | 間違えるとつながらず、タイムアウトまで待たされます |
| `x-api-key` | 作成した X-API-KEY の鍵 | 違うと `code` が `401` で返ります |
| `keyword` | 調べたい番号、または題名の語 | 必須です。入れないと入力内容の検査で弾かれます |
| `waitTime` | 各取得元を何秒待つか。省略すると既定値 | 通信が遅いときに小さすぎると、結果がそろう前に答えが返ります |
| `source` / `id` | 前の手順で得た取得元と ID | 間違っている、または取得元が有効でないと取り込みに失敗します |
| `Content-Type` | JSON の本文を送るときは `application/json` | 書かないと、サーバーが本文を読み違えることがあります |

## うまくいかないときは

- **ブラウザで健康診断が開かない**：住所かポートが違います。AMMDS が動いているかを確認し、別の機器からなら `127.0.0.1` を使わないでください。
- **`code` が `401`**：オープン API のスイッチが OFF、鍵の種別が X-API-KEY でない、鍵のコピーが不完全、のいずれかです。
- **検索結果が空**：たいていは取得元が一つも有効になっていません。プラグイン設定で一つ有効にし、接続を試してください。
- **取り込みに失敗する**：取得元が有効か、引数が正しいかを確認してください。番号がすでに存在する場合、二重に取り込んでも二件にはなりません。
