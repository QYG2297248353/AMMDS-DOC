# 업그레이드 안내

1.x 버전을 사용하다가 2.x로 바꾸려고 한다면, 먼저 이 페이지를 끝까지 읽고 어떻게 할지 결정하세요. **v1과 v2의 데이터는 서로 호환되지 않습니다.** 프로그램만 갈아끼운다고 기존 자료가 그대로 넘어가지 않으며, 잘못 다루면 기존 데이터가 '사라진 것처럼' 보일 수도 있습니다.

:::warning[세 가지만 기억하세요]
1. v1과 v2는 **호환되지 않으므로**, 덮어써서 업그레이드할 수 없습니다.
2. 강제 업그레이드는 권하지 않습니다. 먼저 할 만한 가치가 있는지 따져 보세요.
3. 현재 가능한 방법은 **v1에서 자료를 내보낸 뒤 v2로 가져오기**입니다. 더 편한 방법은 **완전히 새로운 v2를 설치해 처음부터 다시 시작하는 것**입니다.
:::

## 직접 업그레이드할 수 없는 이유

v2는 데이터 저장 방식과 내부 구조를 다시 설계했습니다. v1의 데이터베이스 파일을 v2에서 읽을 수 없고, 그 반대도 마찬가지입니다. '업그레이드만 하면 호환된다'는 관계가 아니라, 서로 독립된 두 시스템입니다.

그래서 아래 방식은 모두 **안 됩니다**:

- v1의 `db/`, `data/` 디렉터리를 그대로 v2에 마운트해 실행하기.
- v2의 프로그램 파일로 v1 설치 디렉터리를 덮어써서 기존 데이터를 계속 쓰려 하기.
- 같은 데이터 디렉터리에서 버전만 바꿔가며 실행해 '운을 시험'하기.

이렇게 하면 대개 v2가 기존 데이터를 읽지 못하고 빈 상태로 다시 초기화하거나, 온갖 오류가 발생합니다. 영상 파일 자체는 사라지지 않습니다(디스크 위의 일반 파일일 뿐입니다). 하지만 정리해 둔 자료는 읽을 수 없게 됩니다.

## 가능한 두 가지 경로

| 경로 | 누구에게 적합한가요 | 대략 필요한 작업 |
| --- | --- | --- |
| 내보내기 → 가져오기 | v1에 이미 많은 자료를 정리해 두었고, 항목이 너무 많아 다시 스크레이핑하고 싶지 않은 사람 | v1에서 백업 패키지를 내보내고, v2를 설치한 뒤 백업 패키지를 다시 가져옵니다 |
| 처음부터 다시 시작 | 자료가 많지 않거나, 버전을 바꾸는 김에 한 번 정리하고 싶은 사람 | v2를 새로 설치하고, 초기 설정을 다시 진행한 뒤 프로그램이 스캔·식별·스크레이핑을 하도록 합니다 |

### 경로 1: 내보내기·가져오기

현재 v1의 자료를 v2로 옮길 수 있는 유일한 방법이며, 세 단계로 진행합니다.

1. **v1에서 내보내기**. v1의 백업과 복원 페이지로 가서 영화, 배우, 만화, 소설 각 종류의 자료를 각각 백업 패키지로 내보냅니다. 이미지가 필요하다면 '이미지 파일도 함께 내보내기'를 체크하세요. 자세한 방법은 [백업과 복원](./backend/system/backup-restore.md)을 참고하세요.
2. **v2 새로 설치하기**. v1의 데이터 디렉터리를 재사용하지 말고, [먼저 설치 방법 고르기](./getting-started/overview.md)에 따라 정상적으로 설치한 뒤 첫 실행 시의 초기 설정까지 마칩니다.
3. **v2에서 가져오기**. v2의 백업과 복원 페이지로 가서 1단계에서 내보낸 백업 패키지를 하나씩 가져옵니다.

가져오기 전에 다음을 확인하세요:

- 가져오기는 **자료**(글과 이미지)만 옮기고, 시스템 설정, 플러그인 키, 다운로더와 미디어 서버 연결 설정은 옮기지 않습니다. 이것들은 v2에서 다시 설정해야 합니다.
- 가져오기가 끝나면 스캔과 스크레이핑을 한 번 더 실행해, 파일 정보나 작업 기록처럼 옮겨오지 못한 내용을 채우는 것이 좋습니다.
- v1 백업 패키지의 형식과 v2의 검증 규칙은 [백업과 복원](./backend/system/backup-restore.md) 페이지를 기준으로 합니다. 가져오기가 거부된다면 먼저 '미리 보기로 분석'으로 구체적인 이유를 확인하세요.

### 경로 2: 처음부터 다시 시작 (더 추천)

솔직히 말해 대부분의 사람에게 이 경로가 **더 편합니다**:

- 백업 패키지 형식, 검증 규칙, 이미지 경로 같은 세부 사항을 신경 쓰지 않아도 됩니다.
- v2의 식별과 스크레이핑은 v1보다 나아졌기 때문에, 다시 실행한 결과가 보통 기존 자료를 옮겨온 것보다 더 좋습니다.
- 설정을 v2 방식으로 바로 하면 되므로, v1을 먼저 배우고 v2를 다시 배울 필요가 없습니다.

방법은 간단합니다. 완전히 새로운 v2를 설치하고 영상 디렉터리를 가리킨 뒤, 프로그램이 스캔·식별·스크레이핑을 다시 하도록 하면 됩니다. 영상 파일은 건드릴 필요가 없으며, 옮기는 것은 '프로그램'일 뿐 '파일'이 아닙니다.

v1의 자료가 너무 많아 다시 스크레이핑하는 비용이 크다면, 그때 경로 1을 사용하세요.

## 어떤 경로를 택하든 먼저 백업

업그레이드는 버전을 바꾸는 일이므로, 손을 대기 전에 v1의 `db/`와 `data/`를 완전히 복사해 둘 사본을 만들어 두세요. 이렇게 해 두면 가져오기 과정에서 문제가 생겨도 기존 환경으로 언제든 되돌아가 계속 사용할 수 있어 양쪽 다 놓치는 일이 없습니다.

기존 인스턴스는 **v2가 모두 정상적으로 동작한 뒤에** 제거하는 것이 좋으며, 종료하기 전에 '내 정보 → 라이선스'에서 온라인 라이선스를 중지해 새 인스턴스에 자리를 넘겨 주세요. 자세한 내용은 [라이선스와 워터마크](./faq.md#라이선스와-워터마크)를 참고하세요.

## 비 Docker 설치: 2.0을 설치하기 전에 데이터 디렉터리 처리하기

Docker의 데이터는 마운트된 디렉터리에 있으므로 이미지를 교체해 컨테이너를 다시 만들어도 영향이 없습니다. 하지만 **설치 패키지, 바이너리, NAS 앱 패키지 같은 방식은 다릅니다**: 데이터 디렉터리가 프로그램 디렉터리 바로 옆에 있어, 이전 버전을 제거하고 새 버전을 설치할 때 데이터 디렉터리가 함께 지워질 수 있습니다. 따라서 2.0을 설치하기 전에 데이터 디렉터리를 **정리하거나 백업해 두는 것**이 좋습니다.

- '내보내기·가져오기' 경로를 택한다면: 백업 패키지가 모두 다운로드되었는지 확인한 뒤 기존 환경을 손대세요.
- '처음부터 다시 시작' 경로를 택한다면: 데이터가 필요 없더라도 `db/`와 `data/`를 복사해 사본을 남겨 두는 것이 좋습니다. 마음이 바뀌었을 때 빈손이 되지 않도록요.

Windows 설치 패키지를 예로 들면 순서는 다음과 같습니다:

1. **서비스 중지**: 트레이 아이콘을 마우스 오른쪽 버튼으로 눌러 AMMDS를 중지합니다.
2. **데이터 디렉터리 찾기**: 트레이 아이콘의 '로그 보기'나 데이터 디렉터리 항목을 통해 데이터 디렉터리의 위치를 찾을 수 있습니다.
3. **데이터 디렉터리 옮기기**: 전체를 프로그램 디렉터리 밖의 장소(예: 다른 드라이브)로 복사합니다. 이 단계가 위에서 말한 백업입니다.
4. **이전 버전 제거**: 시스템의 제거 절차를 따릅니다.
5. **새 버전 설치**: 2.0을 설치하고 새 설치와 같이 초기 설정을 진행합니다.

다른 설치 프로그램(NAS 앱 패키지 등)도 기본적으로 같습니다: **먼저 서비스를 중지하고, 데이터를 밖으로 옮긴 뒤, 제거합니다.** 제거 프로그램마다 동작이 달라 어떤 것은 스스로 데이터 디렉터리를 삭제하기도 하고, 어떤 것은 제거할 때 데이터를 유지할지 묻기도 합니다. 어떤 경우든 제거 프로그램의 안내에만 기대지 말고, 미리 수동으로 옮겨 두는 것이 가장 안전합니다.
