# 라이브러리 상태 점검

라이브러리 상태 점검은 '뭔가 이상해 보이는' 부분을 한곳에 모아 찾아줍니다. 구독이 멈췄거나, 재생 위치가 삭제된 영상을 가리키거나, 저장 디렉터리를 열 수 없거나, 포스터가 없거나 하는 문제들입니다. 점검은 확인만 하고 데이터를 스스로 바꾸지 않습니다. 무엇을 고칠지는 직접 눌러서 결정합니다.

## 진입점

오른쪽 위 아바타를 누르고 드롭다운 메뉴에서 '라이브러리 상태 점검'을 선택합니다.

:::note[미디어 관리 메뉴에는 왜 없나요]
의도된 설계입니다. 점검 진입점은 아바타 메뉴에만 두고 미디어 관리 사이드바에는 표시하지 않아, 평소의 미디어 관리 작업과 섞이지 않게 했습니다. 직접 접속 주소는 `/admin/media/health`입니다.
:::

## 점검은 읽기 전용입니다

페이지 위쪽에 '점검 자체는 읽기 전용이며 어떤 데이터도 수정하지 않습니다. 수리 작업은 직접 실행해야 합니다'라고 적혀 있습니다. 즉:

- 페이지를 열거나, 필터를 바꾸거나, '점검 시작'을 눌러도 아무것도 삭제·수정되지 않습니다
- 문제 항목 뒤의 수리 버튼을 누를 때만 실제로 수정이 실행됩니다
- 삭제가 관련된 작업은 먼저 한 번 더 확인을 받고, 일부는 '되돌릴 수 없음'으로 표시되기도 합니다

## 무엇을 찾아낼 수 있나요

| 분류 | 쉽게 말하면 |
| --- | --- |
| 무효한 파일 연결 | 데이터베이스에는 파일이 기록되어 있지만 디스크에서 찾을 수 없거나 사용 불가로 표시된 상태 |
| 포스터 / 배경 이미지 누락 | 영상은 있지만 로컬에 포스터나 배경 이미지가 없음 |
| 커버 비율 이상 | 커버 이미지의 크기 비율이 규범에 맞지 않음 |
| 중복 파일 | 같은 스캔 경로, 같은 작품 번호 또는 같은 파일이 여러 번 기록됨 |
| 미매칭 번호 / 메타데이터 | 파일은 스캔되었지만 어떤 작품인지 아직 식별되지 않음 |
| 스캔 잔여 / 고아 | 스캔이 남긴 무효 기록, 또는 어떤 파일에도 대응하지 않는 메타데이터 |
| 만화 페이지 손실 | 챕터 기록은 남아 있지만 디스크의 만화 이미지가 삭제되었거나 디스크를 사용할 수 없음 |
| 구독 이상 | RSS 구독이 중지되었거나 오래 갱신되지 않음. 영화·드라마 구독이 일시 정지되었거나 오래 매칭되지 않음 |
| 재생 위치 이상 | 재생 위치가 삭제된 영상·파일을 가리키거나 파일을 사용할 수 없음 |
| 저장 디렉터리 이상 | 데이터 디렉터리가 없거나 쓰기 권한이 없음 |
| 불완전한 메타데이터 | 개봉일, 상영 시간, 줄거리 같은 핵심 정보가 빠져 있음 |

'스캔 잔여 / 고아'에는 '파일 없는 메타데이터'라는 유형이 있는데, 이는 일부러 남겨 둔 순수 자료 항목일 수 있으므로 시스템이 기본적으로 삭제 버튼을 주지 않습니다.

## 심각도는 어떻게 보나요

| 수준 | 의미 | 권장 조치 |
| --- | --- | --- |
| 심각 | 재생, 스크레이핑 또는 데이터 보안에 직접 영향을 줌 | 우선 처리 |
| 경고 | 기능은 동작하지만 상태가 올바르지 않음 | 여유 있을 때 수리 |
| 안내 | 정리되지 않았을 뿐 사용에는 영향 없음 | 무시해도 됨 |

## 필터와 검색

- **라이브러리 종류**: 영화, 드라마, 만화, 구독, 시스템
- **심각도**: 심각, 경고, 안내
- **키워드**: 제목, 경로 또는 작품 번호 검색

목록의 각 항목은 커버, 항목, 핵심 정보, 상태, 사용 가능한 작업을 보여 줍니다. 실행할 수 있는 작업이 없는 항목에는 '읽기 전용'이라고 표시됩니다.

## 무엇을 한 번에 고칠 수 있나요

| 버튼 | 실제로 하는 일 | 주의 |
| --- | --- | --- |
| 다시 감지 | 디스크에 파일이 남아 있는지 다시 확인하고 사용 가능 상태를 갱신 | 안전 |
| 다시 스크레이핑 | 백그라운드 스크레이핑 작업을 제출해 메타데이터와 이미지를 다시 가져옴 | 즉시 끝나지 않으며 작업이 완료될 때까지 기다려야 함 |
| 무시 | 무시로 표시해 이후 스캔에서 이 항목을 알리지 않음 | 안전 |
| 표시 지우기 | '커버 비율 이상' 표시만 지우고 커버 파일은 건드리지 않음 | 안전 |
| 연결 삭제 | 데이터베이스의 파일 연결 기록만 삭제하고, **디스크 파일은 삭제하지 않음** | 안전 |
| 참조 해제 | 무효한 메타데이터 참조를 해제해 항목을 미매칭 상태로 되돌림 | 안전 |
| 중복 병합 | 기존 규칙에 따라 가장 오래된 항목을 남기고 나머지를 삭제·합침 | **되돌릴 수 없음** |
| 즉시 가져오기 | 이 RSS 구독의 최신 내용을 바로 한 번 가져옴 | 안전 |
| 구독 활성화 | 중지된 RSS 구독을 다시 켜고 이후 예정대로 가져옴 | 안전 |
| 다시 매칭 | 매칭 횟수를 비우고 구독 상태를 복원해 매칭 대기열에 다시 넣음 | 안전 |
| 위치 삭제 | 무효한 영상이나 파일을 가리키는 재생 위치 기록을 삭제 | 영상과 파일 자체에는 영향 없음 |
| 저장 관리 | 저장 관리 페이지로 이동해 디스크와 디렉터리 상태를 확인 | 이동만 함 |

## 일괄 수리

1. 여러 문제를 체크합니다.
2. 아래에 '선택한 N건'이 나타나면 '일괄 수리'를 누릅니다.
3. 선택한 모든 항목이 지원하는 수리 작업만 선택지에 나타납니다. 공통 작업이 없으면 '선택한 항목에 공통으로 사용할 수 있는 수리 작업이 없습니다'라고 안내합니다.
4. 팝업에 이번에 영향을 받는 건수가 표시되며, 확인하면 실행됩니다.

실행 후에는 'N건을 처리했습니다' 또는 '성공 X건, 실패 Y건'으로 요약 안내가 뜹니다.

## 점검 기록

- '점검 시작'을 누르면 새 기록이 생성되고, 완료되면 통계와 목록이 자동으로 갱신됩니다
- '기록'에서 시작 시각, 상태, 결과, 소요 시간, 실행 방식을 확인할 수 있습니다
- 실행 방식은 '수동'과 '예약'으로 나뉘며, 상태는 '실행 중', '완료', '실패'가 있습니다
- '보기'를 누르면 해당 점검의 분류별 상세 내용을 볼 수 있습니다

## 자주 묻는 질문

| 현상 | 설명 |
| --- | --- |
| 수리를 눌러도 반응이 없음 | 항목이 읽기 전용이거나, 먼저 체크한 뒤 일괄 수리해야 할 수 있습니다 |
| 수리 후 목록이 그대로임 | 다시 감지 계열 작업은 즉시 갱신됩니다. 스크레이핑·가져오기는 백그라운드 작업이므로 완료 후에 다시 보세요 |
| 연결을 삭제했는데 파일이 남아 있음 | 정상입니다. 연결 삭제는 데이터베이스 기록만 정리합니다 |
| 저장 디렉터리 이상을 수리할 수 없음 | 이런 문제는 사람이 직접 처리해야 합니다. 안내에 따라 '저장 관리'에서 마운트와 권한을 확인하세요 |
