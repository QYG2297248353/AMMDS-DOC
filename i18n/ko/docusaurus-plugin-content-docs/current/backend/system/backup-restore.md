# 백업과 복원

이 페이지는 서로 다른 두 일을 다룹니다. **자료 옮기기**(정리한 정보를 내보내 다른 곳에서 되살리기)와 **설정을 다른 곳에 보관하기**입니다. 글과 그림만 다루고, 시스템 설정과 플러그인 값은 담지 않습니다.

> **메타데이터**: 항목을 설명하는 정보입니다. 제목, 출연자, 줄거리, 표지, 챕터 같은 것이 여기 들며, 영상 파일 자체는 들어가지 않습니다.

## 1. 자료 내보내기

**시스템 관리 → 백업과 복원 → 자료 내보내기**를 엽니다. 네 종류의 카드가 있고, 각각 그림을 함께 담을지를 따로 정합니다.

| 종류 | 내보내는 것 | "그림도 함께 내보내기"를 고르면 더 담기는 것 |
| --- | --- | --- |
| 작품 | 작품 정보, 파일 정보, 연결된 출연자·시리즈·마그넷·자막 | 포스터, 배경, 작은 그림, 장면 그림, 큰 그림 |
| 출연자 | 출연자 정보(체형, 태그, 소셜 등) | 얼굴 사진과 포스터 |
| 만화 | 앨범 정보, 챕터, 챕터 쪽 기록 | 앞표지, 뒤표지, 모든 챕터 쪽 그림 |
| 소설 | 소설 정보와 챕터 본문 | 앞표지와 뒤표지 |

내보내기는 뒤에서 도므로 기다리지 않고 페이지를 떠나도 됩니다. 「내보내기 기록」에서 종류, 파일 이름, 상태(내보내는 중 / 완료 / 실패), 크기, 만든 시각을 보고 내려받거나 지울 수 있습니다. 같은 종류가 내보내는 중일 때는 버튼이 불러오는 표시로 남아 두 번 시작되지 않습니다.

:::tip[담기는 것은 내 기기의 그림뿐입니다]
데이터 폴더에 저장되어 있고 실제로 있는 그림만 담깁니다. 바깥 주소로 된 그림은 담기지 않습니다. 옮긴 뒤에 원래 데이터 폴더를 남겨 두었다면 옛 경로를 그대로 쓸 수 있고, 바깥 주소는 원래 사이트가 살아 있어야 합니다.
:::

## 2. 백업 안에 무엇이 있나

표준 백업은 압축 파일이며 맨 위에 `manifest.json` 과 `data.json` 이 꼭 있어야 하고 그림 폴더는 없어도 됩니다.

| 파일 | 구실 |
| --- | --- |
| `manifest.json` | 목록. 형식 표시, 판, 종류, 개수, 그림 목록 |
| `data.json` | 자료 자체. 한 항목씩 적혀 있습니다 |
| `images/` | 그림을 내보냈을 때만 있고, 항목마다 폴더가 나뉩니다 |

하나의 백업에는 한 종류만 들어갑니다. 목록의 개수와 `data.json` 의 실제 개수가 같아야 하며, 다르면 가져오기가 거절됩니다.

## 3. 자료 되살리기

1. **자료 가져오기**를 열고 압축 파일이나 `data.json` 하나를 끌어다 놓습니다.
2. 가져오기 방식을 고릅니다(아래 표).
3. 「미리 보기」를 눌러 개수, 담긴 그림 수, 크기, 파일 수를 봅니다.
4. 확인이 통하면 「가져오기 시작」을 누릅니다. 끝나면 성공·건너뜀·덮어쓰기·실패가 각각 몇 개인지 나옵니다.

미리 볼 때 다음을 확인합니다. 목록이나 자료 파일이 없는지, 항목 경로가 바르지 않은지, 형식 표시가 다른지, 판이 받아들일 수 없는지, 종류가 허용되지 않는지, 목록의 개수와 실제 개수가 맞는지, 그림 경로가 `images/` 밖이거나 파일이 없는지. 하나라도 걸리면 **가져오기가 금지**되고 자료는 조금도 바뀌지 않습니다.

한 항목이 실패해도 전체가 멈추지 않습니다. 이유가 적히고, 자세히 보기에 최대 50개까지 나옵니다.

### 설정 항목: 세 가지 방식

| 방식 | 하는 일 | 쓰기 좋은 때 |
| --- | --- | --- |
| 이미 있는 것 건너뛰기 | 맞는 것이 있으면 아무것도 쓰지 않고 고치지도 않습니다 | 빠진 것만 채우고 싶고, 있는 것을 망치고 싶지 않을 때 |
| 덮어쓰기 | 맞는 것을 덮어씁니다. 만화·소설·드라마는 챕터나 시즌·회를 다시 만듭니다 | 백업의 내용으로 지금 것을 바꾸고 싶을 때 |
| 합치기 | 빠진 항목만 채우고 목록은 겹침을 걷어 모읍니다. 지우지는 않습니다 | 양쪽을 합치고 싶을 때 |

"같은 항목"으로 보는 기준: 작품은 작품 번호가 겹치면 같다고 보고(합치기에서는 제목도 봄), 출연자는 이름이 완전히 같을 때, 만화는 ISBN을 먼저 그다음 앨범 이름, 소설은 책 이름이나 ISBN, 드라마는 바깥 사이트의 ID를 차례로 맞춰 봅니다.

## 4. 공유 링크로 가져오기

**공유 가져오기** 탭에서 합니다.

| 설정 항목 | 무엇을 정하는지 / 입력법 | 비워 두면 |
| --- | --- | --- |
| 공유 링크 또는 짧은 코드 | 남에게 받은 공개 주소, 또는 끝부분의 짧은 코드 | 미리 볼 수 없습니다 |
| 접근 비밀번호 | 상대가 정했을 때만 넣습니다 | 비밀번호를 요구받고 가져올 수 없습니다 |
| 가져오기 방식 | 건너뛰기 / 덮어쓰기 / 합치기 | 기본은 "건너뛰기"입니다 |

넣고 「공유 미리보기」로 종류·제목·개수를 확인한 뒤 「공유 가져오기」를 누릅니다. 가져오기가 허용되지 않았으면 "이 공유는 가져올 수 없습니다"라고 나오니, 이유를 적어 신청할 수 있습니다(먼저 사용자 ID, 별명, 메일을 채워야 합니다).

같은 페이지 아래에서 「링크 기록」(성공, 권한 없음, 링크 무효, 만료, 실패)과 「신청 기록」(대상, 이유, 상태. 대기 중은 취소 가능)을 오갈 수 있습니다. 기록을 지워도 이미 가져온 자료에는 영향이 없습니다.

## 5. 설정은 따로 다른 곳에

위의 백업에는 **시스템 설정, 플러그인 값, 구독 규칙이 들어 있지 않습니다**. 설정을 다른 곳에 남기려면 **통합 앱 → 클라우드 동기화**의 네트워크 드라이브나 오브젝트 저장을 씁니다.

- "설정 갈래"만 담고 그림이나 작품 항목은 없으므로 크기가 아주 작습니다.
- 백업은 암호화되며, **암호를 잃으면 되살릴 수 없습니다**. 파일과 따로 간직하세요.
- 되살릴 때는 합치기, 내 것 우선, 먼 곳 우선 중에서 고를 수 있습니다.
- 그 서비스들의 연결 설정은 되살리지 않습니다. 되살린 뒤 먼 곳에 못 붙는 일을 막기 위해서입니다.
- 네트워크 드라이브는 설정 백업만 맡습니다. 그림 같은 자료를 먼 곳에 두려면 오브젝트 저장을 씁니다. 둘은 서로 독립입니다.

> **암호**: 백업을 잠그고 여는 데 쓰는, 내가 정한 한 줄의 글입니다. 시스템이 대신 간직해 주지 않으므로, 잊으면 새로 만들어야 합니다.

## 익혀 두면 좋은 습관

1. 자료는 종류별로 내보내고, 그림이 필요할 때만 "그림도 함께 내보내기"를 고릅니다.
2. 설정은 클라우드에 따로 저장하고, 암호는 백업과 떼어 보관합니다.
3. 되살리기 전에 같은 판의 환경에서 「미리 보기」를 돌려 확인이 통하는지 봅니다.
4. 큰 판 올리기 전에 한 번 모두 내보내고, 올린 뒤에 시스템 점검을 돌립니다.

## 문제가 생기면

- **가져오기가 거절된다**: 백업이 모자라거나 목록과 개수가 안 맞는 일이 많습니다. 다시 내보내고, 안의 파일을 손으로 고치지 마세요.
- **가져왔는데 달라진 것이 없다**: "이미 있는 것 건너뛰기"를 고르지 않았는지 보세요. 바꾸려면 "덮어쓰기"입니다.
- **그림이 안 살아난다**: 내보낼 때 그림을 고르지 않았거나 그림이 바깥 주소입니다. 그림을 붙여 다시 내보내세요.
- **내보내기 기록이 실패다**: 작업 로그에서 이유를 보세요. 디스크 공간 부족이 흔합니다.
- **클라우드 설정이 안 살아난다**: 암호가 맞는지, 먼 곳의 파일이 깨지지 않았는지 보세요. 연결 설정은 되살리지 않으므로 손으로 넣습니다.
- **되살린 뒤가 궁금하다**: [시스템 점검, 로그, 저장소, 라이선스와 사용자](./maintenance.md)에서 전체 점검을 돌려 보세요.
