# 자동 실행, 작업 기록, 실패 재시도

매번 「立即扫描（지금 스캔）」을 누르기 번거롭다면 이 페이지입니다. 작업을 정해진 시각에 자동으로 돌리는 법, 전체를 제어하는 스위치 위치, 시간표 작성법, 실행 뒤 기록 확인, 그리고 실패 후 재시도와 로그 정리를 다룹니다.

## 먼저 알아 두기

> **스크레이핑**: 자료 사이트에서 표지·줄거리·출연진을 찾아 자동으로 채워 넣는 일입니다.

> **메타데이터**: 작품의 표지·줄거리·출연진·태그 같은 설명 정보입니다.

> **작품 번호 / 식별 코드**: 파일명에 들어 있는 식별 번호로, AMMDS는 이것으로 작품을 알아봅니다.

> **NFO**: 동영상과 같은 곳에 두는 작은 설명 파일로 재생기도 읽습니다.

> **Cron**: 「언제 실행할까」를 숫자와 기호로 적은 짧은 문자열입니다. 매일 몇 시, 몇 분마다 등을 정합니다.

> **정기 작업**: 재생 기록 동기화, 순위표 수집, 임시 파일 정리처럼 프로그램이 정해진 시각에 스스로 하는 일거리입니다.

> **스케줄러**: 시간이 되면 해당 작업을 깨우는 프로그램 안의 장치입니다. 하나하나 손으로 켤 필요가 없습니다.

> **환경 변수**: 앱을 켜기 전 시스템에 설정하는 스위치 값입니다. 보통 설치에서는 건드리지 않고, 바꾸면 대개 재시작이 필요합니다.

> **동시 처리**: 여러 일을 한꺼번에 진행하는 것입니다.

> **로그**: 「언제 무엇을 했고 잘 됐는지」 적어 둔 기록으로, 문제가 생기면 거슬러 올라가 확인합니다.

## 정해진 시각에 자동으로 돌리기

### 「计划任务（정기 작업）」페이지 열기

系统管理 → 计划任务（시스템 관리 → 정기 작업）으로 갑니다. 위쪽에 전체 스위치 상태, 실행 중인 개수, 「自动刷新（자동 새로고침）」스위치, 「刷新（새로 고침）」버튼이 있고 아래에 작업 표가 있습니다.

| 항목 | 내용 |
| --- | --- |
| 任务名称（작업 이름） | 주 제목은 작업 이름이고 아래 줄은 내부 식별자 `类名#方法名`입니다. 대조용입니다 |
| 执行周期（실행 주기） | 사람이 읽을 수 있는 주기 문장입니다. 마우스를 올리면 원본 Cron이나 고정 간격 식이 보입니다 |
| 运行状态（실행 상태） | 이 페이지에서 수동으로 켠 실행이 「실행 중 / 쉼」인지와, 아래에 지난 수동 실행 결과 요약이 붙습니다 |
| 上次执行（마지막 실행） | 지난 수동 실행의 시작 시각입니다. 실패면 빨간 「失败（실패）」태그가 붙고, 한 번도 수동 실행하지 않았으면 「从未执行（실행한 적 없음）」입니다 |
| 操作（동작） | 「执行（실행）」버튼. 실행 중이거나 전체 스위치가 꺼지면 흐려집니다 |

:::note[이 두 항목은 수동 실행만 기록합니다]
「运行状态（실행 상태）」와 「上次执行（마지막 실행）」은 **이 페이지에서 수동으로 켠 실행**만 기록합니다. 자동 스케줄로 돈 것은 이 두 항목에 되돌려 쓰지 않습니다. 자동 작업의 상황은 「系统管理 → 运行日志（시스템 관리 → 실행 로그）」에서 봅니다.
:::

:::note[주기 문장이 낯설 때]
화면이 알아보기 쉬운 문장으로 바꾸는 것은 「매일 정시」「N분마다」「N시간마다」「N일마다 정시」같은 흔한 형태뿐입니다. 알아보지 못하는 Cron은 식을 그대로 보여 줍니다. 짐작으로 잘못 읽히지 않게 하려는 의도적인 동작입니다.
:::

### 전체 스위치: 끄면 여러 계획이 한꺼번에 멈춥니다

전체 스위치는 환경 변수 `AMMDS_SCHEDULER_ENABLE`(설정 항목 `ammds.scheduler.enable`)로 제어되며 **기본은 켜짐**입니다.

- 끄면 위쪽에 「计划任务已关闭（정기 작업이 꺼졌습니다）」가 뜨고 설명도 나옵니다.
- 수동 「执行（실행）」은 백엔드가 거부하고 버튼도 흐려집니다.
- 앱이 켜질 때 「任务级 Cron（작업 단위 Cron）」과 「IYUU 自动辅种（IYUU 자동 시딩）」등록을 건너뛰어 이 둘은 효력을 잃습니다.
- 프로그램 내장 정기 작업은 이 스위치 영향을 받지 않습니다. 페이지에 계속 나열되고 각자 주기대로 돕니다. 백그라운드 작업을 전부 멈추려면 인스턴스 자체를 끄거나 배포 단계에서 처리해야 합니다.

**이 스위치는 앱을 다시 켜야 적용됩니다.** 변경 방법은 시스템 설정 섹션의 시스템 설정 페이지에 있습니다.

### 한 번만 수동으로 실행하기

어느 행의 「执行（실행）」은 한 번만 실행을 넣고 원래 주기는 바꾸지 않습니다.

1. 백엔드가 이번 실행을 전용 대기열에 넣고 끝나기를 기다리지 않고 바로 돌아옵니다.
2. 같은 작업이 이미 실행 중이면 다시 누르면 거부되고 「任务正在执行中（작업 실행 중）」이 뜹니다.
3. 화면은 곧바로 그 행을 실행 중으로 표시하고 3초마다 결과를 묻습니다. 전부 끝나면 자동으로 묻기를 멈춥니다.
4. 끝나면 「上次执行（마지막 실행）」이 갱신되고 결과 요약이 실행 상태 아래에 적힙니다. 실패 시 요약은 오류 종류와 메시지이며 너무 길면 잘립니다.

「自动刷新（자동 새로고침）」스위치는 작업이 도는 동안 3초마다 물어볼지를 정합니다. 끄면 「刷新（새로 고침）」을 직접 눌러야 최신 상태가 보입니다.

### Cron 작성법

앱은 여섯 항목 Cron을 쓰고 순서는 `秒 分 时 日 月 周`(초, 분, 시, 일, 월, 요일)입니다.

| 식 | 뜻 |
| --- | --- |
| `0 0/20 * * * ?` | 20분마다 |
| `0 0/2 * * * ?` | 2분마다 |
| `0 0 9 * * ?` | 매일 09:00 |
| `0 30 4 * * ?` | 매일 04:30 |
| `0 10 */6 * * ?` | 6시간마다 10분째 |
| `0 0 3 1/13 * ?` | 13일마다 03:00 |

Cron 외에 `fixedRate`(고정 간격)나 `fixedDelay`(지난 실행이 끝난 뒤부터 계산)를 쓰는 작업도 있습니다. 화면은 이를 「N분 / 시간마다」로 바꾸고 초기 지연도 표시합니다.

### 어떤 자동 작업이 있나

목록은 앱이 켜질 때 자동으로 훑어 만들므로 손으로 관리할 필요가 없습니다. 자주 보이는 그룹입니다.

| 그룹 | 대표 작업 |
| --- | --- |
| 구독·다운로드 | 구독 대기 작품 일괄 다운로드(20분마다), 구독 다운로드 진행 갱신(2분마다), 대조 안 된 구독 메타데이터 갱신(300분마다) |
| 사이트·계정 | PT 사이트 인증 실행, 전체 PT 사이트 사용자 데이터 동기화, PT 사이트 계정 보안 상태 확인 |
| 미디어 서버 | Jellyfin / Emby 재생 기록·라이브러리 동기화, 라이브러리 배우 데이터 보충 |
| 정보 센터 | RSS 글 갱신, RSS 오프라인 캐시, RSS 자동 보관, 인기 구독 새로고침, 인기 구독 유효성 검사 |
| 순위표 | ThePornDB 최근 업데이트, FANZA DMM 당일 순위표와 앞으로 3일 순위표 수집 |
| 유지보수 | 스캔 찌꺼기 정리, 장 번호 복구, 파일 탐색기 임시 파일 정리, 지각 해시 계산, 디스크 용량 확인, 저장소 통계, 라이선스 확인, MeiliSearch 자동 색인 |
| 기타 | 시리즈 라이브러리 동기화, 厂牌规则（제작사 규칙）수집, 공식 상점 동기화, 로컬 자료 S3 동기화 |

실제 페이지 목록이 기준입니다. 앞으로 내장 작업이 늘어나도 다시 켜면 자동으로 나타나고 화면을 고칠 필요가 없습니다.

### 두 장치를 혼동하지 마세요

「计划任务（정기 작업）」페이지와 작업 설정의 Cron은 별개입니다.

| 장치 | 설정 위치 | 「정기 작업」페이지에 나오나요? |
| --- | --- | --- |
| 내장 정기 작업 | 앱에 처음부터 포함 | 나옵니다 |
| 스캔 작업 Cron | 任务配置 → 编辑任务 → 计划任务（작업 설정 → 작업 편집 → 일정） | 아니요. 스케줄러가 따로 등록합니다 |
| 자동 스크레이핑 간격 | 任务配置 → 刮削规则（작업 설정 → 스크레이핑 규칙） | 아니요. 간격대로 스스로 돌고 전체 스위치 영향을 받지 않습니다 |
| IYUU 자동 시딩 | 工具箱 → PT 辅种 → 辅种计划（도구 상자 → PT 시딩 → 시딩 계획） | 아니요. 스케줄러가 따로 등록합니다 |

스캔 작업에서 폴더 감시를 켜면 Cron을 쓰지 않습니다. 감시를 끄고 Cron을 적으면 앱 시작이나 설정 변경 뒤 스케줄러에 등록됩니다. 작업 단위 Cron과 IYUU 자동 시딩은 전체 스위치를 따르고, 내장 정기 작업은 따르지 않습니다.

:::warning[한 작업에 두 가지 실행 방법을 넣지 마세요]
같은 스캔 작업에 Cron과 폴더 감시를 모두 넣어도 의미가 없고, 저장할 때 하나만 남습니다. 「새 파일이 오면 바로 처리」는 폴더 감시, 「정해진 시각에 전체 스캔」은 Cron입니다. [스캔: AMMDS가 내 파일을 알게 하기](./scan.md) 참고.
:::

## 실행 뒤 기록은 어디서 보나

### 세 종류의 기록

| 기록 | 위치 | 기록하는 것 |
| --- | --- | --- |
| 扫描日志（스캔 로그） | 任务管理 → 扫描日志（작업 관리 → 스캔 로그） | 스캔 작업의 매 실행 |
| 刮削日志（스크레이핑 로그） | 任务管理 → 刮削日志（작업 관리 → 스크레이핑 로그） | 스크레이핑 작업의 각 묶음 |
| 任务日志（작업 로그） | 系统管理 → 日志审计 → 任务日志（시스템 관리 → 로그 감사 → 작업 로그） | 파일 조작, 백업, RSS, 만화 / 소설 정리 같은 백그라운드 작업 |

### 스캔 로그

「查询（조회）」로 조건대로 갱신하고 「重置（초기화）」로 기본값으로 돌립니다. 작업 카드의 「记录（기록）」으로 들어오면 해당 작업으로 자동 필터링됩니다.

| 조회 조건 | 선택지 |
| --- | --- |
| 任务类型（작업 종류） | 전체 / 影视（영상）/ 剧集（시리즈） |
| 任务选择（작업 선택） | 작업 이름으로 좁히기, 전체도 가능 |
| 运行类型（실행 종류） | 수동 실행, 정기 작업, 실시간 감시, 초기화 |
| 任务状态（작업 상태） | 생성, 스캔 중, 감시 중, 스캔 대기, 스캔 완료, 스캔 취소, 스캔 오류 |

| 목록 항목 | 내용 |
| --- | --- |
| 任务名称（작업 이름） | 이번 스캔이 속한 작업 |
| 类型（종류） | 실행 종류, 곧 실행 계기 |
| 开始时间（시작 시각） | 실행을 시작한 시각 |
| 任务耗时（소요 시간） | 있으면 표시. 스캔 중에는 「扫描中（스캔 중）」, 그 밖에 소요 시간이 없으면 「扫描中断（중단）」 |
| 任务状态（상태） | 완료는 초록 점, 나머지는 회색 |
| 识别媒体数量（인식 미디어 수） | 이번에 찾은 동영상 파일 수 |
| 新增媒体数量（추가 미디어 수） | 새로 등록한 파일 수 |
| 更新媒体数量（갱신 미디어 수） | 이미 있어 이번 스캔에 다시 연결한 기록 수 |
| 操作（동작） | 「取消（취소）」. 「스캔 중」이고 실행 종류가 실시간 감시·초기화가 아닐 때만 가능 |

아래쪽에서 페이지 이동, 페이지당 건수, 표 밀도, 열 보이기 / 숨기기를 바꿀 수 있습니다. 위쪽 「清理日志（로그 비우기）」는 스캔 기록을 전부 지우며 **되돌릴 수 없습니다**.

:::note[스캔 로그에는 개별 상세가 없습니다]
스캔 로그는 묶음 단위 정보만 적습니다. 파일 하나의 식별 번호, 스크레이핑 상태, 단계가 필요하면 **任务管理 → 刮削入库（작업 관리 → 등록 대기）**로 가세요. 항목별 단계 타임라인은 「查看步骤（단계 보기）」에 있습니다.
:::

### 스크레이핑 로그

| 조회 조건 | 선택지 |
| --- | --- |
| 任务类型（작업 종류） | 전체 / 影视（영상）/ 剧集（시리즈） |
| 运行类型（실행 종류） | 수동 실행, 정기 작업 등 |
| 任务状态（상태） | 스크레이핑 중, 완료, 대기, 취소, 오류 |

| 목록 항목 | 내용 |
| --- | --- |
| 任务名称（작업 이름） | 이 묶음의 작업 이름. 멀티스레드면 스레드 접미사가 붙습니다 |
| 开始时间（시작 시각） | 묶음 시작 시각 |
| 刮削结果（결과） | 묶음 결과 요약 |
| 任务耗时（소요 시간） | 실행 중에는 「刮削中（스크레이핑 중）」, 그 밖에 소요 시간이 없으면 「刮削中断（중단）」 |
| 任务状态（상태） | 완료는 초록, 나머지는 주황 |
| 刮削媒体数量（대상 미디어 수） | 이 묶음에서 처리하려는 수 |
| 刮削成功数量 / 失败数量（성공 / 실패 수） | 이 묶음의 성공·실패 수 |
| 操作（동작） | 「取消（취소）」. 「스크레이핑 중」이고 실행 종류가 실시간 / 초기화가 아닐 때만 가능 |

「清理日志（로그 비우기）」는 지울 수 있는 지난 기록만 없앱니다. 실행 중인 작업은 지워지지 않으니 멈추려면 먼저 「取消（취소）」를 누르세요.

### 시스템 작업 로그

파일 업로드·다운로드·복사·이동·압축, 백업 가져오기 / 내보내기, RSS 갱신, 만화 / 소설 정리 등이 여기 적힙니다.

- 키워드, 작업 종류, 상태로 좁힐 수 있습니다.
- 목록에는 종류, 제목, 상태, 진행, 메시지, 시작 시각, 소요 시간이 나옵니다.
- 「详情（상세）」를 누르면 서랍이 열려 상태, 진행, 완료 수 / 전체 수, 메시지, 오류, 시작 / 종료 시각, 줄별 실행 로그를 볼 수 있습니다. `ERROR`와 `WARN`은 강조됩니다.
- 「取消（취소）」는 실행 중이고 백엔드가 취소 가능이라 표시한 작업에만 나옵니다.
- 실행 중인 작업은 지울 수 없습니다. 끝난 것은 하나씩 지우거나 「清理（비우기）」로 한꺼번에 지울 수 있습니다.
- 「自动刷新（자동 새로고침）」을 켜면 5초마다 목록을 갱신합니다.

### 상태 대조

| 경로 | 나올 수 있는 상태 |
| --- | --- |
| 스캔 작업 | 생성, 스캔 중, 감시 중, 스캔 대기, 스캔 완료, 스캔 취소, 스캔 오류, 작업 삭제 |
| 스크레이핑 작업 | 스크레이핑 중, 완료, 대기, 취소, 오류, 삭제 |
| 시스템 작업 | 실행 중, 완료, 실패, 취소됨 |

「等待（대기）」는 작업이 만들어졌지만 아직 차례가 오지 않은 상태이고, 「异常（오류）」는 도중에 처리되지 않은 오류가 난 상태라 로그와 단계를 함께 봐야 합니다.

## 실패 뒤 어떻게 다시 돌리나

기록 페이지 자체에는 **「다시 실행」버튼이 없습니다**. 다시 돌리는 일은 해당 기능 페이지로 가서 합니다.

| 상황 | 다시 돌리는 법 |
| --- | --- |
| 스캔 실패, 또는 다시 스캔 | 작업 설정에서 「立即扫描（지금 스캔）」을 한 번 더. 실행 중이면 먼저 취소 |
| 항목 하나만 스크레이핑 실패 | 「刮削入库（등록 대기）」에서 「刮削整理（스크레이핑 + 정리）」를 누르면 실패분이 다시 대기열에 듭니다. [스크레이핑: 작품 정보 자동으로 채우기](./scrape.md) 참고 |
| 작품 번호를 잘못 인식 | 「刮削入库（등록 대기）」에서 인식 번호 태그를 눌러 고치고 다시 스크레이핑 |
| 메타데이터 대조 실패 | 「绑定（연결）」로 라이브러리 기록에 수동 연결한 뒤 스크레이핑 |
| 이미지나 NFO 누락 | 작업에 「查漏补缺（빠진 것 보충）」을 써서 부속 파일만 채우기 |
| 구독 다운로드 실패 | 구독 관리에서 「立即搜索（지금 검색）」을 누르거나 다음 자동 차례를 기다리기 |
| 파일 조작 실패 | 시스템 작업 로그에서 오류를 보고 경로 / 권한을 고친 뒤 다시 시작 |

:::tip[먼저 단계, 그다음 로그]
스크레이핑이 실패하면 먼저 「刮削入库 → 查看步骤（등록 대기 → 단계 보기）」에서 파일 검사·번호 판별·출처 조회·이미지나 NFO 생성 중 어디서 실패했는지 찾으세요. 단계 오류가 보통 묶음 로그보다 구체적입니다.
:::

## 로그를 비우기 전에

- 로그 비우기는 **미디어 기록을 지우지 않고**, 이미 정리한 파일을 되돌리지도 않습니다.
- 스캔 로그를 비우면 지난 묶음은 다시 추적할 수 없습니다. 근거를 남기려면 먼저 내보내거나 화면을 저장하세요.
- 스크레이핑 로그는 지울 수 있는 지난 기록만 지우고 실행 중인 것은 남습니다.
- 시스템 작업 로그의 「清理（비우기）」는 끝난 작업만 지우고 실행 중인 것은 남깁니다.

## 설정 항목 설명

| 설정 항목 | 입력할 것 | 비우거나 틀리면 |
| --- | --- | --- |
| 전체 정기 작업 스위치 `AMMDS_SCHEDULER_ENABLE` | 기본 켜짐. 시스템 설정에서 바꾸고 바꾼 뒤 앱 재시작 | 끄면 「计划任务已关闭」가 뜨고 실행 버튼이 흐려지며 작업 단위 Cron과 IYUU 자동 시딩이 등록되지 않습니다. 내장 작업은 계속 돕니다 |
| 스캔 작업 「计划任务（일정）」의 Cron | 여섯 항목 식 `秒 分 时 日 月 周`. 폴더 감시가 꺼졌을 때만 표시 | 비우면 수동만. 식이 틀리거나 시간대가 다르면 실행되지 않습니다. 전체 스위치가 켜졌는지도 확인하세요 |
| 目录监控（폴더 감시） | Cron과 둘 중 하나 | 둘 다 넣으면 하나만 남습니다. 감시를 켜면 Cron 스케줄에 참여하지 않습니다 |
| 自动刮削（자동 스크레이핑）간격 | 영상 / 시리즈별 스위치와 간격. 기본 3분마다 대기 항목 확인 | 끄면 수동만. 너무 짧으면 자주 돕니다. 전체 스위치 영향은 받지 않습니다 |
| 수동 「执行（실행）」 | 「정기 작업」페이지에서 해당 행 버튼을 누릅니다 | 실행 중이거나 전체 스위치가 꺼지면 흐려집니다. 이미 실행 중이면 「任务正在执行中」이 뜹니다 |
| 自动刷新（정기 작업 페이지） | 작업이 도는 동안 3초마다 물어볼지 | 끄면 「刷新（새로 고침）」을 눌러야 최신 상태가 보입니다 |
| 自动刷新（시스템 작업 로그） | 켜기 / 끄기. 켜면 5초마다 갱신 | 끄면 목록이 저절로 갱신되지 않습니다 |
| 扫描 / 刮削日志（스캔 / 스크레이핑 로그）조회 조건 | 작업 종류, 작업 선택, 실행 종류, 상태 | 조건이 틀리면 원하는 기록이 안 나옵니다. 「重置（초기화）」로 기본값 복귀 |
| 清理日志（로그 비우기） | 세 종류 각자의 비우기 버튼 | 되돌릴 수 없습니다. 비우면 지난 묶음을 추적할 수 없고, 실행 중인 것은 지워지지 않습니다 |
| 保存配置 / 刷新配置（규칙 패널） | 고친 뒤 「保存配置」로 항목마다 제출 | 저장하지 않으면 반영되지 않습니다. 「刷新配置」는 저장 안 한 변경을 버립니다 |

## 문제가 생기면

| 증상 | 예상 원인 | 조치 |
| --- | --- | --- |
| 「计划任务已关闭（정기 작업 꺼짐）」표시 | 전체 스위치가 꺼짐 | `AMMDS_SCHEDULER_ENABLE`을 바꾸고 앱을 다시 켭니다 |
| 「执行（실행）」버튼이 흐려짐 | 실행 중이거나 전체 스위치 꺼짐 | 현재 실행이 끝나길 기다리거나 전체 스위치를 확인하세요 |
| 「上次执行（마지막 실행）」이 실패 | 상위 서비스 중단, 인증 만료, 네트워크 이상 | 결과 요약과 「系统管理 → 运行日志（시스템 관리 → 실행 로그）」를 보고 고친 뒤 수동으로 한 번 실행하세요 |
| 정각에 실행되지 않음 | Cron 오류, 시간대 불일치, 전체 스위치 꺼짐 | 여섯 항목 식과 앱 시간대를 대조하세요 |
| 「정기 작업」목록이 비었음 | 시작 시 훑기가 덜 끝났거나 찾을 작업이 없음 | 먼저 새로 고침하세요. 그래도 비면 시작 로그를 보세요 |
| 자동 실행은 되는데 「上次执行」이 그대로 | 이 두 항목은 수동 실행만 기록합니다 | 「系统管理 → 运行日志（시스템 관리 → 실행 로그）」에서 자동 스케줄 상황을 확인하세요 |
| 스캔 / 스크레이핑 기록에 파일 단위가 없음 | 로그는 묶음 단위만 | 「任务管理 → 刮削入库（작업 관리 → 등록 대기）」와 「查看步骤（단계 보기）」에서 개별 확인 |

- 스캔을 정각에 돌리려면 Cron을 적는 것 외에 전체 스위치가 켜졌는지도 확인하세요. [스캔: AMMDS가 내 파일을 알게 하기](./scan.md) 참고.
- 스크레이핑 실행 방법, 자동 간격, 빠진 것 보충은 [스크레이핑: 작품 정보 자동으로 채우기](./scrape.md)에 있습니다.
- 로그를 비우기 전에 화면을 저장하거나 내보내세요. 한 번 비우면 되돌릴 수 없습니다.
