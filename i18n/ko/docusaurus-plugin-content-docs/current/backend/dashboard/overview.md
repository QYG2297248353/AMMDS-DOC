# 홈 화면: 처음 열면 보이는 것들

로그인하면 기본으로 工作台（홈 화면）가 열립니다. 한 화면에 디스크 용량, 작품 수, 날씨, 네트워크, 버전 정보 카드가 모이고, 그 아래 세 가지 순위표가 있어 시청 기록을 돌아보고, 새 작품을 찾고, 각 사이트 계정 상태를 확인할 수 있습니다. 이 페이지에서는 각 숫자의 뜻, 데이터 출처, 이상할 때 먼저 볼 곳을 알려 줍니다.

## 먼저 알아 두기

> **홈 화면**: 로그인 후 기본으로 열리는 페이지입니다. 자주 확인하는 정보를 한 화면에 모아 메뉴를 여기저기 열지 않아도 되게 합니다.

> **순위표**: 어떤 기준으로 매긴 순위나 통계입니다. 여기에는 세 가지가 있고 각각 다른 데이터를 쓰므로 서로 영향을 주지 않습니다.

> **자동 새로고침**: 직접 누르지 않아도 페이지가 일정 간격으로 숫자를 다시 가져와 조용히 갱신합니다.

카드 순서는 고정입니다. 저장 공간, 미디어 통계, 날씨, 네트워크 정보, 시스템 정보, AMMDS 서비스 상태, 응원하기. 화면이 좁으면 세로로 쌓여 전체 너비 행이 됩니다.

## 카드 읽기

### 저장 공간

왼쪽에 고리형 그래프, 오른쪽에 두 수치입니다.

| 보이는 것 | 뜻 |
| --- | --- |
| 전체 용량 | AMMDS를 돌리는 기기의 디스크 총용량입니다. Linux와 컨테이너는 데이터 폴더가 있는 파일 시스템 기준, Windows는 모든 드라이브를 더합니다 |
| 영상 용량 | 등록된 영상 파일을 모두 합한 크기입니다. 만화·소설, 다운로드 중인 파일은 포함하지 않습니다 |
| 사용함 / 남은 공간 | 디스크 전체의 사용량과 여유량이며, 고리 그래프의 두 구간이 됩니다 |

10초마다 자동으로 갱신됩니다.

### 미디어 통계

한 줄에 다섯 개입니다. 즐겨찾기 영상, 즐겨찾기 배우, 구독 영상, 만화(앨범 수), 소설. 역시 10초마다 갱신됩니다. 0이라고 고장이 아니라 아직 해당 데이터가 없다는 뜻입니다.

### 날씨

아이콘, 기온, 날씨 상태, 바람 방향과 세기, 성과 도시를 보여 줍니다.

- 도시는 먼저 集成应用 → 高德地图（연동 앱 → 가오더 지도）에서 설정한 도시 코드(`adcode`, 3~6자리 도시 번호)를 씁니다.
- 설정하지 않으면 먼저 공인 IP를 조회해 도시로 환산합니다.
- 직접 가오더 지도 설정을 켜지 않았다면 프로그램 내장 키를 써서 날씨가 그대로 표시됩니다.

> **프록시**: 대상 사이트에 바로 접속하지 않고 백엔드 서버가 대신 요청을 전달하게 하는 것입니다. 직접 연결이 실패하면 자동으로 이 경로로 바뀝니다.

실패하면 카드에 「天气信息加载失败（날씨 정보를 불러오지 못했습니다）」와 重试（다시 시도）버튼이 나옵니다.

:::note[날씨에는 인터넷이 필요합니다]
날씨는 가오더 지도 서비스에 의존합니다. 직접 연결이 실패하면 백엔드 경유로 바뀌고, 두 경로 모두 안 될 때만 실패로 표시합니다. 그때는 먼저 이 섹션의 [인터넷이 안 되나요? 먼저 여기를](./network.md) 보세요.
:::

### 네트워크 정보

서버 쪽에서 본 공인 주소, 사용 중인 연결 종류, 위치, 프록시 사용 여부를 보여 줍니다. 팝업에는 连通性（연결성）탭도 있어 프로그램이 쓰는 공개 사이트를 하나씩 검사할 수 있습니다. 판정 기준과 점검법은 별도 페이지 [인터넷이 안 되나요? 먼저 여기를](./network.md)에 있습니다.

### 시스템 정보

기본에는 네 줄만 있어 버전을 빠르게 확인할 수 있습니다.

| 줄 | 내용 |
| --- | --- |
| Java 버전, Spring Boot | 프로그램이 의존하는 하위 실행 환경의 버전입니다. 평소에는 신경 쓰지 않아도 됩니다 |
| AMMDS 코어 버전 | AMMDS 자체 버전입니다. 최신판인지는 이것으로 확인합니다 |
| 실행 시스템 | 운영체제와 아키텍처입니다. 컨테이너 안에서는 모두 `Docker`로 표시됩니다 |

> **컨테이너**: 프로그램과 필요한 것들을 격리된 상자에 묶어 실행하는 설치 방식입니다. 상자 안의 시스템은 모두 `Docker`로 기록됩니다.

카드 아무 곳이나 누르면 「系统信息详情（시스템 정보 상세）」가 열리며 두 부분입니다.

- **서버 정보**: 앱 이름과 설명, 세 가지 버전, 실행 환경과 공급사, 시스템과 아키텍처, 프로세서 코어 수, 메모리 사용량, 가동 시간, 서버 시각과 시간대, 수신 주소, 개발사와 공식 사이트, 연락 이메일.
- **브라우저 정보**: 브라우저 식별자, 실행 플랫폼, 언어, 시간대, 화면과 창 크기, 픽셀 비율, 논리 코어 수, 기기 메모리, 네트워크 상태, Cookie 지원 여부, 현재 주소.

이 데이터는 홈 화면에 들어올 때 한 번 가져와 상세에서 재사용하며, 이 네 줄은 주기적으로 갱신되지 않습니다.

### AMMDS 서비스 상태

여섯 숫자이며 모두 최근 24시간 기준입니다.

| 지표 | 뜻 |
| --- | --- |
| 접속자 수 | 현재 접속 중인 방문자 수 |
| 조회수 | 최근 24시간 페이지 조회수 |
| 순 방문자 | 최근 24시간 순 방문자 수 |
| 방문 | 최근 24시간 방문 횟수 |
| 이탈률 | 최근 24시간 이탈률 |
| 평균 체류 시간 | 총 체류 시간을 방문 횟수로 나눈 값이며 일 / 시 / 분 / 초로 표시합니다 |

:::warning[이건 내 기기 상태가 아닙니다]
이 숫자는 AMMDS 공식 통계 서비스에서 오며 **공식 사이트**의 이용 상황을 보여 줄 뿐, 내 AMMDS의 실행 지표가 아닙니다. 10초마다 갱신되고 통계 서비스에 닿지 않으면 모두 0이 될 수 있습니다. 내 기기의 CPU·메모리·디스크·DB 연결·플러그인 상태는 「系统检查（시스템 점검）」, 내 기기의 포트·버전·수신 주소는 위의 「系统信息（시스템 정보）」카드를 보세요.
:::

### 응원하기

누를 수 있는 이미지로, 누르면 공식 상점 구매 페이지를 새 탭으로 엽니다. 어떤 통계에도 포함되지 않고 기능에도 영향이 없습니다.

## 세 가지 순위표, 각자 하는 일

세 가지 모두 대시보드 아래에 있고 데이터 출처가 완전히 다릅니다. 일부만 켜도 됩니다.

### 내가 얼마나 봤는지 돌아보기 —— 巅峰榜单（최고 순위표）

> **미디어 서버**: Jellyfin, Emby처럼 파일을 보관하고 TV·휴대폰으로 재생해 주는 소프트웨어입니다.

재생 기록은 Jellyfin과 Emby 연동에서 옵니다. 플러그인을 켜고 사용자를 연결하면 백엔드가 5분마다 재생 기록을 동기화해 로컬에 저장합니다. 순위표는 **연결한 사용자**만 집계하고 미디어 서버 자체 보고서는 읽지 않습니다.

| 영역 | 내용 |
| --- | --- |
| 상단 통계 | 재생 횟수, 총 시청 시간(분), 일평균 시청(분 / 일), 대상 일수 |
| 재생 추이 / 시청 시간 | 클라이언트별 시청 시간과 합계를 일별로 보여 주는 막대·꺾은선 그래프 |
| 재생 출처 분포 | 클라이언트별 시청 시간을 모은 원형 그래프 |
| 월간 캘린더 | 이번 달 각 날의 시청 열기로, 색이 진할수록 그날 더 많이 봤습니다 |

오른쪽 위 「7 天 / 14 天 / 30 天（7 / 14 / 30일）」버튼은 상단 통계와 추이 그래프에 모두 적용되며 기본값은 14일입니다.

헷갈리기 쉬운 집계 기준:

- 날짜는 재생 기록의 **시작 시각** 기준으로 묶으며 `yyyy-MM-dd`로 통일합니다.
- 종료 시각이 빈 기록은 다 보지 못한 것으로 보고 일별 집계에서 제외합니다.
- 기록이 없는 날도 결과에 나오고(값 0), 그래서 「대상 일수」는 선택한 일수와 같습니다.
- 상단 「재생 횟수」는 시청 시간에서 환산한 값으로 10분마다 1회, 올림입니다. 기록 건수가 아닙니다.
- 월간 캘린더의 「재생 횟수」는 기록 건수로 상단과 기준이 다르며, 마우스를 올리면 둘 다 표시됩니다.

:::note[비어 있으면 먼저 연결을 확인하세요]
페이지가 비었으면 集成应用 → Jellyfin / Emby（연동 앱 → Jellyfin / Emby）에서 플러그인이 켜졌는지, 주소와 키가 연결되는지, 사용자가 연결됐는지 확인합니다. 「系统检查（시스템 점검）」에서도 플러그인 활성·설정 상태를 볼 수 있습니다.
:::

### 최근 새 작품 찾기 —— 电影榜单（영화 순위표）

> **메타데이터**: 작품의 표지·줄거리·출연진·태그 같은 설명 정보입니다.

> **작품 번호**: 파일명에 들어 있는 식별 번호로, AMMDS는 이것으로 작품을 알아봅니다.

데이터는 백엔드 정기 작업이 연동 플러그인에서 모아 로컬에 저장한 것이고, 페이지는 로컬만 읽습니다. 열 때 상위 사이트에 임시로 요청하지 않습니다.

| 순위표 출처 | 어디서 오나 | 수집에 필요한 조건 |
| --- | --- | --- |
| ThePornDB | ThePornDB의 「최근 업데이트」 | 「启用状态（사용）」과 「榜单采集（순위표 수집）」이 모두 켜지고 서비스 주소·API Key가 채워져 있을 것 |
| Fanza DMM | FANZA DMM의 날짜 순위표 | 「启用状态（사용）」과 「榜单采集（순위표 수집）」이 모두 켜짐 |

수집은 모두 백엔드에서 자동 실행되며 누를 것이 없습니다.

- ThePornDB: 시작 약 8분 후 첫 실행, 이후 6시간 10분마다. 1회 최대 10페이지·페이지당 20건이며 「상위 ID + 순위표 종류」로 중복을 제거해 같은 항목이 두 번 들어오지 않습니다.
- Fanza DMM 오늘의 신작: 시작 약 10분 후 첫 실행, 이후 6시간 15분마다. 그날 이미 데이터가 있으면 건너뜁니다.
- Fanza DMM 공개 예정: 시작 약 10분 후 첫 실행, 이후 13시간 30분마다. 앞으로 3일 중 기록이 없는 날짜만 채웁니다.

페이지 사용법:

1. 상단에서 출처를 고릅니다. **ThePornDB** 또는 **Fanza DMM**.
2. 분류를 고릅니다. ThePornDB는 「Jav即将上映（JAV 공개 예정）」「欧美即将上映（서양 공개 예정）」, Fanza DMM은 「今日上新（오늘의 신작）」「即将上映（공개 예정）」.
3. 카드는 공개일 최신순으로 최대 30건입니다. 표지, 작품 번호, 공개일, 제목, 출연진, 스틸 사진 수가 들어갑니다.
4. 카드 오른쪽 위가 상태 버튼입니다.

| 버튼 | 뜻 |
| --- | --- |
| 完成（완료） | 이 작품 번호는 이미 등록되어 버튼을 누를 수 없습니다 |
| 订阅（구독） | 아직 구독 전입니다. 누르면 구독을 등록하고 백엔드가 작품 정보를 채웁니다 |
| 已订阅（구독됨） | 이미 구독 기록이 있어 버튼을 누를 수 없습니다 |

:::tip[구독한 뒤에는]
구독하면 구독 기록이 생기고 백엔드에서 작품 정보가 보충된 뒤, 구독·다운로드 흐름에서 자원을 맞춰 봅니다. 오래 진전이 없으면 먼저 다운로더 플러그인과 사이트 설정을, 다음에 구독 상태를 확인하세요.
:::

### 각 사이트 계정 상태 보기 —— PT 站点榜单（PT 사이트 순위표）

> **PT 사이트**: 계정 가입이 필요하고 업로드·다운로드량으로 점수를 매기는 자료 사이트입니다.

> **시딩(做种)**: 다운로드를 마친 뒤에도 열어 두어 다른 사람이 파일을 받게 하는 행동입니다.

> **비율(分享率)**: 업로드량을 다운로드량으로 나눈 값으로, 사이트는 보통 일정 값 이상을 요구합니다.

> **마력 값(魔力值)**: 시딩 같은 기여에 대해 사이트가 주는 포인트입니다.

데이터는 설정해 둔 PT 사이트 계정에서 사이트 체계별로 가져옵니다. M-Team, Rousi, FSM, NexusPHP 계열 사이트입니다. 먼저 「站点认证（사이트 인증）」을 마칠 필요는 없고, 사이트가 설정되고 데이터를 동기화했으면 표시됩니다.

| 지표 | 집계 방법 |
| --- | --- |
| 사이트 총수 | 데이터가 있는 사이트 수 |
| 총 업로드 / 총 다운로드 | 각 사이트의 업로드·다운로드 바이트 합계 |
| 총 시드 수 / 총 다운로드 수 | 각 사이트의 시드·다운로드 작업 수 합계 |
| 평균 비율 | 비율이 있는 사이트만 평균 |
| 총 마력 값 | 각 사이트의 마력 값 합계 |
| 활성 사이트 | 최근 30일 안에 로그인 기록이 있는 사이트 수 |

각 사이트 카드에는 로고, 이름, 체계 태그 외에 비율, 마력 값, 업로드량, 다운로드량, 시드 수, 다운로드 수, 시드 시간, 다운로드 시간, 사용자 이름과 아바타, 경고 / 흡혈 / 등급 태그, 가입일시와 마지막 로그인이 나옵니다. 오른쪽 위에 두 버튼, 刷新（새로 고침, 이 사이트만）와 打开主页（홈 열기）가 있습니다. 새로 고침은 체계에 맞는 인터페이스를 호출하고 NexusPHP 계열은 사이트 ID로 갱신합니다.

상단에 작업이 두 개 더 있습니다.

| 버튼 | 역할 |
| --- | --- |
| 刷新数据（데이터 새로 고침） | 로컬에 있는 사이트 데이터만 다시 읽고 사이트에는 요청하지 않습니다 |
| 更新所有站点（모든 사이트 갱신） | 백엔드가 각 사이트에서 최신 데이터를 하나씩 가져오게 합니다. 오래 걸립니다 |

상단 안내줄에는 이 페이지에서 마지막으로 갱신한 시각이 나옵니다. 페이지 안의 타임스탬프일 뿐, 서버에서 데이터가 실제로 갱신된 시각은 아닙니다.

:::warning[갱신을 계속 누르지 마세요]
「更新所有站点（모든 사이트 갱신）」을 자주 누르면 각 사이트로 요청이 연달아 날아가 이상으로 판단돼 일시 차단될 수 있습니다. 실시간 데이터가 꼭 필요하지 않다면 기본 간격을 유지하세요.
:::

## 문제가 생기면

- 저장 공간이 「存储管理（저장소 관리）」숫자와 다름: 기준이 다릅니다. 이 카드는 디스크 전체와 영상 파일 합계, 「存储管理」는 `data/`·`db/` 바로 아래 1단계 폴더별로 셉니다.
- 미디어 통계가 계속 0: 즐겨찾기·구독·만화·소설 데이터가 실제로 있는지 확인하세요. 막 설치했다면 0이 정상입니다.
- 날씨 도시가 틀림: 集成应用 → 高德地图（연동 앱 → 가오더 지도）에서 도시 코드를 바로잡거나, 사용자 도시를 꺼서 공인 IP 위치 확인에 맡깁니다.
- 「AMMDS 서비스 상태」가 전부 0: 공식 통계 서비스에 닿지 않은 것뿐입니다. 내 기기 기능과 무관하므로 조치가 필요 없습니다.
- 순위표가 빔: 巅峰榜单（최고 순위표）는 연결 사용자, 电影榜单（영화 순위표）는 수집 스위치와 플러그인 설정, PT 站点榜单（PT 사이트 순위표）는 사이트 설정·동기화 여부를 확인합니다.
