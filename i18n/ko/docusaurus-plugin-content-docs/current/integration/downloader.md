# 자료를 자동으로 받기

자료를 찾았다고 끝이 아닙니다. 실제로 받아 줄 프로그램이 있어야 합니다. 이 페이지는 세 가지를 다룹니다. qBittorrent가 내려받기를 맡는 것, Transmission을 다운로더로 등록하는 것, IYUU로 이미 가진 토렌트를 추가 파종하는 것.

> **다운로더**: 실제로 내려받는 프로그램입니다. AMMDS는 찾아서 일을 넘길 뿐이고, 내려받기 자체는 다운로더가 합니다.

> **추가 파종(크로스 시드)**: 같은 자료가 다른 사이트에도 있을 때, 이미 가진 토렌트를 그 사이트에도 넣어 거기서도 계속 올리는 일입니다. 올린 양을 늘릴 수 있습니다.

> **파종 유지(시드)**: 내려받은 뒤에도 파일을 지우지 않고 남에게 계속 나눠 주는 일입니다. 대부분의 PT 사이트가 이것을 기여로 기록합니다.

> **포트**: 한 기기에서 여러 서비스를 갈라보는 번호입니다. 주소 끝에 적습니다. 예: `8080`. 틀리면 다른 서비스로 붙습니다.

## 먼저 역할 나눔을 확인

여기를 틀리면 헛수고가 됩니다.

| 할 수 있는 일 | 누가 맡는가 |
| --- | --- |
| 구독 자동 내려받기 | **qBittorrent** |
| IYUU 자동 추가 파종 | **qBittorrent** |
| 다운로더 등록과 연결 확인 | qBittorrent와 Transmission 둘 다 |
| 시스템 점검의 플러그인 상태 확인 | qBittorrent와 Transmission 둘 다 |

즉, **Transmission만 있으면 구독 자동 내려받기가 그것으로 돌지 않습니다.** 자동 내려받기를 원하면 qBittorrent가 있어야 합니다.

## qBittorrent

qBittorrent는 내려받기 흐름의 끝입니다. 구독이 맞춘 자료를 여기가 디스크에 쓰고, IYUU가 추가 파종으로 넣은 토렌트도 여기가 받습니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 다운로더 → qBittorrent |
| 통신 | qBittorrent 웹 관리 화면의 창구 |
| 인증 | 웹 관리 화면의 로그인 이름과 비밀번호 |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 내려받기 관련 창구가 모두 'qBittorrent가 꺼져 있음'을 돌려줍니다 |
| 서비스 주소 | 기본 `http://127.0.0.1:8080`. 프로토콜 포함. 컨테이너라면 호스트 주소나 서비스 이름 | 컨테이너에서 `127.0.0.1`을 적으면 AMMDS 자신에게 붙습니다 |
| RPC 경로 | 기본 `/`. 웹 화면이 `/qbittorrent` 같은 아래 경로에 있으면 같은 값으로 | 안 맞으면 로그인이 404가 되어 '연결 테스트는 통과하는데 정보 가져오기 실패'가 납니다 |
| 사용자 이름 | 기본 `admin` | 틀리면 앱 정보를 못 가져옵니다 |
| 비밀번호 | 웹 관리 화면 로그인 비밀번호 | 위와 같음 |

:::warning[역방향 프록시 경로를 맞추기]
qBittorrent가 아래 경로에 있으면 'RPC 경로'를 거기에 맞추세요. 안 맞으면 로그인이 404가 됩니다.
:::

### 단추

| 단추 | 나오는 것 |
| --- | --- |
| 연결 테스트 | 서비스 주소에 닿는지 확인 |
| 앱 정보 가져오기 | 사용자 이름, 주소, 기본 저장 위치, 창구 버전, 프로그램 버전, 토렌트 수 |

'앱 정보 가져오기'가 자격 증명을 확인하는 가장 확실한 길입니다. 기본 저장 위치와 토렌트 수가 오면 로그인이 된 것이고 창구 버전도 맞다는 뜻입니다.

### 저장 위치와 태그

| 항목 | 동작 |
| --- | --- |
| 저장 위치 | 구독 설정의 **내려받을 폴더**를 우선. 없으면 qBittorrent의 기본 저장 위치로 감 |
| 분류 | 추가할 때 분류를 넘길 수 있음. 구독에서 보낼 때는 기본으로 지정하지 않음 |
| 태그 | 구독에서 보낼 때 `AMMDS订阅` 태그와 출처 사이트 태그가 붙습니다. 나중에 멈출 토렌트에는 `AMMDS暂停` 태그도 붙습니다 |
| 위치의 주인 | 저장 위치는 **다운로더가 도는 기기**의 경로이며 AMMDS 컨테이너의 경로가 아닙니다 |

:::tip[경로 적는 법]
AMMDS와 qBittorrent가 다른 컨테이너라면 qBittorrent가 보는 경로(예 `/downloads`)를 적습니다. AMMDS에서 붙이기 전의 경로가 아닙니다.
:::

### 내려받기 한 바퀴

1. **구독 검색**이 사이트에서 자료를 맞춥니다.
2. **내려받기 보내기**: 얻은 토렌트 주소로 qBittorrent에 추가하며 저장 위치와 구독 태그를 붙입니다.
3. **상태 되짚기**: 태그로 작업을 찾아, 끝났으면 구독을 완료로 하고 알림을 보냅니다. 작업이 사라졌으면 실패로 적습니다.
4. **추가 파종**: IYUU가 넣은 토렌트도 qBittorrent가 받습니다. 지금 버전의 자동 추가 파종은 qBittorrent만 됩니다.

평소의 멈춤·시작·지우기·묶음 처리는 **도구함 → 다운로더 → 작업 관리**에서 합니다.

## Transmission

Transmission은 가벼운 내려받기 프로그램입니다. AMMDS는 그 창구로 인스턴스를 등록하고 닿는지 확인하며, 아울러 시스템 점검 대상에도 넣습니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 다운로더 → Transmission |
| 창구 경로 | 기본 `/transmission/rpc`. 다운로더 설정과 같아야 합니다 |
| 인증 | 창구의 사용자 이름과 비밀번호(인증을 켰다면) |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 시스템 점검의 플러그인 상태 확인에 안 붙습니다 |
| 서비스 주소 | 기본 `http://127.0.0.1:8080`. **실제 포트로 반드시 고치세요** | 안 고치면 qBittorrent의 포트로 붙습니다 |
| RPC 경로 | 기본 `/transmission/rpc`. 역방향 프록시가 경로를 바꿨으면 같이 고침 | 안 맞으면 데이터를 못 가져옵니다 |
| 사용자 이름 | 기본 `admin` | 인증이 켜졌을 때 틀리면 연결이 안 됩니다 |
| 비밀번호 | 창구 인증 비밀번호 | 위와 같음 |

:::warning[기본 포트는 꼭 고치기]
Transmission이 흔히 쓰는 포트는 `9091`인데, 여기의 기본값은 `8080`(qBittorrent 기본과 같음)입니다. 둘을 함께 쓰면 Transmission의 실제 포트로 바꾸세요.
:::

'연결 테스트'는 주소를 살펴보고 무슨 응답이든 오면 성공으로 봅니다. 주의할 점은 Transmission 창구가 식별자가 없으면 409를 돌려주는데, **409도 응답**입니다. 그러니 테스트가 통과했다는 것은 주소와 포트가 맞다는 뜻이고, 사용자 이름과 비밀번호가 맞다는 뜻은 아닙니다.

:::note[시스템 점검이 쓰는 방식]
시스템 점검은 이 플러그인의 '사용 상태'와 '서비스 주소'를 읽습니다. 켜졌는데 주소가 비었거나 닿지 않으면 플러그인 상태 확인에서 이상으로 표시되고, 영향을 받는 기능은 '토렌트 내려받기 보내기'로 나옵니다.
:::

## IYUU

IYUU는 토렌트의 특징을 단서로 다른 사이트를 찾아 주는 서비스입니다. 이미 파종 중인 토렌트를 다른 사이트와 견주어, 같으면 그 사이트에도 넣어 파종을 이어 갑니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 다운로더 → IYUU |
| 토큰 | IYUU 공식 사이트에 로그인해 사용자 센터에서 계정 토큰을 복사 |
| 나눔 | IYUU는 **찾기**만 합니다. 다운로더에 실제로 넣는 것은 qBittorrent입니다 |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 추가 파종 창구와 보내기 테스트가 모두 실패합니다 |
| API 서비스 주소 | 기본 `https://2025.iyuu.cn` | 틀리면 연결이 안 됩니다 |
| 서비스 주소 | 기본 `https://iyuu.cn`. 화면 이동과 관리 화면 입구에 사용 | 틀려도 이동만 달라집니다 |
| 키 | IYUU 계정 토큰. 창구에서 신분을 나타내는 표식 | 비면 추가 파종과 보내기가 모두 실패. 계정을 바꾸면 토큰도 바꿉니다 |
| 그림 숨기기 | 기본 **켜짐**. 켜면 만들어지는 메시지에 그림이 없습니다 | 끄면 메시지에 그림이 붙습니다 |

### 단추

| 단추 | 확인하는 것 |
| --- | --- |
| 연결 테스트 | 'API 서비스 주소'에 닿는지. 토큰은 확인하지 않습니다 |
| 보내기 테스트 | 내장 형식으로 실제로 한 통을 보내 토큰과 알림 흐름을 확인 |

### 추가 파종 예약

**도구함 → PT 추가 파종 → 사이트 관리**에서 '파종 예약'을 누르면 설정 창이 열립니다.

| 항목 | 내용 |
| --- | --- |
| 사용 | 자동 추가 파종을 할지 |
| 실행 주기 | 정해진 때를 적는 식. 비면 예약을 등록하지 않고 손으로만 |
| 파종 클라이언트 | 파종을 맡을 다운로더.**지금 버전에서는 qBittorrent만 됩니다** |
| 알림 | 파종이 끝나면 알림을 보낼지 |

보내기 전에 주기 식을 검사하고, 잘못된 식은 저장이 거부됩니다.

### 흐름

1. 예약대로 또는 '지금 파종'으로 손수 시작합니다.
2. 시작할 때 30~300초의 무작위 대기를 두어 여러 대가 동시에 IYUU를 두드리지 않게 합니다.
3. 한 바퀴에 최대 100건의 '파종 대기'를 꺼내 하나씩 IYUU에 파종 가능한 사이트를 묻습니다.
4. 사이트 요구에 맞춰 넣는 방식을 고릅니다. 인증이 필요한 사이트는 토렌트 파일을 먼저 받고, 쿠키가 필요한 사이트는 사이트 쿠키를 붙이고, 나머지는 토렌트 주소를 바로 보냅니다.
5. 사이트별 결과는 바로 기록되고 상태는 `파종 안 됨`, `파종 대기`, `파종 완료`, `파종 실패` 중 하나가 됩니다.

:::warning[전제 조건은 IYUU 계정에]
자동 추가 파종은 IYUU 계정에서 파종이 켜져 있고 파종 클라이언트가 qBittorrent로 지정돼 있어야 합니다. 이 스위치는 IYUU에 있고 AMMDS에 없습니다. 계정 쪽이 꺼져 있으면 여기서 시작해도 아무 일이 없습니다.
:::

### 사이트와 기록

| 화면 | 쓰임 |
| --- | --- |
| 도구함 → PT 추가 파종 → 사이트 관리 | 파종 가능 사이트 카드, 사이트 설정 변경, **사이트 가져오기**(JSON 설정 파일), '지금 파종' |
| 도구함 → PT 추가 파종 → 파종 기록 | 작업 단위 기록: 자동 / 수동, 결과, 개수, 시각, 이유 |
| 도구함 → PT 추가 파종 → 파종 작업 | 토렌트 단위 내역: 상태, 파종 시각, 맞은 사이트 토렌트, 실패 이유 |

기록과 작업 목록은 모두 비울 수 있고, **비우기는 되돌릴 수 없습니다**.

## 문제가 생겼을 때

- **'다운로더가 꺼져 있음'**: 해당 플러그인의 '사용 상태'를 켜고 저장하세요.
- **연결 테스트는 통과하는데 정보 가져오기 실패**: 사용자 이름이나 비밀번호가 틀렸거나, 'RPC 경로'가 실제 경로와 안 맞습니다.
- **토렌트 추가 실패**: 저장 위치가 다운로더 기기에 없습니다. 다운로더가 보는 유효한 경로를 쓰세요.
- **구독이 끝까지 안 끝남**: `AMMDS订阅` 태그를 손으로 바꾸지 마세요. 바꾸면 되짚을 때 못 찾습니다.
- **내려받았는데 등록이 안 됨**: 스캔 폴더와 저장 위치가 다릅니다. 스캔 작업의 폴더 설정을 확인하세요.
- **'지금 파종'이 0을 돌려줌**: '파종 대기' 기록이 없거나 IYUU 계정에서 파종이 꺼져 있습니다.
- **'지원하지 않는 클라이언트'**: 파종 클라이언트로 Transmission이 골라졌습니다. qBittorrent로 바꾸세요.
- **'파종 실패'가 많음**: 사이트가 쿠키를 요구하거나 인증이 만료됐습니다. 사이트 카드에서 값을 갱신하고 다시 하세요.
- **보내기 테스트가 안 옴**: 토큰이 틀렸거나 시스템 쪽 알림 스위치가 꺼져 있습니다.
