# 자료는 어디서 찾나요

AMMDS가 작품을 찾게 하려면 '어느 사이트를 볼지' 알려 주어야 합니다. 이 페이지는 사이트 자료 연동을 한곳에 모아, 각각이 무엇인지, 계정이 필요한지, 설정을 어떻게 채우는지 알려 줍니다.

> **사이트 자료**: AMMDS가 자료를 찾으러 가는 곳입니다. 대부분 초대가 필요한 공유 사이트이고, 직접 구축하는 검색 서비스도 있습니다.

> **PT 사이트(공유 사이트)**: 올리는 양으로 돌아가는 자료 사이트입니다. 내려받으면서 남에게도 올리게 되고, 사이트가 그 기록을 남깁니다. 오래 로그인하지 않으면 계정이 삭제될 수 있습니다.

> **토렌트**: 파일이 어디 있고 누가 가지고 있는지 적어 둔 작은 파일, 또는 링크입니다. 다운로드 프로그램이 이것으로 시작합니다.

> **마그넷**: 다운로드 프로그램에 바로 넘길 수 있는 한 줄의 글입니다. 토렌트 파일과 같은 일을 하지만 사이트에 파일을 맡길 필요가 없습니다.

> **RSS**: 사이트가 새 내용을 정해진 형식으로 늘어놓은 목록입니다. 다른 프로그램이 정해진 때에 와서 읽습니다.

> **인증**: 상대에게 '내가 이 계정의 주인이다'라고 밝히는 일입니다. 보통 나와 사이트만 아는 문자열로 합니다.

## 먼저 둘 확인

1. **사이트 계정은 스스로 준비합니다.** AMMDS는 어떤 사이트의 계정도, 초대도, 가입 창구도 주지 않습니다. 건네받은 자격 증명으로 찾기만 합니다.
2. **검색 순서에 기본값이 있습니다.** 구독 검색 순서의 기본값은 `M-Team,NexusPHP,Rousi,Prowlarr`입니다. 앞에 있을수록 결과가 우선하고, 순서에 없는 곳은 맞은 곳 뒤로 밀립니다. **Prowlarr만 예외로 늘어 맨 마지막입니다.**

| 사이트 / 서비스 | 무엇인가 | 계정 | 주된 쓰임 |
| --- | --- | --- | --- |
| M-Team | 종합 공유 사이트. 초대 가입 필요 | 필요: 패스키 + 액세스 토큰 | 구독 검색과 내려받기, 그리고 DMM 작품 정보 |
| NexusPHP | 사이트를 만드는 프로그램.**플러그인 하나가 여러 사이트를 관리** | 필요: 사이트마다 사이트 토큰 | 구독 검색, 사용자 정보 동기화, 경보 |
| KamePT | NexusPHP로 만든 사이트. 독자 플러그인 화면 없음 | 필요: 사이트 토큰. 사이트 인증은 선택 | NexusPHP 플러그인에 넣으면 검색에 참여 |
| Rousi | 종합 공유 사이트. 초대 가입 필요 | 필요: 패스키(임시 인증 코드는 선택) | 구독 검색, 토렌트 상세 보충, 내려받기 링크 |
| FSM | 자체 구조의 사이트 | 필요: 패스키 + API 토큰 | 구독 검색과 내려받기 |
| Prowlarr | 직접 구축하는 색인 모음 서비스 | 필요: Prowlarr 인증 키 | 한 번 요청으로 뒤의 모든 색인을 뒤짐 |
| BitMagnet | 직접 구축하는 토렌트 검색 서비스 | 사이트 계정은 없지만 직접 구축해야 함 | 마그넷 검색, 파일 목록과 폴더 구조 |

## M-Team

M-Team은 두 일을 한꺼번에 합니다. 구독 검색에 참여해 내려받기 주소를 만드는 것과, 사이트에 딸린 DMM 창구로 작품 정보를 주는 것입니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 사이트 자료 → M-Team |
| 네트워크 | 사이트 페이지 도메인과 API 도메인이 다릅니다. 켜기 전에 둘 다 닿는지 확인하세요 |
| 자격 증명 | 패스키: 관리 화면 → 설정 → 메인, '열쇠'에서 메일로 보내기. 액세스 토큰: 관리 화면 → 설정 → 실험실에서 만들어 복사(한 번만 표시) |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 검색도 정보 검색도 계정 보호 확인도 안 합니다 |
| 서비스 주소 | 기본 `https://api.m-team.io/api`. `https://api.m-team.cc/api` 나 `https://api2.m-team.cc/api` 로 바꿀 수 있음 | 틀리면 연결이 안 됩니다 |
| 키(패스키) | 토렌트 내려받기 링크를 만드는 데 사용 | 없으면 **검색은 되고 내려받기가 실패**합니다 |
| 액세스 토큰 | 사이트 창구를 부르는 증표. 검색과 정보 검색이 모두 이것에 기댐 | 없으면 결과가 나오지 않습니다 |
| 임시 인증 코드 | 헤더 `Authorization` 으로 보냄. 일부 창구에서 필요 | 필요할 때만 |
| 계정 보호 알림 | 기본 꺼짐. 로그인 상태를 주기적으로 확인하고 알림 | 오래 로그인하지 않은 계정은 사이트에서 차단·삭제됩니다 |
| 메타데이터 검색 | 기본 꺼짐. 켜면 DMM 창구가 온라인 검색과 정보 가져오기에 참여 | 끄면 검색 테스트가 먼저 켜라고 안내합니다 |

:::warning[두 자격 증명은 서로 대신 못 합니다]
액세스 토큰은 **검색**용, 패스키는 **내려받기 링크 만들기**용입니다. 하나만 넣으면 '찾히는데 못 받는' 또는 '받을 수 있는데 안 찾히는' 상태가 됩니다.
:::

화면에는 테스트가 둘 있습니다. '연결 테스트'는 닿는지만 보고 자격 증명은 확인하지 않습니다. '검색 테스트'는 '메타데이터 검색'을 먼저 켜야 하며 `DMM 메타데이터`, `여배우 / 기획`, `모음집`, `키워드`를 골라 찾을 수 있습니다.

:::tip[정보 기능은 내려받기에 영향 없음]
메타데이터 검색이 영향을 주는 것은 판별과 정보 가져오기 흐름뿐입니다. 꺼도 구독 내려받기는 돌아갑니다.
:::

## NexusPHP

NexusPHP는 널리 쓰이는 사이트 제작 프로그램입니다. 이 플러그인은 '사이트마다 플러그인'이 아니라 **플러그인 하나가 여러 사이트를 관리**합니다. KamePT, Rousi의 NexusPHP 계열, Kelu, NicePT, ilolicon 등을 함께 넣을 수 있고 직접 사이트를 추가할 수도 있습니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 사이트 자료 → NexusPHP |
| 사이트 버전 | 화면에는 NexusPHP 1.9.0+ 호환으로 표시됩니다(바닥글의 `Powered by NexusPHP` 로 확인). 프로그램은 사이트 버전을 자동으로 검사하지 않으므로 참고용으로만 보세요. 오래된 사이트는 호환되지 않을 수 있으니 직접 확인하세요. |
| 사이트 토큰 | 사이트 '관리 패널 → 설정'에서 만듦. 권한은 적어도 '토렌트 목록 보기', '토렌트 상세 보기', '사용자 기본 정보 보기'가 있어야 함 |

### 설정 항목 설명(플러그인)

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 사이트 목록 조회 외의 모든 창구가 거부됩니다 |
| 검색 기능 | 기본 꺼짐. 켜면 사이트가 구독 검색에 참여 | 끄면 이 사이트들은 검색되지 않습니다 |
| 사용자 정보 동기화 | 기본 꺼짐 | 끄면 하나만이든 전부든 동기화가 거부됩니다 |
| 경보 알림 | 기본 꺼짐. 사이트 이상이나 계정 위험을 알림 | 끄면 경보가 오지 않습니다 |

### 사이트 추가

1. '사이트 추가'를 눌러 창을 엽니다.
2. '사이트 이름'은 직접 적어도 되고 공식 목록에서 골라도 됩니다. 목록에서 고르면 주소와 로고가 자동으로 채워집니다.
3. **사이트 토큰**을 넣고 '사용함'이 켜져 있는지 확인합니다.
4. '상태 검사'로 주소와 토큰을 확인하고, 통과하면 '추가'를 누릅니다.

| 항목 | 화면 이름 | 필수 | 비었거나 틀리면 |
| --- | --- | --- | --- |
| `name` | 사이트 이름 | 예 | 검색 결과와 경보에 나오는 표시 이름 |
| `url` | 사이트 주소 | 예 | 첫 화면의 전체 주소. 프로토콜 포함. 틀리면 상태 검사 실패 |
| `logo` | 사이트 로고 | 아니요 | 화면 표시용 |
| `token` | 사이트 토큰 | 예 | 고칠 때 비워 두면 기존 토큰 유지. 권한이 부족하면 '권한 부족'으로 기록됨 |
| `enable` | 사용함 | 예 | 꺼진 사이트는 추가 파종과 사용자 정보 동기화에 안 붙음 |

사이트 카드 오른쪽 위에 단추가 셋 있습니다: **새로고침**(목록 다시 가져오기), **사용자 정보 동기화**(켜진 모든 사이트를 차례로), **사이트 추가**. 동기화는 뒤에서 비동기로 돌고 창구는 바로 '작업이 접수되었습니다'를 돌려줍니다.

:::warning[목록에서 골라도 토큰은 직접]
공식 목록이 채워 주는 것은 이름·주소·로고뿐입니다. 토큰은 반드시 사이트에서 발급받으세요. 목록에 들어 있지 않고, 시스템이 대신 채워 주지도 않습니다.
:::

상태 검사는 사이트의 `/api/v1/sections` 와 `/api/v1/profile` 을 찾아가 '분류와 토렌트를 읽을 수 있는지', '계정 정보를 읽을 수 있는지'를 확인합니다. 권한이 부족하면 로그에 분명히 남습니다.

## KamePT

KamePT는 NexusPHP로 만든 사이트로 **독자 플러그인 화면이 없습니다**. 검색은 NexusPHP 플러그인이 맡고, 따로 '사이트 인증'이라는 길이 있습니다.

| 항목 | 내용 |
| --- | --- |
| 사이트 주소 | `https://kamept.com` |
| 검색 입구 | 연동 앱 → 사이트 자료 → NexusPHP. 사이트를 추가할 때 '사이트 이름'에서 **KamePT** 를 고르면 주소와 로고가 자동으로 채워집니다 |
| 인증 입구 | 오른쪽 위 아이콘 메뉴 → 사이트 인증 → KamePT 선택 |

### 순서

1. NexusPHP 플러그인을 열고 '사용 상태'를 켜고 저장합니다.
2. 'NexusPHP 사이트' 카드에서 '사이트 추가'를 누릅니다.
3. 사이트 이름에서 **KamePT** 를 고릅니다.
4. **사이트 토큰**을 넣습니다(사이트 '관리 패널 → 설정'의 '액세스 토큰'에서 생성). '사용함'은 켜진 채로 둡니다.
5. 먼저 '상태 검사'를 누르고, 통과하면 '추가'를 누릅니다.

### 사이트 인증(선택)

사이트 인증은 플러그인 설정과 다른 길입니다.

1. 오른쪽 위 아이콘 메뉴에서 **사이트 인증**을 엽니다.
2. 사이트 목록에서 **KamePT** 를 고릅니다.
3. 사이트의 **UID** 와 **패스키**를 넣어 보냅니다.
4. 인증이 통과해야 그 결과에 기대는 기능이 쓰입니다. **서비스를 다시 시작할 때마다 다시 인증해야 합니다.**

:::note[검색 결과 이름]
KamePT 결과는 `NexusPHP` 로 기록됩니다. 구독 기본 순서에 NexusPHP가 들어 있으므로 따로 넣을 것은 없습니다. 검색은 먼저 사이트의 주 창구를 묻고, 다음에 설정된 분류를 하나씩 찾아 모읍니다. 한 분류가 실패해도 다른 데는 영향이 없습니다.
:::

## Rousi

Rousi는 **RSS 서비스**와 **API 서비스**를 서로 다른 주소로 따로 설정합니다. 도메인이 다를 수 있기 때문입니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 사이트 자료 → Rousi |
| 기본 도메인 | RSS `https://rousi.pro`, API `https://rousi.pro/api` |
| 자격 증명 | 로그인 → 오른쪽 위 아이콘 → 계정 설정 → 패스키, 복사해서 넣기 |

:::note[사이트 무리의 도메인 차이]
시스템에는 Rousi가 둘 등록되어 있습니다. `rousi.pro` 와 `rousi.zip`(폐쇄 예정 안내 있음)입니다. 플러그인 기본값은 `rousi.pro` 입니다. 다른 도메인을 쓴다면 사이트 사정에 맞춰 두 주소를 고치세요.
:::

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 검색도 내려받기도 계정 보호 확인도 안 합니다 |
| RSS 서비스 주소 | 기본 `https://rousi.pro`. RSS 흐름과, 상대 경로 표지를 온전한 주소로 만들 때 사용 | 틀리면 표지 그림이 깨집니다 |
| API 서비스 주소 | 기본 `https://rousi.pro/api`. 검색 창구는 이것에 `/v1/search` 를 붙인 것 | 틀리면 아무것도 안 잡힙니다 |
| 키(패스키) | 검색할 때 `Bearer` 토큰으로 쓰이고, 내려받기 링크를 만들 때도 쓰임 | 없으면 검색은 되고 내려받기가 실패 |
| 임시 인증 코드 | 헤더 `Authorization` 으로 보냄 | 검색 본줄은 패스키만으로 돕니다. 필요 없으면 비워 둬도 됩니다 |
| 계정 보호 알림 | 기본 꺼짐. 로그인 상태를 주기적으로 확인하고 알림 | 오래 로그인하지 않은 계정은 차단·삭제됩니다 |

테스트 단추는 둘입니다: **RSS 연결 테스트**(RSS 서비스 주소 확인), **API 연결 테스트**(API 서비스 주소 확인. 구독 검색이 기대는 것). 둘 다 닿는지만 보고 패스키는 확인하지 않습니다.

## FSM

FSM은 자체 구조의 사이트로 **NexusPHP가 아니며** 사이트 인증 흐름에도 참여하지 않고 플러그인 설정만 씁니다. 창구와 RSS가 서로 다른 도메인이고, 검색은 API 토큰, 내려받기 링크는 패스키를 씁니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 사이트 자료 → FSM |
| 자격 증명 | 로그인해서 계정 설정에서 패스키와 API 토큰을 확인 |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 검색도 내려받기도 안 됩니다 |
| API 서비스 주소 | 기본 `https://fsm.name/api`. 검색 경로는 이것에 `/Torrents/listTorrents` 를 붙인 것 | 사이트 첫 화면을 적으면 연결이 안 됩니다 |
| RSS 서비스 주소 | 기본 `https://api.fsm.name`. API와 다른 도메인 | 하나만 적으면 그쪽 기능이 안 됩니다 |
| 키(패스키) | 토렌트 내려받기 주소를 얻는 데 사용 | 없으면 검색은 되고 내려받기가 실패 |
| 인증 코드(API 토큰) | 검색할 때의 증표. 헤더 `APITOKEN` 으로 보냄 | 무효면 검색 결과가 빕니다 |

:::warning[둘이 반씩 맡습니다]
API 토큰은 찾을 수 있는지, 패스키는 내려받을 수 있는지를 정합니다. 둘 다 맞아야 흐름이 완성됩니다.
:::

테스트 단추는 둘입니다: **RSS 연결 테스트**와 **API 연결 테스트**. 둘 다 도메인에 닿는지만 보고 자격 증명은 확인하지 않습니다.

:::tip[FSM을 앞에 두려면 순서에 넣기]
구독 기본 순서 `M-Team,NexusPHP,Rousi,Prowlarr` 에는 FSM이 없습니다. 순서에 없는 곳은 우선되지 않지만 빠지지도 않습니다. FSM 결과를 우선하려면 구독 설정의 검색 순서에 `FSM` 을 넣으세요.
:::

## Prowlarr

Prowlarr는 직접 구축하는 색인 모음 서비스입니다. 여러 사이트의 검색을 한 창구로 모으므로, AMMDS는 Prowlarr에만 묻고 나머지는 Prowlarr가 나눠 줍니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 사이트 자료 → Prowlarr |
| 구축 형태 | 직접 준비. AMMDS는 그 주소에 닿기만 하면 됩니다 |
| 직접 연결 사이트와 다른 점 | 직접 플러그인은 사이트 하나만. Prowlarr는 한 번 요청으로 아래의 모든 색인을 덮습니다 |
| 자격 증명 | Prowlarr 관리 화면 → Settings → General → API Key |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 검색하지 않습니다 |
| 서비스 주소 | Prowlarr 주소. 프로토콜 포함. 예: `http://127.0.0.1:9696` | 비면 검색 결과가 비고 로그에 '색인 설정이 미완성'이 남습니다 |
| 인증 키 | Prowlarr의 API 키. 헤더 `X-Api-Key` 로 보냄 | 틀리면 '연결은 되는데 검색이 계속 빔'으로 나타납니다 |

:::warning[둘 다 필요]
서비스 주소와 인증 키는 모두 필요합니다. 하나가 비어도 흐름이 멈추지는 않고, 검색이 계속 빌 뿐입니다.
:::

검색 조건은 성인 분류로 고정됩니다. Prowlarr 쪽에 그 분류를 받는 색인이 없으면 결과가 빕니다. Prowlarr 결과에는 바로 링크가 붙어 있어 내려받을 때 주소를 다시 얻을 필요가 없습니다.

:::tip[보조로 쓰기에 알맞음]
직접 연결 사이트에서 안 잡히는 번호를 Prowlarr가 아래의 모든 색인으로 찾게 하세요. Prowlarr는 늘 맨 뒤라 직접 연결 사이트의 우선순위는 유지됩니다.
:::

## BitMagnet

BitMagnet은 직접 구축할 수 있는 열린 토렌트 검색 서비스입니다. 스스로 계속 토렌트를 찾아 분류합니다. 연결하면 설정한 PT 사이트에만 갇히지 않고 공개된 토렌트를 마그넷 검색으로 찾을 수 있습니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 사이트 자료 → BitMagnet |
| 구축 형태 | **직접 구축이 필수**. AMMDS에는 찾아다니는 장치가 내장되어 있지 않습니다 |
| 포트 | 최소한 화면용 `3333` 과 탐색용 `3334`(TCP/UDP), 그리고 데이터베이스가 필요 |
| 자리 | 구독 검색 순서에 들어가지 않고 마그넷 검색만 맡음 |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 검색과 파일 조회 창구가 'BitMagnet 연동 플러그인이 꺼져 있음'을 돌려줍니다 |
| 서비스 주소 | 기본 `http://127.0.0.1:3333`. 컨테이너라면 `127.0.0.1` 대신 호스트 주소나 서비스 이름(예 `http://bitmagnet:3333`) | `127.0.0.1` 을 적으면 AMMDS 자신에게 붙습니다 |

:::warning[컨테이너 주소 함정]
Docker에서 `127.0.0.1` 은 컨테이너 자신입니다. 호스트 주소나 서비스 이름을 쓰세요.
:::

단추는 둘입니다: **연결 테스트**(주소에 닿는지만), **앱 상태 가져오기**('기본 정보'와 '서비스 상태' 두 탭). 상태에서 탐색 서비스, 데이터베이스, TMDB 셋이 건강한지 볼 수 있습니다.

:::tip[먼저 상태 보기]
검색이 비면 먼저 '앱 상태 가져오기'를 누르세요. 탐색 서비스가 이상하면 아직 토렌트를 못 찾고 있다는 뜻이고, 원인은 AMMDS가 아니라 BitMagnet 쪽입니다.
:::

:::note[구독 순서에 안 들어감]
BitMagnet은 구독 설정의 검색 순서에 없으므로 구독 자동 내려받기가 이것을 쓰지 않습니다. 마그넷 검색 화면을 맡으며, 검색어로 귀한 자료를 찾기에 알맞습니다.
:::

## 문제가 생겼을 때

- **저장했는데 안 잡힘**: '사용 상태'가 켜진 채 저장됐는지 확인하세요. NexusPHP라면 '검색 기능'이 켜졌는지, 사이트가 '사용함'인지도 확인합니다.
- **연결 테스트 실패**: 서비스 주소의 프로토콜과 포트를 확인합니다. 컨테이너의 AMMDS에서 `127.0.0.1` 을 쓰지 마세요. 그리고 밖으로 나갈 수 있는지 확인합니다.
- **잡히는데 내려받기가 안 됨**: 대개 패스키가 비었거나 만료됐습니다. 사이트에서 다시 받으세요.
- **'설정이 사라짐' 안내**: 서비스 주소나 토큰이 빈 것입니다. 채워 저장하고 다시 검색하세요.
- **상태 검사 실패 / 권한 부족**: 사이트 주소가 틀렸거나, 토큰을 덜 복사했거나, 권한이 모자랍니다. 같은 토큰을 되풀이하지 말고 사이트에서 새로 만드세요.
- **FSM 결과가 늘 없음**: FSM은 기본 순서에 없습니다. 필요하면 구독 설정의 검색 순서에 `FSM` 을 넣으세요.
- **계정 보호 알림이 자주 옴**: 브라우저로 사이트에 한 번 로그인하세요. 필요 없으면 알림을 끌 수 있습니다.
