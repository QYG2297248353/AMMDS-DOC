# 휴대전화로 알림 보내기

검사가 끝났다, 구독이 맞았다, 작품이 등록됐다 같은 일을 관리 화면에서 지켜볼 필요는 없습니다. 알림 경로 하나를 붙이면 AMMDS가 그때 알려 줍니다.

> **푸시 알림**: AMMDS가 먼저 휴대전화나 다른 프로그램으로 메시지를 보내는 일입니다. 찾아보러 갈 필요가 없습니다.

> **웹훅(Webhook)**: '무슨 일이 생기면 정해진 주소로 한 마디 보낸다'는 방식입니다. 네트워크 메시지를 받을 수 있으면 무엇이든 AMMDS 알림을 받을 수 있습니다.

> **봇(Bot)**: 채팅 앱 안에 만드는 자동 계정입니다. 명령을 보내면 그대로 일합니다.

## 먼저 경로 하나 고르기

| 경로 | 어울리는 사람 | 준비할 것 | 특징 |
| --- | --- | --- | --- |
| Bark | 아이폰을 쓰고 가장 간단한 것을 원하는 사람 | Bark 앱을 깔고 기기 키를 복사 | 키 하나로 받을 수 있습니다 |
| Telegram | 휴대전화 명령으로 조작하고 싶은 사람 | `@BotFather` 로 봇을 만들고 토큰과 Chat ID를 받음 | **되돌려 조작하는 것에 유일하게 대응**. 검색·구독·작업 실행이 됩니다 |
| Webhook | 직접 만든 서비스나 자동화 흐름으로 흘려 보내고 싶은 사람 | 네트워크 메시지를 받을 수 있는 주소 | 되돌려 받을 곳을 여러 개 두고, 보내는 내용을 마음대로 만들 수 있음 |

:::warning[원 스위치가 세 개 더 있습니다]
경로 설정은 첫 걸음일 뿐입니다. 메시지가 실제로 나가려면 시스템 쪽 스위치(아래 '세 개의 시스템 스위치')도 통과해야 합니다. 하나도 안 오면 먼저 그곳을 보세요.
:::

## Bark

Bark는 iOS용 가벼운 알림 도구입니다. 기기 키 하나로 받을 수 있습니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 알림 → Bark |
| 대상 | iOS(Bark 앱) |
| 서비스 형태 | 공식 `api.day.app`, 또는 직접 세운 서버 |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 보내기 테스트가 'Bark 플러그인을 켜세요'를 돌려주고 알림도 이 경로를 타지 않습니다 |
| 서비스 주소 | 기본 `https://api.day.app`. 직접 세웠으면 그 주소로 | 주소와 키의 출처가 다르면 거부됩니다 |
| 기기 키 | Bark 앱 첫 화면에 나오는 보내는 주소에서 `api.day.app/` 뒤쪽 부분 | 비거나 틀리면 보내기 테스트가 실패합니다 |
| 알림 아이콘 | 기본은 AMMDS 아이콘. 다른 그림 주소로 바꿀 수도 있음 | 주소에 닿지 않으면 아이콘이 안 나옵니다 |
| 알림 묶음 | 기본 `AMMDS`. 같은 묶음은 알림 센터에서 함께 접힙니다 | 비우면 묶이지 않습니다 |
| Markdown 우선 | 기본 꺼짐. 켜면 본문을 Markdown으로 그립니다 | 오래된 앱에서는 어긋날 수 있습니다. 그러면 끄세요 |

### 단추

| 단추 | 확인하는 것 |
| --- | --- |
| 연결 테스트 | 서비스 주소에 닿는지만 확인. 기기 키는 확인하지 않습니다 |
| 보내기 테스트 | 형식으로 실제로 한 통을 보내 키와 서버를 확인 |

이 경로는 상태 조회도 있어 서버 판, 빌드 정보, **등록된 기기 수**를 돌려줍니다. 서버가 정상인지 판단하는 데 쓸 수 있습니다.

:::tip[직접 세운 서버라면]
직접 세운 서버를 쓴다면 '서비스 주소'를 그 주소로 바꾸고, 키도 그 서버가 보여 주는 것을 쓰세요. 출처가 다르면 거부됩니다.
:::

## Telegram

Telegram은 주력 알림 경로이며, 되돌려 조작하는 것에 대응하는 유일한 경로입니다. 알림만 받는 것이 아니라 명령으로 일도 시킬 수 있습니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 알림 → Telegram |
| 메시지 형태 | 글 + 그림. 그림에는 스포일러 가리개를 붙일 수 있음 |
| 양방향 | 알림 + 봇 명령 조작 |
| 자격 증명 | Telegram에서 `@BotFather` 를 찾아 안내대로 봇을 만들고 토큰을 복사 |

### 설정 항목 설명

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 Telegram 창구가 모두 'Telegram 플러그인을 켜세요'를 돌려줍니다 |
| 서비스 주소 | 기본 `https://api.telegram.org`. 직접 만든 역방향 프록시로도 가능 | 틀리면 연결이 안 됩니다 |
| 봇 토큰 | `@BotFather` 가 발급한 토큰 | 비면 Chat ID도 못 받고 보내지도 못합니다 |
| Chat ID | 받을 개인 대화, 그룹, 채널의 ID. 개인은 양수, 그룹과 채널은 보통 음수 | 틀리면 '보내기 테스트는 성공하는데 안 옴'으로 나타납니다. 그룹이라면 봇을 먼저 넣으세요 |
| Webhook URL | 되돌아올 주소. 비면 등록하지 않음 | 등록 전에 시스템 설정에서 도메인 연결이 끝나 있어야 합니다. 없으면 창구가 거부합니다 |
| 스포일러 모드 | 기본 꺼짐. 켜면 그림에 가리개를 붙입니다 | 끄면 그림이 그대로 보입니다 |

### 단추

| 단추 | 하는 일 | 전제 조건 |
| --- | --- | --- |
| Chat ID 가져오기 | 봇의 최근 대화에서 Chat ID를 읽음 | 봇 토큰이 들어 있고, 봇에게 메시지를 한 번 보냈을 것 |
| 명령 등록 | 봇에 명령 목록을 등록 | 서비스 주소와 봇 토큰이 들어 있을 것 |
| Webhook 등록 | 되돌아올 주소를 Telegram에 등록 | 시스템 설정에서 **도메인 연결**이 끝나 있을 것 |
| 보내기 테스트 | 형식으로 한 통을 보냄 | 봇 토큰과 Chat ID가 들어 있을 것 |
| 연결 테스트 | 창구 주소에 닿는지 확인 | 없음 |

명령 등록은 다시 해도 안전합니다. 꼭 필요한 명령(`ammds`, `movie`, `actor`, `resource`, `deepseek`, `system`)이 이미 있으면 다시 보내지 않으므로, 직접 넣은 명령이 덮이지 않습니다.

쓸 수 있는 명령: `/start`, `/stop`, `/help`, `/version`, `/movie`, `/actor`, `/resource`, `/magnet`, `/search`, `/deepseek`, `/system`, `/subscribe`, `/unsubscribe`, `/favorite`, `/unfavorite`, `/scan`, `/scrape`, `/media_sync`, `/restart`.

:::warning[Webhook은 밖에서 닿아야 합니다]
Webhook 등록 전에 시스템 설정에서 도메인 연결을 끝내세요. 없으면 창구가 바로 거부합니다. 집 안 네트워크라면 등록하지 말고 기본 수신 방식으로 명령을 받는 것이 좋습니다.
:::

## Webhook

Webhook은 가장 널리 쓸 수 있는 출구입니다. 특정 앱에 묶이지 않고, 네트워크 메시지를 받을 수 있으면 무엇이든 받을 수 있습니다.

| 항목 | 내용 |
| --- | --- |
| 위치 | 연동 앱 → 알림 → Webhook |
| 특징 | 되돌려 받을 곳을 여러 개 동시에, 보내는 내용을 완전히 직접, 실패하면 다시 보냄 |
| 어울리는 곳 | 사내 시스템, 자동화 흐름, 직접 만든 메시지 관문 |

### 설정 항목 설명(플러그인)

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 사용 상태 | 스위치를 켬 | 끄면 모든 되돌려 받을 곳으로의 전송이 멈춥니다 |
| 재시도 횟수 | 기본 `3`. 실패 뒤 다시 보내는 횟수. 최소 1 | 상대가 가끔 실패하면 늘리는 편이 낫습니다 |
| 재시도 간격 | 기본 `5`초. 재시도 사이에 기다리는 초. 최소 1 | 상대의 제한이 빡빡하면 횟수보다 간격을 늘리는 편이 낫습니다 |

### 설정 항목 설명(되돌려 받을 곳마다)

'Webhook 서비스 관리' 카드의 '새로 만들기'로 만듭니다. 여러 개를 함께 두고 필요한 것만 켤 수 있습니다.

| 설정 항목 | 무엇을 적는지 | 비었거나 틀리면 |
| --- | --- | --- |
| 서비스 이름 | 목록에서 보여 주고 구분하는 데 씁니다 | 필수. 비면 구분이 안 됩니다 |
| 요청 방식 | `POST`, `GET` 등 | 필수. 상대가 요구하는 것과 다르면 거부됩니다 |
| Webhook URL | 알림을 받을 온전한 주소 | 필수. 안 닿으면 전송이 실패하고 재시도합니다 |
| 설명 | 쓰임새 메모 | 선택 |
| 사용 상태 | 꺼도 설정은 남지만 보내지 않습니다 | 끄면 안 옵니다 |
| 헤더 | JSON 배열 형식. 예: `[{"key":"Content-Type","value":"application/json"}]` | 올바른 JSON 배열이 아니면 적용되지 않습니다 |
| 본문 | JSON 형식. 알림 치환 변수를 씁니다 | 틀려도 오류는 아니고 상대에게 엉뚱한 내용이 갑니다 |
| 검사 종류 | `상태 코드` 또는 `응답 본문`. 비면 검사하지 않음 | 판정이 실제와 안 맞으면 늘 실패로 뜹니다 |
| 검사 값 | 기대하는 상태 코드, 또는 응답 본문에 꼭 들어 있어야 하는 글 | 위와 같음 |

목록에서 곧바로 켜기·끄기, 고치기, 지우기를 할 수 있고 되돌려 받을 곳마다 '보내기 테스트'도 됩니다.

### 쓸 수 있는 변수

헤더와 본문 둘 다에서 다음 치환 표식을 쓸 수 있고, 보낼 때 바뀝니다.

| 변수 | 뜻 |
| --- | --- |
| `{{sign}}` | 서명. 알림이 어디서 왔는지 확인하는 데 씁니다 |
| `{{title}}` | 알림 제목 |
| `{{subTitle}}` | 알림 부제목 |
| `{{logo}}` | 로고 그림 주소 |
| `{{image}}` | 내용 그림 주소 |
| `{{message}}` | 본문 |
| `{{time}}` | 보낸 시각 |
| `{{type}}` | 일의 종류 |

본문 예:

```json
{
  "event": "{{type}}",
  "title": "{{title}}",
  "text": "{{message}}",
  "timestamp": "{{time}}",
  "image": "{{image}}"
}
```

:::warning['보냈음'은 '받았음'이 아닙니다]
보내기 테스트가 '푸시 요청을 보냈습니다'라고 하는 것은 요청을 냈다는 뜻이고 상대가 처리했다는 뜻이 아닙니다. 실제 결과는 상대 쪽 로그로 확인하세요. '검사 종류'를 상태 코드나 응답 본문으로 두면 시스템이 규칙대로 판정해 줍니다.
:::

## 세 개의 시스템 스위치

보내기 전에 다음 셋이 차례로 검사됩니다(**시스템 설정 → 알림**).

| 설정 항목 | 무엇을 정하는지 | 안 하거나 틀리면 |
| --- | --- | --- |
| 알림 보내기 사용 | 기본 **켜짐**. 원 스위치 | 끄면 어떤 경로도 조용해지고 하나도 안 나갑니다 |
| 메시지 종류 | 종류 허용 목록. 여러 개는 쉼표로 구분. 기본 `system,subscription,download,library,certification,vip,scrape,actor_scrape` | 고르지 않은 종류는 보내지 않습니다 |
| 밤에는 조용히 | 기본 꺼짐. 켜면 22:00부터 다음 날 08:00까지 안 보냄 | 그 시간대 알림은 '보낼 필요 없음'으로 건너뛰며, **나중에 다시 보내지 않습니다** |

:::note[건너뛰어도 실패가 아닙니다]
조용한 시간이거나 고르지 않은 종류라면 시스템은 '보낼 필요 없음'으로 기록만 남깁니다. 오류도 아니고 나중에 다시 보내지도 않습니다.
:::

## 어떤 일이 생기면 알림이 가나요

세 경로는 같은 알림 내용을 함께 씁니다.

| 종류 | 일어나는 때 |
| --- | --- |
| 시스템 | 서비스 시작 / 정지, 디스크 남은 공간 부족, 계정의 오랜 미로그인 |
| 구독 | 구독이 자료에 맞음, 구독 실패 |
| 내려받기 | 내려받기로 보냄, 내려받기 완료 |
| 등록 | 작품 등록 완료 |
| 인증 | 사이트 인증 결과 |
| 작품 정보 가져오기 | 성공 |
| 배우 정보 가져오기 | 성공 |
| 테스트 | 손으로 하는 보내기 테스트 |

## 문제가 생겼을 때

- **하나도 안 옴**: 시스템 설정의 '알림 보내기 사용'이 켜졌는지, 조용한 시간대인지, 그리고 종류가 허용 목록에 있는지를 차례로 확인하세요.
- **보내기 테스트 실패**: Bark는 기기 키와 주소의 출처를, Telegram은 토큰과 Chat ID를, Webhook은 주소에 닿는지를 확인합니다.
- **Telegram은 성공하는데 안 옴**: Chat ID가 다른 대화의 것이거나 봇이 그룹에서 빠졌습니다. 봇에게 메시지를 한 번 보내고 'Chat ID 가져오기'를 다시 하세요.
- **Chat ID를 못 받음**: 아직 봇에게 메시지를 안 보냈습니다. 한 번 보내고 누르세요.
- **Webhook 등록이 거부됨**: 시스템 설정에서 도메인 연결이 안 끝났습니다.
- **Webhook이 늘 실패로 판정**: 검사 종류·검사 값이 실제 응답과 안 맞습니다. 상태 코드로 바꾸고 `200` 을 넣거나 검사를 비우세요.
- **변수가 안 바뀜**: 잘못 적었습니다. 변수 표와 한 글자씩 비교하세요. 중괄호가 두 쌍인 점도 주의.
- **같은 알림이 겹쳐 옴**: 상대가 시간 초과가 나서 재시도한 것입니다. 상대의 처리를 짧게 하거나 재시도 횟수를 줄이세요.
- **명령 목록이 옛것**: 예전에 일부 명령이 등록되어 있습니다. 지우고 다시 등록하세요.
