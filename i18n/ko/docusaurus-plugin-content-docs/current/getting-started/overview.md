# 설치 방법부터 고르기

AMMDS가 사용자에게 내놓는 것은 **두 가지**뿐이고, 그 안에서 돌아가는 프로그램은 같습니다.

1. **Docker 이미지** —— 실행에 필요한 환경이 이미 갖춰진 컨테이너 묶음입니다.
2. **바이너리 프로그램** —— 바로 실행할 수 있는 실행 파일 하나입니다.

두 가지 모두 GraalVM Native Image 기술로 묶었습니다. 프로그램을 배포하기 전에 미리 하나의 독립 실행 파일로 컴파일해 두므로, 실행할 때 **Java를 설치할 필요가 없고 JAR / WAR 같은 파일도 없습니다**. 내려받는 것은 프로그램 파일 하나이거나, 그 파일이 들어 있는 Docker 이미지입니다. 실행하기만 하면 됩니다.

> **GraalVM Native Image**: 프로그램을 묶는 기술입니다. 프로그램을 미리 하나의 독립 실행 파일로 만들어 두므로, 받은 사람은 실행 환경을 따로 설치하지 않아도 되고 두 번 누르거나 명령줄에서 실행하기만 하면 켜집니다. 원리를 알 필요는 없고 두 가지만 기억하세요. **Java를 설치하지 않아도 된다**, **JAR 파일이 없다**는 점입니다.

> **바이너리 프로그램**: 실행 파일이라고도 부릅니다. Windows에서는 보통 `.exe`로 끝나는 파일이고, Linux에서는 확장자가 없는 파일입니다. AMMDS 배포판에 들어 있는 이 프로그램의 이름은 `ammds`이고(Windows에서는 `ammds.exe`), 정확한 이름은 내려받은 배포판을 기준으로 하세요.

그러므로 '어느 버전의 Java를 설치할까' 'JAR 파일을 어디에 둘까' 같은 안내를 찾아볼 필요가 없습니다. 그런 일은 소스를 직접 컴파일할 때나 하는 것이지, AMMDS를 설치할 때 하는 일이 아닙니다.

아직 못 정했다면 질문 하나에 먼저 답해 보세요. **기기에 Docker가 있나요?** 있으면 Docker를 고르고, 없으면 바이너리 프로그램을 내려받아 바로 실행하세요.

## 시작하기 전 세 가지

| 항목 | 설명 |
| --- | --- |
| 시스템 | 64비트 시스템이 필요합니다. 시스템 점검은 32비트를 경고로 표시하고 FFmpeg 같은 부속 프로그램이 동작하지 않을 수 있다고 알립니다 |
| 실행 환경 | 두 가지 형태 모두 Java나 다른 실행 환경을 따로 설치할 필요가 없습니다. 프로그램에 이미 들어 있습니다 |
| 바이너리 프로그램은 시스템에 맞춰야 함 | 실행 파일은 시스템마다 따로 컴파일되므로 Windows용과 Linux용이 각각 있습니다. 내려받을 때 자기 시스템을 확인하세요 |
| 네트워크 | 정보 자동 채우기, 자료 찾기, 알림 보내기에는 인터넷이 필요합니다. 내부망만 쓰는 곳에서는 이미 있는 로컬 자료만 쓸 수 있습니다 |

> **Docker**: 프로그램을 필요한 환경까지 한꺼번에 담아 실행하는 방식입니다. Docker를 한 번 설치하면 묶음을 받아 바로 실행할 수 있고, 필요한 것을 하나씩 설치하지 않아도 됩니다.

> **이미지**: 프로그램 묶음 파일로, '설치용 디스크' 같은 것입니다. `qyg2297248353/ammds:latest`처럼 적고 콜론 뒤가 버전 태그입니다.

> **컨테이너**: 이미지를 실행한 뒤 실제로 돌고 있는 그 한 벌입니다.

## 두 가지 비교

| 방법 | 어떻게 돌아가나요 | 누구에게 맞나요 | 나중에 어떻게 올리나요 |
| --- | --- | --- | --- |
| Docker 이미지 | 컨테이너 하나에서 화면 서비스와 본체가 함께 돌고, 밖으로는 포트 하나만 내보냅니다 | Docker가 설치된 Linux 서버와 NAS | 새 이미지를 받아 컨테이너를 다시 만듭니다. 자료는 연결해 둔 디렉터리에 남습니다 |
| 바이너리 프로그램 | 실행 파일 하나를 바로 실행하며, 화면과 창구를 모두 그것이 제공합니다 | Docker가 없는 Windows / Linux 기기, 또는 프로세스 하나를 직접 관리하고 싶은 분 | 새 버전의 실행 파일로 바꾼 뒤 다시 실행합니다 |

### 고르는 법

| 내 상황 | 권하는 것 |
| --- | --- |
| 서버에 Docker가 이미 있거나, 포트·디렉터리·부팅 시 자동 실행을 한곳에서 관리하고 싶음 | Docker. [Docker로 설치하기](./docker.md)를 보세요 |
| 기기가 FnOS나 QNAP이고, 앱 센터에서 프로그램을 관리하는 게 익숙함 | NAS 앱 패키지. [NAS에 설치하기](./nas.md)를 보세요 |
| Windows / Linux 기기에 Docker가 없고 프로그램 하나를 바로 실행하고 싶음 | 바이너리 프로그램. [Windows / Linux에서 직접 실행하기](./native.md)를 보세요 |
| 시스템 서비스에 맡겨 프로그램 하나를 부팅 때 자동으로 띄우고 싶음 | 바이너리 프로그램. [Windows / Linux에서 직접 실행하기](./native.md)를 보세요 |

:::note[NAS 앱 패키지는 세 번째 프로그램이 아닙니다]
FnOS와 QNAP의 '앱 패키지'는 이 기기들이 프로그램을 대신 설치하고 관리해 주는 통로일 뿐입니다. 그 안에는 위에서 말한 것과 똑같은 프로그램이 들어 있습니다. 두 가지 방식과 부딪히지 않으며, 명령을 직접 입력하는 단계를 줄여 줄 뿐입니다.
:::

## 포트: 설치 뒤 어느 주소로 열까요

| 방법 | 브라우저에서 쓰는 포트 | 설명 |
| --- | --- | --- |
| Docker | 컨테이너 안은 `80`이고, 기기 쪽 포트는 직접 정합니다 | `8080:80`으로 이어 주면 `http://기기주소:8080`으로 엽니다 |
| 바이너리 프로그램 | `8080` | '서비스 포트' 설정 항목으로 바꿀 수 있습니다 |
| NAS 앱 패키지 | 설치할 때 직접 정한 것 | 설치 뒤에는 `http://NAS주소:포트`로 엽니다 |

Docker 이미지는 안에서 본체용으로 `8080` 포트를 하나 더 띄우지만, 컨테이너 안에서만 화면 서비스가 넘겨 줄 뿐이므로 기기 쪽으로 이어 줄 필요가 없습니다.

:::note[휴대폰이나 클라이언트가 자동으로 찾게 하려면]
데스크톱 클라이언트는 같은 네트워크에서 AMMDS를 자동으로 찾는데, 두 개의 UDP 포트(`47823` 찾기, `47824` 알림)를 씁니다. Docker는 TCP만 넘기므로 자동 찾기를 쓰려면 이 두 UDP 포트를 따로 이어 주어야 합니다. 필요 없다면 클라이언트에 서비스 주소를 직접 적어도 됩니다.
:::

## 자료 디렉터리: 어디에 두는지 먼저 확인하세요

어느 방식을 쓰든 프로그램은 **실행한 자리**를 기준으로 상대 경로를 읽습니다. 고정된 디렉터리를 하나 만들고 거기서 실행하세요.

| 디렉터리 | 무엇이 들어있나요 |
| --- | --- |
| `data/` | 그림, 임시 저장, 자막, 기록, 복구 키, 그리고 자동으로 받는 FFmpeg 같은 부속 프로그램 |
| `db/` | 데이터베이스 파일입니다. 작품, 작업, 설정 등 모든 자료가 담깁니다 |
| `download/` | 이미지가 미리 마련해 둔 디렉터리로, 보통 다운로더의 저장 폴더와 함께 써 받은 뒤 바로 스캔하기 좋습니다 |
| `data/logs/` | 실행 기록입니다. 시스템 점검과 '실행 기록' 화면이 여기를 읽습니다 |

:::tip[백업 우선순위]
`db/`와 `data/`는 반드시 남겨야 하는 둘입니다. 앞쪽은 모든 자료, 뒤쪽에는 그림과 복구 키가 있습니다. 영상 파일은 평소 방식대로 하세요.
:::

## 설정 항목

설치 단계에서 정하는 것은 이 정도입니다. 잘못 정했을 때 어떻게 되는지도 봐 주세요.

| 설정 항목 | 무엇을 정하나요 | 정하지 않으면 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 서비스 포트(`AMMDS_SERVER_PORT`) | 브라우저에서 열 때 쓰는 번호 | 프로그램 기본값(`8080`)을 씁니다 | 필요 |
| 미디어 디렉터리 경로 | 작품 파일을 어디에서 찾을지 알려 줍니다 | 스캔할 대상이 없어집니다. 잘못 적으면 아무것도 못 찾아 '사라진 것'처럼 보입니다 | 아니요, 언제든 바꿀 수 있습니다 |
| 자료 디렉터리(`data/`, `db/`) | 그림, 기록, 복구 키, 데이터베이스가 놓일 곳 | Docker에서 밖으로 빼지 않으면 컨테이너를 지울 때 함께 사라집니다 | 필요 |
| 시간대(`TZ`) | 기록 시각과 예약 작업이 따를 시간대 | 기본 시간대를 쓰며 작업 시각이 생활과 어긋날 수 있습니다 | 필요 |
| 실행 사용자(`PUID` / `PGID`) | 어떤 사용자로 읽고 쓸지(Docker일 때) | 기본 사용자로 돕니다. 기기 쪽 소유자와 다르면 '쓰기 실패'나 '권한 없음'이 납니다 | 필요 |

:::warning[작품 디렉터리를 프로그램 디렉터리에 넣지 마세요]
Docker를 쓸 때는 기기의 작품 디렉터리를 **같은 경로로** 컨테이너에 이어 주세요(예: `/mnt/media:/mnt/media`). `/ammds` 아래에는 두지 마세요. 프로그램 자료와 섞여 정리할 때 함께 지울 수 있습니다.
:::

## 설치를 마친 뒤

1. 브라우저로 접속 주소를 열고 기본 관리자 계정으로 들어갑니다. [처음 열기: 로그인과 기본 설정](./first-login.md)을 보세요.
2. 포트나 업로드 용량 같은 실행 설정을 바꾸려면 [포트나 업로드 용량을 바꾸려면](./settings.md)을 보세요.
3. 바로 결과를 보고 싶다면 [10분에 첫 작품 정리하기](./first-library.md)를 한 번 따라 해 보세요.

## 문제가 생기면

- **무엇을 골라야 할지 모름**: Docker가 있으면 Docker를 쓰고, 없으면 바이너리 프로그램을 내려받아 바로 실행하세요. 잘못 골라도 바꿀 수 있으니 자료 디렉터리만 잘 백업해 두면 됩니다.
- **바이너리 프로그램을 두 번 눌러도 반응이 없거나 실행할 수 없다고 나옴**: 대개 다른 시스템용 배포판을 받은 경우입니다(Windows와 Linux는 서로 통하지 않습니다). Linux에서는 먼저 실행 권한을 주어야 합니다. [Windows / Linux에서 직접 실행하기](./native.md)를 보세요.
- **화면이 안 열림**: 서비스 포트와 이어 준 포트가 같은지 먼저 보고, 방화벽이 허용하는지 확인하세요. 처음 실행은 부속 프로그램을 다 받을 때까지 기다려야 하니 기록이 계속 늘어나는지 보세요.
- **자료가 '사라짐'**: 실행한 자리가 바뀌어 다른 곳에 `data/`와 `db/`가 새로 만들어졌을 가능성이 큽니다. 원래 디렉터리로 돌아가 다시 실행하세요.
- **실행하자마자 끝남**: 기록에 `inotify`나 CPU 명령어 관련 글이 있는지 보세요. 두 경우 모두 [자주 묻는 질문](../faq.md)에 조치 방법이 있습니다.
