# NAS에 설치하기

NAS는 AMMDS를 많이 돌리는 곳입니다. Docker 말고도 FnOS와 QNAP에는 **앱 패키지**가 있습니다. NAS의 앱 센터가 설치·정지·실행·올리기를 맡으므로 컨테이너를 관리하지 않아도 됩니다.

이 글은 두 갈래를 고르는 법, 설치 절차, 디렉터리 계획을 알려 줍니다. Docker의 일반적인 내용은 [Docker로 설치하기](./docker.md)에 있습니다. 앱 패키지는 NAS가 프로그램을 대신 설치해 주는 통로일 뿐이며, 그 안에 들어 있는 것도 GraalVM Native Image로 미리 실행 파일 하나로 묶은 똑같은 프로그램입니다. 다른 판이 아닙니다.

> **NAS**: 파일을 담아 두는 네트워크 기기입니다(FnOS, QNAP 등).

> **앱 패키지**: NAS 전용 설치 묶음으로, NAS의 앱 센터가 관리합니다.

## 먼저 갈래를 고르세요

| 갈래 | 특징 | 어울리는 곳 |
| --- | --- | --- |
| 앱 패키지 | 앱 센터가 설치하고 안내에서 비밀번호와 포트를 정합니다. 정지·실행·올리기도 거기서 합니다 | 손댈 것을 줄이고 싶고 NAS가 주된 기기인 분 |
| Docker 컨테이너 | 포트, 디렉터리, 환경 변수를 모두 직접 정할 수 있고 올리기는 이미지 갈아 끼우기입니다 | NAS가 Docker를 지원하고 컨테이너에 익은 분 |

두 갈래의 디렉터리 뜻은 같습니다. `data/`에 그림·임시 저장·기록·부속 프로그램, `db/`에 데이터베이스, 작품 파일은 저장 공간에 따로 둡니다.

:::warning[설치 묶음은 공식에서만]
설치 묶음은 공식 배포 페이지에서만 받으세요. 남이 고쳐 만든 것에는 뜻밖의 스크립트가 섞였을 수 있고, 지금 판과 디렉터리 구조가 달라 올릴 때 자료를 잃을 수 있습니다.
:::

## FnOS

### 받기

공식 배포 페이지에서 최신 설치 묶음을 받습니다: https://github.com/QYG2297248353/AMMDS-Offline-FnNas/releases

컴퓨터에 받아 올려도 되고, 기기에서 바로 받아도 됩니다.

### 설치

1. **앱 센터**를 열고 왼쪽 아래의 **수동 설치**에서 받아 둔 파일을 고릅니다.
2. **설치**를 누르고 안내에 따라 진행합니다.
3. 이용 안내를 읽고 동의합니다.
4. 설치 자리를 고릅니다. 여유가 넉넉하고, **임시 폴더로 여겨져 자동으로 지워지지 않을** 저장 공간을 고르세요.
5. 관리 화면 비밀번호를 정합니다. 굳센 것으로 하세요.
6. 접속 포트를 정하고 적어 둡니다. 설치 뒤에 이것으로 엽니다.
7. 내용을 확인하고 진행 표시가 끝날 때까지 기다립니다.

### 설치한 뒤

- `http://NAS주소:설치 때 정한 포트`로 엽니다.
- 작품을 스캔하려면 먼저 NAS에서 AMMDS에 작품 폴더 읽기 권한을 주고, 그다음 AMMDS에 폴더를 추가합니다.
- 올릴 때는 앱 센터에서 새 패키지를 설치합니다. 그전에 설치 폴더의 `db/`와 `data/`를 백업하세요.

## QNAP

### 받기

기기 종류(x86 또는 ARM)에 맞는 설치 묶음을 배포 페이지에서 받습니다: https://github.com/QYG2297248353/AMMDS-Offline-QNAP/releases

### 설치

1. QNAP 관리 화면에 들어가 **App Center**를 엽니다.
2. 수동 설치나 로컬 패키지 가져오기를 골라 받아 둔 파일을 지정합니다.
3. 안내에 따라 설치 볼륨을 고르고 접속 포트를 정합니다.
4. 설치 뒤에는 앱 목록에서 AMMDS를 실행합니다.

Container Station이 있다면 Docker 방식으로 해도 됩니다. 디렉터리와 포트는 일반적인 Docker와 같습니다.

### 설치한 뒤

- `http://NAS주소:포트`로 엽니다. 포트는 설치 안내에서 정한 것입니다.
- 작품 폴더는 같은 저장 공간에 두면 볼륨을 넘나드는 권한 문제를 피할 수 있습니다.
- 올리기 전에는 마찬가지로 `db/`와 `data/`를 백업합니다.

## 디렉터리 계획

| 자리 | 권하는 것 |
| --- | --- |
| 프로그램과 자료 폴더 | 주된 저장 볼륨의 전용 폴더에 둡니다. 시스템 영역이나 자동으로 지워지는 임시 자리는 피합니다 |
| 작품 폴더 | 공유 폴더를 따로 만들고 AMMDS를 돌리는 계정에 읽기(또는 읽고 쓰기)를 허용합니다 |
| 내려받기 폴더 | 다운로더와 같은 폴더를 함께 쓰고 양쪽이 보는 경로를 같게 합니다 |
| 백업 | `db/`와 `data/`를 다른 디스크나 먼 곳에 정기적으로 복사합니다 |

:::tip[모든 앱에 같은 경로로 보이게]
NAS에서 다운로더나 플레이어도 돌고 있다면 작품 폴더를 **똑같은 경로로** 보이게 하세요(같은 공유 폴더 경로를 쓰는 등). 그러면 AMMDS가 보낸 내려받기를 못 찾는 일을 막을 수 있습니다.
:::

## 설정 항목

| 설정 항목 | 무엇을 정하나요 | 정하지 않으면 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 접속 포트 | 브라우저에서 열 번호로, 설치 안내에서 정합니다 | 열 주소가 없습니다. 잊었으면 앱 센터 설정에서 볼 수 있습니다 | 필요 |
| 관리 비밀번호 | 관리 화면에 들어가는 비밀번호로, 설치 안내에서 정합니다 | 정하지 않으면 기본 비밀번호가 남아 그 포트에 닿는 누구나 들어올 수 있습니다 | 아니요, 로그인 뒤에 바꿀 수 있습니다 |
| 설치 자리 | 프로그램과 자료를 둘 저장 볼륨 | 여유가 없거나 지워지는 곳이면 설치가 실패하거나 자료를 잃습니다 | 필요(다시 설치) |
| 작품 폴더와 권한 | 어디를 찾을지, 읽을 수 있는지 | 권한이 없으면 스캔되지 않고 '비어 있는' 것처럼 보입니다 | 아니요, 권한을 고치면 바로 먹습니다 |
| 부팅 때 자동 실행 | NAS를 다시 켠 뒤 서비스가 저절로 뜨는지 | 정하지 않으면 다시 켤 때마다 직접 켜야 합니다 | 필요 |

로그인 뒤에 바꿀 수 있는 실행 설정은 [포트나 업로드 용량을 바꾸려면](./settings.md)에 있습니다.

## NAS에서 흔한 증상

| 증상 | 흔한 원인 | 조치 |
| --- | --- | --- |
| 설치할 때 여유가 없다고 나옴 | 고른 볼륨의 남은 공간이 부족합니다 | 다른 볼륨을 고르거나 공간을 비웁니다 |
| 화면은 열리는데 스캔이 안 됨 | 앱 계정에 공유 폴더 권한이 없습니다 | NAS의 공유 폴더 권한에서 허용합니다 |
| NAS를 다시 켰더니 안 돌고 있음 | 자동 실행이 꺼져 있습니다 | 앱 센터에서 자동 실행을 켭니다 |
| 올린 뒤 자료가 비어 있음 | 새 판이 다른 폴더에 설치되었거나 이전 폴더가 남지 않았습니다 | 올리기 전의 `db/`, `data/`를 돌려놓고 설치 경로를 확인합니다 |
| 휴대폰이나 클라이언트가 못 찾음 | NAS 네트워크에서 알림이 막혔거나 UDP 포트가 허용되지 않았습니다(Docker일 때) | 클라이언트에 주소를 직접 적거나, Docker 글대로 UDP를 이어 줍니다 |

## 문제가 생기면

- **설치가 안 됨**: 공간이 부족한지, 기기 종류에 맞는 묶음(x86인지 ARM인지)을 골랐는지 확인합니다.
- **화면이 안 열림**: NAS 방화벽이 그 포트를 허용하는지, 주소와 포트가 맞는지 확인합니다.
- **스캔이 안 됨**: NAS에서 가장 흔한 증상이며 열에 아홉은 공유 폴더 권한입니다. 먼저 NAS에서 허용하고 다시 시도하세요.
- **올린 뒤 이상함**: 먼저 `db/`와 `data/` 백업을 돌려놓고 설치 경로가 바뀌었는지 확인합니다. 맞는 증상이 없으면 [자주 묻는 질문](../faq.md)에서 찾아 보세요.
