# 10분에 첫 작품 정리하기

이 글은 처음부터 끝까지 이어지는 따라하기입니다. '방금 설치해 아무것도 없는' 상태에서 '라이브러리에 표지와 줄거리가 붙은 작품이 늘어선' 상태까지를 목표로 합니다. 1-2-3 순서대로 하세요. 각 단계마다 **끝나면 무엇이 보여야 하는지**를 적고, 막혔을 때의 확인점도 붙였습니다.

시작하기 전에 [처음 열기: 로그인과 기본 설정](./first-login.md)을 끝내고 시스템 점검을 한 번 돌려 주세요.

## 먼저 준비

필요한 것은 세 가지뿐입니다.

| 준비물 | 설명 |
| --- | --- |
| 작품 파일이 든 폴더 하나 | 먼저 열 편 남짓으로 해 보세요. 처음부터 수만 개를 던지지 마세요 |
| 파일 이름에서 작품 번호가 보일 것 | 작품 번호는 작품을 구분하는 식별 번호입니다. 파일 이름에 있으면 판별이 정확해집니다 |
| 쓸 수 있는 정보 출처 | 정보를 채우려면 정보 사이트를 찾아야 하니, 연동 앱에서 설정하고 연결을 확인해 둡니다. 완전히 내부망이면 할 수 없습니다 |

> **스캔**: 지정한 폴더를 훑어 어떤 작품이 있는지 알아내게 하는 것입니다.

> **정보 가져오기(스크레이핑)**: 정보 사이트에서 표지·줄거리·출연진·태그를 찾아 자동으로 채워 넣는 것입니다.

> **작품 번호**: 작품을 구분하는 식별 번호로, 보통 파일 이름에 들어 있습니다. 읽지 못하면 정보가 채워지지 않습니다.

## 하나, 파일이 어디 있는지 알려 주기

1. 스캔 작업 화면을 열고 작품 폴더를 추가하는 곳을 찾습니다.
2. 작품을 둔 폴더 경로를 적습니다. Docker라면 **컨테이너에서 보이는 경로**를 적습니다. 그래서 마운트를 같은 경로로 하는 것이 좋습니다.
3. 저장합니다.

### 끝나면 무엇이 보이나요

폴더가 목록에 나오고 프로그램이 읽을 수 있는 상태——저장할 때 '경로가 없습니다'나 '권한이 없습니다'가 뜨지 않는 것입니다.

### 막히면 확인할 점

- 경로를 잘못 적음: 단계가 하나 많거나 적어도 읽히지 않습니다. 경로를 복사해 맞춰 보세요.
- 권한이 없음: NAS에서 가장 흔합니다. NAS의 공유 폴더 권한에서 AMMDS에 허용하세요([NAS에 설치하기](./nas.md) 참고).
- Docker에서 경로가 없음: 그 폴더를 컨테이너에 이어 주었는지 확인합니다.

## 둘, 한 번 스캔해서 알게 하기

1. 스캔 작업 화면에서 작업을 만들고 방금 추가한 폴더를 고릅니다.
2. 정리 모드를 고릅니다. 처음에는 **판별만 하고 파일은 옮기지 않는** 모드가 좋습니다. 이미 잘 정리되어 있고 빠진 그림과 정보 파일만 채우고 싶다면 '빠진 부분 채우기' 모드를 씁니다.
3. 실행하고 끝날 때까지 기다립니다.

### 끝나면 무엇이 보이나요

작업이 완료로 바뀌고, 판별된 작품이 목록에 나오며 작품 번호가 맞아 보이는 것입니다.

### 막히면 확인할 점

- 작업이 실패로 뜸: 작업 기록에서 그 작업을 열어 보세요. 실패 이유와 마지막으로 성공한 단계가 적혀 있습니다.
- 목록이 비어 있음: 폴더에 판별할 수 있는 파일이 없거나 형식이 대상이 아닙니다. 확실히 판별되는 파일 하나로 먼저 시도해 보세요.
- 중간에 멈춘 것 같음: 파일이 아주 많으면 원래 오래 걸립니다. 작업이 도는지 먼저 보고 기록의 오류를 확인하세요.

## 셋, 작품 번호가 맞는지 확인하기

1. 스캔 결과에서 몇 개를 골라 프로그램이 읽은 번호가 내가 아는 작품과 같은지 봅니다.
2. 틀린 것은 파일 이름부터 고칩니다(번호를 앞에, 구분을 한결같이). 그리고 다시 스캔합니다.

### 끝나면 무엇이 보이나요

대부분의 번호가 맞는 것입니다. 몇 개가 안 읽히는 것은 자연스러우니 한 번에 완벽할 필요는 없습니다.

### 막히면 확인할 점

- 번호 표기가 특이함: 파일 이름에 읽을 수 있는 번호가 없거나 드문 표기면 읽지 못합니다. 흔한 표기로 고쳐 다시 스캔하세요.
- 같은 작품이 여러 개 나옴: 파일 이름 표기가 제각각이라서 그렇습니다. 한 가지로 통일하세요.

## 넷, 표지와 줄거리 채우기

1. 정보 가져오기 작업 화면에서 작업을 만들고 방금 스캔한 결과를 고릅니다.
2. 어떤 정보 출처를 쓸지 고릅니다(여러 개면 먼저 하나만 골라 시도합니다).
3. 실행하고 기다립니다. 한 번에 다루는 수에 한도가 있어 많으면 몇 번 나눕니다.

### 끝나면 무엇이 보이나요

작품에 표지, 줄거리, 출연진, 태그가 붙기 시작하고 비어 있던 칸이 채워지는 것입니다.

### 막히면 확인할 점

- 성공인데 내용이 비어 있음: 번호가 맞지 않거나 그 정보 출처에 작품이 없습니다. 세 번째 단계로 돌아가거나 다른 정보 출처로 시도합니다.
- 언제나 실패하며 연결할 수 없다고 나옴: 정보 출처 주소나 인증 코드가 틀렸거나 사이트가 막은 것입니다. 플러그인 설정에서 연결 확인을 하고, 시스템 점검에서 '이상'인지 '설정 미완'인지 봅니다.
- 일부만 실패함: 흔한 일입니다. 실패한 것만 골라 다시 실행하세요.

## 다섯, 라이브러리에서 결과 보기

미디어 메뉴를 열어 목록을 봅니다. 표지와 줄거리가 붙은 작품이 가지런히 놓여 있습니다. 상세로 들어가면 포스터, 장면 사진, 출연진, 태그도 볼 수 있습니다.

여기까지 하면 첫 묶음은 끝입니다. 다음도 할 수 있습니다(당장 하지 않아도 됩니다).

| 하고 싶은 일 | 어디에서 |
| --- | --- |
| 시리즈, 제작사, 태그로 묶기 | 미디어 메뉴의 정리 화면 |
| 앞으로 자동으로 스캔하고 채우기 | 스캔 작업의 '디렉터리 감시'를 켜거나 예약 스캔을 추가 |
| 텔레비전에서 포스터 벽 보기 | 연동 앱에서 미디어 서버 잇기 |
| 새 자료를 계속 지켜보기 | 구독 화면에서 설정 |

## 여섯, 앞으로는 스스로 돌게 하기

1. 스캔 작업의 **디렉터리 감시**를 켭니다. 파일이 바뀌면 저절로 스캔합니다.
2. 또는 예약 스캔 작업을 만듭니다(하루에 한 번 등).
3. 예약 작업의 전체 스위치가 켜져 있는지 확인합니다. 꺼져 있으면 직접 실행도 거절됩니다.

## 설정 항목

| 설정 항목 | 무엇을 적나요 | 적지 않거나 틀리면 |
| --- | --- | --- |
| 작품 폴더 경로 | 작품 파일이 있는 폴더 | 잘못 적거나 권한이 없으면 스캔되지 않습니다. Docker는 컨테이너 안 경로를 씁니다 |
| 정리 모드 | 처음은 '판별만 하고 옮기지 않기', 잘 정리된 폴더는 '빠진 부분 채우기' | 옮기거나 이름을 바꾸는 모드는 파일 자리가 바뀝니다. 쓰기 전에 생각하세요 |
| 디렉터리 감시 스위치 | 파일이 바뀌면 바로 스캔할지 | 끄면 예약이나 직접 실행만 남습니다 |
| 예약 작업 시각 | 얼마나 자주 돌릴지 | 틀려도 오류는 나지 않고 시각만 어긋납니다 |
| 정보 출처 | 어느 사이트를 찾아볼지와 그 주소, 인증 코드 | 없거나 틀리면 정보가 안 들어옵니다. 먼저 플러그인에서 연결 확인을 하세요 |
| 한 번에 다루는 개수 | 한 번에 몇 개를 처리할지 | 정하지 않으면 기본값입니다. 많으면 여러 번으로 나뉩니다 |

## 문제가 생기면

- **스캔 결과가 아주 비어 있음**: 대개 경로나 권한 문제입니다. 첫 단계의 확인점으로 돌아가세요.
- **정보 가져오기가 늘 실패함**: 그 정보 사이트에 닿는지 확인합니다. 시스템 점검의 네트워크 항목에서 알 수 있습니다.
- **표지는 있는데 줄거리가 없음(또는 반대)**: 그 정보 출처의 자료가 비어 있는 것입니다. 다른 출처로 채워 보세요.
- **기록에 오류가 없는데 작업이 실패함**: 작업 기록에서 그 작업의 '상세'를 열어 실패 이유와 마지막으로 성공한 단계를 보세요.
- **해당하는 것이 없음**: [자주 묻는 질문](../faq.md)에서 증상으로 찾거나, 버전·시각·로그를 담아 GitHub로 알려 주세요: https://github.com/QYG2297248353/AMMDS-Docker/issues/new
