# Windows / Linux에서 직접 실행하기

Docker가 없거나 프로그램 프로세스 하나를 직접 관리하는 게 더 편하다면 이 방식을 쓰세요. 배포판에 들어 있는 실행 파일을 실행하면 화면과 창구를 모두 그것이 제공하고, 기본으로 `8080` 포트를 씁니다.

시작 전에 할 일은 하나뿐입니다. **자기 시스템에 맞는 배포판을 내려받으세요.** Java를 설치할 필요도, 다른 실행 환경을 준비할 필요도 없습니다. 어떤 방식을 쓸지 아직 못 정했다면 [설치 방법부터 고르기](./overview.md)를 먼저 보세요.

> **바이너리 프로그램**: 실행 파일이라고도 부릅니다. Windows에서는 `.exe`로 끝나는 파일, Linux에서는 확장자가 없는 파일입니다. AMMDS는 GraalVM Native Image 기술로 프로그램을 미리 이런 파일 하나로 컴파일해 두므로, 실행할 때 Java가 필요 없고 JAR / WAR 같은 파일을 관리할 일도 없습니다.

## 필요한 환경

| 항목 | 조건 |
| --- | --- |
| 시스템 | 64비트 Windows 또는 64비트 Linux입니다. 실행 파일은 시스템마다 따로 컴파일되므로, 내려받을 때 자기 시스템에 맞는 것을 고르세요 |
| 실행 환경 | Java가 필요 없고, 다른 실행 환경을 설치할 필요도 없습니다 |
| 디스크 | 작품 파일과 별도로 `data/`, `db/` 자리가 필요합니다. 처음 실행에서는 부속 프로그램도 받습니다 |
| 네트워크 | 정보 자동 채우기와 자료 찾기에는 인터넷이 필요합니다 |

## 프로그램 파일 마련하기

공식 배포 페이지에서 자기 시스템에 맞는 배포판을 내려받아 압축을 풀면 실행 파일 하나가 나옵니다. Linux에서는 보통 `ammds`, Windows에서는 `ammds.exe`라고 부르며, 파일 이름의 버전은 배포판과 같습니다. 정확한 이름은 내려받은 것을 기준으로 하세요.

:::note[Windows에는 설치 프로그램도 있습니다]
Windows용 오프라인 설치 프로그램도 따로 제공됩니다. 설치 안내 화면을 따라가거나 부팅 때 자동 실행을 쓰고 싶다면 배포 페이지를 살펴보세요: https://github.com/QYG2297248353/AMMDS-Launcher/releases
:::

## Windows에서 실행하기

1. 실행 파일을 고정된 폴더에 둡니다(예: `C:\AMMDS\`).
2. PowerShell이나 명령 프롬프트를 열어 **그 폴더로 이동합니다**.
3. 실행합니다.

```powershell
cd C:\AMMDS
.\ammds.exe
```

4. 브라우저에서 `http://127.0.0.1:8080`을 엽니다.

창을 닫으면 서비스가 멈춥니다. 오래 돌리려면 이 명령을 배치 파일에 적고 '작업 스케줄러'로 부팅 때 실행하게 하세요. 원하는 상주 관리 도구에 맡겨도 됩니다.

## Linux에서 실행하기

```bash
mkdir -p /opt/ammds
cd /opt/ammds
chmod +x ./ammds
./ammds
```

:::note['권한이 부족하다'라고 나올 때]
Linux에서 새로 받은 파일에는 기본으로 실행 권한이 없습니다. `chmod +x ./ammds`를 한 번 실행한 뒤 켜세요.
:::

부팅 때 자동으로 띄우려면 시스템 서비스에 맡기면 됩니다. 아래는 참고용 설정입니다.

```ini title="/etc/systemd/system/ammds.service"
[Unit]
Description=AMMDS
After=network-online.target

[Service]
WorkingDirectory=/opt/ammds
ExecStart=/opt/ammds/ammds
Restart=on-failure
User=ammds

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now ammds
journalctl -u ammds -f
```

:::note[위 설정의 실행 계정에 대하여]
`User=ammds`는 기기에 그 이름의 계정이 있다는 뜻입니다. 없다면 실제로 실행할 계정으로 바꾸거나, 계정을 먼저 만들고 `/opt/ammds`의 소유자를 그 계정으로 바꿔 주세요.
:::

## 작업 폴더와 자료 위치

AMMDS는 **실행한 자리**를 기준으로 `data/`, `db/` 같은 상대 경로를 읽습니다. 반드시 프로그램 폴더로 이동한 뒤 실행하고, 시스템 서비스에 맡길 때는 작업 폴더를 지정하세요.

| 경로 | 무엇이 담기나요 |
| --- | --- |
| `data/` | 그림, 임시 저장, 자막, 기록, 복구 키, 그리고 자동으로 받는 FFmpeg 같은 부속 프로그램 |
| `data/logs/` | 실행 기록입니다. 날마다 새 파일로 갈리고 오류만 담은 파일도 따로 있습니다 |
| `db/` | 데이터베이스 파일로 작품, 작업, 설정 등 모든 자료가 들어갑니다 |
| `download/` | 선택해서 쓰는 내려받기 폴더이며, 다운로더와 함께 쓴다면 경로를 같게 두면 됩니다 |

:::warning[임시 폴더에서 실행하지 마세요]
파일을 임시 폴더나 내려받기 폴더에 두고 바로 실행하면 작업 자리가 엉뚱한 곳이 되어 자료가 흩어집니다. 전용 폴더를 먼저 만들고 거기서 실행하세요.
:::

## 처음 실행에서는 부속 프로그램을 받습니다

실행하면 FFmpeg 같은 부속 프로그램을 필요한 대로 자동으로 받아 `data/` 아래 알맞은 폴더에 둡니다. 처음 실행 기록에 받는 진행 상황이 보이니, 회선이 느리면 여유를 두고 기다려 주세요. 준비가 되었는지는 아바타 메뉴의 **시스템 점검**에서 항목마다 확인할 수 있습니다.

## 설정 항목

이 설정들은 모두 실행 전에 환경 변수로 정하며, 바꾼 뒤에는 **반드시 다시 실행**해야 적용됩니다.

| 설정 항목 | 무엇을 정하나요(쉬운 말로) | 정하지 않으면 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 서비스 포트(`AMMDS_SERVER_PORT`) | 브라우저에서 열 때 쓰는 번호 | 기본 `8080`을 씁니다 | 필요 |
| 받아들일 주소(`AMMDS_SERVER_HOST`) | 어떤 기기의 접속을 허용할지, 기본은 모두입니다 | 기본값을 씁니다. 자기 기기만으로 좁히면 다른 기기에서 못 붙습니다 | 필요 |
| 업로드 용량(`AMMDS_MAX_FILE_SIZE` / `AMMDS_MAX_REQUEST_SIZE`) | 파일 하나, 한 번 요청의 크기 한도 | 프로그램 기본값을 씁니다. 큰 파일이 실패하면 둘을 함께 올립니다 | 필요 |
| 임시 저장 폴더(`AMMDS_CACHE_PATH`) | 업로드할 때 잠시 담아 둘 곳 | `data/cache`를 씁니다. 그 디스크가 꽉 차면 업로드가 실패합니다 | 필요 |
| 기록 자세함(`AMMDS_DEBUG`) | 기록을 얼마나 자세히 남길지 | 기본 단계를 씁니다. 살펴볼 때만 가장 자세하게 할 수 있습니다 | 필요 |
| 자동 찾기 스위치와 포트(`AMMDS_DISCOVERY_ENABLED` / `AMMDS_DISCOVERY_PORT` / `AMMDS_DISCOVERY_ANNOUNCE_ENABLED` / `AMMDS_DISCOVERY_ANNOUNCE_PORT`) | 클라이언트가 자동으로 찾게 할지, 어느 두 UDP 포트를 쓸지 | 기본은 켜짐입니다. 끄면 클라이언트에 직접 적어야 합니다 | 필요 |
| 예약 작업 전체 스위치(`AMMDS_SCHEDULER_ENABLE`) | 시각에 맞춰 도는 작업을 돌릴지 | 기본은 켜짐입니다. 끄면 직접 실행도 거절됩니다 | 필요 |
| 디렉터리 감시 스위치(`AMMDS_MONITOR_ENABLE`) | 파일이 바뀌면 바로 스캔할지 | 기본은 켜짐입니다. 끄면 예약 스캔만 남습니다 | 필요 |
| 메모리 한도(`-Xmx`, Docker에서는 `AMMDS_MAX_HEAP`) | 프로그램이 쓸 수 있는 메모리 | 프로그램 기본 한도를 씁니다. 부담이 커 보이면 직접 정하세요 | 필요 |

포트를 바꾸는 방법입니다.

```bash
# Linux
AMMDS_SERVER_PORT=9090 ./ammds

# Windows PowerShell
$env:AMMDS_SERVER_PORT = "9090"
.\ammds.exe
```

:::tip[메모리 사용이 높아 보일 때]
바이너리 프로그램은 기본으로 기기 메모리에 맞춰 한도를 잡아 둡니다. 그래서 스캔이나 정보 가져오기가 끝난 뒤에도 사용량이 높게 남을 수 있습니다. `./ammds -Xmx2g`처럼 한도를 직접 정하고, Linux에서는 환경 변수 `MALLOC_ARENA_MAX=2`를 함께 쓰면 확실히 줄어듭니다. 정한 값은 자원 사용 화면에서 지금 적용된 한도로 볼 수 있습니다.
:::

실행 설정 전체는 [포트나 업로드 용량을 바꾸려면](./settings.md)에 있습니다.

## 버전 올리기

1. 프로그램을 멈춥니다(시스템 서비스면 `systemctl stop ammds`, 또는 콘솔 창을 닫습니다).
2. `db/`와 `data/`를 백업합니다.
3. 이전 파일을 새 버전의 실행 파일로 바꿉니다.
4. 다시 실행해 화면의 버전과 '시스템 점검' 결과를 확인합니다.

데이터베이스 구조는 저절로 맞춰지므로 평소 올리기에서 손댈 일은 없습니다. 다만 큰 버전을 넘을 때는 올리기 전 데이터베이스 복사본을 남겨 두세요.

## 문제가 생기면

- **두 번 눌러도 반응이 없거나 실행할 수 있는 프로그램이 아니라고 나옴**: 대개 다른 시스템용 배포판을 받은 경우입니다(Windows와 Linux는 서로 통하지 않습니다). 자기 시스템에 맞는 것을 다시 받고, Linux에서는 `chmod +x ./ammds`를 실행했는지도 확인하세요.
- **시작하자마자 CPU 명령어를 지원하지 않는다고 나옴**: 받은 배포판이 기기와 맞는지 확인하세요. 오래된 기기라면 구형 CPU에 맞춘 배포판으로 바꾸거나 `ol8` 태그가 붙은 Docker 이미지를 쓰면 됩니다.
- **화면이 안 열림**: 프로세스가 아직 도는지, 포트를 다른 프로그램이 쓰고 있지 않은지, 방화벽이 허용하는지 확인합니다. 처음 실행에서는 부속 프로그램을 다 받을 때까지 기다려야 합니다.
- **실행은 되는데 동작이 이상함**: `data/logs/`의 실행 기록을 보고 시스템 점검을 한 번 돌려 보세요.
- **자료가 '사라짐'**: 실행한 자리가 바뀌어 다른 곳에 자료 디렉터리가 새로 만들어졌을 가능성이 큽니다. 원래 폴더로 돌아가 다시 실행하세요.
- **그래도 안 됨**: [자주 묻는 질문](../faq.md)에서 증상으로 찾아 보세요.
