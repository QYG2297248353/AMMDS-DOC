# Docker로 설치하기

가장 많이 쓰는 설치 방법입니다. 컨테이너 하나에서 화면 서비스와 본체가 함께 돌고, 화면과 창구를 같은 포트로 제공합니다. 이 글은 그대로 쓸 수 있는 명령 둘과 디렉터리·권한 정하는 법을 알려 줍니다.

컨테이너 안에서 도는 것은 배포판에 들어 있는 GraalVM Native Image 바이너리 프로그램 그 자체입니다. 그래서 컨테이너에 Java를 설치할 필요가 없고, JAR / WAR 파일도 따로 챙길 것이 없습니다.

시작 전에 확인하세요. Docker가 설치되어 있고, 작품 파일이 어떤 폴더에 있는지 알고 있어야 합니다. 방법을 아직 안 정했다면 [설치 방법 고르기](./overview.md)를 먼저 보세요.

> **이미지**: 프로그램 묶음 파일로, '설치용 디스크' 같은 것입니다. `qyg2297248353/ammds:latest`처럼 적고 콜론 뒤가 버전 태그입니다.

> **컨테이너**: 이미지를 실제로 실행하고 있는 덩어리입니다.

> **마운트**: 기기에 있는 실제 디렉터리를 컨테이너 안의 자리에 이어 주어 읽고 쓸 수 있게 하는 것입니다. '기기 쪽:컨테이너 쪽'으로 적습니다.

## 어떤 이미지를 쓸까요

| 이미지 | 설명 |
| --- | --- |
| `qyg2297248353/ammds:latest` | 가장 최신입니다. 먼저 이것을 권합니다 |
| `qyg2297248353/ammds:버전` | 버전을 고정합니다. 올릴 때를 직접 정하고 싶을 때 알맞습니다 |
| `qyg2297248353/ammds:latest-ol8` | 오래된 시스템용입니다. 기본 이미지가 안 도는 낡은 기기에서 씁니다 |
| `ghcr.io/qyg2297248353/ammds:latest` | 다른 배포원입니다. 받기가 잘 안 될 때 바꿔 보세요 |

이미지는 64비트 x86과 ARM 두 가지로 나오며, 받을 때 알맞은 것이 저절로 골라집니다.

## 명령 하나로 실행하기

```bash title="docker run"
docker run -d \
  --name AMMDS \
  -p 8080:80 \
  -v /opt/ammds/data:/ammds/data \
  -v /opt/ammds/db:/ammds/db \
  -v /opt/ammds/download:/ammds/download \
  -v /mnt/media:/mnt/media \
  -e TZ=Asia/Shanghai \
  -e PUID=1000 \
  -e PGID=1000 \
  --restart always \
  qyg2297248353/ammds:latest
```

실행하면 `http://기기주소:8080`으로 엽니다. 8080을 이미 쓰고 있다면 콜론 왼쪽만 바꾸세요(예: `8090:80`).

## 구성 파일로 실행하기(오래 쓸 때 권함)

아래를 `docker-compose.yml`로 저장해, 자료를 두려는 폴더에 넣으세요.

```yaml title="docker-compose.yml"
services:
  ammds:
    image: qyg2297248353/ammds:latest
    container_name: AMMDS
    ports:
      - "8080:80"          # 화면과 창구
      - "47823:47823/udp"  # 같은 네트워크에서 찾기(선택)
      - "47824:47824/udp"  # 같은 네트워크 알림(선택)
    volumes:
      - ./data:/ammds/data
      - ./db:/ammds/db
      - ./download:/ammds/download
      - /mnt/media:/mnt/media
    environment:
      TZ: Asia/Shanghai
      PUID: "1000"
      PGID: "1000"
      UMASK: "022"
    restart: always
```

그다음 실행합니다.

```bash
docker compose up -d
```

:::note[두 개의 UDP 포트가 필요한가요]
화면 서비스는 TCP만 중계합니다. 휴대폰이나 클라이언트가 자동으로 찾게 할 필요가 없다면 이 두 줄을 지워도 됩니다. 클라이언트에는 주소를 직접 적습니다.
:::

## 포트가 하는 일

| 포트 | 쓰임 | 밖으로 이어 주나요 |
| --- | --- | --- |
| `80` | 컨테이너 안의 화면 서비스로, 화면과 창구를 줍니다 | 예, 기기 쪽 번호는 자유입니다 |
| `8080` | 컨테이너 안의 본체로, 안에서만 중계됩니다 | 아니요 |
| `47823/udp` | 클라이언트가 서비스를 찾는 데 씁니다 | 자동 찾기가 필요할 때만 |
| `47824/udp` | 서비스가 스스로 알리는 데 씁니다 | 자동 찾기가 필요할 때만 |

## 디렉터리 연결

| 컨테이너 안 경로 | 무엇이 담기나요 | 권하는 것 |
| --- | --- | --- |
| `/ammds/data` | 그림, 임시 저장, 자막, 기록, 부속 프로그램, 복구 키 | 반드시 밖으로 빼기 |
| `/ammds/db` | 데이터베이스 파일 | 반드시 밖으로 빼고 백업에 넣기 |
| `/ammds/download` | 내려받기용으로 마련된 폴더로, 보통 다운로더와 함께 씁니다 | 밖으로 빼기를 권함 |
| 작품 폴더 | 스캔하고 정리할 대상 | 기기와 컨테이너의 경로를 같게 |

:::warning[작품을 /ammds에 넣지 마세요]
`/ammds`는 프로그램과 자료의 기준 폴더입니다. 작품은 따로 이어 주세요(예: `/mnt/media:/mnt/media`). 아니면 정리하거나 컨테이너를 다시 만들 때 함께 지울 수 있습니다.
:::

## 권한: '쓰기 실패'가 뜨면 여기

컨테이너는 기본적으로 가장 높은 권한의 사용자로 돕니다. `PUID`와 `PGID`를 0이 아닌 값으로 주면 시작할 때 그 사용자로 바꾸고, `UMASK`(기본 `022`)로 새로 만드는 파일의 권한을 정합니다.

밖으로 뺀 폴더에서 '쓰기 실패'나 '권한 없음'이 나면 먼저 `PUID` / `PGID`를 그 폴더를 가진 사용자로 맞추세요.

## 실행되었는지 확인하기

```bash
docker logs -f AMMDS
```

기록에 '서비스가 시작되었습니다'가 보이면 화면 서비스와 본체가 모두 준비된 것입니다. 화면에 '서비스가 시작 중입니다. 잠시 기다려 주세요'가 뜨면 화면 쪽은 떴지만 본체가 아직 준비 중입니다. 조금 기다렸다가 새로 고침 하세요.

:::tip[처음 실행은 조금 걸립니다]
처음 실행에서는 FFmpeg 같은 부속 프로그램을 자동으로 받습니다. 걸리는 시간은 회선에 따라 다릅니다. 준비되었는지는 아바타 메뉴의 **시스템 점검**에서 항목마다 확인할 수 있습니다.
:::

## 설정 항목

| 설정 항목 | 무엇을 정하나요 | 정하지 않으면 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 접속 포트(기기 쪽, 컨테이너 안은 `NGINX_PORT`) | 브라우저에서 열 때 쓰는 번호 | 컨테이너 기본값을 씁니다. 이어 주지 않으면 열 수 없습니다 | 필요(컨테이너 다시 만들기) |
| 시간대(`TZ`) | 기록 시각과 예약 작업이 따를 시간대 | 기본 시간대를 쓰며 시각이 어긋날 수 있습니다 | 필요 |
| 실행 사용자(`PUID` / `PGID`) | 어떤 사용자로 읽고 쓸지 | 기본 사용자로 돕니다. 소유자와 다르면 권한 오류가 납니다 | 필요 |
| 새 파일 권한(`UMASK`) | 새로 만드는 파일의 권한 | 기본값을 쓰며 보통 바꿀 일이 없습니다 | 필요 |
| 업로드 용량(`AMMDS_MAX_FILE_SIZE` / `AMMDS_MAX_REQUEST_SIZE`) | 파일 하나, 한 번 요청의 크기 한도 | 기본값을 씁니다. 큰 파일이 거절되면 올립니다 | 필요 |
| 자동 찾기 스위치와 포트(`AMMDS_DISCOVERY_ENABLED` / `AMMDS_DISCOVERY_PORT` / `AMMDS_DISCOVERY_ANNOUNCE_ENABLED` / `AMMDS_DISCOVERY_ANNOUNCE_PORT`) | 클라이언트가 자동으로 찾게 할지, 어느 두 UDP 포트를 쓸지 | 기본은 켜짐입니다. UDP를 이어 주지 않으면 찾지 못해 직접 적어야 합니다 | 필요 |
| 메모리 한도(`AMMDS_MAX_HEAP`) | 프로그램이 쓸 수 있는 메모리 | 컨테이너 한도에서 자동으로 정해집니다. 부담이 커 보이면 직접 정하세요 | 필요 |

실행 설정은 더 있습니다. [포트나 업로드 용량을 바꾸려면](./settings.md)을 보세요.

## 버전 올리기

1. 밖으로 뺀 `db/`와 `data/`를 백업합니다.
2. 새 이미지를 받습니다: `docker compose pull`(또는 `docker pull qyg2297248353/ammds:latest`).
3. 컨테이너를 다시 만듭니다: `docker compose up -d`(또는 이전 컨테이너를 지우고 `docker run`을 다시 합니다).
4. 화면에서 버전과 '시스템 점검' 결과를 확인합니다.

자료는 밖으로 뺀 폴더에 있어 컨테이너를 다시 만들어도 사라지지 않습니다. 다만 큰 판을 넘어 올릴 때는 데이터베이스 복사본을 남겨 두세요.

## 문제가 생기면

| 증상 | 흔한 원인 | 조치 |
| --- | --- | --- |
| 실행하자마자 끝남 | 기기 종류와 이미지가 안 맞거나, 폴더에 쓰기 권한이 없음 | `docker logs AMMDS`로 내용을 봅니다. ARM 기기라면 arm64 이미지를 받았는지 확인합니다 |
| 화면이 502, 또는 '시작 중'이라고 함 | 본체가 아직 준비 중입니다 | 잠시 기다려 기록을 보고, 포트 충돌이나 데이터베이스 손상이 없는지 확인합니다 |
| 작품 폴더에 쓸 수 없음 | 컨테이너 안 사용자와 기기 쪽 소유자가 다름 | `PUID` / `PGID`를 맞추거나 폴더 권한을 고칩니다 |
| 클라이언트가 못 찾음 | TCP 포트만 이어 주었음 | UDP 둘을 더하거나 클라이언트에 주소를 직접 적습니다 |

- **해당하는 것이 없음**: 먼저 `docker logs AMMDS`를 보고, [자주 묻는 질문](../faq.md)에서 증상으로 찾아 보세요.
- **설정이 적용됐는지 확인하려면**: 포트와 버전은 워크벤치의 '시스템 정보'에, 외부 서비스 상태는 아바타 메뉴의 **시스템 점검**에 나옵니다.
