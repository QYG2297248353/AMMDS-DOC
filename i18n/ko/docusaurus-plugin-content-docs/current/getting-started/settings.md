# 포트나 업로드 용량을 바꾸려면

AMMDS에는 **실행 설정**이 있어, 화면에서 바꿀 수 없는 포트나 업로드 용량 같은 것을 정합니다. 이 글은 하나씩, 비우면 어떻게 되는지와 다시 실행이 필요한지를 적어 둡니다.

기본값으로도 충분히 돌아가므로 대부분의 분은 **하나도 바꿀 필요가 없습니다**. 포트가 겹치거나, 큰 파일 올리기가 실패하거나, 기록이 부족할 때 해당 항목을 찾아 오세요.

> **환경 변수**: 실행 전에 프로그램에 건네주는 설정입니다. Docker에서는 설정 파일의 `environment` 항목에, 직접 실행할 때는 실행 파일의 실행 명령 앞에 적습니다. 이름을 잘못 적으면 조용히 무시되고 기본값으로 동작합니다.

> **포트**: 한 기기 안에서 서비스를 구분하는 번호입니다. `http://기기주소:8080`의 8080이 포트입니다.

## 바꾸는 법

세 가지 상황에서 적는 법입니다.

| 설치 방법 | 바꾸는 법 |
| --- | --- |
| Docker / Compose | `environment` 항목에 적고 컨테이너를 다시 만듭니다 |
| 명령으로 직접 실행 | 실행 파일의 실행 명령 앞에 적습니다(예: `AMMDS_SERVER_PORT=9090 ./ammds`, Windows는 `ammds.exe`) |
| 서비스에 맡김 | 서비스 설정에 환경 변수를 더하고 다시 실행합니다 |

:::warning[바꾼 뒤에는 반드시 다시 실행]
실행 설정은 **실행할 때 읽힙니다**. 다시 실행하지 않으면 먹지 않습니다. 화면의 시스템 설정에서 바꾸는 항목은 저장하면 바로 먹고, 여기서는 다루지 않습니다.
:::

## 서비스와 네트워크

| 설정 항목 | 무엇을 정하나요 | 비우면 어떻게 되나요 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 서비스 포트(`AMMDS_SERVER_PORT`) | 브라우저에서 열 때 쓰는 번호 | 기본 `8080`을 씁니다 | 필요 |
| 받아들일 주소(`AMMDS_SERVER_HOST`) | 어떤 기기의 접속을 허용할지, 기본은 모두입니다 | 기본값을 씁니다. 자기 기기만으로 좁히면 다른 기기에서 못 붙습니다 | 필요 |
| 밖에 알리는 주소(`AMMDS_SERVICE_ADDRESS`) | 프로그램이 자기 주소로 알리는 값으로, 창구 문서나 찾기에 쓰입니다 | 기본값을 씁니다. 로그인에 성공하면 그때의 주소가 자동으로 적힙니다 | 필요 |
| 연결 대기 시간(`AMMDS_CONNECTION_TIMEOUT`) | 연결 하나가 기다릴 수 있는 시간(밀리초) | 기본값을 쓰며 보통 바꿀 일이 없습니다 | 필요 |
| 업로드 임시 폴더(`AMMDS_CACHE_PATH`) | 올릴 때 잠시 담아 둘 곳 | `data/cache`를 씁니다. 그 디스크가 꽉 차면 올리기가 실패합니다 | 필요 |
| 파일 하나 크기 한도(`AMMDS_MAX_FILE_SIZE`) | 한 번에 올릴 수 있는 파일 크기 | 기본값을 씁니다. 큰 파일이 거절되면 올립니다 | 필요 |
| 한 번 요청 크기 한도(`AMMDS_MAX_REQUEST_SIZE`) | 한 번 요청(여러 파일을 담을 수 있습니다)의 합계 | 기본값을 씁니다. 위 항목과 함께 올리고 그보다 작게 두지 마세요 | 필요 |
| 기록 자세함(`AMMDS_DEBUG`) | 기록을 얼마나 자세히 남길지 | 기본 단계를 씁니다. 살펴볼 때만 `DEBUG`로 하고 끝나면 되돌립니다 | 필요 |

:::note[업로드 용량의 함정]
Docker 이미지에 들어 있는 화면 서비스에도 자체 한도(약 10G)가 있습니다. 위 둘을 더 크게 해도 그쪽에서 먼저 거절할 수 있으니 함께 올려야 합니다. 앞에 다른 중계가 있어도 같습니다.
:::

## 기능 스위치

| 설정 항목 | 무엇을 정하나요 | 비우면 어떻게 되나요 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 예약 작업 전체 스위치(`AMMDS_SCHEDULER_ENABLE`) | 시각에 맞춰 도는 작업을 돌릴지 | 기본은 켜짐입니다. 끄면 직접 실행도 거절됩니다 | 필요 |
| 디렉터리 감시 스위치(`AMMDS_MONITOR_ENABLE`) | 파일이 바뀌면 바로 스캔할지 | 기본은 켜짐입니다. 끄면 예약 스캔만 남습니다 | 필요 |
| 실행 모드(`AMMDS_SYSTEM_MODE`) | 전체 / 관리만 / 창구만 | 기본은 전체입니다. 범위 밖의 값은 무시됩니다 | 필요 |
| 외부 요청 대기 시간(`AMMDS_NETWORK_TIMEOUT`) | 외부 사이트를 몇 초까지 기다릴지 | 기본값(일 분 남짓)입니다. 회선이 느리면 올립니다 | 필요 |
| 한 번에 다루는 개수(`AMMDS_SCRAPE_LIMIT`) | 정보 가져오기를 한 번에 몇 개 할지 | 기본값을 씁니다. 많으면 여러 번으로 나뉩니다 | 필요 |
| 디스크 경고 기준(`AMMDS_DISK_THRESHOLD`) | 남은 공간이 이보다 적으면 알립니다(단위는 바이트) | 기본값을 씁니다. 알림을 늦게 받고 싶으면 줄입니다 | 필요 |
| 디스크 경고 비율(`AMMDS_DISK_RATIO`) | 남은 비율이 이보다 적으면 알립니다 | 기본값을 쓰며 위 항목과 함께 작동합니다 | 필요 |

## 같은 네트워크에서 자동 찾기

데스크톱 클라이언트는 이 묶음 설정으로 같은 네트워크의 AMMDS를 찾습니다.

| 설정 항목 | 무엇을 정하나요 | 비우면 어떻게 되나요 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 찾기 스위치(`AMMDS_DISCOVERY_ENABLED`) | 자동 찾기를 쓸지 | 기본은 켜짐입니다. 끄면 클라이언트에 직접 적어야 합니다 | 필요 |
| 찾기 포트(`AMMDS_DISCOVERY_PORT`) | 클라이언트가 찾을 때 쓰는 번호, 기본 `47823` | 기본 번호를 씁니다. 바꾸면 방화벽과 이어 주기도 고쳐야 합니다 | 필요 |
| 알림 스위치(`AMMDS_DISCOVERY_ANNOUNCE_ENABLED`) | 스스로 존재를 알릴지 | 기본은 켜짐입니다 | 필요 |
| 알림 포트(`AMMDS_DISCOVERY_ANNOUNCE_PORT`) | 알릴 때 쓰는 번호, 기본 `47824` | 기본 번호를 씁니다 | 필요 |
| 알림 간격(`AMMDS_DISCOVERY_ANNOUNCE_INTERVAL_SECONDS`) | 몇 초마다 알릴지, 기본 15초 | 기본 간격입니다. 0이나 음수는 15초로 돌아갑니다 | 필요 |
| 알림 받을 곳(`AMMDS_DISCOVERY_ANNOUNCE_TARGETS`) | 누구에게 알릴지, 여러 개는 쉼표로 구분 | 비우면 알림 주소와 각 회선 주소를 자동으로 씁니다. 잘못 적으면 클라이언트가 못 받습니다 | 필요 |

:::note[Docker를 쓰는 분께]
컨테이너 안의 화면 서비스는 TCP만 다룹니다. 자동 찾기를 쓰려면 이 두 UDP 포트를 반드시 따로 이어 주어야 합니다. 아니면 클라이언트가 찾지 못합니다.
:::

## 관리자 계정

| 설정 항목 | 무엇을 정하나요 | 비우면 어떻게 되나요 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 관리자 이름(`ADMIN_USER`) | 로그인에 쓰는 이름, **`ammds`로 고정**입니다 | `ammds`를 씁니다. **다른 값은 실행 실패로 이어집니다** | 필요 |
| 관리자 처음 비밀번호(`ADMIN_PASS`) | 데이터베이스를 처음 만들 때 쓰는 비밀번호 | 기본 비밀번호를 씁니다. 이미 관리자가 있으면 바꿔도 **먹지 않습니다**. 비밀번호는 내 정보에서 바꿉니다 | 필요(처음 데이터베이스를 만들 때만) |

## 외부 서비스

아래에 값을 넣으면 실행할 때마다 해당 서비스 설정으로 적히고 그 서비스가 켜집니다. 여러 대를 한꺼번에 세울 때 알맞습니다. 한두 개라면 화면에 적고 연결 확인을 하는 편이 더 알기 쉽습니다.

| 설정 항목 | 무엇을 정하나요 | 비우면 어떻게 되나요 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| MetaTube 주소와 인증 코드(`AMMDS_METATUBE_URL` / `AMMDS_METATUBE_TOKEN`) | 작품 정보 서비스의 주소와 인증 코드 | 켜지지 않습니다. 틀리면 연결이 안 되어 정보가 안 들어옵니다 | 필요 |
| Prowlarr 주소와 키(`AMMDS_PROWLARR_URL` / `AMMDS_PROWLARR_TOKEN`) | 자료 검색 서비스의 주소와 키 | 위와 같습니다 | 필요 |
| IYUU 인증 코드(`AMMDS_IYUU_TOKEN`) | 추가 시드 서비스의 인증 코드 | 켜지지 않습니다 | 필요 |
| qBittorrent 주소와 계정(`AMMDS_QBITTORRENT_URL` / `AMMDS_QBITTORRENT_USERNAME` / `AMMDS_QBITTORRENT_PASSWORD`) | 다운로더 주소와 로그인 | 켜지지 않습니다. 틀리면 보내도 아무 일이 없습니다 | 필요 |
| 텔레그램 봇(`AMMDS_TELEGRAM_BOT_TOKEN` / `AMMDS_TELEGRAM_CHAT_ID`) | 텔레그램 알림에 쓸 증표와 받는 곳 | 켜지지 않습니다. 틀리면 알림이 안 갑니다 | 필요 |

:::tip[화면에서 바꾼 것은 덮어써집니다]
이 묶음은 **실행할 때마다 다시 적힙니다**. 즉 같은 서비스를 화면에서 바꿔도 다시 실행하면 이쪽 값이 이깁니다. 덮어쓰기를 원하지 않으면 이 환경 변수를 지우세요.
:::

## 컨테이너 전용

Docker로 설치했을 때만 해당합니다.

| 설정 항목 | 무엇을 정하나요 | 비우면 어떻게 되나요 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 시간대(`TZ`) | 기록 시각과 예약 작업이 따를 시간대 | 기본 시간대를 쓰며 시각이 어긋날 수 있습니다 | 필요 |
| 실행 사용자(`PUID` / `PGID`) | 어떤 사용자로 읽고 쓸지 | 기본 사용자로 돕니다. 소유자와 다르면 '쓰기 실패'나 '권한 없음'이 납니다 | 필요 |
| 새 파일 권한(`UMASK`) | 새로 만드는 파일의 권한 | 기본값을 쓰며 보통 바꿀 일이 없습니다 | 필요 |
| 컨테이너 안 화면 포트(`NGINX_PORT`) | 컨테이너 안 화면 서비스가 기다릴 번호 | `80`을 씁니다. 바꾸면 이어 주기도 고쳐야 합니다 | 필요 |
| 메모리 한도(`AMMDS_MAX_HEAP`) | 프로그램이 쓸 수 있는 메모리 | 컨테이너 한도에서 자동으로 정해집니다. 부담이 커 보이면 직접 정하세요 | 필요 |

| 설정 항목 | 무엇을 정하나요 | 비우면 어떻게 되나요 | 다시 실행이 필요한가요 |
| --- | --- | --- | --- |
| 압축 도구 경로(`AMMDS_RAR_TOOL`) | 외부 압축 프로그램이 있는 곳 | 비우면 내장된 것을 먼저 쓰고, 못 찾을 때만 여기를 씁니다 | 필요 |
| 개발용 디버그(`AMMDS_DEVELOP_DEBUG`) | 실행할 때 일부 확인을 건너뜁니다 | 기본은 꺼짐입니다. 일상에서 켜면 예상 못 한 문제가 생깁니다 | 필요 |

## 바꾼 것이 먹었는지 확인하기

| 확인하고 싶은 것 | 보는 곳 |
| --- | --- |
| 지금 포트 | 워크벤치 '시스템 정보' 상세의 받아들이는 주소 |
| 버전과 실행 환경 | 워크벤치의 '시스템 정보' |
| 외부 서비스가 붙는지 | 아바타 메뉴 → **시스템 점검** 의 플러그인 항목 |
| 프록시와 네트워크 | 시스템 설정 → 네트워크 설정, 그리고 시스템 점검 |
| 메모리 한도가 먹었는지 | 자원 화면에 나오는 지금의 한도 |

## 문제가 생기면

- **포트를 바꿨는데 안 열림**: 새 번호로 열고 있는지 확인합니다. 다른 프로그램이 쓰고 있지 않은지, 방화벽이 허용하는지도 봅니다.
- **용량을 올렸는데도 못 올림**: 둘을 함께 올리고 요청 한도가 파일 한도보다 작지 않게 하세요. Docker라면 컨테이너 안 화면 서비스의 한도도 확인합니다.
- **설정이 아예 안 먹음**: 먼저 이름을 잘못 적지 않았는지 봅니다(틀리면 조용히 무시됩니다). 그다음 다시 실행이나 컨테이너 다시 만들기를 했는지 확인합니다.
- **바꾼 뒤 실행이 안 됨**: 그 항목을 지워 기본으로 돌리고 하나씩 더해 원인을 좁힙니다. 사용자 이름 항목은 특히 건드리지 마세요.
- **그래도 안 됨**: [자주 묻는 질문](../faq.md)에서 증상으로 찾거나, 버전과 로그를 담아 GitHub로 알려 주세요: https://github.com/QYG2297248353/AMMDS-Docker/issues/new
