프로젝트를 시작하며 비슷한 도구를 조사할 때 TinyMediaManager(약칭 TMM)는 우리가 거듭 살펴본 대상이었습니다. 이는 Java로 작성된 무료 오픈 소스 미디어 관리 도구로 Windows, Linux, macOS에서 플랫폼을 가리지 않고 실행됩니다. 이 도구는 우리의 경쟁자가 아니라 훌륭한 "교과서"였습니다.

{/* truncate */}

## 도대체 무엇을 하는가

TMM의 핵심 위치는 다음과 같습니다. **로컬 미디어 라이브러리를 정리하고 메타데이터, 표지, 파일 구조를 미리 준비해** Kodi, Plex, Emby, Jellyfin 같은 미디어 센터에서 쓰게 하는 것입니다. 다시 말해 이 도구는 AMMDS와 생태계의 같은 층에 있습니다. 둘 다 "정리"를 담당하지 "재생"을 담당하지 않습니다.

공개된 기능 목록을 보면 몇 가지 일을 매우 탄탄하게 해냅니다.

- **다중 소스 스크래핑**: IMDb, TheMovieDB, TVDb, OFDb, Moviemeter, Trakt 등 여러 메타데이터 소스를 지원합니다.
- **자료 다운로드**: 포스터, 배경 이미지, 로고, 그리고 FanArt.tv의 아트 이미지를 받습니다.
- **자막**: OpenSubtitles.org에서 가져옵니다.
- **기술 정보**: MediaInfo 라이브러리로 인코딩, 재생 시간, 해상도 등을 추출해 NFO에 기록합니다.
- **일괄 이름 변경**: 사용자가 정의한 형식에 따라 파일명과 디렉터리를 자동으로 정리합니다.
- **NFO 출력**: 모든 정보를 Kodi 호환 NFO 파일에 자동으로 기록합니다.
- **두 가지 인터페이스**: 그래픽 인터페이스와 명령줄 인터페이스를 모두 제공합니다.

## 배울 만한 세 가지

### 첫째, 데이터가 소프트웨어에 갇히지 않음

TMM은 모든 것을 자체 사유 데이터베이스에 가두지 않고 NFO 파일에 기록합니다. 우리는 이 점에 전적으로 동의합니다. **사용자의 데이터는 반드시 가져갈 수 있어야 합니다.** 이것이 AMMDS가 표준 NFO와 표준 백업 패키지를 고집하는 근본 이유입니다.

### 둘째, 다중 소스 + 수동 수정

여러 메타데이터 소스를 지원하면서도 사용자가 모든 필드를 직접 편집할 수 있게 합니다. 이 조합이 중요합니다. 자동 스크래핑은 효율을 맡고, 수동 수정은 정확성을 맡습니다. 우리가 나중에 [우선순위 규칙 엔진](/blog/plugin-architecture)을 만들 때도 같은 발상을 따랐습니다.

### 셋째, 크로스 플랫폼의 기반은 JVM

TMM은 Java 애플리케이션으로 Java 런타임(최소 JRE 8)에 의존하기 때문에 자연스럽게 플랫폼을 넘나듭니다. 이는 [기술 선택](/blog/tech-stack-decision)에서 우리가 Java 생태계를 높이 평가한 판단을 뒷받침합니다. 다만 우리는 GraalVM으로 런타임까지 함께 패키징해 사용자가 JRE조차 설치하지 않도록 했습니다.

## 우리와의 차이점

TMM은 데스크톱 애플리케이션인 반면, AMMDS는 처음부터 **셀프 호스팅 + 웹 패널** 형태로 NAS나 항상 켜져 있는 기기에서 실행되고 브라우저로 접근합니다. 이는 제품 포지셔닝의 차이일 뿐 우열의 문제가 아닙니다. 자신의 컴퓨터에서 폴더 하나만 정리하려면 TMM이 잘 맞고, 온 가족의 기기에서 언제든 미디어 라이브러리를 관리하려면 AMMDS 같은 서비스가 필요합니다.

거인의 어깨 위에 서기에 우리는 시행착오를 줄일 수 있었습니다. TMM이 검증한 많은 방식이 오늘날 AMMDS의 설계에도 반영되어 있습니다.
