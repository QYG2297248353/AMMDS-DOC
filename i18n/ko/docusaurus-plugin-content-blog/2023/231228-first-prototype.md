2023년 마지막 주, AMMDS의 첫 실행 가능한 프로토타입이 태어났습니다. 오늘의 눈으로 보면 너무나 조촐해서 꺼내 말하기 부끄러울 정도이지만, 바로 이 프로토타입 덕분에 가장 중요한 한 가지를 확인했습니다. 이 길은 갈 수 있다는 점입니다.

{/* truncate */}

## 프로토타입은 세 가지 일만 했다

당시의 AMMDS에는 인터페이스도, 플러그인 마켓도, 지금 같은 화려한 기능도 없었습니다. 단 세 가지 일만 했습니다:

1. 단일 사이트에서 토렌트 목록 가져오기;
2. 토렌트에 담긴 메타데이터 정보 파싱;
3. 가장 기본적인 NFO 파일 생성.

이 세 단계가 전부였습니다. 하지만 전체 흐름을 처음부터 끝까지 관통했습니다. '하드디스크에 이름이 엉망인 파일'에서 '미디어 서버가 알아볼 수 있는 기록'까지요.

## 왜 가장 단순한 흐름부터 만들었는가

프로토타입 단계에서 저희는 '모든 기능을 다 만들고 싶다'는 충동을 일부러 눌렀습니다. 이유는 매우 현실적이었습니다:

- **핵심 가설 검증**: 사이트에서 데이터를 가져오고 파싱하고 NFO를 기록하는 이 가장 기본적인 흐름조차 작동하지 않는다면, 이후의 모든 거창한 계획은 공상에 불과합니다.
- **미지의 것을 최대한 일찍 드러내기**: 사이트 페이지 구조, 메타데이터 필드, NFO 형식의 세부 사항처럼 실제로 코드를 작성할 때야 비로소 드러나는 문제는 일찍 마주할수록 좋습니다.
- **아키텍처를 시험할 장 마련**: 플러그인 엔진, 파이프라인 방식 데이터 처리, 가상 스레드 기반 스케줄링 같은 훗날 이어진 설계는 모두 이 프로토타입에서 필요에 의해 처음 생겨났습니다.

## 다시 작성된 코드들

오늘 되돌아보면 프로토타입의 많은 코드가 이미 여러 번 다시 작성되었습니다:

| 프로토타입 단계 | 현재의 방식 |
| :--- | :--- |
| 단일 사이트 파싱 하드코딩 | 교체 가능한 사이트 어댑터 |
| 일회성 처리 흐름 | 파이프라인 방식 데이터 처리 |
| 동기 순차 실행 | 가상 스레드 스케줄링 |
| 고정 NFO 템플릿 | 다중 형식 자동 대응 |

코드는 바뀌었지만 **아키텍처의 방향은 바뀌지 않았습니다**. 이것이 프로토타입이 우리에게 남긴 가장 값진 것으로, 더 많은 자원을 투입하기 전에 기술 선택이 올바름을 확인하게 해 주었습니다.

## 흐름이 처음 통했을 때의 느낌

프로토타입이 처음으로 완전히 작동한 그날 밤, 저희는 화면에 생성된 NFO 파일을 한참 동안 바라보았습니다. 완벽하지도, 빠진 필드가 없지도, 배열이 예쁘지도 않았습니다. 하지만 그것은 저희가 직접 만든 프로그램이 뒤섞인 데이터 더미 속에서 한 편의 작품을 알아내고, 이를 구조화된 정보로 정리해 낸 결과였습니다.

그 순간 저희는 확신했습니다. 이 일은 계속해 볼 가치가 있다고요.

이후 일어난 모든 일, 즉 2024년의 아키텍처 완성부터 2025년의 v1.0.0 출시에 이르기까지, 전부 이 초라한 프로토타입에서 시작되었습니다.
