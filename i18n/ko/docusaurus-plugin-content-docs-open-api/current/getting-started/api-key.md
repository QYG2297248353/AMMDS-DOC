# 먼저 열쇠부터 받기

다른 프로그램이 AMMDS 자료를 읽으려면 먼저 '열쇠'가 필요합니다. 이 페이지에서는 열쇠가 무엇인지, 어떻게 얻는지, 어떻게 보관하는지, 잃어버리면 어떻게 하는지를 다룹니다.

열쇠가 필요한지부터 모르겠다면 [오픈 플랫폼으로 할 수 있는 일](./overview.md)을 먼저 보세요.

## 먼저 말부터 정리합니다

> **API 키**: 문자 한 줄로, 집 열쇠 같은 것입니다. 가진 사람은 그 권한 범위에서 자료를 읽을 수 있습니다. AMMDS는 '누구인지'가 아니라 '그 문자열이 맞는지'만 봅니다.

> **인증**: 들어가기 전에 신분을 밝히는 일입니다. 오픈 API에서는 요청에 열쇠를 넣어 보내는 것이 여기에 해당합니다.

> **헤더**: 본문과 별개로 요청에 함께 실어 보내는 작은 부가 정보입니다. '열쇠는 이것', '형식은 이것' 같은 것을 알리는 데 씁니다.

## 세 단계로 열쇠를 얻습니다

### 1단계: 오픈 API 켜기

1. AMMDS 관리 화면에 로그인하고 **시스템 → 시스템 설정**을 엽니다.
2. 오픈 API 스위치(설정 키 `GLOBAL_OPEN_API`)를 켭니다.
3. 설정을 저장합니다.

:::warning[두 조건이 모두 맞아야 통과합니다]
요청에 유효한 `x-api-key`가 들어 있어야 **하고**, 오픈 API 스위치도 켜져 있어야 합니다. 하나라도 빠지면 들어갈 수 없습니다.
:::

### 2단계: 열쇠 만들기

1. **시스템 → 키 관리**를 엽니다.
2. 키 만들기를 선택합니다.
3. 이름에는 나중에 구분할 수 있게 용도를 적습니다. 예: '백업 스크립트'.
4. 종류는 **X-API-KEY**(`secret_x_api_key`)를 고릅니다.
5. 저장한 뒤 **바로 열쇠를 복사**하세요. 화면을 닫으면 전체를 다시 볼 수 없습니다.

:::note[열쇠 종류는 서로 섞이지 않습니다]
키 관리에는 'AMMDS 도우미'와 'Mihon 확장'이라는 종류도 있습니다. **Mihon**용 인증 코드는 `/api/mihon`에서만 쓸 수 있고 `/api/v1`에서는 호출할 수 없습니다. 그 밖의 종류(X-API-KEY와 AMMDS 도우미 포함)는 기술적으로 `/api/v1`에서 쓸 수 있습니다. 다만 오픈 API에는 **X-API-KEY** 사용을 권장합니다. 용도가 분명하고 문제를 파악하기 가장 쉽기 때문입니다.
:::

### 3단계: 요청에 열쇠 실어 보내기

명령줄에서 하는 완전한 호출입니다. `<내 열쇠>`를 복사한 문자열로 바꾸세요.

```bash
curl -H "x-api-key: <내 열쇠>" \
  "http://127.0.0.1:8080/api/v1/movie/count"
```

| 항목 | 값 |
| --- | --- |
| 헤더 이름 | `x-api-key`(소문자, 가운데는 붙임표) |
| 적용 범위 | `/api/v1/**`만 |
| 열쇠가 필요 없는 주소 | `/api/v1/health/**` |

## 설정 항목

| 설정 항목 | 무엇을 넣나 | 넣지 않거나 잘못 넣으면 |
| --- | --- | --- |
| 오픈 API 스위치 | 시스템 → 시스템 설정에서 켜졌는지 확인. 설정 키 `GLOBAL_OPEN_API`(기본값은 켜짐) | 꺼져 있으면 멀쩡한 열쇠도 거절됩니다 |
| 키 이름 | 아무거나 되지만 용도를 적으면 나중에 구분하기 쉽습니다 | 동작에는 영향이 없고, 나중에 구분이 어려워집니다 |
| 키 종류 | **X-API-KEY** 권장 | Mihon 종류는 `/api/v1`에서 쓸 수 없습니다. 다른 종류는 쓸 수 있지만 권장하지 않습니다 |
| 열쇠 문자열 | 만들 때 복사한 전체 | 한 글자 빠지거나 공백이 섞이면 인증이 실패합니다 |
| 헤더 이름 | 반드시 `x-api-key` | `api-key`나 `X_API_KEY`는 인식되지 않습니다 |

## 열쇠를 잃어버렸거나 새어 나갔을 때는

열쇠는 비밀번호처럼 고칠 수 없습니다. '옛것을 무효로 하고 새것을 만드는' 방법뿐입니다.

1. **시스템 → 키 관리**에서 문제가 된 열쇠를 **삭제**합니다.
2. 새 열쇠를 만들고 문자열을 복사합니다.
3. 옛 열쇠를 쓰던 곳(스크립트, 클라이언트, 도구 설정)을 모두 새 열쇠로 바꿉니다.

:::warning[새어 나갔다면 이것부터]
옛 열쇠 삭제가 먼저입니다. 삭제한 순간 그 열쇠는 더는 쓸 수 없으니, 남의 손에 있어도 쓸 수 없습니다. 새 열쇠는 비밀번호처럼 다루고, 대화방이나 게시판, 코드 보관소에는 붙이지 마세요.
:::

평소에 지키면 좋은 것들입니다.

- **용도별로 나누기**: 백업용 하나, 휴대전화용 하나. 문제가 생긴 열쇠만 무효로 할 수 있습니다.
- **웹 앞단에 두지 않기**: 브라우저의 네트워크 목록에 열쇠가 그대로 보이므로, 공개하는 것과 같습니다. 서버 쪽이나 내 기기에 두세요.
- **때때로 교체하기**: 삭제하고 다시 만들면 그것이 한 번 교체입니다.
- **기본은 집 안 네트워크에서**: 오픈 API를 외부에 공개하는 것은 피하고 싶습니다. 꼭 필요하면 앞에 로그인 장치를 하나 더 두세요.

## 거절당했을 때의 모습

인증에 실패해도 AMMDS는 답을 돌려보냅니다. 다만 안의 `code`가 `401`입니다.

```json
{
  "code": 401,
  "message": "您的登录已过期，请重新登录",
  "data": null,
  "timestamp": 1753958400000
}
```

`message`는 서버가 실제로 돌려주는 문구이며 중국어입니다. 뜻은 '로그인이 만료되었습니다'입니다.

아래를 순서대로 확인하세요.

1. 오픈 API 스위치가 켜져 있나요.
2. 헤더 이름이 `x-api-key`(소문자, 붙임표)로 되어 있나요.
3. 열쇠 종류가 X-API-KEY인가요.
4. 열쇠가 삭제되거나 다시 만들어지지 않았나요.
5. 그 주소가 정말 `/api/v1` 아래인가요. (열쇠를 든 채 관리 쪽으로 가면 거절됩니다. 의도된 동작입니다.)

## 잘 안 될 때는

- **`401`이 계속 옵니다**: 위 다섯 가지를 순서대로 확인하세요. 가장 흔한 것은 스위치가 꺼져 있는 경우와 열쇠 종류가 다른 경우입니다.
- **열쇠를 중간까지 복사했습니다**: 삭제하고 다시 만든 뒤, 첫 글자와 마지막 글자를 빼먹지 않게 복사하세요.
- **열쇠를 넣으면 관리 쪽 인터페이스가 안 됩니다**: 그렇게 만들었습니다. 열쇠가 여는 것은 `/api/v1`뿐이라, 오래 쓰는 열쇠로 로그인 기록을 건너뛸 수 없습니다.
- **방문객에게 열쇠를 주고 싶습니다**: 권하지 않습니다. 열쇠의 권한은 내 계정과 같고, 사용자별 로그인 기록도 남지 않아 나중에 추적할 수 없습니다.
