# 첫 번째 호출

이 페이지에서는 AMMDS에 물음을 보내고, 답을 받고, 그 안의 항목이 무엇을 뜻하는지 하나씩 이해하는 과정 전체를 함께 해 봅니다. 예시는 그대로 옮겨 쓸 수 있고, 주소와 내 열쇠만 바꾸면 됩니다.

시작하기 전에 [먼저 열쇠부터 받기](./api-key.md)의 두 가지를 준비하세요. 오픈 API 스위치가 켜져 있어야 하고, X-API-KEY 열쇠를 가지고 있어야 합니다.

## 먼저 말부터 정리합니다

> **요청**: 프로그램이 AMMDS에 보내는 '이걸 원한다'는 물음입니다.

> **응답**: AMMDS가 돌려보내는 내용 묶음입니다.

> **JSON**: 그 내용의 형식으로, '항목 이름'과 '값'이 짝을 이룹니다. 예: `{"code": 200, "data": true}`.

> **상태 코드**: 답변 안의 `code` 항목입니다. 숫자 하나로 이번에 되었는지 바로 알 수 있습니다.

## 준비물

| 항목 | 내용 |
| --- | --- |
| 인스턴스 주소 | AMMDS가 도는 기기의 주소. 예: `http://192.168.1.10:8080` |
| 열쇠 | 시스템 → 키 관리에서 만들고, 종류는 X-API-KEY |
| 오픈 API 스위치 | 시스템 → 시스템 설정에서 켜기(설정 키 `GLOBAL_OPEN_API`) |

아래 예시에서는 `http://192.168.1.10:8080`을 씁니다. 내 주소로 바꾸세요.

## 1단계: 브라우저로 서비스가 도는지 확인하기

상태 확인 주소는 **열쇠가 필요 없어서** 브라우저로 바로 열 수 있습니다. 아래를 주소창에 붙이고 Enter를 누르세요.

`http://192.168.1.10:8080/api/v1/health/check`

브라우저에 이렇게 보입니다.

```json
{
  "code": 200,
  "message": "success",
  "data": true,
  "timestamp": 1753958400000
}
```

`data`가 `true`이면 서비스가 돌고 있고 주소도 맞습니다.

:::note[여기서 알 수 없는 것]
상태 확인은 '프로그램이 돌고 있다'는 것만 알려 줍니다. 데이터베이스, 디스크, 외부 서비스는 보지 않습니다. 그런 것은 관리 화면의 '시스템 점검'에서 확인하세요.
:::

## 2단계: 열쇠를 넣어 작품 개수 묻기

여기에는 열쇠가 필요합니다. 브라우저 주소창으로는 열쇠를 보낼 수 없으니 명령줄을 씁니다. `<내 열쇠>`를 바꿔서 실행하세요.

```bash
curl -s -H "x-api-key: <내 열쇠>" \
  http://192.168.1.10:8080/api/v1/movie/count
```

답은 이렇습니다.

```json
{ "code": 200, "message": "success", "data": 1286, "timestamp": 1753958400000 }
```

`data`의 `1286`이 라이브러리에 있는 작품 개수입니다. `code`가 `401`이면 [먼저 열쇠부터 받기](./api-key.md)를 하나씩 확인하세요.

## 3단계: 번호로 작품 찾기

```bash
curl -s -X POST http://192.168.1.10:8080/api/v1/movie/search \
  -H "x-api-key: <내 열쇠>" \
  -H "Content-Type: application/json" \
  -d '{"keyword":"ABC-123","waitTime":30}'
```

답의 `data`는 목록이고, 요소 하나가 자료 한 건입니다.

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "source": "metatube",
      "provider": "jav",
      "number": "ABC-123",
      "title": "示例标题",
      "summary": "示例简介",
      "cover": "https://example.com/cover.jpg",
      "actors": ["演员A"],
      "genres": ["类型A"],
      "score": 8.6,
      "runtime": 120,
      "release": "2025-10-16 00:00:00",
      "extras": {}
    }
  ],
  "timestamp": 1753958400000
}
```

### 항목이 뜻하는 것

| 항목 | 뜻 |
| --- | --- |
| `code` | 이번에 되었는지. `200`에서 `299` 사이가 성공입니다 |
| `message` | 한 줄 설명입니다. 실패하면 이유가 적히니 그대로 보여 줘도 됩니다 |
| `data` | 진짜 자료입니다. 실패하면 대개 `null`입니다 |
| `timestamp` | 서버가 답한 시각. 밀리초 단위 숫자입니다 |
| `source` / `provider` | 어느 출처인지, 그리고 그 안의 구분 |
| `number` / `title` / `summary` | 번호, 제목, 줄거리 |
| `cover` | 표지 그림 주소 |
| `actors` / `genres` | 출연진, 장르. 대괄호 안에 여러 개가 들어갑니다 |
| `score` / `runtime` / `release` | 평점(10점 만점), 길이(분), 발매일 |
| `extras` | 그 출처에만 있는 추가 항목 |

:::note[항목이 비어 있을 수 있습니다]
출처마다 줄 수 있는 정보가 달라서, 못 주는 것은 비어서 돌아옵니다. 이상이 아니니 비었다고 해서 오류로 다루지 마세요.
:::

## 4단계(생략 가능): 찾은 자료를 라이브러리에 넣기

`source`와 `id`를 얻었으면 바로 넣을 수 있습니다.

```bash
curl -s -X POST http://192.168.1.10:8080/api/v1/movie/import/from-source \
  -H "x-api-key: <내 열쇠>" \
  -H "Content-Type: application/json" \
  -d '{"source":"metatube","id":"12345","provider":"jav"}'
```

답의 `data`가 넣은 뒤의 작품 ID입니다.

## 설정 항목

| 설정 항목 | 무엇을 넣나 | 넣지 않거나 잘못 넣으면 |
| --- | --- | --- |
| 인스턴스 주소 | `http://<주소>:<포트>`. 포트 기본값은 `8080` | 잘못 쓰면 연결이 안 되고 시간 초과까지 기다립니다 |
| `x-api-key` | 만든 X-API-KEY 열쇠 | 다르면 `code`가 `401`로 옵니다 |
| `keyword` | 찾을 번호나 제목 낱말 | 필수입니다. 없으면 입력 검사에서 걸립니다 |
| `waitTime` | 각 출처를 몇 초 기다릴지. 생략하면 기본값 | 통신이 느릴 때 너무 작으면 결과가 모이기 전에 답이 옵니다 |
| `source` / `id` | 앞 단계에서 얻은 출처와 ID | 잘못됐거나 출처가 켜져 있지 않으면 넣기가 실패합니다 |
| `Content-Type` | JSON 본문을 보낼 때는 `application/json` | 쓰지 않으면 서버가 본문을 잘못 읽을 수 있습니다 |

## 잘 안 될 때는

- **브라우저에서 상태 확인이 안 열립니다**: 주소나 포트가 다릅니다. AMMDS가 도는지 확인하고, 다른 기기에서라면 `127.0.0.1`을 쓰지 마세요.
- **`code`가 `401`입니다**: 오픈 API 스위치가 꺼져 있거나, 열쇠 종류가 X-API-KEY가 아니거나, 열쇠 복사가 덜 된 것입니다.
- **검색 결과가 비어 있습니다**: 대개 출처가 하나도 켜져 있지 않습니다. 플러그인 설정에서 하나를 켜고 연결을 시험하세요.
- **넣기가 실패합니다**: 출처가 켜져 있는지, 값이 맞는지 확인하세요. 번호가 이미 있으면 두 번 넣어도 두 건이 되지 않습니다.
