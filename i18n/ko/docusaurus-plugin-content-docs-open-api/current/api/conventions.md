# 요청과 응답 읽는 법

오픈 API의 모든 인터페이스는 같은 규칙을 따릅니다. 이 페이지를 먼저 읽으면 뒤에서 생길 잘못된 해석과 판단의 대부분을 피할 수 있습니다.

## 먼저 말부터 정리합니다

> **요청**: 프로그램이 AMMDS에 보내는 '이걸 원한다'는 물음입니다.

> **응답**: AMMDS가 돌려보내는 내용 묶음입니다.

> **JSON**: 그 내용의 형식으로, '항목 이름'과 '값'이 짝을 이룹니다. 예: `{"code": 200, "data": true}`.

> **헤더**: 본문과 별개로 요청에 함께 실어 보내는 작은 부가 정보입니다. 열쇠나 형식을 알리는 데 씁니다.

> **상태 코드**: 답변 안의 `code` 항목입니다. 숫자로, 되었는지와 안 되었다면 대략 무엇 때문인지 알려 줍니다.

> **페이지 나누기(페이지네이션)**: 자료가 많을 때 페이지 번호와 페이지당 개수로 조금씩 나눠 건네는 방식입니다.

## 기본 정보

| 항목 | 내용 |
| --- | --- |
| 주소 | `http://<호스트>:<포트>`. 포트 기본값은 `8080` |
| 문자 인코딩 | UTF-8 |
| 요청과 응답 형식 | `application/json`(파일을 보내는 인터페이스는 `multipart/form-data`) |
| 인증 | 헤더에 `x-api-key` |

## 돌아오는 내용의 생김새

성공이든 실패든 같은 모양입니다.

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1753958400000
}
```

| 항목 | 뜻 |
| --- | --- |
| `code` | 이번에 되었는지 알려 주는 숫자 |
| `message` | 한 줄 설명입니다. 실패하면 이유가 적히니 사용자에게 그대로 보여 줘도 됩니다 |
| `data` | 진짜 자료입니다. 실패하면 대개 `null`입니다 |
| `timestamp` | 서버가 답한 시각. 밀리초 단위 숫자입니다 |

:::warning[HTTP 상태만 보지 마세요]
만화 리더용을 빼고는, 처리상의 실패도 **HTTP로는 성공으로 돌아오는** 것이 보통입니다. 진짜 결과는 내용 안의 `code`에 나옵니다. 성공 판정은 `200 <= code < 300`입니다.
:::

## 상태 코드

| `code` | 뜻 | 흔한 원인 |
| --- | --- | --- |
| `200` | 되었습니다 | `data`에 원한 것이 들어 있습니다 |
| `400` | 보낸 것이 잘못되었습니다 | 검사를 통과하지 못함, 필수 항목 누락 |
| `401` | 권한이 없습니다 | 열쇠가 없거나 무효, 또는 오픈 API가 꺼져 있음 |
| `403` | 거절되었습니다 | 권한이 모자람 |
| `404` | 찾을 수 없습니다 | 주소나 대상이 없음 |
| `500` | 서버 쪽 문제입니다 | 안에서 실패. `message`에 이유 요약이 들어 있습니다 |

:::note[일부는 data로 실패를 알립니다]
넣기 같은 일부 인터페이스는 실패할 때 `code=500`과 `data=false`를 돌려보냅니다. 한 항목으로 결과를 읽게 하려는 것입니다. 각 인터페이스 설명을 따르세요.
:::

## 날짜는 어떻게 쓰나요

| 상황 | 형식 | 예 |
| --- | --- | --- |
| 응답 속 날짜와 시각 | `yyyy-MM-dd HH:mm:ss`(UTC+8) | `2025-10-16 20:30:00` |
| 요청에 보내는 날짜 | `yyyy-MM-dd` | `2025-10-16` |
| 타임스탬프 | 밀리초 | `1753958400000` |

## 값이 여러 개인 항목은요

작품 자료에서 '번호, 표지, 장르, 태그, 감독, 제작사'는 **여러 값이 든 항목**입니다.

- **읽을 때**: 표준 JSON 배열로 옵니다. 예: `"actors": ["演员A", "演员B"]`
- **쓸 때**: 간단 넣기 인터페이스는 배열을 그대로 받고, 양식 전송(`multipart/form-data`)은 배열을 문자열로 적어 받습니다.

## 페이지 나누기

오픈 API 쪽의 작품 인터페이스는 **페이지를 나누지 않습니다**. 검색 결과가 한 번에 모두 옵니다.

만화 리더용은 `page`와 `pageSize`로 페이지를 나누고, 페이지 번호는 `1`부터 시작합니다.

## 두 번 불러도 괜찮나요

- **검색, 상세, 개수, 대조**: 읽기만 하므로 몇 번 다시 해도 안전합니다.
- **넣기**: 고유 번호로 중복을 판정하므로 두 번 넣어도 두 건이 되지 않습니다.
- **번역**: 아무런 부작용이 없습니다.

## 얼마나 기다려야 하나요

| 인터페이스 종류 | 권장 시간 초과 |
| --- | --- |
| 상태 확인, 개수 조회 | 5초 |
| 상세, 로컬 대조 | 10초 |
| 여러 출처 검색 | 60초 이상(`waitTime`으로 조절) |
| 번역 | 30초 |

## 헤더 한눈에 보기

| 이름 | 값 | 적용 범위 |
| --- | --- | --- |
| `x-api-key` | 내 열쇠 | `/api/v1/**`만 |
| `Authorization` | `Bearer <인증 코드>` | `/api/mihon/**`만 |
| `Content-Type` | `application/json` 또는 `multipart/form-data` | 인터페이스가 정한 대로 |

> **User-Agent**: 요청에 붙는 한 줄로, '내가 어떤 프로그램인지'를 알려 줍니다. 채우지도 바꾸지도 않아도 됩니다.

## 설정 항목

한 번 호출에 채우는 것은 이것뿐입니다.

| 설정 항목 | 무엇을 넣나 | 넣지 않거나 잘못 넣으면 |
| --- | --- | --- |
| 호스트와 포트 | `http://<호스트>:<포트>`. 포트 기본값은 `8080` | 잘못 쓰면 아무것도 연결되지 않습니다 |
| `x-api-key` | 시스템에서 만든 X-API-KEY 열쇠 | 없거나 다르면 `code`가 `401` |
| `Content-Type` | JSON 본문이면 `application/json`, 파일 전송이면 `multipart/form-data` | 잘못 쓰면 본문을 잘못 읽을 수 있습니다 |
| 여러 값 항목 | 간단 넣기는 JSON 배열, 양식 전송은 배열을 문자열로 | 형식이 다르면 검사에서 걸립니다 |
| 날짜 값 | `yyyy-MM-dd`로 적기 | 다른 형식이면 검사를 통과하지 못합니다 |

## 잘 안 될 때는

- **HTTP는 성공인데 자료가 다릅니다**: HTTP 상태를 보지 말고 내용 안의 `code`와 `message`를 보세요.
- **`code`가 `400`입니다**: 인터페이스 설명을 보며 필수 값을 확인하세요. 항목 이름과 자료형이 흔한 원인입니다.
- **`code`가 `401`입니다**: 오픈 API 스위치가 켜져 있는지, 열쇠 종류가 X-API-KEY인지, 헤더 이름이 `x-api-key`인지 확인하세요.
- **시각이 어긋납니다**: 응답의 시각은 UTC+8이라 내 시계와 몇 시간 다를 수 있습니다. 정상입니다.
- **어떤 항목이 비어 있습니다**: 출처마다 줄 수 있는 정보가 달라서, 못 주는 것은 비어서 옵니다. 고장이 아닙니다.
