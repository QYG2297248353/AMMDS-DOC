# 백업 패키지 안에는 무엇이 있나요

AMMDS는 작품과 배우 자료를 압축 파일(백업 패키지)로 내보내고, 나중에 다시 넣을 수 있습니다. 이 페이지는 **백업 스크립트를 직접 작성**하거나 **압축 파일을 열어 내용을 확인**하고 싶은 분을 위한 것입니다. 올바른 패키지가 어떤 모습인지, 어디에서 실수하기 쉬운지를 다룹니다.

화면에서 백업하고 되돌리는 것만으로 충분하다면 관리 기능의 '백업과 복원'이면 됩니다. 이 페이지는 넘어가셔도 괜찮습니다.

## 먼저 말부터 정리합니다

> **백업 패키지**: 내보낸 자료가 든 zip 압축 파일입니다. 두 AMMDS 사이에서 자료를 옮기거나 오래 보관할 때 씁니다.

> **JSON**: 안의 자료 파일 형식으로, '항목 이름'과 '값'이 짝을 이룹니다. 사람도 프로그램도 읽을 수 있습니다.

> **목록 파일(매니페스트)**: 압축 파일 안에 '이 패키지가 무엇인지, 몇 건인지, 그림이 어디 있는지'를 적어 둔 파일입니다. 넣을 때 AMMDS가 가장 먼저 읽습니다.

> **고유 식별자**: 작품의 번호입니다. 넣을 때 '이 자료가 이미 있는지'를 판단하는 데 씁니다.

## 압축 파일에 무엇이 들어가나요

| 파일 | 꼭 있어야 하나 | 내용 |
| --- | --- | --- |
| `manifest.json` | 예 | 목록 파일. 형식 표시, 버전, 자료 종류, 만든 시각, 건수, 그림 대응표 |
| `data.json` | 예 | 진짜 자료. JSON 배열이고, 요소 하나가 작품 한 편이나 배우 한 명 |
| `images/` | 아니오 | 그림 폴더. 내보낼 때 '그림 파일도 함께 내보내기'를 고른 경우에만 있습니다 |

꼭 필요한 두 파일은 압축 파일의 **맨 위 폴더**에 둡니다.

:::warning[한 패키지에는 한 종류만]
패키지에는 **작품**이나 **배우** 중 하나만 들어가고, 섞어 담을 수 없습니다. 종류는 목록 파일의 `type`에 적습니다. 작품은 `movie`, 배우는 `actor`입니다.
:::

## 목록 파일에 적히는 것

| 항목 | 설명 |
| --- | --- |
| `format` | 형식 표시. 늘 `ammds-backup` |
| `formatVersion` | 형식 버전 번호. 지금은 `1` |
| `type` | 자료 종류. `movie`(작품) 또는 `actor`(배우) |
| `generatedAt` | 만든 시각 |
| `appVersion` | 이 패키지를 만든 AMMDS 버전 |
| `includeImages` | 그림 파일이 들어 있는지 |
| `count` | `data.json`의 건수 |
| `imageFiles` | 그림 대응표. '원래 경로 → 패키지 안 경로 → 파일 요약값'을 한 건씩 적어 둠 |

'그림 파일도 함께 내보내기'를 고르지 않았다면 `images/`가 없고, `includeImages`는 `false`, `imageFiles`는 빈 목록입니다.

## 그림은 어떻게 다루나요

패키지 안의 그림 항목은 **원래 참조 형태** 그대로입니다. 두 가지가 있습니다.

| 형태 | 생김새 | 내보낼 때 들어가나 | 넣을 때 어떻게 되나 |
| --- | --- | --- | --- |
| 외부 링크 | `http`나 `https`로 시작하는 완전한 주소 | **들어가지 않습니다** | 처음부터 끝까지 그대로이고, 고쳐 쓰지 않습니다 |
| 로컬 경로 | `data`로 시작하는 상대 경로 | 파일이 실제로 있을 때만 들어갑니다 | 저장한 뒤 항목이 새 `data` 경로로 고쳐 쓰입니다 |

둘이 같은 항목 안에 함께 있어도 됩니다.

요점은 두 문장입니다. 외부 링크는 내보낼 때도 넣을 때도 전혀 건드리지 않습니다. 로컬 경로는 파일이 실제로 있을 때만 패키지에 들어가고, 넣은 뒤 새 경로로 고쳐 쓰입니다.

:::note[넣을 때 그림은 겹침을 걷어냅니다]
그림이 든 패키지를 넣을 때 파일 내용으로 겹침을 판정해, 같은 것은 하나만 저장합니다. 같은 패키지를 여러 번 넣어도 디스크가 늘어나지 않습니다.
:::

## 넣을 때 어떻게 같은 자료로 보나요

| 자료 종류 | 같은 자료로 보는 기준 |
| --- | --- |
| 작품(`movie`) | 식별자가 겹치는지. 이미 있는 번호와 넣는 자료의 번호가 하나라도 같으면 같은 자료입니다 |
| 배우(`actor`) | 이름이 완전히 같아야 같은 자료입니다 |

이미 있는 자료를 만나면 고른 방식대로 처리합니다.

| 방식 | 동작 |
| --- | --- |
| 건너뛰기 | 이미 있는 것은 건드리지 않고, 새로운 것만 더합니다 |
| 덮어쓰기 | 이미 있는 것을 패키지 내용으로 갱신하고, 없으면 새로 만듭니다 |

## 어떤 패키지가 거절되나요

아래의 하나라도 해당하면 넣기 전체가 거절되고, **이미 있던 자료는 조금도 바뀌지 않습니다**.

- 목록 파일의 `format`이 `ammds-backup`이 아닙니다.
- 형식 버전이 지금 프로그램이 받는 범위보다 높습니다.
- `manifest.json`이나 `data.json`이 없습니다.
- 압축 파일 안에, 풀리는 폴더 밖으로 빠져나가려는 수상한 파일 경로가 있습니다.

## 설정 항목

| 설정 항목 | 무엇을 넣나 | 넣지 않거나 잘못 넣으면 |
| --- | --- | --- |
| `format` | 늘 `ammds-backup` | 다르면 패키지 전체가 거절됩니다 |
| `formatVersion` | 지금 버전 `1` | 받는 범위보다 높으면 거절됩니다 |
| `type` | `movie` 또는 `actor` | 다른 값이거나 두 종류를 섞으면 올바르지 않습니다 |
| `data.json` | 자료 배열. 항목은 AMMDS의 자료 구조에 맞춥니다 | 파일이 없으면 거절, 항목이 다르면 넣기가 실패합니다 |
| 그림 참조 | 외부 그림은 완전한 주소, 로컬은 `data`로 시작하는 상대 경로 | 경로가 다르면 넣은 뒤 그림이 없습니다 |
| 겹침 처리 방식 | '건너뛰기'나 '덮어쓰기'를 고릅니다 | 고르지 않으면 겹칠 때 동작이 정해지지 않습니다 |

## 잘 안 될 때는

- **넣기가 거절됩니다**: `manifest.json`을 열어 `format`이 `ammds-backup`인지, `type`이 `movie`나 `actor`인지 확인하세요. 이 두 가지가 가장 흔한 원인입니다.
- **넣은 뒤 그림이 안 나옵니다**: 외부 링크는 처리되지 않으니 그 주소가 지금도 열리는지 확인하세요. 로컬 경로라면 내보낼 때 '그림 파일도 함께 내보내기'를 골랐는지 확인합니다.
- **넣은 뒤 건수가 맞지 않습니다**: 작품은 번호로, 배우는 이름이 완전히 같아야 같은 자료로 봅니다. 번호 표기가 다르거나 이름에 공백이 덧붙으면 새 자료로 다뤄집니다.
- **패키지가 바뀌지 않았는지 확인하고 싶습니다**: 목록 파일에 적힌 각 그림의 요약값과, 패키지 안 실제 파일의 요약값을 비교하세요.

## 완전한 규격

이 페이지는 요점만 다룹니다. 폴더 구성, 목록 파일과 자료의 항목 정의, 그림 대응 규칙, 넣기 규칙 전체는 같은 폴더의 [백업 패키지 규격](./spec.md)에 있습니다. 소스 저장소의 설명도 여기에 남겨 둡니다: https://github.com/QYG2297248353/AMMDS-Docker

크롤링한 데이터를 AI로 표준 백업 패키지를 만들게 하려면 [AI 제작 가이드](./ai-guide.md)를 따르세요. 네 가지 질문에 답하고 프롬프트 하나를 복사한 뒤 산출물을 확인하면 됩니다. 템플릿 저장소: https://github.com/QYG2297248353/AMMDS-BackupPackage.git
